# 主动请求创建时预算与测试计划续写

2026-09-10，N0-03。Chat、风险建议、测试计划建议和报告映射在新运行INSERT的同一事务内创建预算绑定。配置继续来自已验证的应用Gateway和固定获批profile，不读取用户/模型传入的额度。默认仍legacy，没有真实计量发布或生产采用。

## 创建与准入

`freeze_created_application_run`在四个入口的新运行分支执行，使用当前事务连接写入不可变lineage和run link；运行创建失败或后续事务抛错时一起回滚。期限从数据库冻结时刻计算，独立于模型首次调用时刻。Chat/风险在后续上下文处理前已提交运行和预算；测试计划先完成确定性来源和请求校验，再原子保存请求event/audit、运行及预算；报告映射继续在项目写事务外创建运行和预算。

预算创建方法要求当前事务刚写入的running记录，调用方必须仅在新INSERT分支使用；Owner拥有的通用账本仍是受信服务端口，不能将它开放为模型工具。新运行尚未对其他事务可见，run link唯一约束约束重复绑定，父级profile/link不可变，因此这里不在已持租户行锁之后再获取全租户预算锁。实际模型预留仍沿既有SQL租户锁串行化，不改变累计额度和并发裁决。

显式应用工厂使用`ExistingRunBudgetLedger`：模型入口只核对创建时已有的绑定和profile，缺少绑定返回`BUDGET_RUN_UNBOUND`，不自动建立新期限或回退legacy。自定义运行包装如果遗漏创建端口，也无法通过该工厂补分额度。已有同号请求重放继续走原结果分支，不重写预算；终态失败不因重放变成新调用。

## 测试计划续写

`previous_finding_id`已经通过当前项目/计划、候选状态、版本和来源校验后，服务从该Finding取得父run；用户不能直接指定任意lineage。新的续写run绑定父run既有lineage，继承原profile、绝对期限和累计用量，不创建第二份额度。

- 父run不在同租户/项目、原预算过期或当前profile不一致时拒绝，新的运行、请求event/audit和预算绑定一起回滚。
- budgeted模式遇到旧未绑定父run时返回冲突，包含`BUDGET_PARENT_RUN_UNBOUND`；不会把原对话当新额度自动迁移。
- 即使续写进程切回legacy，已有父预算仍被继承，0070共同准入拒绝无控制器执行，返回`MODEL_CALL_BUDGET_REQUIRED`；不会把子run变成绕行入口。
- 每次已发送的模型调用仍计入同一预算。short档位的三次调用上限跨三次续写生效，第四个run即使已经创建也会在模型出口被拦截，不增加provider请求。

用户重新发起一个独立请求与续写已有对话不同，仍受租户每日额度和并发准入控制。本片不新增可重置预算的恢复按钮或批量迁移旧对话的操作。

## 范围

不新增表或迁移，复用0060以后预算元数据和0070绑定后强制预算准入；没有增加worker/Agent写权限。运行创建和预算绑定是应用服务元数据，AI业务输出仍沿现有Finding与独立人审应用路径。报告映射成功和Chat回答继续保持其只读/解析候选边界。

本片接通四个主动入口及测试计划续写的实际共账；未来新增关联run/多席位能力仍须在各领域入口显式继承，不能仅凭公共端口宣称已完成。活动时间、checkpoint恢复、工具循环、嵌入覆盖、真实计量资格和正式切换继续。真实部署/外部计量请求仍按原授权关卡。
