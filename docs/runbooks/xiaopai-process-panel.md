# 小Pai处理过程

按 v1.1 §06.10、§06.14 建设，适用于个人、品类和提案内的小Pai运行。此面板只读，打开、刷新与翻页均不派发模型或业务动作。

## 使用

打开原运行后，处理过程显示当前真实状态、已保存处理次数、实际业务提交数和历时。展开“查看步骤、依据与提交记录”可看已加载的方法、实际处理步骤、绑定依据版本、业务回执和未完成事项。步骤返回与业务批准分别展示，不用调用成功推断目标已经全部完成。

首屏至多 25 条，步骤、绑定依据与提交记录分别翻页；步骤按发生顺序展示，更早页合并去重。读取失败保留重试入口。权限失效时停止展示已缓存过程，必须重新核对当前状态。

历时从原工作受理开始，包含等待人员答复或运行条件恢复的时间。运行中按服务器观察时间更新；完成、失败、取消后使用真实追加终态记录固定时间，刷新不继续增长。旧终态缺少结束记录时显示“结束时刻未记录”，不会用当前时间补造。

## 服务器边界

- `GET /v1/personal/agent-runs/{run_id}` 及品类对应入口返回 `process` 元数据；普通运行结果仍沿原契约读取。
- `GET .../{run_id}/process` 按当前身份和 RLS 重验，仅投影必要元数据，使用同一只读快照。`before` 是步骤序号；`source_cursor`、`receipt_cursor` 是原运行内 UUID；`page_size` 为 1–100。
- 原始模型增量、内部推理、工具参数、模型结果、原件正文不进入过程投影。处理说明来自服务器登记的行动类型，不使用模型业务 JSON 冒充已执行事实。
- 完成、失败、模型不可用和取消记录与原 Run 状态同事务追加；失败一起回滚。原请求重放不追加重复取消事件。
- 主页面沿既有运行刷新周期更新；终态停止计时。追加过程记录不会改变工具、提示前缀、写入档位、资格或业务批准。
- 管理员结束未知等待后，通知现有 `cancel(tenant_id, run_id)` 端口；通知不可用时保留已提交核对记录，沿原恢复出口处理。
