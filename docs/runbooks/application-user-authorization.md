# 主动请求用户授权

2026-09-11，本地候选0081。Chat、风险建议、测试计划建议和报告映射四个预算主动入口在新run事务内固定用户AuthorizationEnvelope，之后才能计量与派发模型调用。这是应用侧Manifest的授权前置工作；完整应用Manifest仍需继续接线。

## 创建与复核

创建事务先沿既有规则固定或继承预算lineage，再根据服务端传入的实际发起人和固定用途签发授权。四个HTTP入口传入原会话auth_version；等待期间账号或会话版本改变时，创建事务整体回滚，不用当前新版本替代原登录凭据。没有启用预算的旧路径不补造授权。

四个HTTP入口在创建阶段发现授权失效时返回403，且没有模型调用。其他创建预算冲突继续使用受控不可用/冲突响应，不把运行授权失败暴露为未处理的服务端异常。

用途采用对应入口的既有操作权限：Chat用ai_chat.use，风险建议用risk_suggestion.create，测试计划建议用work_item.edit，报告映射用product_engineering.edit。当前用户必须属于同一活动租户且处于启用状态；角色必须具备该操作。Owner/Admin使用既有项目访问权，其他用户固定直接成员记录；没有直接成员记录时，固定一条当前有效的委托和委托人的项目成员记录。借用的是项目可达范围，操作资格仍来自发起人自身角色。

Envelope保存用户身份、具体purpose、原lineage、项目锚点、签发和截止时间及策略来源摘要。内部pins另外保存当前角色、auth_version、成员记录ID、成员用户和委托ID。期限不超过原lineage绝对截止时间，委托路径还受原委托截止时间限制。子run另行签发当前用户授权，但继承原预算与原绝对截止时间。

Gateway在调用登记前、每次输入计量前、预留后派发前复核当前授权。当前源码政策摘要、项目或Agent绑定变化会阻止继续；数据库派发触发器再次检查账号、角色/会话版本、租户、run状态、原成员记录及原委托的当前有效性。删除成员后重新添加另一条记录不恢复旧授权。原生输入计数可能发送提示词，因此同样受计量前复核约束。

模型响应后再次复核授权。此时失权会阻止返回模型输出，但已完成的模型调用仍保留成功trace和已发生用量；应用run记录不可用原因。结构化修复重试同样经过下一次计量前复核。派发前失权取消尚未派发的预留；已派发/未知调用沿既有结算规则处理，不因授权失效把用量清零。

## 数据与权限

application_authorizations位于既有cehub_ai namespace，独立记录用户主体，不把用户塞入事件服务主体表。四组复合外键约束run、lineage、用户和项目；历史不能UPDATE/DELETE。授权只在应用服务端创建，不进入模型上下文，也不授予Agent新的业务写权限。

Agent和Worker没有此表直接访问权，也不能调用其私有当前授权函数。迁移安装私有检查及预算派发触发器，无新增Agent可执行端口，因此DBA模板无需新增授权。新表有历史时禁止降级；空历史可降回0080。既有预算主动运行如果缺失授权，在模型准入前停止，不在调用时补写一份新授权。

## 后续范围

本片没有完成应用端ContextManifest/Observation、完整capability/toolset/release内容版本、Owner租约与持久恢复、多项目锚点或衍生来源ACL。Envelope中的capability/toolset仍为明确的入口政策家族标识，不能当作完整运行内容包。现有业务来源与提交时校验继续保留。真实模型用途资格、收费工具/嵌入核算和生产采用仍按原计划与授权推进，N0-03保持部分完成。
