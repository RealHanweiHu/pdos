# pdos-next 中断运行结果核对

适用 v1.1 §06.11、AT-61。此页只适用于 `pdos-next/`，不改变 T0/T1/T2、资格或业务批准。

## 页面办理

1. 在个人或品类小Pai的本人运行历史中打开“原调用结果待核对”。页面先读取当前可见的原调用、实际业务提交回执和自动核对时间；不重新执行原任务。
2. 当前租户管理员可点击“保留已做结果，结束本次等待”。只办理本人且当前仍可读的运行；管理员身份不会开放其他人的私有任务。普通用户可查看本人状态并等待自动核对。
3. 若保存响应不确定，保留原请求，读取原核对记录或刷新重开。刷新不自动提交；显式重试也先读原记录，已完成则返回同一核对事件。
4. 核对后，先看已保留动作和未完成事项，再按需要以新请求继续。原运行整体不会被误标为全部完成。已提交对象及其回执保留；旧未提交候选不能在已结束的运行内继续采用。

## 自动出口与费用

- `needs_reconciliation` 由真实 Temporal 持久计时器等待 5 分钟，再调用 `reconcile_xiaopai_run`。执行 Activity 三次重试耗尽后也进入同一技术核对路径。
- 技术核对以最长 1 分钟的间隔持续重试，直到依赖恢复或工作流被取消；不会因三次临时故障而永久遗留运行中作业。该 Activity 不建立模型宿主、不调用 LLM、不重发领域或外部动作。
- 原 Run 加锁，按实际 RequestKey、作者、请求人、操作及 Run 读取真实回执。有实际回执的调用补记完成；没有凭证的未完调用记失败。存在业务回执时 Run 为部分结果，否则为未完成；原目标仍保留未完成提示。
- 释放 Run/预算的活动预留。未知模型费用保留原预留上界的估算，不能当成免费或实际账单；后续真实计量资格另行办理。
- `cancel_epoch` 增加以阻断迟到的旧执行。一次事务同时落调用状态、预算、Run 和追加核对事件；失败全部回滚。接受过的原请求重放返回同一事件。
- 无幂等/查询凭证的外部副作用仍须向对方核实。技术上结束等待不代表远端未生效，也不批准再次外发。当前默认 MCP 图只执行已准入的读取。

## 接口与故障恢复

- 本人入口：`GET/POST /v1/personal/agent-runs/{run_id}/reconciliation`，品类入口为 `/v1/categories/{category_id}/agent-runs/{run_id}/reconciliation`。
- POST 只收 `expected_cancel_epoch`。身份、管理员资格、运行和回执范围由服务器核对；模型参数/客户端系统标记不能增加权限。
- GET 只返回核对元数据，不返回工具参数、原始模型回复或其他用户内容。`page_size` 最大 100，调用与回执分别使用原 Run 内游标。
- API 顶层 `reconciliation` 与读取接口的 `completed` 来自追加的真实 `run_reconciled` 事件。模型业务 JSON 中同名字段不能充当技术核对凭证。
- 页面显示最早自动时间。Worker/数据库停用时可延后；恢复相同 Temporal namespace/队列及数据库后持续处理。管理员已核对但后台取消暂不可达时，真实记录仍有效，原工作流恢复后只读取终态。
- 当前权限或来源撤回时拒绝读取/补记，不将不可读回执当作“没有结果”。系统沿既有受控失权收尾路径处理，不扩大读取范围。
