# Agent 租约到期与续租

2026-09-10，N0-03 本地候选，migration `0071_agent_lease_expiry`。沿用已批准的三档运行政策：租约60秒、每20秒续租。实际受限事件执行器和未绑定预算的兼容运行均执行此期限；预算模式默认仍为legacy。

## 行为

`claim_agent_run` 使用 PostgreSQL `clock_timestamp()` 创建租约，调用方的时间不能延长权限。服务端保留 `_lease_token`、`_lease_expires_at`、`_lease_renewed_at`；持久上下文接口不能用模型或调用方载荷覆盖它们。续租只更新这些控制字段，不改变模型前缀、冻结来源或预算绝对期限。

`RestrictedAgentRunStore.scope` 启动独立连接心跳，正常退出后停止。`renew_agent_run_lease` 在取得运行行锁后重新检查token和到期时间，已到期token不能复活；续租SQL的锁等待和语句超时均为5秒。心跳第一次失败便停止，后续受限操作返回 `AGENT_RUN_LEASE_LOST`，错误处理不会调用模型。线程退出最多等待1秒，连接建立仍可能由后台线程等待驱动超时。

投影视图、运行绑定、上下文持久化、完成/失败及Finding创建均检查数据库当前租约。已绑定事务在到期后再次查询也失去投影访问。Finding在锁等待之后、首次写入之前再次检查，保留原人审状态机及业务表零写边界。私有检查函数不直接授权给Agent，新增授权仅为持token的续租窄接口。

执行器失去权限时返回失败结果及明确错误码，但无权把数据库运行改成failed；数据库记录仍为running，留给可信服务恢复。此处运行日志失败不等于持久运行已经终结。迟到响应不能继续写trace/Finding或关闭在途记录；预算保留此前的已派发预留，不因失去租约自动释放或重发。

## 迁移与兼容

本次仅在pdos_test验证，未部署。未来生产采用仍须逐次批准：先停止新领取并排空旧执行器，确认无旧running任务，再执行迁移及匹配版本的DBA模板/执行器。0071不会给缺失到期字段的旧running token自动续命；不能通过补字段延长旧权限来绕过恢复流程。遇到未终结运行，应先保留在途费用/调用证据，等待可信恢复能力或具名处置。

迁移保存十个现有函数的不可变前后快照，不读取可变模板执行历史迁移。已有受限函数会被升级；全新库的受限角色及原函数仍由DBA手册安装。DBA模板与迁移函数有一致性检查，撤销模板也包含新函数的正确删除顺序。

存在带到期字段的running租约时拒绝降级；空历史往返已验证。其他预算/调用历史保护仍有效，不能据此直接降级有历史的环境。
