# 主动请求的 Owner 租约与过期清理

2026-09-11，本地候选 0084。显式预算模式下，Chat、风险建议、测试计划建议和报告映射在新运行的创建事务内取得执行租约，关联原用户授权。租约保存在 `cehub_ai.application_run_leases`，与冻结观察正文分开。

## 持有者与派发

真实 application gateway 工厂持有本次请求的随机 owner ID 和服务端 token 映射。token 不从模型参数或当前数据库值反向取得；另一个 gateway 实例无法凭 run ID 接管原请求。创建回滚时没有生效租约。默认 legacy 入口仍沿原兼容路径，已有预算运行不能回退 legacy。

心跳沿获批配置每 20 秒续租，租约最长 60 秒，并且不能超过原用户授权和预算绝对期限。续租锁定原 run，按数据库时间复核 token、运行状态、授权和到期时间；失效或结束的租约不能被心跳复活。工厂退出后停止心跳，未完成请求交由确定性清理。当前版本未实现新持有者领取或自动重跑。

Gateway 在计量前、Manifest 构建/派发前和响应后复核原租约。每个应用 Manifest 通过同租户/run 外键关联本次 lease ID，数据库在实际预算派发时重新检查该租约；跳过应用层检查不能继续派发。业务候选 INSERT 与 run 成功状态转换另有数据库门禁，必须由持有原 token 的事务绑定后提交。

租约丢失后不发布新 Finding 或成功结果。已经发生的模型调用仍记录真实 trace、结算可证实用量；失败结果可由原持有者收口，不能借收口路径变为成功。正常结束会固定 ended_at/stop_reason；lease 的身份字段与结束历史不可覆盖。两个人工动作的业务应用边界保持。

## 预算时间与监督

活动时间沿现有 `budget_activity_spans` 计量。创建事务内的原活动片段绑定租约，心跳同步期限；租约停止时，活动时间封顶到原 lease_expires_at，不把等待清理的时间继续计入活动使用量。

现有 dispatcher 每轮调用 `expire_application_runs(100)`。该窄函数采用 run 锁和 SKIP LOCKED，并在取得锁后复核期限；已失效的主动请求转为 degraded。没有未知派发回执时标记 APPLICATION_RUN_LEASE_EXPIRED；有已派发且尚未结算的最新预留时标记 APPLICATION_CALL_RECEIPT_UNKNOWN。重复清理不再次改变已结束运行。

清理不发起 LLM、工具或业务写入，不重置原 lineage/预算，也不释放未知回执额度。旧调用会话和未知预留继续保留供后续对账。该函数仅额外授予受信 Worker 执行权限；Agent 无执行权限，Agent/Worker 对租约表与私有有效性检查函数均无直接权限。DBA 安装脚本复用同一窄授权，回退脚本既有全函数撤权覆盖它。

## 迁移与剩余范围

0084 新增一张运行控制表和一个 Manifest 外键列；不添加 namespace。旧 Manifest 的新列为空，不补造历史；新预算请求必须在原创建事务内取得租约。有租约历史时拒绝降级到 0083，空库可回退并重新升级。
