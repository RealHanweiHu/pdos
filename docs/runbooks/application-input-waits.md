# 应用运行的持久等待

0089 在已采用完整预算的测试计划建议入口接通 waiting_input。模型仍只产生待审 Finding；如果候选包含未解决的问题，发布事务同时保存 application_input_waits，运行显示“等待补充”，结束 Owner 租约并停止活动计时。没有占用进程等待用户。

等待记录关联原 run、Finding、成功模型 checkpoint 和责任用户，保存问题、摘要、计划/候选摘要、来源、已完成回执及下一步；身份和交接内容不可改写，解决回执只追加一次。原绝对截止继续流逝。

现有的测试计划后续建议接口接收 previous_finding_id 和用户消息。创建后续 run 时复核计划、来源、候选和原用户/登录/政策，继承原 lineage/profile/截止；领取输入、关联后续 run 和结束原等待在同一事务完成。输入已接收后，后续执行成败由新 run 报告，旧等待记录保留追溯关系；重复或过期的旧等待不能重新领取。原请求号重放仍返回已有候选。

用户通过原 Finding 审阅入口接受（必要时编辑问题/判定条件）或拒绝，也会结束等待；这不替代独立的应用动作。拒绝理由、来源/计划复查等已有业务规则继续有效。等待超时由现有 dispatcher/application worker 的 expire_application_runs 处理，保存 APPLICATION_INPUT_WAIT_EXPIRED，不调用模型。

项目运行查询返回 input_wait，包含问题、责任人、截止、解决原因和后续 run。前端运行卡显示“等待补充”及问题，并链接到原候选。旧无预算/无授权适配器保持原生命周期，不追填可信等待记录。

当前接通的是测试计划已有的补充问题流程；其他能力的等待点、完整 RunControl 公共接口、通用取消/暂停和无最终模型结果的分步恢复继续按 N0-03 推进。生产及真实供应商资格未因本次本地验证改变。
