# 报告映射请求运行与重放

2026-09-10，迁移0069。Excel未知模板映射沿现有`quality_intelligence`和IMPORT_PROMPT创建用户发起的持久运行；服务端用途固定为`report-mapping-request-v1`。订阅与事件首尾为NULL、事件数为0、事件数组为空，不构造业务事件。旧事件Agent约束和worker/Agent写权限不变。模型只建议字段映射，映射成功不等于报告实绩已确认、Finding已应用或Gate已通过。

服务器以认证发起人、计划ID及原文件SHA-256生成稳定请求号，在tenant/project/agent范围内定位运行。仅改文件名不会产生新请求。同文件导入先持请求advisory锁串行化；创建运行只在短租户锁事务内执行，不持项目行锁等待模型。运行先提交，然后以固定`REPORT_MAPPING`调用槽调用Gateway。

运行保存计划ID、文件摘要、输入投影摘要、完整prompt摘要及版本、输出schema摘要。采样行原文不重复保存到运行请求元数据。相同请求的这些固定内容变化时返回409，不用新版本重新发出旧请求。运行结果和模型trace身份在业务写入前独立提交；Document/批次/实测草稿事务失败后，再次上传相同文件可复用已经成功的映射，仍按当前权限和最新业务事实决定是否落库。

终态失败返回`IMPORT_MODEL_UNAVAILABLE`；仍在运行或固定内容冲突返回`IMPORT_MAPPING_REQUEST_CONFLICT`。网关异常保留失败记录，进程在完成保存前崩溃可能保持running。相同请求不会自动新建运行或重发模型；自动恢复/人工对账后同lineage续跑尚未交付。已有确认映射或报告表单仍可走确定性路径，不要求重发失败的模型请求。

请求等待后、模型前后、取得最终项目锁后复查当前用户/认证版本和项目编辑权限。最终事务重新检查计划、已有批次及最新已确认映射；如预检映射已失效且没有候选，返回`IMPORT_MAPPING_CHANGED`。模型阶段无项目写锁，模型已产生的预算与trace不会因业务失败而抹除。

用户请求运行列表只向原发起人展示其请求；旧事件运行的项目访问规则保持。运行卡将零事件Quality运行显示为“报告映射”，来源为“主动请求”。其他项目成员仍沿原业务权限查看导入结果；运行隐私不改变业务报告的协作权限。

0069只扩展数据库允许的主动运行形状，不新增Agent键或业务写权限。有持久报告映射历史时降级被拒绝，禁止删历史绕过。仅本机pdos_test完成迁移和回归，生产未变更。预算在新映射run创建事务内冻结，再通过[显式应用工厂](application-budget-adoption.md)进行模型准入；默认仍legacy，合成计量发布包不可用于真实采用。
