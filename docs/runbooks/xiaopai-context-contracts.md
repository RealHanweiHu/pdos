# 小Pai按方法提供资料

实现 v1.1 §06.3、§06.7–8。十二个技能包分别声明 `context_schema`，引用同目录 [context-schemas.json](../../pdos-next/server/pdos_next/skill_packages/context-schemas.json)。配置加载时只解析登记的本地 schema，展开内容计入技能 digest；不访问网络或任意文件，不将版本写进数据库约束。

## 使用与查看

原有个人、品类和提案内委派入口保持。执行开始时先加载本次方法，再从当前 Run 的实际范围组装资料；公开研究和品类澄清不预装提案正文，提案起草、抽取、对标和查漏等工作方法可取得绑定的当前提案。需要更多资料仍由已注册的领域读取提供，来源与受众规则保持。

`skill.load` 后追加新方法所需的上下文与实际快照引用。系统提示和工具定义保持固定；不把技能元数据、模型参数或快照当成权限授予。删去部分提案内容不会把服务器绑定的内部/客户资料类别改成公开。

打开本人的运行，展开「处理过程 → 查看步骤、依据与提交记录」，可以看到资料范围核对、已省略字段数量和原因。记录不含被省略的字段值、完整资料正文或模型推理。刷新与重开只读原记录，不派发新的模型调用。

## 运行环境

`PDOS_ENVIRONMENT` 可取 `development`、`test`、`production`；未设置时按 `development`。开发和测试中，任何字段被投影删除都会报 `VALIDATION_FAILED` 并保留核对原因。生产环境省略未声明字段，记录原因并继续；必要字段缺失或类型错误在所有环境均拒绝发送。未知环境名称也拒绝执行，不自行当成生产。

上下文 schema 关闭根字段与固定对象字段；规格条目内容、正式领域引用等可变业务载荷继续受其原有专用领域 schema 校验，不再建立第二套领域规则。上下文合同不替代来源失效、权限、服务商协议、预算或资格核对。

## 快照与恢复

Run 的 `context_snapshots` 保存实际快照引用、字段范围、schema/内容摘要、已加载方法和确切原件读集/范围元数据，不复制正文。与对应 `context_projected` 事件在同一锁定事务内记录；同一份投影可重放原引用。发送前核对消息中的上下文内容及方法与实际快照一致，其他运行的引用不能借用。

图的持久检查点保留实际上下文与引用，重启沿原检查点恢复。原状态缺少当前字段合同快照、方法版本变化或内容不一致时显示版本/来源失效，不重发旧模型请求来补造快照。历史模型与业务回执保留；核对当前条件后可从原工作以新请求继续。
