# 主动请求的新持有者接续

0086 为已保存结果的预算应用请求提供原请求重试接续。当前入口是原 HTTP 请求的幂等重试；后台可领取队列、持久 waiting_input 和无结果时的分步恢复继续建设。

同一用户再次提交相同内容/request_id（报告为原文件/计划/用户摘要）时，服务端检查原结果 checkpoint。如果旧租约已过期，或监督器已将该 run 标记为 APPLICATION_RUN_LEASE_EXPIRED，新的请求工厂可领取下一代租约。仍在执行、已成功结束、其他终止原因、缺少可靠结果或存在未决回执的运行不会据此重新执行模型。

领取在同一事务内锁定原 run、验证原用户/登录版本/政策/profile 与已知回执，结束前一代、转换运行状态并建立新租约。原 AuthorizationEnvelope、lineage/profile、绝对截止、模型 trace、来源与预算账本保持；等待间隔不计入活动时间，新执行段重新计时。代次最多为 3（初次执行加两次恢复），不是模型重试额度。失败事务不保留半完成领取。

租约记录保留 generation、previous_lease_id 和 recovery_checkpoint_id，同租户/run 外键关联不可变历史；一个 run 同时最多一个未结束租约。续租与发布只接受当前请求工厂实际取得的 token，旧持有者不能成功发布或补写失败结果。恢复代次在数据库层禁止新的模型派发，已保存结果仍需 Gateway 的来源、内容包、模型政策、权限和活动预算复核。

- Chat 使用原观察中的引用重建答案，复核原来源；不会重新执行嵌入检索。
- 报告映射从相同上传内容重建输入，复用原模型映射，再按原导入事务/去重规则生成批次。
- 风险建议使用原冻结上下文重新预检；若 Finding 已发布，匹配原 origin/trace/payload 后复用其回执，不追加创建动作或事件。
- 测试计划复用原状态、消息、来源和候选上下文，重新校验当前计划/来源/前序候选；发布仍在原 Finding/事件/run 完成事务中进行，不重建请求事件。

这里的恢复不会自动接受或应用 Finding，不取消任何人工关卡；旧无授权/结果的历史不补写成可恢复运行。模型/内容包或来源发生变化时停止披露和新候选发布，不换一个新请求绕过原预算。未知调用仍待有据对账。

仅在本地 pdos_test 验证；生产和真实供应商资格依原批准规则执行。
