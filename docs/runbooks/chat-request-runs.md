# Chat 主动请求运行与重放

2026-09-10，迁移0068。已存在的只读项目问答使用`ai_chat`持久run，不借用事件Agent身份，也不创建业务Event或Finding。用户请求以`tenant/project/agent/request_id`唯一定位，并绑定当前认证的用户；订阅及事件首尾为NULL、事件数0、事件数组空。现有事件Agent继续要求真实订阅与非空事件。

`POST /api/ai/chat`接受可选`request_id`（去空白后1～128字符）。现有前端提交时生成UUID，在本组件存续期间，如果网络响应丢失，再次提交相同项目/问题沿用原号；收到终态结果后，下一次主动提交使用新号。问题或项目改变也生成新号。旧客户端未提供请求号时由服务端生成，每次HTTP调用都视为新请求，不能据此宣称旧客户端跨请求去重或刷新页面后的请求恢复已实现。

同号、同人、同问题的终态请求复用原结果；在途、内容变化或其他发起人复用返回409。不可通过新prompt内容或不同transport重试重发同一逻辑调用。数据库唯一约束兜底，事务租户行锁串行化查找与创建；不持锁等待模型。运行记录绑定稳定`CHAT_ANSWER`调用槽，真实模型trace与预算lineage指向同一个run。

首次模型出口和回答披露前重新读取用户、租户、认证版本、AI动作资格和项目权限。重放也重新鉴权；已撤销的权限不会因历史成功而恢复。冻结的来源摘要在模型调用前、回答返回前和历史回答重放时复查；来源改变或不再可读返回`CHAT_EVIDENCE_CHANGED`，不返回旧答案/引用，也不自动调用模型补写。复查不重新调用嵌入服务：普通来源按现有投影读取，知识直接检查当前同项目verified记录。新事件挤出旧投影等情况也可能令旧回答失效，此时可明确发起新的问题。

未知异常保留运行为不可用或在途，重放不得自行重新派发。保留的错误结果不会被请求重放改成成功。进程在最终保存前崩溃时可能保持running；自动租约回收/checkpoint恢复仍待建设。当前数据不自动清理，原保留政策和purge关闭状态不变。

项目运行列表只向原发起人展示其Chat运行，其他项目成员的旧事件Agent列表权限保持。项目问答使用独立中文标签和“主动请求”来源；普通事件仍显示事件数。提示词仍是已存在的`ai_chat_v1`，身份、请求号和运行元数据不加入模型提示词。

数据库worker的INSERT改为既有字段清单，不获新请求号/发起人字段的写权限。它继续能够派发事件Agent，不能伪造主动Chat请求。0068在已有Chat历史时拒绝downgrade；不要删除历史来绕过。升级现有安装会同步收窄该库已存在worker角色的列权限；新安装使用更新后的`agent-runtime.sql`。本次仅迁移测试库，生产须沿原授权流程。

Chat创建时已冻结预算，见[主动请求预算手册](application-run-budget-creation.md)。预算采用仍见[应用预算手册](application-budget-adoption.md)：默认legacy；真实计量资格及正式采用尚未就绪，合成测试发布包不得用于部署。报告映射已在0069另行接入；Agent预绑定、活动时间和全部N0-03仍未完成。
