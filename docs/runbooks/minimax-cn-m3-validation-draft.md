## 已完成的本地协议接线

- 服务器选择官方 `https://api.minimax.cn/v1`（及国际站同结构地址）时，小Pai 使用版本化的 `minimax-functions/v1` 格式。格式纳入路由和模型资格身份，不能继承其他格式的自动执行资格；不新增数据库约束或启用配置。
- [官方 Chat Completions 合同](https://platform.minimax.cn/docs/api-reference/text-chat-openai)列出了原生 `function` 工具，未在所读参数表承诺 `response_format=json_schema`。因此本实现选择已明示的 function schema 承载结构化结果，并在服务器继续校验结果；这是实现选择，不把“文档未列出”当成已经证明接口不支持。内部 `pdos_agent_output` 只回传结果，不能与业务工具混用，也不拥有领域执行权。需要答复时，其协议回读只表示收到模型结果，不是人员批准。
- 请求明确 `reasoning_split=true`；返回的分离或内联思考只保留在私有模型调用记录和检查点，工具调用后、等待答复或重启后恢复原助手消息。MiniMax 流式文本完整解析后才发布可公开的内容；过程仍显示真实步骤，公开事件不含思考片段。
- 现有其他地址继续使用原结构化格式；不自动把代理地址当成 MiniMax 官方接口。原输出上限、超时、预算及未知结果核对规则保持，不自动增加费用额度。实际模型是否能在当前额度下完成工作仍须联验。

[本地协议与实际进程证据](../reports/evidence/pdos-next-m3-20261016/minimax-wire/result.md)使用合成 HTTP/SSE 与 KMS。配置草案仍未登记/启用，价格保持过期及未核对标志，没有真实协议或资格；真实模型、账号计费与服务能力不由模拟结果证明。

## 联验顺序与结果

1. **当前本地准备**：沿既有[租户模型宿主手册](pdos-next-tenant-model-runtime.md)核对 DTO、地址、服务商键及失效价格守卫。草案不设置 `PDOS_TENANT_RUNTIME_CONFIG`，不访问 `.env`、真实密钥或云资源。
2. **真实调用前核对**：价格与计费材料已填好（见上表价格行与草案 `pricing` 块，经真实 DTO 加载 + `RateCard.validate` 通过：50 KB 请求预留约 22,115 微美元，20k 输入/2k 输出结算约 8,786 微美元，仅作量级自检）；剩余是实际租户、MiniMax API key 的授权 KMS 引用（替换草案占位 ARN）、预算与外部调用授权；通过既有配置预览/确认保存模型元数据及预算。明确授权外部调用时应列明测试数据范围和额度，而不是以此次服务商选型视为外发批准。
3. **协议范围（按 P26 修订，2026-10-18）**：服务商数据协议已改为可选治理工具，不再是出站前置；默认 Run 仍按实际范围绑定 `internal` 或客户类别并记入出站回执，只把提示词写成"合成"不会改变其分类。三入口含内部/客户资料的真实联验不再因缺少协议而阻塞，仍需取得对应外部调用授权；不得改标签、借假协议或复用原工程资格放行。若日后租户登记了当前有效协议，则按"服务商 × 数据类别"恢复限制执行。
4. **获授权后的单次闭环**：从既有入口受理 → Temporal → Activity → 注册 LangGraph → 模型网关，核对工具候选、一次人工确认及真实回执；等待回答后重启仍用原检查点，核对实际用量、费用和未知结果。直接 SDK 冒烟不替代应用闭环。不重复已通过的整套攻防。
5. **验收保留**：真实模型结果、三入口适用场景、模型与技能资格审阅、恢复和完整 M3/S1 出口按 v1.1 分别记录；用户 2026-10-17 已明确暂跳性能验收，原标准保留，暂缓不记为通过。试点草稿资格仍须用户本人审阅 10–20 个自有或合成案例，本草案不自动授予资格。

恢复真实联验的条件：MiniMax API key 已于 2026-10-19 由用户提供并存入本机 macOS Keychain（本地开发 KMS 路径），价格卡已按官方报价与当日汇率填好（有效期至 2026-11-18，逾期须重新核价），数据协议已按 P26 移除。剩余：预览/正式环境的启用链（模型配置确认、预算 T1、技能启用）与真实业务内容联验的外部调用授权；生产部署仍需阿里云 KMS 凭据。
