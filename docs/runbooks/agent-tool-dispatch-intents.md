# Agent工具调用前登记与次数限制

2026-09-10，N0-03，本地候选migration `0077_tool_dispatch_intents`。本片接通实际受限Agent初始读取节点的调用登记、一次性派发与预算链累计次数。后续0078已让[内部只读模型工具循环](agent-bounded-tool-loop.md)沿用这些端口；全范围工具接入及中途恢复继续。

## 执行顺序

实际执行器先通过`prepare_agent_tool_call`登记工具、稳定调用ID、输入和原预算链，再通过独立事务的`dispatch_agent_tool_call`取得唯一执行许可；两次事务提交后才进入handler。工具参数中的项目必须符合服务端绑定run，专业工具必须符合该Agent身份。模型没有这两个服务端口。

相同run/call_key、ID、工具和输入重复登记返回原记录，不再次占用次数；任一身份内容冲突拒绝。派发许可不能重复领取，包括已取得许可但响应丢失的情况。新调用使用新稳定ID；更换ID不能重置预算。

实际结果仍按0076生成Observation，新增同租户/run的`tool_intent_id`外键。数据库要求结果匹配该次登记的工具、输入、tool_call_id以及当前派发lease，不能在没有派发记录时追加新结果。重复保存相同旧观察保留原时间；历史观察不会被补造为新派发。

## 次数与时间

有创建时预算绑定的run采用原冻结profile的`tool_call_limit`。登记在与模型预算相同的租户锁内累计原lineage所有关联run的工具登记，并计入通用BudgetJournal中的工具调用；通用工具预留也反向计入这里的登记，两个入口不能各领一份额度。未登记到本表的旧Observation按关联run计入，避免仅因格式不同丢失可知历史。

登记即保守占用一次额度；失败、尚未派发、结果未知均保留，不自动释放。没有取消/退款端口。登记及派发都复核当前lease和预算累计活动时间、绝对期限；已排队事件还受原触发期限约束。模型调用次数和token账本保持原规则。

迁移记录不可改写的计数生效时间。预算链中存在此前已开始的run、活动区间或旧观察时，返回`BUDGET_TOOL_HISTORY_UNAVAILABLE`，不能把旧版本可能遗漏的调用算作零次。旧排队但尚未执行的run不因创建时间较早而被误拦截。禁止通过新建关联run、补假零、改时间或删除历史绕过这一限制；生产迁移/旧在途运行处置仍需对应批准和证据。

没有预算绑定的legacy run只记录登记和派发，不声称具有完整次数限额。默认预算模式仍legacy；此次没有切换真实租户。

## 中断及恢复

| 持久证据 | 含义 | 当前恢复行为 |
| --- | --- | --- |
| 只有intent | 没有取得派发许可 | 无结果checkpoint时停止，`AGENT_TOOL_NOT_DISPATCHED` |
| intent及dispatch，无Observation | 可能已经执行，缺持久结果 | 停止，`AGENT_TOOL_RECEIPT_UNKNOWN`，不重发 |
| 有Observation，无模型结果checkpoint | 工具结果已记录，后续模型结果缺失 | 保留原`AGENT_CHECKPOINT_MISSING`处理 |
| 有可信结果checkpoint | 可复用模型结果 | 原来源/版本复查通过后继续，不重复工具登记、嵌入或模型调用 |
| 已有Finding回执 | 业务候选已持久化 | 原回执收口；不改变人工接受/应用状态 |

模型会话/预算未知仍按原更早的未知回执分支停止；触发期限、订阅暂停和恢复次数限制继续生效。登记或派发不证明handler已完成，也不能冒充真实供应商费用回执。

## 权限、迁移与剩余

Agent只增加两个当前lease服务端口，没有新表直接读写权限；Worker不能调用这些端口。三张新增表（计数生效时间、intent、dispatch）及原观察均保留历史保护。0077空intent历史可以降回0076；存在intent时拒绝降级。升级先迁移，再执行现有DBA角色模板；模板的COMMIT位于所有端口定义之后，末尾失败整份装配回滚。撤销脚本只撤销暴露端口，不删除历史或私有触发器。

本片不把调用次数当作费用。真实嵌入/外部收费工具的成本预留、供应商未知费用对账及工具执行时长中断仍未完整接线。完整AuthorizationEnvelope/运行版本束、ContextManifest及压缩、全部衍生来源ACL、模型—工具循环、等待与分步checkpoint、Owner租约、生产采用及保留策略继续；N0-03未关闭。
