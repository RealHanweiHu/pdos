# 原件安全扫描：定时重扫、生产扫描档与病毒库更新

适用欠债总表 D215。此页只写运维步骤和判断依据。写这页时没有做任何生产操作，生产扫描档也还没有建立；下面"生产扫描档"和"病毒库定期更新"两节在执行前都需要对应授权（AGENTS.md"必须保留的批准与验收边界"）。

## 规则（不变）

- 扫描通过的回执有效 24 小时（`evidence_security/types.py` 的 `ScanPolicy.clean_max_age_seconds`）。过期后原件不能下载，AI 也不能引用，页面显示"扫描回执已超过有效期限"。
- 扫描引擎、病毒库或扫描政策的版本一变，按旧版本做出的回执全部失效，页面显示"扫描引擎、规则或政策版本发生变化"。
- 定时重扫只是续期，不放宽上面两条。

## 定时重扫（已实现）

- 每个租户一个长驻工作流 `pdos-next:maintenance:original_rescan:{tenant}`（`workflows/maintenance.py`），由 Worker 的发现循环启动，每小时一轮，持久计时器，一轮失败只记日志，下一轮照常。
- 每轮先由调度角色经 `original_rescan_candidates`（迁移 `s0_0858`）列出候选的引用：已解析、来源有效、未隔离，当前回执为通过，且已超过该回执自己的有效期，或做于 Worker 当前不再使用的扫描配置。函数只返回引用，不返回内容。
- 每个候选在原扫描申请人的范围内重新跑一次真实的扫描判定，确认确实只是过期或扫描配置变化，才经与页面"重新请求扫描"相同的 `request_scan` 提交新的扫描请求，之后走同一个扫描工作流。这与上传后首次扫描以上传人身份提交是同一做法。幂等键 `rescan:{original_id}:{epoch}`，一轮重试不会重复提交。
- 每轮每租户最多 25 页 × 200 条。该轮 Activity 的返回值记录本轮结果：`requested`（已提交）、`current`（复核后无需重扫）、`failed` 及 `failures`（按原因码计数）。没有配置扫描服务的 Worker 返回 `skipped: SCANNER_UNAVAILABLE`。
- 全程不调用模型。

### 页面上能看到什么

| 情形 | 页面状态与原因 |
|---|---|
| 已过期，会被自动重扫 | 扫描依据已失效：扫描回执已超过有效期限；已列入每小时一次的自动重新扫描 |
| 扫描配置变了，会被自动重扫 | 扫描依据已失效：扫描引擎、规则或政策版本发生变化；已列入每小时一次的自动重新扫描 |
| 原扫描申请人已无该品类写入权限 | 扫描依据已失效：……；原扫描申请人已没有写入权限，无法自动重新扫描，请由有权限的成员点"重新请求扫描" |
| 原件未形成可定位文字（未解析） | 扫描依据已失效：……；不会自动重新扫描，需要时请手动重新请求 |
| 重扫进行中 | 扫描处理中 |
| 重扫通过 | 当前扫描通过，AI 可再次引用 |
| 重扫未完成核验（超时、扫描服务错误等） | 扫描未完成核验 + 具体原因；自动重扫不会重复失败的回执，需人工重新请求 |
| 重扫检出风险 | 检测到风险 · 安全隔离 |

### 已知缺口（未在 D215 处理）

- 扫描请求提交后，若扫描执行时原件绑定或扫描配置已变，现有扫描 Activity 不写结果就返回，页面会一直显示"扫描处理中"，定时重扫也不会接手（它只续期通过的回执）。遇到时由有权限的成员手动重新请求扫描。
- 小Pai 选资料面板的扫描标签读的是原件上缓存的最后一次扫描状态，回执过期后仍可能显示"已记录扫描通过"。以原件页的安全状态为准。

## 生产扫描档（待建，须授权）

本地档 `local-synthetic-v1` 只用于开发：固定 digest 的 ClamAV 容器（`security_runtime/scanner.py` 的 `SCANNER_IMAGE`），`--official-db-only`，病毒库随镜像固定，运行中不更新，不构成生产资格。建立生产扫描档时要定：

1. 扫描引擎与镜像来源，以及病毒库的更新方式（定期构建新镜像并换 digest，或常驻扫描服务加独立的病毒库更新进程）；
2. 扫描政策版本名（`ScanPolicy.version`，与本地档区分）、单文件超时、大小与压缩包上限；有效期仍为 24 小时；
3. API 与 Worker 使用同一份扫描配置：两边不一致时，页面判断与 AI 读取时的判断会不同；
4. 部署位置、资源与监控随 D210、D213 一起定。

上线前在隔离环境核对：EICAR 测试串被检出并隔离；干净文件通过；超时与超限文件给出明确原因；扫描服务停掉时页面显示"扫描服务尚不可用"，AI 不引用该原件。

## 病毒库定期更新（运维步骤）

频率建议每天一次，与 24 小时有效期同节奏，最终随 D210 部署方案确定。每次：

1. 取得新病毒库或新镜像，在隔离环境按上一节核对一遍检出；
2. 记下新的引擎版本与病毒库版本；
3. 在维护窗口同时更新 API 与 Worker 的扫描配置并一起重启；
4. 重启后，旧回执全部显示"扫描引擎、规则或政策版本发生变化"，AI 暂时不能引用这些原件。定时重扫在下一轮（最迟约一小时）开始按新版本重扫，每轮每租户最多 5000 条；原件多时预留相应时间；
5. 观察 `original_rescan` 工作流各轮的 `requested`/`failed`，有 `failed` 时按原因码排查（申请人失权、扫描服务不可用等），必要时由有权限的成员手动重新请求。
