# pdos-next 默认公开研究运行配置

在 [租户模型宿主文件](pdos-next-tenant-model-runtime.md)增加可选 `research` 块，即可让默认 API/Worker 绑定现有 Searx 搜索、隔离网页/PDF读取、研究台账与作业文件，以及 PostgreSQL 子图检查点。省略或设为 `null` 时保持研究未接入，不影响其他业务。

```json
{
  "research": {
    "search_endpoint": "http://127.0.0.1:18888/search",
    "search_provider": "replace-with-registered-search-provider",
    "artifact_root": "/absolute/private/pdos-next/research"
  }
}
```

上面是需要合入宿主文件的字段示例，不是一份独立宿主文件；端口为占位，不代表本机服务已运行或获得外网调用授权。`search_endpoint` 指向管理员实际选择的 Searx JSON 搜索入口，可用服务器受控的 HTTP/HTTPS 地址，禁止 URL 用户名、密码、查询参数和片段；该适配不从环境继承代理或搜索密钥，也不支持在这个块中配置认证凭据。

`search_provider` 必须与服务商协议标识一致。网页读取逐站使用 `public-web:<hostname>` 标识，在 DNS 和 HTTP 之前检查实际将发送的查询/URL。服务器从当前 Run 的客户身份、型号、绑定原件文件名/正文、提案视图及已读领域事实识别敏感匹配，按实际命中的 `customer/internal/customer_original` 类别核对当前协议；无命中的公开查询标为 `public`，不因 Run 曾接触私有资料而要求所有站点签约。调用参数中的资料类别不能改写此投影，配置文件不会创建或批准协议。模型请求仍按完整 Run 的资料类别执行原有签约检查。

匹配使用 NFKC、大小写归一、两层 URL 解码和去分隔符；客户名、型号和文件名按完整标识匹配，正文按完整短值/查询及连续 12 个 UTF-8 字节的规范化片段匹配，覆盖短中文片段。该实现是确定性字面匹配，不是自动语义脱敏或真实资格证明；命中时拦截未获对应许可的传输，不由模型自行声明“已去标识”。查不到当前绑定原件身份或来源已变化时不降级成公开查询。

查询字段投影不会改写 Run 的私有上下文、资料范围或后续快照/Claim 的受众；私有提案中的公开发现继续按原提案受众处理。

`artifact_root` 为 API 与 Worker 都能访问的同一私有持久目录，须使用绝对路径。多主机部署需要挂载同一底层存储，不能仅让目录名称相同。按运行服务器 UUID 隔离保存正文快照及不可变研究台账；HTTP/模型工具参数不指定文件路径。保留这个目录及其数据库关联作为恢复材料，不把临时缓存目录当成长期作业卷。目录不可用时只禁用依赖的研究端口；恢复挂载后重启 API/Worker。

Worker 沿用 `PDOS_CHECKPOINT_DATABASE_URL` 及既有检查点目标核对机制；研究子图用独立 thread，与主图共同写入已核对的 `pdos_checkpoints`。缺少或不匹配的连接不会降级为内存检查点。本地 profile 需要 `PDOS_STATE_DB_PORT`、`PDOS_STATE_DB_MARKER` 对应现有独立环境，不填写业务库或复用未经核对的目标。

默认接线保留现有读取规则：本轮搜索/本人消息才可提供 URL，只有只读研究子任务接收网页正文；主循环读取逐字核对台账、实际快照引用与代码生成的覆盖/失败。公开 PDF 沿用隔离解析容器和固定镜像，解析服务不可用时如实失败，不在主进程替代解析。正式登记快照经受控命令；无资格/授权时保留 T1 预览和本人一次确认。

新完成的研究运行会由服务器把实际台账固定到结果的 `research` 区：去重来源/行数量、原快照标题/地址/读取时间、逐字片段与定位、覆盖和失败。模型提交的同名统计被替换；存在未完成研究时，不保留整体 `completed` 标签。品类/提案及个人小Pai共用同一展示组件，刷新和重开只读取原记录。旧运行没有该结果字段时不伪造空覆盖或零来源，也不批量改写历史结果。

小Pai准备的 `snapshot_candidate` 与其他领域候选共用“待你确认的动作”：先显示实际来源的标题、地址和保存范围，点击核对后预览，由本人一次确认登记。候选列表是只读查询，不创建确认材料、不登记快照、不重新调用模型；尚未登记的来源须重新核对原运行、读取证明和保留的快照内容，来源不可用或运行取消/失败时不能继续采用。已经保存的候选按实际命令、原请求和业务回执显示，原工作卷缺失不会把已保存记录变成新候选。

保存结果暂未返回时，页面保留原命令和确认材料并显示“保存结果待核对”。刷新或重开同一运行先读实际回执，已经成功则直接恢复；仍待保存时，只能在当前候选重新读取一致后由本人核对原请求，不自动再提交，也不生成新的命令或确认材料。[页面登记与恢复证据](../reports/evidence/pdos-next-m3-20261016/snapshot-ui/result.md)覆盖桌面亮色正常保存和 320px 暗色下实际提交成功后将响应替换为一次 503、重开读取同一回执；每例仅一次预览与一次保存提交。

修改研究服务端点、provider 或作业卷后须重启 API/Worker。模型/凭据/价格卡继续按原手册逐次读取。完成的研究台账可从同一作业文件恢复，核对原快照与实际读取证明，不重跑搜索或模型；终态 Run 不因此取得发起新工具调用的权限。

研究中途 Worker 重启时，默认持久宿主接续原 `research.fanout` 调用与固定作业 ID；同一编排由数据库会话锁排他执行，进程退出后释放，不在网络等待期间持有业务事务。服务器首次保存任务与规格字典版本计划，未完成作业接续时计划变化会拒绝继续。子图检查点同时按作业和任务隔离，两个作业即使问题相同也不会共用进度；同一作业恢复前按实际模型/读取回执重建已完成的搜索和来源状态，逐字重验原文件。已完成步骤不再次搜索、读取或调用模型。仅编排本身可接续，未完成的模型、搜索或网页调用仍按原未知结果规则办理，不能据此盲目重发。台账已写入作业卷但父调用尚未结算时，按固定作业 ID 读回原台账并结算。

[本地闭环证据](../reports/evidence/pdos-next-m3-20261016/research-host/result.md)使用实际默认 API/lifespan、Temporal、Worker 主入口、LangGraph/PostgreSQL、人工确认及业务快照；模型、KMS、搜索、DNS 和网页网络传输均为合成。真实搜索质量、站点连通性、真实协议和模型资格、生产卷/Temporal 恢复与完整 M3/S1 验收仍需对应证据。本次配置不创建云资源、不自动启动真实联网研究。
