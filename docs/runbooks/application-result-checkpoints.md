# 主动请求结构化结果 checkpoint

0085 将四个预算应用入口的成功结构化结果保存在 `cehub_ai.application_result_checkpoints`。结果关联同租户/run 的真实 Observation、最终尝试 Manifest、原 Owner lease 和模型 trace；唯一键是 tenant/run/model_call_id。新表不增加 Agent/Worker 直接读取或写入权限。

Gateway 先完成用量结算、trace 和来源复核，再在同一事务中关闭 model call session 并保存结果。保存失败时该事务回滚；既有 trace/实际用量不回滚，外层保留 unknown session。保存成功而调用者在返回前中断时，结果与 closed 收据均已持久化。

再次调用同一 Gateway 运行时，先检查原用户授权、当前租约、出站合同、完整本地内容包和当前来源；模型仍须可用且路由与原结果一致。命中 checkpoint 后再核对收据、累计活动时间并复核来源。命中路径不重新计量、准入、派发、生成 trace 或追加预算。不同用户/租约、撤权、来源/合同变化不能通过缓存取得结果。

数据库保存门禁要求：当前事务持有有效 Owner token 且累计活动时间未耗尽；trace 为已知用量的成功结果；最终 Manifest 对应同一 call 的最后结构化尝试；每次实际尝试已结算；run 下不存在未决预算或未关闭的其他调用。结果历史只允许追加，不能修改/删除；非空结果表阻止降级删除。只保存通过结构校验的输出，不保存原始供应商响应文本。

若保存瞬间租约或授权失效，返回不可用且不保存/披露输出，已知调用收据仍关闭，真实用量保留。超时、未知响应、结构失败和旧无授权历史不生成可复用结果，也不自动对账或重发。

本切片尚不提供 HTTP 请求的新持有者领取、租约代次、可领取队列、持久等待或分步重放。运行完成后的 API 幂等仍复用原业务结果；运行中 HTTP 重试仍遵守既有冲突处理。checkpoint 不是 Finding 审阅/应用回执，模型结果落库不代表业务候选发布或应用成功。跨进程自动接续须继续实现领取、原授权/版本复核和领域发布恢复。

仅本地 `pdos_test` 验证。生产部署、真实计量资格及各出口按原授权关卡执行。
