# 小Pai本次工作反馈

适用 v1.1 §06.14。个人、品类和提案内的小Pai使用同一入口，反馈保存在本人实际 Run 中。

## 页面使用

1. 打开本人运行，展开“反馈这次工作”。关闭时不读取反馈；展开后读取当前权限下的原记录。
2. 选择错误对象、错误数值、缺少来源、无价值、操作过多或不应自动执行，可多选。可补充说明，并选择本次实际加载的方法或本次工作整体。
3. 点击保存。服务器绑定原 Run、实际作者、原模型/工具/提示前缀版本及实际加载方法，不接受客户端指定版本。没有执行版本或方法时保留未知。
4. 需要立即停止后续执行时使用原取消入口。反馈只作私人记录，不修改业务决定、试点资格或 golden-case，也不自动进入模型上下文。

## 保存不确定与历史

- 提交前保留同一请求编号与内容，按本人、入口和 Run 隔离本地待核对请求。保存响应不确定时冻结该表单，避免把修改后的内容当成原请求。
- 刷新、重开和“读取原反馈记录”只读原请求记录，不自动再次 POST。已有记录则恢复同一反馈并清除本地待核对状态；显式重试也先核对原编号，再提交同一内容。
- 相同编号及内容返回同一事件；同编号不同内容返回 `DUPLICATE_INTENT_CONFLICT`。写入失败全部回滚，可以同一请求重试。
- 历史按事件序号倒序分页，默认 25 条、最多 100 条。“更早反馈”继续原 Run 的完整历史。每次读取和写入重验当前本人、品类/个人入口和来源权限；只读成员可记录本人反馈，其他成员不可读写该私有记录。

## 接口与记录

- `GET/POST /v1/personal/agent-runs/{run_id}/feedback`
- `GET/POST /v1/categories/{category_id}/agent-runs/{run_id}/feedback`
- POST 仅接受 `idempotency_key`、`categories`、`comment`（最多 2000 字符）和可选 `skill_load_event_id`。方法引用必须属于本次实际 `skill_loaded` 事件。
- GET 支持 `page_size`、本运行反馈序号 `before`，或按原 `request_key` 精确核对；后两者不能混用。
- 追加 `AgentEvent.type=run_feedback`，由 Run 行锁串行分配事件序号；不创建领域 `ActionReceipt`，不改变 Run 状态、固定历时、预算或模型调用计数。
- 版本来自原运行记录；读写只投影所需身份与版本元数据，不读取 Run 目标、结果全文或工具结果。反馈自由文本不进入默认模型上下文或公开过程投影。

无新增迁移，head 保持 `s0_0771`。见[本轮验证证据](../reports/evidence/pdos-next-m3-20261016/run-feedback/result.md)。真实模型、正式 M3/S1 出口及后续效果复查仍按唯一清单推进。
