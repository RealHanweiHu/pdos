# N0-03 主动请求新持有者恢复验证

2026-09-11，本地候选 0086。四个应用 HTTP 入口可在旧执行者过期后，按同一用户和原请求接续已持久化结果。新代次保留原预算/授权及调用记录，不重新生成模型结果；N0-03 仍为部分完成。[运行说明与限制](../runbooks/application-result-recovery.md)。

## 实现与实际入口

- Owner lease 新增 generation、previous_lease_id、recovery_checkpoint_id；同租户/run 外键保留代次链与原结果，一个 run 最多一个未结束租约。历史和身份字段不可覆盖。
- 领取事务验证原 actor、登录版本、政策和预算 profile，校验所有已知回执后结束旧代次、恢复原 run 并建立新代次。并发竞争只产生一次领取；最多三代，原 Envelope、lineage、绝对截止及原模型调用不重新签发。
- 监督器已停止的运行和仍未清理但租约已过期的运行均能从结果接续。旧 token 不能发布成功或补写失败；活动时间保留旧分段并从新持有者执行段继续累计，等待间隔不重算。
- Chat 用原引用构建答案，允许必要的确定性来源复核，不重做嵌入检索。报告映射复用原文件/计划/用户请求与模型映射，业务导入去重保留。
- 风险建议复用原冻结上下文重新预检；已发布 Finding 匹配原 origin、trace、payload 后复用回执，不增加创建动作或事件。测试计划复用原状态、消息、来源和前序候选，重新验证后在原事务里发布，恢复不创建新的请求事件。
- 改变原授权/profile 或存在未决调用时，不产生新租约；改变本地内容包则停止恢复输出与候选。恢复代次禁止再次派发模型，已存结果仍受 Gateway 的当前模型政策、权限、来源和活动预算检查约束。

## 验证结果

197 项不同测试通过：19 项新增恢复用例、27 项租约/checkpoint 回归、109 项业务 API/上下文回归，以及独立测试库的 42 项受限账号/活动预算回归。新增用例覆盖四个真实 HTTP 入口重试、并发领取、次数上限、原授权与版本检查、已发布 Finding 去重及禁止新增模型派发。模型响应使用合成 transport，没有真实模型费用。

首次大批业务回归为 109 通过、1 失败：新禁派发测试走了未绑定预算的测试接口，数据库已拒绝派发，但抛出的异常类型与测试预期不同。改用实际绑定预算接口后单项复验通过；不重复计算通过用例。较早的内容包变更测试已修正为变更所有领域共享的源码摘要，18 项恢复测试整批通过。

7 个源码文件类型检查、12 个文件 Ruff/格式检查、4 份共同合同与 5 份运行合同导出检查通过。两个 pdos_test 数据库均核对至 0086，函数体与迁移快照一致，代次链外键及唯一活动租约约束存在；专用 57433 测试容器已清理。两份获批 manifest 原件摘要不变。
