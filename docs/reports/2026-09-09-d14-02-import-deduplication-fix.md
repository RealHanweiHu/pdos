# DUP-01 相同报告复用批次：修复与验收

日期：2026-09-09。用户明确要求“修复重复内容识别，并提示复用已有批次”。本地修复已完成：同一租户、项目、测试计划内，相同文件字节按 SHA-256 识别，返回原批次及状态，不再创建文件、批次或 Run。改文件名仍复用；不同计划或文件内容变化分别导入。

## 最终行为

- 新文件导入返回 HTTP 201、`reused_existing=false`；重复文件返回 HTTP 200、`reused_existing=true`，原 `document_id`、批次 ID、Run ID 与跳行说明不变。
- 待确认、已确认、零有效记录批次均可复用；复用不触发确认、不修改旧结果、不增加事件/审计或模型调用。
- 历史重复批次保留，优先选择已确认批次；同状态按创建时间及 ID 稳定选择最早一批。不清理或合并用户历史记录。
- 项目事务锁覆盖重复查询、文件保存和批次创建，两个并发上传只产生一批。文档与批次共用连接和事务；解析失败回滚文档元数据并清理已暂存文件，允许重试。
- 使用已有字段与项目锁，无 schema 改动或新增迁移。直接 SQL/旧版本服务绕过本次入口的写入不由该锁自动防重；未来如新增导入入口须复用该服务。

质量页每个可编辑测试计划增加“导入 Excel 测试报告”入口，复用后显示“相同报告已上传，已复用待确认批次”或“相同报告已确认，已复用原批次”，明确未新增记录，展示状态、记录数量和批次编号。已确认批次提示无需再次确认，零记录提示核对缺项。上传完成会刷新用例与覆盖数字，同时保留批次提示；本次没有新增整批确认按钮。
