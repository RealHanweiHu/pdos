# N0-03 持久运行内的稳定模型调用身份

2026-09-10。事件执行、风险建议和测试计划建议三个已有持久run的真实入口，现向Gateway传递服务端生成的稳定model_call_id。N0-03保持部分完成，默认预算工厂尚未启用。

`call_identity.py` 用持久run UUID作为UUIDv5命名空间，以固定的`pdos-model-call.v1`和具名操作槽位生成调用ID。同一run/操作重复构造得到相同ID，不同run或操作分离。身份不随prompt修订、输入变化或传输重试变化；实际请求摘要继续由预算账本绑定，已派发请求的内容变更返回冲突，不能靠新ID重复取得派发权。该标识是关联键，不是授权凭据。

真实入口的回归fake检查收到的调用ID；另有数据库用例证明首次请求成功后，同run/槽位改变指令再调用会返回BUDGET_ATTEMPT_CONFLICT，只有一次请求抵达模拟Provider，预算仅保留原三条预留/派发/结算记录。身份生成器还验证序列化后稳定、操作和运行隔离，以及无持久UUID或无服务端具名操作时拒绝。

33项身份、实际入口和预算重放测试通过，9个相关文件Ruff通过。4个实现文件Mypy通过；共同合同检查通过，运行合同清单已刷新并通过检查。获批原件保持不变。机器摘要见[证据](evidence/2026-09-10-n0-03-model-call-identity.json)。测试只连接`127.0.0.1:57432/pdos_test`，不运行修改角色密码的fixture，不访问真实模型。没有新增迁移；测试库随现有fixture升级至0067。
