# N0-03 逐次模型预算接线验证

2026-09-10。继续已批准 DC-07，新增 Gateway → ModelBudgetController → BudgetLedger → Provider 的实际调用路径。N0-03 仍部分完成；此路径须显式装配，默认应用/受限 Agent 工厂尚未启用。

## 实际路径

1. 可信服务传入固定 model_call_id、run/tenant、预算 profile 和具体 provider/model 的计量资格。没有身份或资格、计量失败/非法、超过上下文交集时，零 provider 请求并返回明确错误码。资格包含模型窗口、输出能力、输出参数名、计量版本和证据引用；不从用户正文推断。输入上限保留合同规定的下一工具和安全余量，输出上限取运行预算与模型资格的较小值。
2. 对实际 structured messages（包括 JSON Schema、投影上下文与重试提示）、路由地址和输出参数计算摘要。0062 在追加账本中保存请求绑定，包含 call/attempt、模型、资格和限额；正文与凭据不存入预算账本。对同一稳定 call_id 和结构化尝试序号生成固定 attempt_id，预留时比较完整绑定，不能用相同 token 数替换正文或资格。
3. 每次结构化重试分别预留；预留成功后取得数据库唯一派发授权才调用真实适配器。所有尝试沿已绑定 lineage 累计，额度不足时不会发送下一请求；同一 call_id 并发或重放最多一次派发。派发前运行终止则取消仍未派发的预留；并发已授予的派发不能被取消释放。
4. Provider 返回正常、正文无效、截断等响应时，有可信 usage 才以结构化用量凭据结算。账本验证请求摘要、输入/输出和、请求标识及凭据摘要引用；缓存仍为总输入的分项，金额未知保持 NULL。Provider 超过实际输出或输入上限时按真实用量结算并拒绝输出，不把超额用量截成预算上限。
5. 超时、无有效 usage、SDK 异常或中断按未知响应保留全部额度。重放旧调用不能再次发出请求，新调用也不能绕过同 lineage 的未知占用。回执持久化失败保留预留，并按已发生调用留痕，不能变成 not_invoked。以后有匹配的回执可通过同一受控结算接口对账。
6. model_invocations 增加 budget_call_id，以稳定调用关联逐次账本与本次聚合 trace。0062 只追加列和 JSON 形状约束，保留旧数据、旧调用接口与追加触发器；新模型预算证据存在时拒绝降级，空证据可往返。

## 验证状态

最终结果：综合回归 114 passed（含当时 23 个集成测试），模型输出资格交集补充后集成文件 24 passed；与合同/日历 160 passed 合计 **275 个不同测试通过**，复验不重复计数。Ruff/格式检查覆盖 10 个本片相关文件；Mypy 覆盖 model_budget、budget_evidence、budget_ledger、gateway、schema 五个实现文件。两套当前合同导出检查均通过，获批原件摘要未变。源码、当前合同及获批摘要见[机器证据](evidence/2026-09-10-n0-03-model-budget-integration.json)。

测试仅连接本机 `127.0.0.1:57432/pdos_test`；0062 未应用到开发/生产库。计量器和模型资格均为明确的合成测试数据，Provider 使用真实适配器和 MockTransport，另外回归两种协议的本机 HTTP socket 合同。没有调用真实模型或新增真实模型资格。

初轮 57 passed / 10 failed：9 个新断言误读了 seed 的历史 trace，已改为按本次 GatewayResult.invocation_id 查证；1 个测试缺少 degraded 状态必要的错误码，已修正为合法运行终止。修正后原 16 个集成测试全过。后续增加 SDK/中断未知持有、资格窗口交集、资格替换、DB JSON 负向及模型输出能力交集。

综合回归曾停在 Python 导入缓存的文件读取。原 pytest 进程和数据库容器均仍运行，调用栈显示 read，数据库仅等待客户端；未重启测试、终止数据库或清理缓存。之后原会话恢复输出并以 114 passed 正常结束（423.93s）；后续最终集成复验 24 passed（29.05s）。没有因观察超时重复启动原测试。

## 尚未完成的采用条件

- 默认应用/Agent 工厂尚未启用此路径；需实际模型窗口与输入计量资格及其可信加载/评测来源，不能把本轮合成测试当作资格通过。
- run/call_id 的业务入口赋值、跨工作进程固定与 checkpoint/resume 仍需接入。已有已结算响应的正文恢复尚未实现：重放安全拒绝重复请求，不等于能够恢复原业务输出。
- 账本准入尚未合并旧 model_invocations 用量和未对账旧错误；budget_call_id 只提供防重复计量所需的关联。旧调用与新账本混用仍不能声称实现全租户原子预算；这也是默认工厂未采用的原因。
- 受限数据库角色的预算服务接口、活动租约/预算、工具预算调用、完整工具循环、持久 rollout/bundle 和来源 ACL/checkpoint 恢复继续按 N0-03 交付。当前 owner/service ledger 不授予 Agent 新业务写权限。
- 本轮未关闭 N0-03、P/Q/Sprint 出口，未执行生产部署、真实外发、git push 或修改 golden 可信根。
