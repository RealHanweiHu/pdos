## 语义复核后的修正

除程序检查外，独立只读审查了旧 V3–V6 的 42 个保留条目及新增员工场景，并修正以下问题：

1. **早期专业约束不能等待产品定义发布。** N2-03 支持在 opportunity/草案 definition 范围形成专业约束与计划候选；N1-05 以此制定策略，正式任务/基线应用才要求获批输入。
2. **首版计划不能等待计划内的 ID 工作先完成。** N2-04 明确未来 ID/接口冻结作为里程碑和下游前置，不阻塞包含这些工作的首版计划发布。
3. **公共候选编排不能反向等待后续领域。** N3-01 以 Task/Issue 首批真实办理验收；专业适配器分别在 N4/N5 交付，全部联合验证归 N7-02，消除文字条件形成的隐藏循环。N3-05 同样区分基础议程和后续 Forecast/物料接入。
4. **产品矩阵应支持立项前比较。** N6-04 依赖范围与发布定义，不等待正式项目链；项目结果反馈归 N6-05。
5. **新增员工价值必须有对应样本。** N7-03 明确产品经理研究到规格和 DQE/SQE/IE 早期评审样本，不能用已有研发执行数据替代。

本次仅确认计划可追溯、依赖和责任清晰。真实工期/容量、业务指标阈值和功能效果须在相应工作项中取得证据；全部新编号保持未完成，下一项为 N0-01。
