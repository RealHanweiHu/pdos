# ID 立项专项与四专业依赖：本地验证

日期：2026-09-09。用户明确研发包含 ID、结构、硬件与嵌入式；ID 周期占比较大，应在立项阶段单列确认，任务依赖必须明确。

## 本轮结果

- 管理流程更新为 [v1.1](../design/2026-09-09-management-process-v1.md)：立项先确认 ID 来源/范围、具名责任与资源、设计/评审/反馈等待/缓冲周期、冻结目标及下游影响。后续完成方案冻结，两个节点分开。
- 项目概览新增四专业说明和 20 项任务依赖基线，每项显示前置任务、交付物与接收专业；ID 计划在概念、规划、设计阶段单独展示。
- 前端与隔离模拟共同消费 [JSON 基线](../../web/src/components/projects/npd-disciplinary-task-template.json)，避免依赖定义分叉。
- 模拟新增 ID、结构、嵌入式三个独立 Engineer 账号，原研发账号承担硬件任务；不增加权限角色或修改现有 Gate 三槽签核政策。

## 真实 API 模拟验证

使用 `scripts/simulations/npd_project_lifecycle.py --disciplines`，保持完整需求→案例→七阶段→问题整改→移交→归档主线，新增 20 项具名任务及依赖。最终 **28 个任务完成、7 个 Gate 批准、1 个问题关闭**。

| 场景 | 实际检查结果 |
|---|---|
| 立项 ID 计划 | 形成独立决策，明确 ID 负责人、确认人、范围、模拟预算、周期与冻结目标；完成 ID-PLAN 任务 |
| ID 与预研并行 | 同一快照中 ID-CONCEPT、MD-PRE、EE-PRE、FW-PRE 均处于 in_progress |
| 共同接口前置 | 三专业预研完成但 ID 方案未完成时，INTERFACE 开工返回 TASK_DEPENDENCIES_INCOMPLETE |
| ID 未冻结 | MD-ENVELOPE、EE-PCB 提前开工均被拒；FW-BASE 可开始，结构板框保持 waiting |
| 结构/硬件并行 | 板框完成后，MD-DETAIL 与 EE-PCB 同时处于 in_progress |
| 板级联调汇合 | 固件基础完成但 PCB 未完成时，FW-BRINGUP 开工被拒；两者完成后可开始 |
| ID 延期 | 模拟方案确认由 10/02 改至 10/09、冻结目标由 10/16 改至 10/23；独立 rebaseline 决策和任务更新保留原值及影响说明 |

上述日期、周期及预算仅为合成场景，不构成实际项目承诺。除 ID 专项节点外，其余模拟任务使用宽泛的场景日期窗口，未据此推算实际关键路径或总工期。实例中的设计/BOM/报告与任务采用模拟证据引用；系统尚未将每种业务产物创建动作自动绑定到任务依赖。

## 工程与界面验证

- 15 项聚焦测试通过；完整前端 **75 个文件、358 项通过**。
- 受影响前端 ESLint 通过；Next.js webpack 生产构建及 TypeScript 检查通过。
- 基线检查覆盖唯一编号、引用有效、无环、前置阶段顺序，以及可并行/必须等待的核心关系。
- 本机真实浏览器核对完整模拟项目的 28 项任务；额外 concept 页面夹具核对 ID 立项专项、本阶段 2 项和完整 20 项基线。桌面 1440px、手机 390px 无指引横向溢出，页面异常为 0。
- 浏览器首次检查同时定位到本阶段和折叠的完整基线中的同名任务；限定当前项后通过。两次尝试创建的临时 concept 项目随同回滚。
- 5 个相关前端文件与隔离构建目录逐字节一致。本轮未更改服务端业务逻辑，不宣称重跑后端全量测试。
