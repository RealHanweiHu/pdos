# N0-03 新旧用量对账验证

2026-09-10。继续已批准 DC-07，补齐显式预算准入读取旧 trace、追加对账证据与新账本去重的路径。N0-03 仍部分完成，默认运行工厂尚未采用完整预算路径。

## 实际变更

- 0063 为 model_invocations 增加用量状态与输入计量版本，旧行默认 legacy_unverified，原 token/费用值不重写。Gateway 新记录明确区分 known、partial、unknown、not_invoked，并标记 normalized_input.v1；金额未知与 token 用量未知分别记录。已收到完整 usage 的错误响应可以具有 known 用量，传输失败的先前尝试用量只算 partial。
- BudgetLedger 在原 tenant 事务锁内合并最新账本与未绑定的已知 trace；读取当前租户预算设置，与调用方旧快照取较小限额。未核实的旧计量或没有完整响应的旧调用，缺少对账证据时返回 BUDGET_LEGACY_USAGE_UNRESOLVED，跨日不自动视为零。
- budget_call_id 必须存在同 tenant/run 的实际账本绑定才能用于去重，空标签不能免扣。账本覆盖的汇总 trace 不再次相加；若已知响应用量高于尚未结算的预留，只补计差额。差额随未决调用跨日保留；延迟到次日的汇总不再给昨日已结算调用重新扣算。绑定覆盖计算包括历史已结算尝试，防止把它们通过汇总又算进今日。
- 新增 legacy_usage_resolutions 追加表与 LegacyUsageReconciler 服务端接口。只有同租户、当前有效的 Owner/Admin 能提交外部可核实的归一化用量证据；检查时锁定用户行，撤权不能在该事务中越过检查。记录来源引用、用量、内容摘要、审核者与版本。完全相同的重放返回原记录，更正需要匹配当前版本并追加，不能覆盖原 trace 或旧对账记录。
- 用量已知或已进入新账本的调用不能走旧记录对账通道。账本调用仍使用其 request/usage evidence 结算接口。SQL 保留租户复合外键、归一化缓存分项约束、追加触发器与新证据存在时的降级保护。
- 准入查询过滤已知的非当日旧记录，并只查候选 trace 关联的账本调用；仍保持对未决历史的检查，不以过期缓存替代真实性判断。

这里的对账是 owner/service 内部接口，尚未新增面向员工或模型的对账 API/工具，也未授予 pdos_agent 对账表写权限。外部证据真实性需要受信审核入口验证，不能仅凭填写一个来源字符串就自动采用。

## 采用仍需完成

1. 老代码或未接线入口正在进行的 provider 调用没有事前预留，本片不能追溯性地锁住它们。默认启用前还需统一准入与切换时的在途协调；不能据此声明新旧入口混用已实现全租户原子预算。
2. 真实模型窗口、输出能力、输入计量资格的受信加载，以及业务入口固定 run/call_id、受限数据库角色预算服务接口、活动租约和 checkpoint/resume 仍待接入。
3. 对账审核入口的来源验证、操作界面/批量准备与统一预算可见状态继续完成。现有治理页汇总尚未改成账本与对账后的完整视图；原始 trace 持续可审计。
4. 工具预算/循环、持久 rollout/bundle 与来源 ACL 等 N0-03 剩余项保持。N0-06/N2-01、P/Q/Sprint 状态不变，没有生产部署、真实外发、git push 或 golden 改写。
