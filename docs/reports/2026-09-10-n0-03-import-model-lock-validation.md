# N0-03 导入模型调用与项目事务分离

2026-09-10。核对导入映射持久运行入口时发现，原`start_import`在项目行`FOR UPDATE`事务内调用Gateway。Gateway使用另一连接写入带项目外键的模型留痕/准入记录，可能等待前一个事务；前一个事务又在等待Gateway结束。这也是后续给映射创建持久run时必须先解决的事务边界。

模型映射现已在项目写事务外执行。相同tenant/project/plan/文件SHA-256先取得请求级advisory事务锁，用于串行化同内容导入；这层事务不写业务记录、不锁项目行。预检检查当前访问、计划、已有批次、文件提取/工作簿边界与已确认映射。未知模板才调用模型；已有模板和报告表单继续走确定性路径。

模型返回后再次取得项目写锁，重新检查当前权限、计划、重复批次及最新确认映射，再以原子事务创建Document、导入批次及确定性实测草稿。如果预检时可用的映射已失效而没有预生成候选，则返回`IMPORT_MAPPING_CHANGED`，不在业务事务内补调模型。待确认导入仍不等于正式实绩采用或Gate通过。

认证检查沿当前`PRODUCT_ENGINEERING_EDIT`，没有提前新增Quality权限。API把已认证会话的auth_version带入服务；请求等待、模型出口和取得项目写锁后复检主体、认证版本、租户和项目权限。模型期间撤权返回403且不落业务记录。模型已产生的计量/trace仍应保留，不回滚成零调用。
