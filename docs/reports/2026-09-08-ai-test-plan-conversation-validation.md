日期：2026-09-08。对应 [功能合同](../design/2026-09-08-ai-test-plan-conversation-contract.md)。**模板 + 用户对话的首个本地闭环已实现并完成工程验证**。此记录不代表完整功能合同、真实试点或 Phase Exit 已通过。

## 交付行为

用户在测试计划旁点“用 AI 调整测试项”，直接描述新增功能或客户要求。系统带入当前模板和对话，生成新增/修改/不适用候选；缺条件时展示追问。用户可继续补充、逐字段修改或取消候选项，再在既有 AI Review 接受、独立应用。

“接受”仅冻结建议；“应用”才创建计划新修订。新用例全部从待执行开始，旧计划、测试运行与报告保留。来源消息、原值、建议值、人工修改和两次动作均可追溯。

当前输入为模板与用户文本，可转述客户要求；**选择 Requirement/Specification/已上传客户文件并绑定版本的入口尚未实现**。系统不把用户转述标成已批准文件。相同标题和重复目标可确定性检查，语义相似、来源冲突及技术依据是否充分仍由用户审阅。

## 实现与数据边界

- 采用既有 Quality Intelligence、统一网关、AI Review 和项目测试对象，新增显式请求能力 `quality_intelligence.test_plan_change`，不订阅事件自动产生测试政策。
- 本地迁移 `0058_ai_test_plan_changes`：扩展 Finding/质量控制类型及 `test_plan` 应用目标；计划增加同租户同项目的父计划/Finding 外键及唯一约束。已有候选或修订时拒绝有损降级，数据库角色权限不变。
- 模型只返回候选结构和当前输入中的来源标识；系统按标识绑定原文（仅去除两端空白），不存在、越界或重复来源拒绝。用户编辑后仍复核引用原文。模型和文本中的“已批准”等内容不作为授权事实。
- 模型不接收执行结果、报告内容、账号信息或自由工具；生成、审阅、应用均按服务端项目/租户范围检查。单轮最多 4,000 字符，最多 12 条消息、60 项候选、100,000 字符上下文；保存载荷最大 200,000 字节，超限显式要求拆分，不静默截断。
- 每轮保存独立 run、调用记录和 Finding；新候选成功后旧候选失效。接受仅冻结，应用事务内创建新计划、用例、事件与审计。一个原计划只有一个后继，下一轮从最新修订继续。
- 源计划、用例、Run、报告指纹在生成结束、接受、应用时复核；发生变化要求重新审阅。降低原项必测要求、排除已有执行决策/Run 的项、取消全部必测项均会被拦截。
- 沿用质量暂停/模型预算与资格门禁；模型失能可见，已存草稿可查看。请求编号避免同次重试重复生成，应用幂等。BFF 的建议请求有独立等待上限；Review 请求体按流限制为 256 KiB，以容纳完整模板，其他 JSON 路由仍默认 16 KiB。

## 真实模型与浏览器证据

使用已存在资格的 MiniMax-M3，输入仅为虚构指示设备的一项模板及虚构用户要求。模板要求“输入 B 显示 B”；对话先要求增加模拟指示功能但未提供条件，再补充“输入 A 显示 A，保存照片”。**未把用户两份真实报告发给模型，也未创建真实 D14-04 项目数据。**

| 调用版本 | 模型调用结果 | 业务预检及观察 | 延时 / 总 token |
|---|---|---|---|
| test-plan-change-v1 | 结构化调用成功，1 次尝试 | 缺输入/判据时生成待补条件，浏览器接受按钮不可用 | 15,728 ms / 5,502 |
| test-plan-change-v2 | 结构化调用成功，1 次尝试 | 模型转述来源导致原文匹配失败，run 降级；没有创建该轮 Finding 或业务计划 | 20,122 ms / 4,585 |
| test-plan-change-v3（当前） | 结构化调用成功，1 次尝试 | 改为模型选来源标识、服务端绑定原文；继承两轮条件，保留原项，只新增一项，没有继续追问已补齐的条件 | 11,051 ms / 2,906 |

以上是三次不同版本的单场景实验，不是统计性能或广泛质量结论。v1/v2 文件保留供调用追溯，当前能力使用 v3；未改 golden 可信集或模型发布资格。

浏览器走查由 Codex 操作测试 Owner，过程及数据库交叉核对如下：

1. 缺条件候选可查看追问，不能直接接受；补充条件生成新候选，旧候选标为已有新修订。
2. 在 AI Review 将新增项名称改为“模拟指示（人工核对）”，点击“确认修改并接受”。界面显示待应用，数据库后继计划数仍为 **0**。
3. 单独点击“应用到业务对象”，核对最终预览后“确认应用”。动作记录依次为 created → accepted → applied；人工修改后的名称保存在正式新用例中，原始模型名称仍在候选历史。
4. 返回质量页：旧计划 **1 项**仍保留；新修订 **v2、2 项待测、0 结果证据、2 项待补**。数据库核对只有一个后继、新用例无 Run/报告，来源绑定内容与输入一致。
5. API 自动测试另用含历史通过 Run/报告的计划验证保留，以及失败项排除拒绝、过期建议拒绝、重复应用与降级保护；浏览器的合成项目本身没有历史报告，不能用它替代这项 API 证据。

模型调用、run、候选、接受/应用动作和新旧计划已归档至 [合成运行证据](evidence/2026-09-08-ai-test-plan-runtime.json)。该文件只含合成内容和测试标识，无登录凭据。临时前后端服务已停止；测试数据由隔离回归清理。运行门禁结果及本切片源码指纹见 [工程验证清单](evidence/2026-09-08-ai-test-plan-engineering.json)。
