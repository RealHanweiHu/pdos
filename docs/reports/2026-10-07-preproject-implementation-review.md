## 0. 结论

**做得扎实的部分：**
- 统一品类身份；
- 规格字典版本只增不改；
- 一案一页的提案；
- 事务化的一次确认保存，带幂等；
- 具名立项决定会留存快照；
- 客户私有提案按权限过滤，去标识沉淀有留证；
- 公开读取有 SSRF 和 DNS 重绑定防护；
- 迁移遇到不安全情况时拒绝执行，不自动合并。

**但真实工作在三处断开：**
- **起点断开。**
  - 客户原件进不来：上传组件已无页面引用，小Pai 不读附件，提案建好后也不能追加证据。
  - 新建品类和提案只能靠 AI，而 10/07 凌晨三次真实研究全部失败。
- **协作断开。**
  - 待决问题只是一段文字，没有负责人和期限。
  - 评审人没有待办，而且可以自审自批。
  - 专家没有参与入口。
- **终点断开。** 立项批准后没有衔接项目的入口，建项目仍要求旧的"已批准 Case"。

**另外有两类风险，必须先于扩大试用处理：**
- **保密。**
  - 提案私有还是共享，由模型判定的提案类型决定，确认时用户看不到；对话原文会写进提案。
  - 模型可以控制读取哪个网址，存在外带内容的风险。
- **可用性与成本。**
  - 中途"停止"或权限变化，会把预算预留记成"未知"；出现两次，全租户的应用 AI 调用就会被拒。
  - 关闭额度后，默认的 legacy 模式完全没有日上限。

**建议：** 先修 §1 的 7 条，再用真实模型和一个真实案例做端到端验收。客户资料能发给哪家模型、要不要先脱敏，这条拍板之前，不要用真实客户 RFQ 试运行。

## 2. 主流程断点（P1）

1. **新建只能靠 AI。** 品类候选必须带本轮研究回执（`preproject_dialogue.py:101-103`），研究通道不可用时就建不了品类，界面上也没有手工建品类或提案的入口。
   - 10/07 凌晨三次真实运行全部降级：输出截断（`PROVIDER_OUTPUT_TRUNCATED`）、结构化输出无效（`STRUCTURED_OUTPUT_INVALID`）、请求断开（`REPLY_REQUEST_FAILED`），见 `docs/reports/evidence/scenario-a-20261007/real-research-*.json`。
   - 需要补一条手工新建的退路，并允许品类先建、研究后补。
2. **批准后断链。** 建项目只认已批准的开发 Case（`projects.py:111-118,408-413`），提案页批准后没有下一步。
   - 设计 §4.4 要求"用触发物直接建项目、待决问题转为任务或风险"，目前没有实现。
3. **评审人找不到要评审的提案。**
   - "我的工作"不含提案（`web/src/components/product-work/preproject-work.tsx:8`），也没有通知。
   - 决定表单放在第 7 个视图"决策记录"里，打开提案时没有"待你决定"的提示。
4. **待决问题只是字符串**（`contracts/product_proposals.py:70`）。
   - 不区分问客户还是问专家，没有负责人和期限，不进对方的"我的工作"，也没有回填入口。
   - 设计 §4.1、§4.3 要求每条问题有负责人和期限，并以 T1 分派给具名专家。
5. **存量产品和派生基线进不来。**
   - 派生要求父型号有已发布定义；而旧定义发布仍要已发布策略、五专业协审、策略至少 3 条路线（`product_definitions.py:42,451`；`product_strategies.py:242`）。设计 §6.4 去关卡的 1/2/3/4/6/7 项在代码里都没有改。
   - 存量规格导入没有做。
6. **AI 起草失败后无法重试。**
   - 返回"未完成"时，前端没有清掉原请求号，再点一次复用同一个幂等键，后端返回同一个失败结果。
   - 页面直接显示错误码（`product-proposals.tsx:59`）。
7. **未保存的改动会静默丢失。**
   - 只拦截了 `beforeunload`，站内跳转会直接丢稿。
   - 反过来，30 分钟内的 AI 稿在打开时会自动载入，并把返回和面包屑都锁住（`product-proposals.tsx:42-50,70`）。
8. **读取失败没有重试，超时也不合适。**
   - 品类资料读取失败后没有重试按钮，"重新读取"也不会重新请求（`product-categories.tsx:23-29`）。
   - 大部分 BFF 请求的默认超时是 5 秒（`web/src/lib/pdos-api.ts:26`）。小Pai 流式回复上限 120 秒，长研究会被截断（`conversations/.../route.ts:38`）。
9. **协作和交接缺位。**
   - 只有负责人能编辑；专家看不到客户需求提案，也不能评论；离职交接不包含提案（`preproject_responsibilities.py:27-38`）；没有销售或业务接口角色。

## 3. 数据与规则

- **现有品类违反 D-1。** "户外便携充气设备"（MKT-OUTDOOR-PUMP）混了帐篷/气垫、球类与桨板、车胎补气三类场景，下面还挂着"自行车充气泵"提案。系统没有任何提示，也没有拆分品类或迁移对象的工具。
- **AI 起草的字典条目没有标识。**
  - 对话建品类时，模型给出的测试条件、方法、判据直接成为正式参数版本，而且是竞品、提案、定义必须逐字匹配的口径（`preproject_dialogue.py:289-299`）。
  - 测试骨架只要方法和判据非空就显示为就绪。
  - 需要给参数加"AI 起草 / 已确认"状态。
- **字典修订后无法映射旧数据。** 提案永远停在创建时的字典版本，测试骨架却总用最新版本，没有旧条目映射入口（`product_proposals.py:254-269`）。
- **竞品库：**
  - 研究出的竞品只是文字草稿，不进竞品库；
  - 竞品来源只认网页快照，内部实测、拆机报告不能作为"实测"依据。
- **用户声音、法规、共享资料：**
  - 用户声音没有导入、归类和样本量；
  - 法规只是"文本 + 地区代码"；
  - 共享资料只能新增，不能修改或删除。
- **产品矩阵：**
  - 要求有一个"值等于场景名的文字参数"，靠命名约定匹配；价格分界默认是"50,70,100"，与品类和币种无关；
  - 变体全部被排除；型号没有"目标细分、目标价"字段。
- **平台：** 不能修改或停用，没有兼容范围和版本字段；"客户变体只对相关人员可见"没有实现。
- **跨品类检索：** 个人会话和项目会话的本地索引检索不限品类，可以读到自己不是成员的品类所爬取的资料（`server/app/ai/research_search.py:192,250`）。
- **去标识与审计：** 去标识只靠一个勾选框；品类知识、字典、平台的写入都不进租户审计和事件流。
- **迁移：**
  - 0426 没有预检"空间编号与产品节点编号冲突"；
  - 0424–0431 都拒绝降级，只能靠备份恢复，而证据写明没做恢复演练；
  - 0428 和 0429 在迁移里 import 当前 schema 建表，以后 schema 一变，旧迁移在空库上建出的表就会漂移；
  - 0429 把预览租户 ID 和调用摘要硬编码进了产品代码和 CHECK 约束。
- **性能：**
  - HTML 正文抽取是平方复杂度（`server/app/domain/research_index.py:104`）。离线测得 80 KB 的病态页面耗时 6.5 秒；模型可控的读取和爬虫都能触发。
  - 解析原件时在事务里持有品类行锁，旧版 Office 走 LibreOffice，最长 45 秒（`product_source_files.py:183-222`）。

## 4. 界面与体验

**界面走查看到的问题（3000 预览，种子账号，10/07）：**
1. **品类页首屏是空表。** 默认打开"规格字典"，看到的是一张空的技术表格；没有品类概要，比如竞品数、提案数、待我评审、字典完成度。
2. **提案只能从小Pai 里找。**
   - 品类页看不到提案数量和列表，要走 立项提案 → 小Pai 面板 → 已有提案 弹窗 才能找到。
   - 只读成员完全没有入口。
3. **品类列表页文案和操作不一致。**
   - 副标题写"开始一份提案"，但列表页只能新建品类。
   - 每一行常驻一个红色"删除"，实际执行的是归档。
4. **看不出提案会建在哪个品类。** 小Pai 面板的上下文显示"已自动带入 产品工作"，而不是当前品类名。
5. **提案页层级混乱。**
   - 提案页仍套着品类页头：品类名是 h1，提案标题却更大。
   - 提案页的"更多操作"是品类级菜单，含"删除品类"；没有提案级的操作。
6. **"关键规格"不是规格。** 新提案默认是 6 行通用字段：适用人群、完整使用路径、主要卖点、关键性能、目标价格带、销售地区/认证。"关键性能"一行装不下多个性能指标。
7. **状态谁定的看不出来。** 状态可以直接选"已确认"，但不记录是谁确认的。
8. **非负责人看不出自己只能看。**
   - 打开别人的提案时，没有"添加规格""提交立项评审"，但页面也没提示"你只能查看"。
   - 负责人这边，页面上也看不出"还差什么才能提交评审"。
9. **几个视图只能让 AI 填。** 竞品对比、用户声音、方案对比都只读，没有手工添加的入口。
10. **露出内部标识。** 证据视图显示内部类型 `brief`；来源定位显示 `parameter/<uuid>/v1` 这类字样。
11. **"场景 × 价格带"几乎出不了图。** 要手选 4 项，价格参数的条件还必须与报价条件逐字一致。
12. **用户声音、法规只是自由文本表单。** 都是"标题 + 正文"，没有导入，也不显示样本量。
13. **品类页视图状态不完整。** 切换按钮没有 ARIA 选中语义，选中的视图也不写进 URL，刷新或分享后会丢。
14. **手机上正文在首屏以下。** 提案页首屏几乎全被品类页头、状态和视图切换占满。
15. **有两个"首页"、两个 AI 入口。** "更多操作 → 专业资料"会进入另一套旧总览（等待你裁决 / 进行中 / 缺口与信号 / AI 最近运行），那里同时有"召唤小Pai"和"立项提案"两个按钮。

**前端审查补充：**
- **图表违反设计规则：**
  - 竞品"实测"和矩阵密度用了强调橙，违反"竞品统一灰色"；
  - 规格"已确认"也用强调橙，而不是状态绿；
  - 报价类型显示英文 `retail`/`promotion`，且没有日期；
  - 共享资料和规格对标都点不开来源（前端类型漏了 `source_refs`）。
- **焦点与键盘：** 弹窗关闭后焦点落到 body；小Pai 面板不是模态，手机全屏时背景仍可用 Tab 进入。
- **提案编辑缺口：**
  - 规格、方案、差异只能添加，不能删除；
  - 提交评审后不能撤回；
  - 退回理由只出现在"决策记录"视图。
- **澄清问题：**
  - 每题必填，没有"暂不确定 / 按推荐先假设"的选项；
  - 答案以"问题id：答案"写进对话；
  - 面板一收起，已填的答案就丢了；站内跳转会清掉提案目标。
- **内部术语外露：** 回执、原请求编号、搜索服务商标识、"单位（文字项填 text）"等。
- **前端工程：**
  - 有多处 2000–3600 字符的超长单行；
  - 幂等键逻辑至少有 5 份，请求封装有两套；
  - 死代码：`ProposalEntry`、`ProductTopicList`；
  - 类型是手写的，漏了后端字段；测试全部 mock 请求，发现不了契约漂移。

## 5. 场景覆盖

| 场景 | 状态 | 主要缺口 |
|---|---|---|
| 新建品类（小Pai 对话） | 部分 | 依赖研究通道；真实链路没跑通；没有手工退路；没有重复或重叠品类检测 |
| 品类改名、归档、恢复 | 可用 | 归档时不检查评审中的提案 |
| 品类合并、拆分、迁移对象 | 未实现 | 现有混合品类无法整理 |
| 品类知识维护 | 部分 | 用户声音、法规太浅；资料只增不改；竞品依据窄 |
| 规格字典 | 部分 | 没有 AI 标识；修订后无法映射旧数据 |
