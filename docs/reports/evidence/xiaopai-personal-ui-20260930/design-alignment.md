# 小Pai个人工作对话：设计与实现核对（2026-09-30）

用户明确的产品定位：类似 Codex Work 的个人 Agent 对话。用户从任意页面打开，系统自动组织该页上下文；用户上传资料、用自然语言交代目标，由 Agent 选择并执行已就绪的工具，持续追问、补充、恢复任务，结果留在同一段工作对话。选择项目或操作类型不能成为开始对话的前置步骤。

## 设计方向已经一致，实现尚未完整

[统一对话与文件输入](../../../design/2026-09-11-unified-conversation-and-file-input.md) §1–3 已明确“说目标/上传资料→识别归属→只补必要缺项→查证或办理→回到同一对话”；[小Pai合同](../../../design/2026-09-28-xiaopai-conversational-agent.md) §2–4 明确全局入口、自动页面上下文、自然语言目标、个人与项目共享边界。实际代码仍主要是项目内首批接线。

## 实施衔接（沿现有N项，不新建第二套Agent）

1. N0-03/N3-01/02：扩展现有会话合同为个人线程及类型化上下文绑定，复用现有会话/附件/运行身份与幂等回执。页面提示不是权限；来源、对象和租户由服务器重验。
2. N3-01/02与当前产品经理主线：先接当前市场空间/产品线真实上下文和私有附件，从自然语言路由至已就绪产品能力；缺项再追问，禁止虚构Project或默认选首个项目。
3. N3-02/N7-02：统一执行协调与结果回链；个人对话仅本人可见，项目持续委托显式进入项目共享范围。跨范围任务保留来源与受众投影，不混发私人内容。
4. N0-03/N7-02：持久恢复目标、文件引用、执行步骤与运行状态。T0真实资格、T1一次确认、T2具名批准、预算及外发边界照旧；“让Agent执行”不授予自动审批或任意写权限。

这些是已明确目标的实现缺口，不能因本次UI修正而关闭N项、宣布全系统Agent完成或真实模型资格通过。无需重开定位采访；后续按当前业务闭环继续实现。
