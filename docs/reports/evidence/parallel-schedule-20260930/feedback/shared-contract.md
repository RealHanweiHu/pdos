# Forecast 反馈集成边界

本轮不修改 material_schedule、schema、迁移、events、AI、公共 UI/导航/类型、唯一清单或 G1/初始计划/正式基线批准流程。只消费统筹维护的桥接合同。

## 物料节点映射

- `material_schedule.conditions(connection, tenant_id, project_id)` 继续返回 `dict[UUID, list[condition]]`；原节点 UUID 是映射依据。
- Forecast 将不在当前正式计划中的键收录为 `unmapped_material_conditions`，保留原节点、收货/Issue 证据和恢复条件，界面在项目层显示。
- 未解除的非 ready 条件使当前 Forecast 不完整、项目完成时间未知；不会把旧节点影响自动分配给新节点。当前节点仍分别展示自己的实际与剩余预测。
- 桥接层须保留被重建计划移除的原节点影响，并按真实释放/重绑状态处理。桥接层若提前丢弃这些键，Forecast 无法凭空恢复来源；此项由统筹补齐并做真实库联验。

## 资源预约与调整

- Forecast basis 纳入当前正式节点的实际预约、资源/人员可用性、最新容量与优先策略版本、策略期限以及本项目资源调整应用回执。回执仅投影本项目事项。
- 整批资源调整的首次成功应用在同一事务内为有正式计划的受影响项目追加 Forecast；重放返回原回执，不追加预测。无正式计划的旧项目保留原服务行为。
- 旧预测因预约改期、释放、容量/优先版本变化或失效而过期。新预测消费当前预约窗口；无法形成可靠剩余资源窗口时，保持未知并给出条件。
- 预测时间不会改写 Baseline/Commitment，也不代表容量重查通过；`capacity_status=not_rechecked` 保留，须沿原容量检查入口核对。

## 剩余估计与实际

- 自动反馈沿用最新人工估计中仍有相同正式计划、分配、日历及节点状态依据的部分。其他节点改变不会清掉未改变节点的估计；本节点开工/完成、纠错或来源变化会使其旧估计失效。
- 进行中的 test_run 真实 `expected_completion_at` 可提供预计结束；保留 actual_start、actual_finish=null 与未知剩余工时。预计期限已过则结束未知，须更新业务依据或人工剩余估计。
- 原预测、Actual 观察、偏差和纠错历史保持连续，可沿记录与预约来源回查；本轮不更改具名批准边界。

数据库与服务使用仍由统筹掌管。本轮仅运行纯计算/模拟组件检查与静态检查，新的真实 PostgreSQL 用例待统筹在已核对的独立临时 pdos_test 执行。
