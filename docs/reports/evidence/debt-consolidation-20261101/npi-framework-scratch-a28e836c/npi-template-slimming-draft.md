# NPI 框架与小Pai 自主建任务（审阅稿 v0.2，未入库）

日期：2026-11-01。状态：讨论稿，未写入 `docs/design`，未改代码或规则。

v0.1 → v0.2：按用户意见，不再维护任务清单模板。只固定 NPI 基本框架，任务由小Pai 按品类和项目自己创建和维护。

## 1. 思路

**框架规定“每个阶段必须达成什么”，小Pai 决定“为此要做哪些任务”。**

这与 v1.1 一致：§03.2 规定模板只管进入条件、交付成熟度、责任和评审，“不是按日历自动推进的检查表”；§03.4 要求工作按结果定义。

原来写在任务清单里的经验，改为写进两处：品类资料（小Pai 的输入）和框架检查（代码执行的底线）。

## 2. NPI 基本框架（固定，由人维护）

### 2.1 阶段与出口成果

出口成果和数值门槛沿用 CEHub v3，可调整。概念阶段已由品类研究、立项提案和 G0 完成，不在项目内。

| 阶段 | 必须达成的出口成果 | 阶段节点（人决定） |
|---|---|---|
| 规划 | 完整规格冻结；初版 BOM 与关键供应商明确 | 计划基线（G1） |
| 设计 | ID 外观、结构 3D、电子原理图与 Layout、BOM v1.0；关键料件规格冻结；DFM/DFA 检查闭环；BOM 成本对比目标 | 设计冻结评审 |
| EVT | EVT 样机；功能/性能测试报告（主要功能通过率 ≥95%，无未关闭 P0/P1） | EVT 评审 |
| DVT | DVT 样机；可靠性测试报告（全部通过，无未关闭 P0/P1） | DVT 评审 |
| PVT | 作业指导书；良率报告（整机直通率 ≥95%）；EOL 100% 测试能力验收；包装与物流验证报告 | PVT 评审 |
| 量产移交 | 首批量产良率稳定、客户放行；售后无未闭环重大问题 | 项目关闭评审 |

**轻量路径**（无电池、无新模、常规风险）：EVT 与 DVT 合为“样机验证”，出口成果合并。

### 2.2 条件成果（按型号属性触发）

| 触发条件 | 增加的出口成果 | 能否去掉 |
|---|---|---|
| 含锂电或受压腔体 | 规划：电芯厂审核或复用确认；设计：安全 FMEA 与保护电路评审；PVT：UN38.3、MSDS、电池安全认证报告 | 红线，不能去掉 |
| 有目标市场认证要求 | DVT：认证报告 | 红线，不能去掉 |
| 含固件或 App | DVT：软件完整测试报告 | 可去掉，须写理由 |
| 需要开新模 | DVT：模具 T1 样品 | 可去掉，须写理由 |

另有三项永久红线：EOL 100% 测试能力、PVT 评审、首批量产放行。

### 2.3 任务的基本要求

每个任务必须有：一个负责角色、一个交付物（对应某项出口成果或其前置）、工期（可以是范围或“未知”），以及来源（框架成果、品类资料、型号定义或 G0 待决项）。

## 3. 小Pai 自主做什么

| 时机 | 小Pai 做的事 | 要不要人确认 |
|---|---|---|
| 项目建立（G0 批准后） | 按框架、品类资料、型号定义和 G0 待决项，生成全部任务：名称、负责角色、交付物、检查项、依赖、工期范围、来源 | 不用。直接写入项目，署名小Pai，可整次撤回 |
| 分派 | 按项目团队角色分派 | 不用。受派人承接时才算承诺 |
| 排日期 | 估工期（优先同品类历史实际用时），日期由排期引擎按日历和依赖算出 | 不用。这是计划日期，不是承诺 |
| 运行中 | 根据测试失败、设计变更、会议决定、延期等，增加、拆分、合并或取消**自己建的、尚未被承接**的任务 | 不用 |
| 运行中 | 修改**已被承接**的任务（范围或日期） | 要。发给承接人一次确认 |
| 计划基线（G1）前 | 计划随时由小Pai 维护 | 不用 |
| 计划基线（G1）后 | 偏离基线时显示差异，并起草调整方案 | 重设基线由负责人具名决定 |

## 4. 框架检查（代码执行，不靠模型）

小Pai 每次生成或修改任务后，由代码检查：

1. 每项出口成果（含触发的条件成果）至少有一个任务产出它；
2. 红线成果必须有任务，且不能被标为不适用；
3. 每个任务都满足 §2.3 的基本要求；
4. 依赖关系无环，阶段节点不作为任务；
5. 工期没有依据时，必须标为“未知”，不能编一个精确值。

不通过时小Pai 自行修改；两次仍不通过，作为例外交给项目负责人。

## 5. 仍由人负责的事

- **阶段评审决定、计划基线批准**：具名决定，属于 DC-11 不可让渡的人裁决最小集。
- **个人承诺日期**：由承接人本人承接时作出。
- **框架本身**：阶段、出口成果、红线和门槛，由你或项目管理部门维护，小Pai 不改。
- **例外**：框架检查不通过、某个角色找不到人、小Pai 要改已承接的任务。

## 6. 例：同一框架下的两种充气泵

以下是示意，实际任务由小Pai 按品类资料生成。

| 出口成果 | 轮胎充气泵（锂电无线、数显自动停机） | 帐篷/气垫充气泵（锂电、大流量低压、带抽气） |
|---|---|---|
| 规划：关键供应商明确 | 气泵机芯（气缸/电机）选型与供应商确认 | 风机/叶轮选型与供应商确认 |
| 设计：电子原理图与 Layout | 压力传感与自动停机电路设计；固件设计 | 电机驱动与充放气切换电路设计（无固件，不建软件任务） |
| EVT：功能/性能测试报告 | 压力精度与自动停机标定测试；气嘴兼容测试（Schrader/Presta） | 风量与充气/抽气双向测试；多种气门适配测试 |
| DVT：可靠性测试报告 | 连续工作温升与热保护测试；跌落测试 | 户外防水防尘测试；连续工作温升测试 |
| 品类依据 | 品类种子 `auto-tire-inflator`（31 个参数、31 个测试项、43 条法规条目） | 尚无品类，需另建；在此之前任务更少、工期多为“未知” |

两者的出口成果完全相同，任务各不相同。

## 7. 质量保障：用资格和指标，不用清单

- **上线前**：按试点资格规则（v1.1 §06.12），用 10–20 个合成项目覆盖不同品类，由你审阅小Pai 生成的任务计划，通过后对该“租户 × 技能包 × 模型版本”开通自动。基线前的计划本质是草稿，适用“草稿类技能包”资格路径。
- **运行中**：跟踪撤回率、人工修改率和框架检查失败率。超过阈值时自动降回“一次确认”（DC-11 §6.3）。
- **沉淀**：同一品类反复出现的任务，小Pai 建议写进品类资料，由你批准后生效。

## 8. 需要的决策与建设

### 8.1 需新增决策记录（拟 P33）

| # | 内容 | 现状 |
|---|---|---|
| 1 | 框架出口成果和品类资料可作为任务来源 | 只认原件、G0 待决项、模板条目 |
| 2 | 小Pai 生成的计划在基线批准前直接生效（`work.plan.apply` 对此情形为自动） | 须负责人一次确认 |
| 3 | 按项目团队角色自动分派（`work.task.assign` 对此情形为自动） | 须负责人一次确认 |
| 4 | 小Pai 可修改、拆分、合并、取消自己建且未被承接的任务 | 无此命令，只能撤回整次运行 |

以上都满足 DC-11 自动档三条判据（可逆、不外发、无签核语义）；DC-11 人裁决最小集不变。

### 8.2 建设项

1. 框架配置：阶段、出口成果、条件成果、红线与门槛，版本化。
2. 框架检查器（§4）。
3. 项目团队与角色对象（现只有项目负责人字段）。
4. 任务修改、取消命令，限 AI 建且未承接的任务。
5. 阶段节点的服务器接口（现缺），接现有阶段评审与决定命令。
6. 真实工作日历（现在传入日历会被拒绝）。
7. pdos-next 停用混合三代模板的任务清单（`domain/work_management/templates.py`）。
