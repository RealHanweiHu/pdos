# S2 多批、分批接收与多 Run 接续

本次实现[接续合同](../../../../design/2026-10-17-pdos-next-s2-multi-run-contract.md)。同一正式请求可在已排期、测试中或已有初步结果后继续接收剩余样件；各 Run 固定自己的非空已接收范围、资源事实和具名承诺，独立开测、返回结果与专业处置。请求保留首次事件时钟，按每个 Run 的当前版本汇总完成范围。来源、实际配置、方法、专业资格、冲突、破坏性使用、T1/T2、CAS、事务和重放守卫保留。

## 可核对的业务链

真实本机合成 API 链创建项目/Build、两个产出 Lot 各一件 A/B 样件，提出同一请求并先接收第一件。Run A 独立计划、承诺、开测，经上传/解析/捕获原始 JSONL 返回部分与最终结果；请求仍为 executing。继续接收第二件，Run B 单独固定资源、承诺和开始，保留 A 的快照与请求首次时钟；B 最终返回后请求才 reported，两个 Run 分别具名复核和处置后才 disposed。原 Start 同键/跨键重放不增加事实，每 Run 的样件、Lot、实际配置与资源消费均可回查。

普通应用角色尝试在后继交接版抹除已有 preliminary_result，被数据库 INSERT 守卫拒绝，回滚后无新事实。B 未承诺时列表不开 Start 能力；定向纯检查在有效执行窗口内明确核对缺少本 Run 承诺或借用其他 Run 版本均拒绝，不以窗外/未来事件的其他失败代替这项证明。
