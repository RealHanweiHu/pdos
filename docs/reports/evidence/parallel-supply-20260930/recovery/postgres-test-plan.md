# 供应短缺与恢复 · PostgreSQL 联验计划

本线仅写入测试并完成 AST/lint/type 静态检查，**没有导入或执行 PostgreSQL 测试夹具，没有连接数据库**。15 个声明用例（按参数展开）不计为已通过；上轮 33 个联合检查的既有证据不重复累计。

## 环境与命令

统筹负责分配一个新独占临时 `pdos_test`、核对真实端口、应用当前整合候选及公共 Issue 关闭接缝。**上轮 57440 未授权使用**，新夹具在推进基础生成器、创建 Engine 前拒绝 57440；基础护栏继续拒绝 57432/57433/57434/57439、5432/55432、缺省端口、非本机/非 PostgreSQL/非 `pdos_test` 及连接目标覆盖参数。

只接受显式 `TEST_DATABASE_URL`，经 `require_test_database_url` 校验，且仅在统筹已经核对独占条件后设置 `SUPPLY_POSTGRES_EXCLUSIVE=1`。不回退 `.env`，不迁移、不清库、不修改触发器。每个用例使用新的专属租户，正常约束下种子源、授权和领域动作；只关闭连接池，已提交记录留给统筹核对与统一收尾。

在 `server/` 中替换占位地址后执行；本线未执行：

```sh
SUPPLY_POSTGRES_EXCLUSIVE=1 \
TEST_DATABASE_URL='<统筹核对的新独占临时 pdos_test 直连地址>' \
.venv/bin/python -m pytest -q -s tests/test_material_recovery_postgres.py
```

共有接缝必须先满足 [具体合同](coordination-needs.md)：`IssueService.transition` 的 `material_closures` 输入、原项目事务内调用供应守卫、原 Issue 审计记录当前来源、工作卡传递类型化引用及 409 映射。联合关闭用例明确检查该服务参数，缺失时直接报告未整合，不以测试内旁路关闭代替。

## 夹具与证据边界

复用已通过上轮检查的专属基础夹具与 Build/BOM/日历/节点/分配 helper；新 `recovery_scope` 在任何基础连接前另加 57440 拒绝护栏。合成文档只注册元数据，无对象下载或真实 ERP 请求。供给快照仅作为合成 captured source 直接种子插入，保留真实 SQL/延迟约束；恢复、对账、分配、共享、Issue 动作均用真实领域服务及真实授权。数据库账号、角色与迁移由统筹核对，不能用 role/SQL mock 替代失败。

唯一 monkeypatch 为故障注入：真实 `EventAuditWriter.record` 完成事件和审计插入后抛异常，验证业务事务一起撤销；不替身 SQL、授权、领域服务或 canonical Issue 关闭。
