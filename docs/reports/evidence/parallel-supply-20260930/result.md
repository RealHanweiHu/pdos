## 已实施的业务能力

- **供给到齐套**：沿现有固定 Build/BOM、授权文件导入、全租户同供给池分配扣除与领料对账，补齐覆盖结果中的本批次现货总/关键齐套。按物料引用与单位合并重复 BOM 行，只有明确分配的合格现货与领用时合格净领料计入；未分配余量、预计到货、同日时刻未知、过期/冻结/不可读占用不冒充齐套。没有正数固定需求不显示通过；无关键需求保持不适用。计算自身固定十进制精度，不再依赖调用者的全局精度。
- **到货恢复**：保留原异常物料键，新增合格领料使当前评估与摘要变化，沿原异常复核；实际收样不代替 ERP 供给、数量对账或质量放行。既有异常 `supply_ready` 判据仍要求本批次明确供给覆盖，不据可用池余量直接关闭。
- **成本口径**：估算、报价、ERP 实际的 BOM 计价单位必须与用量单位一致。单位不一致保留原输入、显示计算缺口，阻断确定总额和后续冻结采用；同料号、同数值但 BOM 单位变化的历史对比不输出节省差额。原币金额、指定汇率版本/时点、税费/运费及 NRE 保留，未猜单位换算。
- **供方回复一次确认入口**：供方工程画像的原有效样品/技术事项可选择本项目已保存的内部回复/收样证据，预览后一次确认补齐首次实际响应或实际收样。服务器从原事项预填，绑定当前租户、项目、供方、事项版本和确认人，并重新核对原件；沿现有受控工程服务，在同事务保存新版本、来源、审计及回复请求摘要。撤权、来源/版本变化、跨事项请求复用均阻断；网络结果不明可按同请求重试返回原回执。已有首次事实纠错须沿具名修订，不由回复入口覆盖。

新增回复端点：`POST /api/projects/{project_id}/npi/supplier-replies/{supplier_id}/{record_id}/preview` 与 `/confirm`。同域新增具体 BFF 路由只允许这两个动作，使用服务器会话令牌与有界 JSON；没有修改共享 `npi-bff.ts`、导航或公共类型。入口仍位于项目“物料·供应 → 供方工程画像 → 原事项”。齐套结果位于原 Build 固定需求/供给分配的覆盖计算中。

原 Cost Gap、降本方案、具名 Frozen Cost、同口径历史/实际对比及定义反馈入口已在现有领域视图连通。本轮修复计量边界，**没有重新宣称这些持久化链路在新候选完成联验**。有效旧计算的输出结构保留；历史单位错误的计算仍保留，采用/冻结/回测时必须重新核对，不能静默修正旧冻结记录。
