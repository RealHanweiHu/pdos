## 运行前提与命令

统筹会话负责新临时容器的创建、实际端口核对、当前整合候选的迁移及独占条件确认。此处没有分配地址，提议的端口也不视为授权。夹具不迁移、不建库、不加载 `.env`、不清库，不触及开发库或存续联验库。实际连接前需要同时满足：

- 显式 `TEST_DATABASE_URL`，通过 `require_test_database_url`，真实 PostgreSQL、数据库名严格为 `pdos_test`，主机为本机，直接指定端口且没有主机/端口/库名/service 覆盖参数。
- `SUPPLY_POSTGRES_EXCLUSIVE=1`：仅在统筹会话已核对临时容器的独占权后设置；这是显式归属确认，不能代替环境核对。
- 端口禁止 `57432/57433/57434/57439`，同时禁止常规开发端口 `5432/55432` 和省略端口。运行时再核对 `current_database()`、`session_replication_role=origin` 和既有供方工程表。
- 已完成当前联合候选的迁移；测试保留真实 SQL 约束与触发器。数据库账号需要正常种子插入及领域事务权限，不禁用约束。

## 夹具与真实执行范围

共用夹具 `supply_postgres_scope` 位于 [回复测试](../../../../server/tests/test_supplier_replies_postgres.py)。每例建立独立 `supply-pg-{UUID}` 租户，以及隔离的外租户用于越权断言；同租户种入实际 owner、project_manager、engineer 用户、两个项目及成员、供方和合成文档注册。打印租户及项目 UUID，不输出 URL 或凭据。文档只有授权合成的元数据注册，不访问对象存储或真实用户文件。fixture `finally` 只关闭连接池；无自动数据删除。种子项目的需求、立项和流程只作最小有效依赖。

原供方事项通过真实 `SupplierEngineeringService.preview/apply` 形成 v1。回复确认使用真实授权与 `SupplierReplyService`，沿同连接工程应用事务保存。并发使用两个独立、单连接池的 Engine，并核对不同 `pg_backend_pid()`；Barrier 使两次调用竞争同一请求/同一池，15 秒语句超时、10 秒锁超时防止无限等待。

[物料/成本测试](../../../../server/tests/test_parallel_supply_postgres.py) 使用现有日历发布、节点注册、Build 固定需求、供给共享双方确认、分配、实际领料、覆盖计算、成本输入、滚算和具名冻结服务。只对合成业务来源/注册数据直接种子插入；SQL、权限和领域服务均不替身。供给源只登记一个池的一个快照，接收项目引用同一快照，不复制库存。成本原始单位漂移使用仅本例 BOM 的真实 UPDATE，保留旧价格与旧计算。

唯一 monkeypatch 是故障注入：先调用真实 `EventAuditWriter.record` 执行业务事务内的事件和审计 SQL，再抛出异常，验证事务撤销；退出补丁后用原请求重试。没有 SQL、授权、事务或业务服务 mock。
