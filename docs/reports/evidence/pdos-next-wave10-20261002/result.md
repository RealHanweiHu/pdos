# 第十波：专业验证前置办理

已接通“固定准备版 → 正式草稿请求 → 逐项方法核对 → 请求级暂定窗口”，复用既有验证规则、一次确认、事务回执、来源读取与历史组件。人员职责、人员资格和 AI 资格分别核对；产品写权限不能授予品质专业资格。G2 仍为部分实现，实物交接和开测尚未开放。

最终冻结 350 份源码/配置，271 份 Python 文件 lint 通过；1,234 项联合检查全部通过，用时 454.53 秒。独立检查最多四进程并行，24 项会修改公共结构的生命周期检查最后单独执行；候选在联合检查期间未变化。生产构建、前端 lint、13 项界面辅助检查、最终 schema 与实际数据回读通过，摘要见 [final-check.json](final-check.json)。

## 当前可用能力

- 6 张新表保存不可变专业事实、当前事实指针、正式请求版本、当前请求指针、方法适用核对及暂定窗口。每个事实绑定租户、产品、项目、主体、操作、用途、签发者、有效期和出处；撤销后恢复也不能让旧确认凭证重新生效。
- 可信专业事实经服务器受控导入，一笔事务保存 RequestKey、Receipt、Audit 和 Outbox。重复旧导入不得回退当前版本；当前权限先于重放检查。该入口没有注册为模型可调用的公共命令。
- 从精确 Preparation 身份、版本及摘要建立正式草稿请求，固定原 Build、双配置、测试项、资料及用途。请求拥有独立首次请求时间；旧准备和计划 Build 不被改写。
- 品质人员逐项保存适用、不适用或未知。肯定适用结论必须同时有实际方法依据及该项全部必要资料，不能以一条方法引用填平校准等缺项。经完整预览、一次确认保存下一不可变请求版本。
- 暂定窗口保留 UTC 起止、原始 IANA 时区、设备/人员等意向、工时和日历缺口。未知数量不填零，实际资源占用始终为 0；没有虚构预约、TestRun 或交接/测试时钟。
- 页面显示当前职责与资格、合成事实标记、固定准备版、请求历史、资料/数量/模穴缺口及方法/窗口来源。旧请求版本只读，读取失败与提交后回执未知分别提示。

## 实际页面与数据回读

本地合成预览从原准备 v2 创建正式请求 v1，完成两个测试项的未知方法核对形成 v2，再保存暂定窗口形成 v3。窗口为 `2026-10-04T16:00:00Z` 至 `18:00:00Z`，原时区 `America/Los_Angeles`，设备身份与数量未知、占用为 0。

尝试将压力项标为适用时，系统因缺少必要校准依据返回 `METHOD_EVIDENCE_INCOMPLETE`，没有写入方法事实；该步骤只证明拒绝保护，不能计作肯定适用的页面验收。随后保存的两项结论均为未知，保留具体原因。10 个资料缺项（包含本轮专业方法必要项）和 4 个数量/模穴缺口保持；原准备本身与第七波记录逐字段一致，原 Build 与第三波记录逐字段一致。三个办理动作各有且只有一笔回执、审计及事件。

旧 v1 页面可回查，方法和窗口按钮均禁用；最终回到 v3。1440×900 和 390×844 的亮/暗四种布局均无横向溢出，临时尺寸设置已恢复。前端最后一次读取失败文案修正已纳入最终生产构建、lint 和真实页面验证；13 项 helper 检查对应未变化的 helper/test 文件。

## 修复、复用与验证范围

初次真实页面并发读取暴露 Product/Project 取锁顺序不一致。共同权限和项目读取统一先锁 Product，保留后续权限/来源核对；两个确定性数据库并发病例覆盖项目读取与来源/授权读取的重叠。

首轮联合检查为 1,232 通过、1 失败，未报全通过。原有文件运行时在并发首次创建锁文件时偶发 ENOENT，保守返回结果未知。双侧诊断定位到子进程创建锁、尚未写入执行尝试；不是超时或许可过期。修复复用上传日志的单创建者模式：排他创建，竞争者安全打开既有文件，保留所有者/权限/链接检查及有限等待。40 项局部检查与额外 20 轮、80 次真实临时并发调用通过，每轮仅一笔尝试和事件、相同结果证明。初次失败、诊断和最终重验分别留存。

57 份旧轨重点资产和 25 份验证核心资产逐文件摘要保持。7 份原件运行资产中 5 份保持，2 份为上述实现/测试修复；不将旧“7 份未变”的历史证据冒充最终状态，也不扩大为整个旧工作区未变。并行归属为专业权威、验证领域与界面三路；共同持久化、命令、API、迁移及公共验证由主线统一。

迁移 `next_0013` 在写入本轮业务前完成上/下/上往返及 schema 核对；保留不可变记录、单调指针、范围外键、RLS 与引用保护。运行注册 34 个 payload，包含 22 个 canonical、10 个辅助和 2 个既有主线扩展；两个主线扩展尚未列入辅助目录，单独记录追溯说明。canonical 目录保留 66 操作、65 事件、48 验收条目。导出模型及 OpenAPI 与实际运行结构一致，不代表全部目标操作已经实现。
