# 固定图核验耗时与失效诊断

第 v3 候选的精确 pg12 复验实际失败：末端 Outbox 故障后回滚检查完成，但正常恢复提交返回 `GRAPH_CAPTURE_EXPIRED`（固定图在本阶段核验期间到期）。原始日志和 result 保留，不能计通过。测试总耗时 2232.44 秒，runner 2234.64 秒；这不是通过修改测试钟、延长 TTL 或复用历史资格解决的情形。

实际浏览器第一次影响提交亦返回 409，页面只展示通用固定依据失效提示；没有取得原错误 code，因此不声称其精确原因已证实。当前 Change 仍 v1 草稿。旧捕获 `150e82e7-3880-483f-b171-ecc73396e21d` 的实际保存/失效为 07:00:39.065220 / 07:10:39.065220 UTC。新独立捕获 `118e51b1-692b-498f-bef3-5b58633a1c29` 为 07:15:16.572207 / 07:25:16.572207 UTC；两者原行和摘要保留。

具体性能接缝：Change 的 `_seed`、OwnerReader、最后刷新和固定图重建均调用完整 Issue 页面读模型；Issue 与 CAPA 同一版分别重复核对，并附带与 Change 办理无关的四项品质写能力评估。实际完整来源性能观测见 `issue-owner-profile-v3-security.json/log`：一次 Current Issue v4 读取为 8.702 秒、3481 次 SQLAlchemy execute；原失败桥累计 7.848 秒，其中两次真实 retained execution 核对累计 7.115 秒。由此不能把全部耗时归给无关写能力评估，主要需减少同阶段同版原失败核对的重复。

优化只允许在单个明确读取阶段复用同版结果，独立最后刷新仍重新读取真实原失败、Current、原件 ACL/安全、风险政策和本操作专业依据。过期、撤回/恢复 epoch、最窄受众和固定 TTL 不变。另发现 Issue/CAPA owner 指纹只存历史 row.source_basis、未比较当前风险政策版本；新候选补入实际当前 policy 指纹，不能用恢复后的 positive 覆盖政策 ABA。新修复候选须另冻源码和受影响复验，不覆盖 v3 失败或把其计为新候选通过。
