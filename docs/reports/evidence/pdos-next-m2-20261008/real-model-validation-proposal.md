## 明确的硬上限

- 总模型 HTTP 尝试 **≤ 60 次**（正常步骤计划 ≤ 52 次，8 次余量只用于已确认“未发送”的协议修复；未知已发请求不重发）。
- 每次输出 **≤ 2,048 tokens**；所有调用输出总量 **≤ 122,880 tokens**。
- 总输入 **≤ 1,200,000 tokens**，包含 cache-read/cache-creation；每个研究父运行的服务器预算 **≤ 500,000 tokens**，并发子任务 **≤ 4**。达到上限保留 partial，不自动补预算。
- 拟定总费用硬上限 **USD 10**。执行前须有当前服务商价格/计费器并能在下一次调用前保守预约费用；无法计算或用户未确认货币上限时停止依赖费用的调用。任何更高费用或新服务商须重新授权。
- 原生工具定义当前 **167,872 UTF8 字节 / 106 个工具**（`tool-footprint.json`；M3 能力尚无执行端时只显示缺配置或候选），按字节保守预约会超出默认 100k Run 限额。因此验证预算须由服务器显式登记为上述 500k 上限，不能静默扩大。子任务只发送其物理隔离的两个 read 工具。

计费器已经实现，机制与合成证据见 `cost-meter.md`。所有协议检查、主运行及子任务须绑定**同一个**经批准的 `validation_budget_id`；宿主不能续开钱包或在真实模型上关闭 `cost_required`。调用前原子预约费用/输入/输出/次数，已知响应按实际 usage 结算，未知结果将全额预约保留为估算已花费；取消、Worker 恢复与直接结束对账不退回未知费用。

价格卡还须绑定准确服务商/模型/配置版本，并提供**已经核对的纯文本 token 上界及来源、所有收费输出受 `max_output_tokens` 约束的依据、覆盖缓存创建 TTL/缓存读取/上下文阶梯/固定费等全部收费的保守价格**。网关禁止多媒体 content；缺少任一依据、价格过期或配置变更时 0 HTTP。本地 fixture 中的 UTF8 比率、4096 framing 和价格均只是合成合同，不赋予任何真实模型计费资格。仅有请求字节估算或事后标记 unknown，不能证明未知服务商的实际账单数学封顶。真实核价与具体预算 ID 的绑定由 B7 可执行候选在获明确授权后办理。
