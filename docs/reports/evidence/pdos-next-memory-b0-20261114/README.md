# 记忆评测 B0 补齐（2026-11-14 至 11-15）

依据：[目标架构](../../../design/2026-11-12-xiaopai-memory-system-assessment-and-target-architecture.md) §8.2–§8.3，清单 D474。分支 `claude/memory-b0-eval-8dee3b`，只改评测文件，没有改产品代码、提示词、工具定义或迁移。

**结论先说：四个组（不进记忆、只搜历史、当前实现、上限）× 17 道题 × 每格 3 次跑完了，175 次计分运行，门禁 0。在这批候选题上，有跨会话记忆比没有明显好（7 道题每次都好）；当前实现和只搜历史分不开；上限比当前实现只多写出 2 次，而且差距全部是“检索到了但回答没出来”，不是“没检索到”。原因已查：模型把以往记录里的内容写进表格单元格，表格结构校验失败后整段摘要被换掉（见“D541”一节）。**

## 做法

- 代码：真实模型运行基于本分支提交 `4668937b`（`4f041b72` 只改评测说明）。主分支上“最后一轮不再执行工具调用”（D477 余项 ③）和多读两种列表写法的改动不在本分支，结果里没有体现。
- 独立临时库：`tools/local_environment.py` 新建的 `127.0.0.1:52491/pdos_test`（标记 `b174dbc9`），迁移 head → base → head 通过，显式 `TEST_DATABASE_URL`，没有读 `.env`，没有用 57105。本地 Temporal 可执行文件经符号链接只读使用主检出的那一份。
- 模型：MiniMax-M3，主检出的运行时元数据（只含密钥引用），改绑到每次测试新建的合成租户。内容全部合成。
- 四个组：`no_memory`（基线 0）、`history_only`（基线 1，评测进程里把 `memory.search` 换成搜本人原话加回答摘要，不带条目和目录）、`real`（当前实现）、`ideal`（上限，评测进程里的模拟：目录换成题目标注的以往运行并带回答和未完成事项，`memory.search` 对任何检索词都只返回它们；个人条目照常）。T03–T05 只跑后三组，T13、T24 只跑当前实现。
- 每格 3 次，单进程串行。判定全部按规则（关键事实是写死的字符串，门禁只看服务器使用清单）；“疑似把记忆说成事实”的正则命中和“需人工看的词”我逐条读过原文（见下）。
- 时间线：TL-01–TL-13 是调参集，TL-14–TL-16 是验收集（TL-14 冒烟时看过一次）。全部是候选，未经你确认。

## D541：回答为什么被整段换掉

11-15 追查，读代码加离线校验已存的输出，没有再调用模型。

- 9 次被换掉的回答里，8 次是“部分任务结果未通过引用或登记字段核对，未核对的内容已标为待确认。”，来自 `server/pdos_next/agent/enterprise_search/assistant_answer.py`：`task_result` 有任何未核对项时整段替换摘要。
- 这 8 次的 `unknowns` 里都有“任务结果结构未通过核对”，没有一次是单元格的引用核对失败。也就是说，模型交了 `task_result` 表格（当前实现 TL-01 q1 用的是 review 格式，TL-10 用的是 cases 格式），结构校验没过，整张表被丢掉，摘要被换掉。
- 有 2 次的表格草稿留在了结果正文里（`real-TL-01-q1.r2`、`ideal-TL-10-q1.r2`）。用服务器的 `TaskResultDraft` 离线校验：错误全部是 `extra_forbidden: analysis`（3 处、5 处）。模型把从以往记录里找到的内容写成 `{"status": "not_recorded", "analysis": "…"}`。把 `analysis` 改名为 `text` 再校验，仍然被拒：“未知单元格不能携带未核对的内容。”
- 所以以往记录（不是可引用的企业证据）写进表格没有合法的位置。提示词 1.0.0 说“Non-owner cells may include grounded analysis text”，字段名是 `text`，且只有已记录的单元格能带，两处都与模型的理解不一致。
- 当前实现 TL-01 q1 那次，模型的草稿里其实写出了全部关键事实（“建议选 B 家，交期比 A 家短 2 周；C 家含税报价超出目标价 12%”），评分时这次也算写出（正文里还留着）；TL-10 的两次草稿没有留在正文里，事实丢了。
- 另 1 次（当前实现 TL-16 第 2 次，“结果未通过完整核对。”）是主图格式修复用尽且没有可保留的摘要，属 D477 那一类，没有再查。
- 没有改代码。可选的方向记在清单 D541，待你定。

## 能确定的

1. 跨会话记忆在这批题上有净收益：不进记忆 0/20，当前实现 21/21（可比的 7 道题），7 道题每次都分得开；不进记忆的运行 token 中位数也最高、追问最多。
2. 当前实现的检索在这 8 道题上都找到了（24/24），包括只记得结论里一个词的 TL-08 和新验收集的 TL-14（D482 之后）。
3. 上限与当前实现的差距只有 2 次，全部来自回答出不来（核对整段替换或预算用完），集中在 TL-10。
4. 个人条目的价值只有当前实现和上限有：改过的项目编号 2/3、3/3，只搜历史 0/3。
5. 五项门禁在 175 次运行里都是 0；T03、T05 没有一次把记忆说成事实。

## 不能确定的

- 当前实现和只搜历史谁更好：21/24 对 20/24，没有一道题分得开。只搜历史同时去掉了条目和目录，两者差别是几个因素合在一起的。只搜历史的 token 中位数更低（9.0 万对 12.0 万），但只是中位数，每格 3 次，没有做显著性检验。
- 题量小：依赖以往运行的关键事实题只有 8 道，验收集只有 TL-14、TL-15 两道（加 TL-16 一道条目题），每格 3 次（3 格只有 2 次）；比例不代表稳定水平。目标架构要求每格至少 5 次，这里是 3 次。
- 上限组只把以往运行理想化了，个人条目仍走当前实现，不是完整的“理想记忆”。
- 所有题和时间线都是候选，历史是脚本固定的、回答摘要很短，真实使用里检索会更难。
- 排序系数（半衰期 30 天、置顶加 0.25、被纠正乘 0.5）没有调，也没有专门考察；这批题的检索几乎都命中，看不出系数的影响。
- T24 的结局受企业检索预算影响，这次没有把它和记忆降级分开。
