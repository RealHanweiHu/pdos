# D214 真人登录（含 D86 邀请与停用、D192 账户生命周期）

日期：2026-11-07 · 分支 `pdos-next/design-v1.1`（基点 `d730291d`）· 迁移 `s0_0855_human_sign_in`（down_revision `s0_0854`）

## 结论

真人现在可以用“登录名 + 密码”登录：服务端签发带空闲超时的会话，Web 只把它放在 HttpOnly cookie 里；账户只由租户管理员开通，邀请和重设链接 72 小时内单次有效，停用账户或重置密码会立即吊销该账户全部会话；任何人不能停用自己、不能更改自己的管理员身份，租户至少保留一位启用的管理员。数据库层用限制性行级策略重复了这几条自我规则。租户开通脚本只在本地带标记的合成环境里演示过。

本结果只是本地实现与本地验证，不是生产启用、真人试点准入或任何资格。

## 决定与口径

- 登录方式：密码 + 限流（用户 2026-11-07 选定）。钉钉扫码等 D64 的应用凭据后再加。
- P78 的“Owner”对应 pdos-next 唯一一级的“启用的人类租户管理员”（`tenant_administrators`），没有新增角色层级。08-20 合同里 Owner/Admin 两级的差别不适用。
- 会话：绝对有效 7 天，空闲 12 小时失效（每分钟最多刷新一次最近活动时间）；限流：同一登录名 15 分钟内失败 5 次、同一来源失败 30 次即暂停，登录成功清零该登录名的计数。这些数值写在数据库函数里，调用方传不进来。
- 口令：至少 10 个字符、最多 128 个、不能等于登录名；用标准库 scrypt（N=2^15, r=8, p=1）哈希，未新增依赖。
- 未知账户也做一次 scrypt，失败提示一律“登录名或密码不正确”，不暴露账户是否存在或已停用。
- 重置密码：旧密码立即失效（哈希清空）、全部会话吊销，另发一个 72 小时单次有效的重设链接；管理员看不到、也设不了别人的密码。
- 停用后可再启用：已吊销的会话不恢复，原密码保留。
- 并发：管理员动作在同一租户内串行（事务级咨询锁），并在拿到锁后重新核对操作者；登录签发和接受链接与管理员动作一样先锁人员行，所以重置或停用与登录同时发生时，后者看到的是已生效的结果。

## 实现位置

- 迁移：`server/migrations/schema_s0_0855.py`、`server/migrations/versions/s0_0855_human_sign_in.py`。`login_sessions` 加 `origin/issued_at/last_seen_at/idle_timeout_seconds` 并开启 FORCE RLS；新表 `human_credentials`、`account_invitations`（库约束“过期时间不超过创建后 72 小时”）、`account_events`（只追加、不存秘密）、`sign_in_attempts`（只存摘要）。
- 角色分工：`pdos_next_auth` 在登录前只能调用 7 个 SECURITY DEFINER 函数，读不到凭据、邀请和限流表；`pdos_next_app` 只有在操作者是启用的人类租户管理员时才能管理账户，读不到口令哈希和链接哈希，只能清空口令；`pdos_agent`、`pdos_next_dispatch` 无任何权限。`tenant_administrators` 原有策略允许“读写自己那一行”，新增的限制性策略禁止写自己的管理员行；`principals` 新增限制性策略禁止把自己设为停用。
- 后端：`server/pdos_next/core/accounts/`（`passwords`、`sign_in`、`management`、`api`），`api.py` 的会话校验改由 `sign_in.resolve` 处理过期、吊销和空闲；`/v1/session` 增加 `login_name`、`administrator`。错误原因登记在 `core/error_catalog.py`。
- 契约：`contracts/auxiliary-operations.json` 登记 8 个账户操作（读取为 READ，其余 T2、仅具名人工）和 4 个登录入站端点；`tools/validate_contracts.py` 把 `/v1/accounts`、`/v1/auth/` 纳入“写接口必须登记”的范围；`contracts/openapi.json` 重新导出（仅新增）。
- Web：`/login`、`/invite`（令牌放在 URL 片段里，不进服务器日志，读取后立即从地址栏和历史中清掉）；BFF `web/src/lib/server/sign-in-proxy.ts`、`accounts-proxy.ts`（同源校验、严格请求体、令牌不进响应体）；设置页新增管理员可见的“账户与邀请”；外壳在 401 时跳到登录页，左下角可退出登录。
- 工具：`tools/tenant_provision.py`（开通租户：首个管理员、首个品类、72 小时邀请链接；链接只写进 0600 的私有状态文件）；走查种子 `tools/seeds/sign-in-walkthrough.json`（合成登录名与本地生成的口令，只用于带标记的 `pdos_test`）。

### 浏览器走查（本机 Web 3055 + API 18898，无本地开发会话）

1. 未登录打开首页 → 跳到 `/login`。
2. 用开通脚本生成的管理员链接打开 `/invite` → 显示姓名、登录名、到期时间；地址栏里的令牌已清除 → 设置口令后直接进入工作区，左下角显示登录名与退出按钮。
3. 设置 → 账户与邀请 → 新建“走查工程师（合成）” → 显示一次性邀请链接（只显示这一次）。
4. 退出登录 → 账户接口返回 401。
5. 打开成员链接设置口令 → 以成员身份进入；成员看不到“账户与邀请”，账户接口返回 403。
6. 再次打开同一链接 → “此链接已经用过”。
7. 管理员重新登录 → 成员显示 1 个在线会话 → 停用并确认 → “已结束 1 个会话”，状态“已停用”；库内该成员会话全部吊销，账户事件已记录。
8. 成员再登录 → “登录名或密码不正确。”，口令框清空。
9. 手机宽度（375）暗色下登录页和失效链接页无横向滚动。走查中发现并修复两处问题：开发模式下邀请页读两次 URL 片段导致令牌丢失；页头主题图标的服务端/客户端渲染不一致。

走查中的口令由页面脚本从种子读取后直接填入，链接经本机 127.0.0.1 跳转打开，对话与日志里都没有出现。
