## Exact gap and schema audit

The applied D family is the tenth generic source type. Existing
`domain/knowledge/assistant_acl.visibility_body()` already generates its
ordinary-RLS branch from `SOURCE_TYPES`; no production Python change is needed.
However, the installed migration lineage pins the helper in schema_s0_0839 to
nine branches, ending unknown types with `RETURN false`. Saving an answer whose
actual source is a native Field row can therefore leave the resulting knowledge
hidden to ordinary readers. The existing five D PG cases do not save knowledge.

The read-only AST scan of every schema_s0 static SQL string is recorded in
`schema-audit.json`. SearchSource (the actual source head), SearchChunk, Outbox,
embedding batches and ChunkEmbedding have no nine-family source CHECK. There is
no separate enterprise-search Document table. The sole table `source_type`
enumeration is the unrelated schema_s0_0729 ProposalSource four-way enum
(`original/snapshot/knowledge/definition`), which must stay unchanged. The other
fixed enumeration is the lifecycle resolver: root's 0844 up expands it to ten;
the nine-way value in the same file is its down pin. The remaining fixed CASE is
the 0839 knowledge visibility helper covered here.

## SQL handoff

- `sql/unnumbered-field-knowledge-visibility-up.sql`: one CREATE OR REPLACE of
  `public.knowledge_answer_sources_visible(uuid,uuid,jsonb)`, generated by the
  existing live `assistant_acl.upgrade_sql()[0]`. All ten branches use the
  existing ordinary source projector and native permissions. It also uses the
  current source CTE identifiers. No policy is copied or recreated.
- `sql/base-0839-knowledge-answer-sources-visible.sql`: exact old function
  extracted from the 0839 static SQL, including its existing nine-branch body.
  This is an **old-pin candidate**, not a claim about current PostgreSQL
  `pg_get_functiondef` output. Root should normalize against the verified actual
  function before pinning a numbered migration. There is intentionally no ready
  down migration here: retained Field proofs must be accounted for in root's
  existing migration retention checks.

The original helper is STABLE **SECURITY INVOKER**, unlike the lifecycle
resolver's SECURITY DEFINER. This delta retains INVOKER, the argument names,
return type, and `search_path=pg_catalog,public,pg_temp`. CREATE OR REPLACE
preserves the existing owner/ACL. There are no OWNER, GRANT, REVOKE, policy,
table, RLS-role or typed-root changes. The old function is 222,467 bytes and the
current ten-family declaration 262,259 bytes; hashes and generator input
fingerprints are in `sql-contract.json`.
