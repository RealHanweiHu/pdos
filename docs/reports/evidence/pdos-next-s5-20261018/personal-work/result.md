## 失败与覆盖边界

首轮 [PG 失败](pg-01.log)发生在第二品类的 G0 夹具：实际成员变动已使品类续版，旧辅助函数仍提交版本 1。新夹具以本人只读事务取得真实版本，仅绑定该次初始提案输入，其余真实预览/保存照常执行；未修改共享 G0 辅助函数或放宽领域校验。

初次静态检查发现测试加载器使用保留变量名，随后又移除一条无效 lint 禁用注释；均是测试代码修正，最终静态通过。页面联验中，已提交旧布局的直达链接未核对品类，补齐与共享 UI 相同的匹配守卫后，以 build-02、两项定向检查及最终实际页面复验。

上述前端修改发生在 PG 浏览器等待期间，因此 [PG 运行记录](pg-02.json)如实保留 `source_changed` 的单个驾驶舱文件，包装器以 99 标记候选变化；pytest 本身为 0。[最终覆盖对照](final-coverage.json)证明后端所有归属 Python 与 PG 开始时逐字相同，最终前端运行源码与 build-02 相同；构建后只移除了测试中的两条多余注释。不宣称同一个完全不变的整仓候选全量通过。
