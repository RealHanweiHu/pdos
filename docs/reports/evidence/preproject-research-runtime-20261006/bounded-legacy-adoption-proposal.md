# 本地自动研究启用：旧未知用量的保守占账方案（待确认）

当前计量包已经批准并实际核验，预算部署文件已准备。继续使用该批准，不重新要求发布确认。

现有切换规则只接受已核验的实际用量。三个已关闭的旧模型调用没有供应商用量回执，因此仍阻止切换；运行服务的原日志也没有保存 token 用量字段。仅修改环境变量不能安全完成启用。

## 建议调整

仅对 [原记录摘要](unresolved-legacy-usage.json) 中的三个调用增加管理员保守占账入口。保持原调用、错误、`usage_status=unknown` 和零值占位原样；另外追加有审核人、原调用引用、上限依据及版本的占账记录，不把上限宣称为实际消耗。

占用额必须依据可核验的原请求限制或当时供应商硬上限计算，不能把新发布包的 17,000 输入上限套用到旧请求。没有可靠上限时仍拒绝办理。占账纳入原调用所属预算期间，不能清空账本、重置额度或释放未经证明的在途调用。以后取得实际回执时追加核对与差额记录，保留原历史。

切换只可由合法登录的本地演示 Owner/Admin 通过受控服务执行，绑定目标租户、当前 revision 和本次人工批准；不借用用户 ID，不改角色，不发伪造身份令牌。只读核对已确认现有 Owner 属于仓库演示种子且原密码校验匹配，见 [管理员可用条件](local-admin-readiness.json)，本轮未登录或写入。

该例外只覆盖列出的三个旧调用；新的预算调用继续保留原 unknown 预留、租约、停止、幂等、并发及计量有效期守卫。不得为所有未知调用开放跳过核对。需要隔离库验证权限、追加历史、重复采用、上限拒绝及期间计账后才应用本地预览。

随后应用原已批准的固定摘要配置，重载 API，执行原已批准的一次合成公开研究验证。客户资料、产品资格、具名立项与规格冻结边界保持；生产、push 和其他外部操作不在此范围。

网络恢复的独立预检已完成：[固定公开 DNS 端点](public-dns-recovery-preflight.json)通过正常 TLS 请求返回 HTTP 200、DNS Status 0 与真实公开地址，无模型调用。后续可接入应用内显式解析配置，保留私网/保留地址拒绝、逐跳核验及直连固定 IP，不调整系统代理或将 `198.18.*` 加入允许名单；这只是恢复途径可用，不代表研究整链已通过。

## 需要确认的选择

建议批准以上限定的保守占账处理并继续启用。另一条路径是保留现有规则，取得三条真实供应商回执后按原 `LegacyUsageReconciler` 采用。

本方案尚未获批，也未改动切换规则、迁移、业务账本或私有配置。需要确认的原因是现有已批准规则要求实际用量，本方案改变了未知用量的恢复方式；不是重复请求计量包发布或自动研究启用许可。
