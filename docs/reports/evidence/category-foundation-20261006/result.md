# 品类共用基础与立项提案 · 2026-10-06

本轮按用户四项结构要求及“汽车与自行车分别建品类，产品线＝品类”修改原 `server/`、`web/` 和3000预览。市场空间仍是权限与工作容器，可以容纳多个独立品类；没有强制空间和品类一对一，也没有猜测旧提案归属。

## 可用能力

- 品类不可变规格字典含稳定参数ID、版本、键、名称、单位、标准条件、方向、方法与判据。竞品指标、提案、产品定义及品类测试骨架引用同一版本；旧自由键需人工映射。修订保留历史，参数身份/单位/条件错误由领域服务与PG守卫拒绝，不把未映射或不兼容版本画为可比值。
- 新提案必须选品类，固定当版字典骨架、场景/用户研究、可用竞品与目标地区法规。私有要求、目标值和价格只补在本案；AI候选保留字典元数据、人工确认值与遗漏的规格骨架。共用来源变化提示需核对，旧稿不被静默改写。
- 新上传客户原件为发起人私有，通过提案文件引用绑定，不写入品类。ODM或任何引用私有原件的提案仅负责人/当次具名评审人可读；类别对标与矩阵排除私有提案和变体。通用审计不含私有提案正文/标题或客户文件名/原文。负责人具名填写并明确勾选去标识后才能共享摘要，私有来源证明留独立表，品类读取不暴露客户原件回链。
- 产品目录新建按品类→型号→变体，族/系列为可选标签；已有层级只保留兼容。技术平台是租户独立对象，与当前可读型号多对多，跨品类复用并留关联/解除版本。无平台层级强制依赖。
- 新增品类资料入口，含字典、场景、竞品对标、用户声音、地区法规、测试骨架和平台。场景×价格带矩阵实时由共用参数及有效报价计算，明确币种/地区/渠道/数量/税运/条件；未知、范围值和未映射场景不猜测归类。没有单独存一份矩阵作为业务事实。
