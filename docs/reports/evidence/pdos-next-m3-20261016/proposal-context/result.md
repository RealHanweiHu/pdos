# M3 提案级私有上下文与出站绑定（2026-10-16）

三入口提案内的小Pai现在可以读取本 Run 绑定的私有提案与条目，并在注册图中继续形成结果。服务器在受理时从实际提案、条目、Claim、知识和固定基线登记来源；原件即使只经条目或 Claim 间接引用，也进入实际读取集与客户原件分类。范围与性质不由模型参数提供。

依据：v1.1 §02.3 客户资料边界、§06.9 服务商数据协议、§08.11 最小读集/快照/请求内复用及路径 A。候选基于 `a82657a`；[最终源码摘要](source-manifest.json)。无迁移，head 仍为 `s0_0760`。

## 可用结果

- 受理将提案来源绑定保存在既有运行版本登记中；固定实际提案、品类、请求人及来源版本，按真实原件/产品范围登记 read_sources。没有原绑定的旧私有 Run 须重新委派，不能把当前 RLS 可读直接当作模型出站授权。
- `proposal.read` / `proposal.items.read` v2 可读同一 Run 的私有文档与条目，保留来源、人工值、版本、问题与决定元数据。历史版本只能使用已经绑定的来源。仍是普通读取回执，不授予计算 Claim 或 AI 写入资格。
- 提案资料范围扩大时不自动扩大原 Run；运行内新增 Claim/快照等引用的受控登记延伸尚未接入，现阶段可能提示重新委派，这是实现余项而非新增设计关卡。来源撤回、当前权限丢失或绑定不符时拒绝继续。开始模型尝试、实际发送前和返回结果前检查当前来源水位；未签约或协议类别不足时零客户端调用/零预约。调用途中来源撤回不释放回答，并清理预约。
- 初始化登记来源后，后续只批量读当前元数据、状态与版本，复用同一读取快照的证明；不逐轮重新展开上游正文。提案权限与安装状态在读取快照内复用，写入流程仍保留原锁与校验。
