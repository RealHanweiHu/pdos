# 公开查询出站投影与固定研究结果 · 2026-10-16

本批按冻结 v1.1 §06.6/06.7、§07.5 补齐查询投影与用户可见研究证据：实际查询/URL 无敏感匹配时按 `public` 检查；命中当前绑定客户名、型号、附件名或正文片段时按实际类别核对协议。研究来源、台账数量、覆盖与失败由服务器固定进入结果，品类/提案及个人小Pai共用一个展示组件。基线 `9f02b89`，无新增迁移或工具/提示词合同变更。

## 已实现与实际闭环

- 研究出站回调从服务器 Run 读取客户身份、绑定原件及文件名、型号、实际提案视图和本 Run 已完成领域读取的内容，校验当前来源/权限；工具回调传入的类别不能覆盖此投影。仅匹配实际查询/URL；模型调用仍走原有完整 Run 的协议检查。
- 标识按 NFKC/大小写、去分隔符和两层 URL 解码后的完整值匹配。正文按完整短值/查询或连续 12 个规范化 UTF-8 字节匹配，覆盖短中文片段；这是确定性字面检测，不是语义脱敏或资格证明。无法核对原件身份时不降级为公开。
- 服务器从实际 `research.fanout` 结果复制来源元数据、逐字台账、覆盖和失败，替换模型的同名 `result.research`，去重统计来源/行。同一作业不能有两个不同台账。研究未完成时将错误的整体 `completed` 收敛为 `partial`，已有未完成状态不提升。
- 新页面展示来源链接/读取时间、品牌型号/值/工况、片段和来源定位、查询/读取/未读情况及原始失败说明；缺字段不伪造零，格式/数量不一致如实提示。既有结果没有该字段时不批量改写历史。

[实际默认 Worker](checks/pg-candidate.log)通过未登记搜索/站点协议的合成服务走完搜索→隔离读取→逐字台账→T1 快照保存；实际出站回执为 `public`、协议引用为空，模型的 999 份来源被固定为 **1 份实际来源、1 行台账**。7 次合成模型调用在实际账本结算 840 微美元、占用归零，见 [business-result.json](business-result.json)。客户名、文件名、原件片段和绑定型号的未签约传输另有真实领域数据用例；实际协议追加停用后仍拒绝私有查询。

浏览器使用另一份本批真实已完成合成 Run，实际 API/BFF/最终构建页面显示同一来源与覆盖。验证了 1280×900 亮色和 320×900 暗色、片段展开、刷新当前状态及关闭重开原记录；模型调用数仍为 7，未发起新推理，见 [browser-result.json](browser-result.json)、[重开后的完整状态](browser-refresh.txt)、[桌面亮色](desktop-light.jpg)和[窄屏暗色](mobile-dark.jpg)。浏览器保存曾误用差异状态而得到“无变化”，随后从重开后的完整状态重新取证；没有把空差异当作缺少页面内容。
