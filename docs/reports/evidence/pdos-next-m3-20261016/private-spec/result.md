# M3 私有提案规格对标接通（2026-10-16）

客户需求、自主新品、派生三入口的私有提案，现在可以在原 Run 中通过 `calc.spec_compare` 与共享型号、共享竞品进行规格对标。使用实际登记的提案条目、字典版本、来源与发布定义，仍是普通读取结果，不建立计算 Claim 或业务记录。

依据：冻结 v1.1 §02.3a 共用规格、§06 工具/运行绑定、§08.11 读取快照和最小读集；对应 AT-02、06、37、38、48、49、51、57 中本次受影响部分。基于 `a20c3f8`，见[源码摘要](source-manifest.json)。无迁移，head 保持 `s0_0760`；无前端改动。

## 可用范围

- 比较前使用已有服务器来源绑定，核对实际提案、当前来源水位与权限。只允许原 Run 的提案；登记内的原件、Claim、快照等来源沿用同一快照的元数据证明，不因为运行接触私有资料而一律拒绝比较。
- 共享型号、当前共享竞品仍执行原有对象检查；其他私有提案或私有型号没有因此开放。新客户原件、撤回来源、缺失原绑定均在比较正文前停止，原件范围、资料分类和客户身份不扩张。
- 数值、单边界、单位、工况和事实性质按原值交给既有比较引擎；缺单位且未映射字典的条目保留为不可比，不补造口径。已引用字典的条目仍遵守领域层的单位一致规则。
- 恢复已完成读取时重新比较当前业务值和来源；内容变化返回 `SOURCE_STALE`，来源撤回拒绝继续，原回执/历史结果保留。
- 工具合同版本升为 4，随实际工具定义摘要钉住；输入 schema、抽取行匹配路径及普通读取性质不变。未添加 T0/T1/T2 权限，也没有更改技能包或模型资格。
