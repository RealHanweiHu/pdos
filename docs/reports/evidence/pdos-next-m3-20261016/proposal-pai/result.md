# M3 · 提案内小Pai委派（2026-10-16）

沿 v1.1 §05–06，在真实提案页接入已有小Pai，取代“接入后可起草与查漏”占位。仍为同一 Agent、注册图与持久工作流；没有另建 Agent 或同步模型通道。候选见 [源码清单](source-manifest.json)。

- 用户可在提案页展开小Pai，委派起草、抽取或查漏；服务器根据实际提案绑定私有范围、客户标识与挂载原件。界面不提供这些政策字段，也不要求先关联虚拟型号。
- 历史只列本人当前提案的运行，分页游标不能跨提案；详情返回真实提案标识，界面核对后再读事件。所有提案运行的详情、事件/流、候选和原委派重放均重验当前提案可读性；品类总历史也按实际可读提案过滤。
- 受理前按本人/品类/提案保留原请求；断线或暂时失败后可在刷新、收起/展开后人工重试原请求。重新打开不会自动派发。明确 4xx 拒绝（408/429 除外）清除待重试状态，表单可继续编辑；受理成功后的只读失败不会重新派发。
- 直接复用前一检查点的候选采用、待答、取消和整次撤回入口；G0 仍由具名评审人办理。
