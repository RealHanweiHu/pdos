# M3 · 研究来源页面登记与原回执恢复

本地闭环已实现：实际默认 Worker 产生的研究快照候选可在小Pai中核对标题、网址和保存范围，经本人一次确认登记；保存结果暂未返回后，重开同一运行读取原回执，不重复提交。M3/S1 尚未完成。

依据冻结 v1.1 §06、§08.11、附录 A `research.snapshot.register` 与 AT-56。无 T0 资格时沿用 T1，不增加批准关卡，不改变 T2。主线基于 `7e226d1`，数据库仍为 `s0_0762`，没有迁移、依赖、提示词或工具版本变更。

## 可用能力

- 既有候选读取接口同时投影 `snapshot_candidate`；服务器核对原 Run、事件、实际读取证明和原快照摘要。列表只返回来源元数据，不泄露正文、不预览、不写业务记录、不调用模型。
- 页面复用既有一次确认和原请求恢复流程，显示真实标题、网址、受众与保存效果。只有当前服务器列表中仍一致的候选可确认；本地保留请求本身不授予写入权。
- 保存后按原请求及真实业务回执判定已采用，保留 AI 作者、Run 和本人确认。未保存来源缺失、运行取消或失败时不暴露新确认；已有业务回执不依赖工作文件继续存在。
- 320px 弹窗居中并限制宽度。未知保存状态统一显示“保存结果待核对”，避免误报“尚未保存”。
