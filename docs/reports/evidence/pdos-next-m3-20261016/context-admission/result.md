# M3 同一运行内采用新事实与快照（2026-10-16）

小Pai在提案内登记的新 Claim、已登记快照，现在可在原 Run 中继续采用、读取并形成结果。新增引用由实际领域回执原子登记，不再因这些本运行产出的引用要求重新委派。

依据：冻结 v1.1 §06.3、§06.7 的实际运行/工具来源与写入分级，及 §08.11 的最小读集、水位和事务规则。基于 `ace7a38`；[源码摘要](source-manifest.json)。无迁移，数据库 head 保持 `s0_0760`。

## 可用能力

- 自动登记与本人一次确认均在原领域事务内登记 Claim/快照来源；业务结果、回执及 Run 来源登记一起提交或回滚。采用失败不消耗人工确认，原请求可重试；已成功请求返回同一回执，不重复引用或业务写入。
- Claim 仅接受同一 Run、同一提案、实际 AI 作者与实际回执；原件必须已在 Run 的服务器来源登记或原件读取集中。快照须为实际登记且状态可用；跨运行共享快照须经过原有实际页面读取证明路径。同一私有运行登记的快照保持私有。
- 原件范围、资料分类、客户身份、模型/技能/工具版本及资格不扩张。没有新增模型可调用的“加来源”入口。新客户原件仍须明确绑定；未绑定旧运行保持既有限制。
- 后续仍批量比较元数据水位，不重新展开上游正文；新 Claim 撤回后，原运行也拒绝继续读取。
