# D66 框架候选与 AT-64 审阅材料

两份 JSON 可提交为隔离库的框架草稿。发布后生成独立的固定版本。新品候选包含 ID、结构、电子与整机设计输出。派生候选增加父定义冻结回执、差异范围、变更后设计和回归依据。两类都保留 EOL 全检能力、PVT 评审和首批量产放行。阈值为 P41 的默认值。

角色使用现有租户目录默认键。实际试点需具名定版角色、各类项目适用专业及启用范围。受压腔体与锂电共用安全触发，正式材料需确认受压产品应采用的报告名称及范围。CEHub 清单保留原位置，条目只用于查漏和编写任务检查项。

| 案例 | 合成项目与输入 | 审阅要点 |
|---|---|---|
| 01 | 轮胎充气泵新品，有锂电、首次用驱动 | 完整路径。安全与运输成果齐全，依赖可追溯 |
| 02 | 帐篷充气泵新品，四字段均否 | 轻量路径，样机验证同时包含 EVT、DVT 成果 |
| 03 | 手动抽气泵派生，四字段均否，评审人要求完整 | 记录具名升级。保留派生来源、差异与回归 |
| 04 | 便携喷淋泵新品，无新模，新认证待核对 | 完整路径。认证风险列入材料，未知工期保留空值 |
| 05 | 水族循环泵新品，已知含 App | 软件结果有任务映射。任何豁免须有对应具名依据 |
| 06 | 隔膜泵新品，含受压腔体 | 安全红线持续适用。不存在豁免入口 |
| 07 | 车载泵派生，源定义未冻结 | G0 派生材料失败定位到原定义。修复条件可见 |
| 08 | 医用抽吸泵派生，认证角色空缺 | 确定性例外进入负责人队列。保留待分派事实 |
| 09 | 泵组新品，测试角色有两名有效成员 | 无唯一分派人。补角色后才发实际承接请求 |
| 10 | 工业加压泵，存在循环依赖和缺 EOL 前置 | 定位具体任务及成果。连续两次失败交负责人 |
| 11 | 工厂停线及调休，既有个人承诺与 G1 | 只更新预测，结果指明日历版本，保留承诺及基线 |
| 12 | AI 计划有人工编辑及下游验收 | 撤回分别列出成功、受保护及依赖原因，记录可追溯 |

每案由具名审阅人在成果覆盖、来源可核、角色与权限、工期可信、状态与回执五项分别标记通过或待修。出现 P42 任一关键错误直接判本案失败，记录精确任务、依据和运行。以上为未审阅的案例候选。
