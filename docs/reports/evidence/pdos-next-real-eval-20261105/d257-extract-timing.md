# D257 抽取耗时分析与并发改动验证（2026-11-08）

数据来自 11-05 回归（`live/runs/` 只留本地），由 [d257-extract-timing.py](d257-extract-timing.py) 计算，结果在 [d257-extract-timing.json](d257-extract-timing.json)。分位数用 nearest-rank。没有调用真实模型。

## 结论

- 并发能缩短典型抽取：2 路时抽取 p95 约从 8.2 降到 5.9 分钟，3 路约 5.6 分钟。
- 并发缩不短最长的那几次：最长的抽取只有 1–2 条引用，并发后估算最多仍约 13.9 分钟（原 14.4）。
- 长尾不在模型。子调用的 HTTP 时间在各轮都约 10 秒（p50）。长会话里慢的是每步的主机侧开销，它随会话轮次线性增长，另登记 D268。

## 2. 一次模型调用的时间花在哪

每次模型调用拆成三段：
- 领取前的主机工作：从上一次模型调用结束算起；
- 从账本领取到发出 HTTP；
- HTTP 本身。

单位秒，格式为 p50 / p95。

| 组 | 隔离 | HTTP | 领取→HTTP | 领取前主机工作 |
|---|---|---|---|---|
| RAG 单轮题 | 主循环 | 10.5 / 72.3 | 0.6 / 1.4 | 2.3 / 4.9 |
| RAG 单轮题 | 抽取子图 | 11.1 / 34.3 | 0.7 / 1.0 | 3.4 / 5.7 |
| CTX-01 第 0–5 轮 | 抽取子图 | 9.7 / 23.2 | 1.9 / 3.5 | 8.4 / 17.1 |
| CTX-01 第 6–17 轮 | 抽取子图 | 8.7 / 25.9 | 7.5 / 17.8 | 42.6 / 99.3 |
| CTX-01 第 18–24 轮 | 抽取子图 | 9.8 / 18.1 | 22.9 / 36.7 | 130.0 / 228.0 |
| CTX-01 第 18–24 轮 | 主循环 | 13.3 / 48.1 | 20.6 / 33.6 | 33.7 / 152.4 |

- HTTP 时间与会话长短无关。
- 主机侧两段都随轮次线性增长。CTX-01 第 18–24 轮里，抽取子图每步的主机开销约 150 秒，模型本身约 10 秒。
- 例：CTX-01 第 18 轮，一次 14 分钟的抽取只有 6 次子模型调用，HTTP 合计约 1 分钟。

由代码推断（未单独剖析），每步都会重跑的守卫会随会话变长：
- `assistant_ledger.carried()` 每次都把本会话所有前序轮次的检索与引用读取重新做证明校验（`issued(..., archive=True)`）。
- `adapter.guard` 在每次模型调用里跑 2 次（`citation_guard`：发起前和发出前），在子图里每次 `current()` 再跑 1 次；子图每步会多次调用 `current()`。
- `check_conversation` 每次模型调用也跑 2 次。

## 3. 改动与测试

改动见清单 D257：`assistant.extract` 的隔离子图改为有上限的并发，`PDOS_ASSISTANT_EXTRACT_CONCURRENCY` 缺省为 2。在隔离临时库 `pdos_test`（head `s0_0855`）上验证：

- `server/tests/agent/enterprise_search/test_assistant_fanout.py`：21 例，覆盖：
  - 结果顺序；
  - 不超过上限；
  - 一条领域错误；
  - 非预期错误时未开始的不开始、在跑的到安全点停；
  - 被放弃的尝试；
  - 上下文传递；
  - 配置校验。

  连跑 15 次全过。
- `server/tests/agent/enterprise_search/test_assistant_extract_concurrency_pg.py`：5 例，用真实账本、价格卡与验证预算：
  - 3 个子调用同时在途（屏障，串行会超时失败）；
  - 结果按引用顺序合并，与 1 路逐条相同；
  - 每个子调用各自预留并按实际结算，运行与预算的占用都归零；
  - 被放弃的尝试：在途的两个子调用结算后不再发起新调用，排队的第三个不启动；下一尝试从检查点续跑，主循环 3 次、子调用 6 次，没有重复发送。检查点用内存与 PostgresSaver（每个子图一个连接）各跑一遍。
  - 取消：取消后不再有子调用，没有遗留的 started 调用，占用归零；
  - 一条子调用被服务商拒绝：只记该引用失败，其余照常，预留释放。
- 反证：去掉子图里的安全点后，被放弃的尝试还会多发 2 次子模型调用，上面的被放弃用例失败。原因是子图的主机在启动时建好，拿不到活动的“已放弃”信号。
- `server/tests/agent/kernel/test_run_attempts.py` 加 1 例：活动的信号能传到抽取线程，尝试结束后清空。
- 受影响范围回归：见下节。
