# Budget recovery and shared entry integration — local implementation

The explicit budget-recovery action starts a new `AgentSession` with empty conversation history and fresh Run/checkpoint identity. It copies the latest server-owned work-state revision after owner/source checks and a revision CAS. Ordinary new conversations remain empty. The browser sends only the original Run ID, expected work-state revision, literal next goal and typed skill selections; it cannot supply work-state content.

The immutable source-state ID/digest closes the set of old origins, candidate event/Run pairs and original citation IDs that the new state may use. Existing continuation/lineage database guards are unchanged. Candidate states still come from current native candidate/receipt readers; citation bodies and current authority still come from the original fixed-source read ledger. Human constraint quotes retain their old Run proof, deleted-constraint tombstones and exclusion/correction state survive. A reused session ID alone does not authorize the old roots. A second restart and ordinary continuation between restarts retain this boundary. The history ACL builder resolves missing old citation roots only from this exact restart proof, so a normal follow-up does not hide otherwise readable restored history.

The restored state also retains the complete source Run ACL manifest, including READs/search candidates that the answer did not cite. Admission classifies that manifest with current metadata; only authority loss blocks, while content updates remain usable. A server-only `_restart_access` state field survives later versions; public and model projections exclude it. The frozen Run stores that access with a digest, checks it before each model call and propagates it into later history ACL closure. Withdrawal of an unquoted candidate therefore hides derived unfinished/questions and stops later disclosure rather than escaping through the new session boundary.

Shared API/DTO integration also carries the skill agent's exact original loaded identities, typed exclusions and explicit replacement choices. Definite skill-selection refusals keep the conversation editable; source/identity withdrawal retains the existing private-context cleanup. A recovery accepted event contains the fully resolved fixed selection and no runtime inherited-skill exclusion; its original client selection remains in the request digest. The skill subsystem validates the server restart proof and permits an empty resolved selection without reviving default preload.

The new recovery button performs no write on opening. It preserves an unknown original request for exact idempotent replay, validates a new server session before opening, and can open an already saved recovery without submitting. Both personal and category/project parent containers accept the new session identity. The BFF forwards the exact original request and keeps eligibility reads read-only.
