# 项目外部交接与原回执读取

“评审与交接”现已汇入本项目的固定外部交接。明确选择一项后读取固定授权、发布包与两项专业决定、双配置、原发送意图、收件方、编号版本映射和文件 manifest；发送、接收、实际生效按服务器投影独立显示。原回执另行展开，保留原发生/收到时点、范围、发行者、来源、对账前驱与冲突，不把授权保存当作外发成功。

依据指定 HTML、最新 v1.1 §05.3/§05.12、§04.14 放行与移交、附录 A/B 及 P13/P21/P22。阶段正式评审仍未接入，S1–S5 未因此验收；性能继续暂缓。

## 本轮实现

- 列表使用原 `project_id/history_cursor`，详情核对明确的固定 id/revision；原回执使用 `before_sequence`，只拼接同一完整水位。翻页、刷新、身份/范围/API 变更、收起及卸载均隐藏旧资料并拒收迟到响应。
- 展示三段各自的原状态、覆盖范围、当前原回执引用和不匹配；保留未知、部分接收、显式对账和冲突，不由客户端计算阶段完成或整体交付结论。
- 保存时职责/资格依据、材料状态和专业事实引用标为历史快照；原 `prepared_at` 不当外部发生时点，不据原资格或状态重新作当前判断。政策撤回后仍显示原内容和“需重核”。
- 复用已有 GET/BFF/领域合同，只新增读器和展示面板；父工作区在 review 标签接入，原办理链接仍绑定本项目。没有新增领域写命令、迁移、模型、资格或外部发送。

## 初始失败与限制

首轮实际八阶段流程执行后，[导出断言失败](initial-export-null-field-failure/backend-tests.log)（110.71 秒）：合法服务器原字段 `approval_token: null` 被按字段名误拒；当轮公共 `command_handlers.py` 有其他施工增量，见[初始候选](initial-export-null-field-failure/backend-candidate.json)。仅修本轮测试导出守卫，递归要求该字段必须为空，继续拒绝非空凭据，原 DTO 不删字段；随后同节点单次补验通过且运行源稳定。首轮合成记录保留，未删库、未将失败记为通过。

检查结束后，其他施工继续扩展现场反馈到受控选择/订单，修改了后端模型/服务及前端变更订单读器；[后续差异](post-check-other-owner-changes.diff)与[哈希边界](post-check-source-boundary.json)单列。这些增量不在本轮构建或实库候选内；本轮新 UI、专属移交读取源及原 DTO 未变，不为仍在施工的独立增量重复验证。

实际本病例的两个游标均为空，未覆盖实际超过 20 条的翻页；翻页、其他原状态、错误及迟到响应只由定向前端检查覆盖。浏览器授权先前被明确拒绝，本轮未重试或绕过；新面板实际页面、320px、亮暗及完整标识展开的视觉复核仍缺。未补新实际 BFF 整链，也未消除上传超大 JSON 传输中断或其他既有失败。

剩余差距见 [design-qa](../../../../../pdos-next/web/design-qa.md)与唯一清单。阶段模板/门禁健康度/冻结点、接口/设计责任人/漂移、阶段正式评审、其他专业分诊、持久会话管理、语音/手动技能、完整制造历史和独立项目资料仍按各自前置接续；不做会话删除。自动续工继续，无 push、部署、真实模型、资料出站或生产操作。
