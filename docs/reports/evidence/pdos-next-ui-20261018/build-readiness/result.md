# Build 保存时准备检查

项目 Builds 中明确选定轮次、重新核对其固定版本后，现可直接查看已保存的准备检查：原结果、逐项缺口、原因、恢复建议及固定来源；展开查看原需求量、覆盖数量与未知值。复用该 Build 已返回的数据，不新增请求或领域动作。

依据指定 HTML 的项目 Builds 结构、v1.1 §02.7、§03.7、§04.3–§04.6、§05.3 及确认稿 P13/P17/P21/P22。这里是保存快照计算的读取，尚非完整阶段规则／门禁／健康度：检查只有原 key，不能自行补出 rule id、版本或阶段实例。

- 保存记录的外层 `blocked` 与内部计算 `unknown` 独立显示；固定双配置来源可读不代表当前资格、准备完成或可开工。
- 检查所选 Build、项目保存版本及固定双配置绑定，保留原对象、`as_of`、来源、十进制字符串与 `null`，不按客户端时钟、最新配置或显示数量重算。保存指纹收入详情，明确本次没有重新复验哈希。
- 尚未返回保存记录与协议／绑定错误分别提示，仅影响本项面板。纯组件没有 API、状态、确认或写入；沿原摘要的刷新、切轮与范围隔离，不增加请求。
- 需求不冒充供应；已知数量为零也不把未知缺口补零。覆盖明细保留原状态、数量、问题与说明，未校验的来源池／使用项仅显示返回记录数，不展开其内部字段或推断实际占用。完整输入快照不直接倾倒到界面。
