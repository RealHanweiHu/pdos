# 全局知识入口与固定规则读取

全局“知识”现默认读取当前品类的经验候选；明确选择真实型号后，才读取该范围候选与配置规则。候选、规则、适用判断和服务器可用状态分开呈现，可展开原正文、固定来源、条件、时限与版本历史，再明确进入原有记录／具名发布办理页。没有自动选择第一个型号。

依据指定 HTML 的全局入口与既有 UI 基线、v1.1 §01.6、§04.15、§05.3、§06.8，以及确认稿 P13/P15/P21/P22。HTML 没有独立知识页的完整演示布局，本轮内容按生效知识页契约和实际接口落地，没有把演示数字放入产品。

## 实现与数据边界

- 新读器复用现有品类／型号 `experience` 与 `products` GET，保留原 `as_of`、署名 ID、来源、权限标记、固定候选、配置与历史元数据；品类范围真实为 `product_id=None`，不伪造型号或人员姓名。固定旧候选／配置不必出现在当前有界列表中，不用 Current 补旧引用。
- 查询与类型筛选仅作用于本次返回内容。各类候选、规则、项目及每种配置最多返回 100 条，界面不把返回数当全库总量；历史只读原元数据，不冒充已读取历史正文。
- 切换身份、品类、API、型号、刷新、离开与 A→B→A 时隔离迟到响应。读取或权限失败隐藏旧资料；旧工作台仅在型号元数据与知识读集成功、用户明确选择后挂载，沿用原表单、命令档位与具名批准，不新建发布流程。
- 服务器按当前读取人的实际权限重核。共享规则可读不代表其私有发布依据可核；前端原样保留 `needs_recheck` 和原因码。候选续版本身不使固定旧规则自动失效，来源失效也不改写已保存内容。
- 本轮为七个前端文件及一个专属 PG 病例；未改生产领域、公共模型、命令、BFF 或迁移。原显式 `bench=knowledge&product=…` 兼容入口保留，普通全局导航进入新目录。

## 剩余差距

品类级记录表单尚未接入；当前目录提供有界读集筛选，尚非全库检索或历史正文阅读器。实际病例没有触及 100 条上限，不声称完整检索／分页验证。型号记录与发布入口的挂载、退出和刷新已定向核对，本轮没有通过新目录完成一次真实浏览器提交。

此前 55210 浏览器操作被明确拒绝，本轮未重试、换入口或探测；知识目录实际交互、320px、亮暗与标识展开视觉复核仍待授权。既有上传超大 JSON 中断、新文件→Run及制造历史真实跨 50 条联验仍未闭合。
