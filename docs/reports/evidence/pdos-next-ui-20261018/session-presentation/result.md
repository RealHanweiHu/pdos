# P20 本人会话改名、置顶与归档恢复 · 2026-10-19

已接通真实持久会话的重命名、恢复原目标名称、置顶/取消置顶、归档/恢复及服务端搜索分页。采用指定 HTML 的会话管理方向，遵守确认稿 P20：没有删除会话的命令；展示修改不改变原 Run、运行回执或业务记录。本记录是一个功能闭环检查点，不是 UI 全部完成、S1–S5 正式验收或生产启用。

## 可用能力

- 列表明确分为“未归档 / 已归档”。服务器先按当前具名本人、个人或品类/提案以及实际产品/项目父对象权限过滤，再按置顶、原建立时间和标识排序、搜索和分页。搜索包含自定义名称、可读 Run 原目标及完整标识；仅名称命中时不合成命中的 Run。
- 新表 `agent_session_presentations` 只追加展示修订，旧会话无历史时由服务器返回修订 0 的默认值。自定义名称可显式清空，随后使用原最新目标展示；原目标始终保留。旧 Session/Run 读取及继续资格沿用，归档后仍可读取原运行。
- 同一请求编号与原内容精确重放，返回原始不可变修订，不能用当前版冒充旧回执。版本过期、同编号改内容会拒绝；重放及回执读取也先核当前所有者与父对象权限。项目撤权后，隐藏的会话管理对象返回 404，原运行读取保持其既有 403 合同。
- 新静态代理限制方法、参数、同站点提交、实际请求流 8 KiB、身份及禁止缓存；不确定的提交结果按未知处理。当前 React 挂载身份内保留原编号和内容，先只读查回执，明确重试也使用原请求。普通面板刷新只读取；身份/API/品类/提案/项目变化或卸载清除本地指针，不声称跨整页重载恢复该内存指针。服务器展示历史与回执持久保留；未使用 localStorage。

## 失败、修正及证据事故

1. 首轮展示操作与 24 表不变断言已经通过，最后撤权夹具遗漏既有 Product 时钟触发变化而失败；仅修夹具精确预期，原件保存在 [initial-acl-boundary](initial-acl-boundary/backend-tests.log)。第二次在最后拒绝检查将隐藏对象误预期为 403 而失败；依据现有 restrictive RLS 和防枚举合同，将三项会话管理精确要求为 404，Run 仍要求 403；原件保存在 [initial-acl-visibility](initial-acl-visibility/backend-tests.log)。两次均未修改生产服务、权限或迁移，最终只重跑这一节点后通过，没有重新运行完整业务链。
2. 首轮报告脚本路径写错，覆盖了前轮 `knowledge-library/backend-tests.log` 和 `backend-candidate.json`。原成功 stdout 已从同聊天原始命令输出恢复；**原完整 backend manifest 未恢复**，现文件明确是恢复说明，未补造哈希图，也未重跑旧用例伪装原证据。前轮原 DTO、前端候选及 final-audit 仍在。完整说明见 [旧证据恢复记录](../knowledge-library/result.md#2026-10-19-证据恢复说明) 和 [恢复来源](../knowledge-library/recovered-process-evidence.json)。本轮所有脚本已固定并断言报告路径。
3. 初次迁移启动器缺少独立 alembic 可执行文件，尚未执行迁移；改为 Python 模块后才执行。初 Ruff 的长 SQL 行仅增加局部规则说明，已应用 SQL 字节未变。最终审计脚本初次误读离线报告键名，仅修其结果字段后完成文件审计，无功能或数据库复验。过程见本目录 `initial-*.json`。
