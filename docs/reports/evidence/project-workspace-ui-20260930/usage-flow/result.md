# 项目工作区使用流程检查点 · 2026-09-30

根据用户“按项目管理软件的使用逻辑、隐式能力不逐一进入UI”的要求，工作区已沿现有Linear风格改为六个日常入口：总览、项目阶段、工作项、计划、评审与交付、资料与协作。专业办理位于工作视图，成员/流程/报告/接口等低频功能位于页头项目设置。没有增加第二套UI库或修改后端业务规则。

总览显示从当前任务、问题及需应对风险派生的真实待推进事项，可直接进入对应记录。清单一次呈现一个类型，链接自动定位其类型与详情；新建表单默认收起，问题/风险的来源、成本、通告、模板和质量关联按记录展开。阶段指南、项目辅助查阅与重复项目聊天从日常页面移除；旧项目会话链接保留。后台提醒重排、触发、已读等记账从默认动态移出，完整历史与显式事件链接保留，未知业务事件没有一并过滤。

本次增量候选11个前端文件的摘要见[candidate.json](candidate.json)，开工前快照位置及摘要见[before.json](before.json)，本轮修改见[ui.patch](ui.patch)。UI使用规则已写入[使用模型](../../../../design/2026-09-30-project-workspace-usage-model.md)与UI基线v0.6.3；该规则不意味着后端自动触发、统一调度或真实模型资格全部完成。

验证通过：4个组件测试文件共56项，覆盖旧业务路由、直接阶段入口、分类/来源展开、评审到风险清单、实际事项链接、后台记录历史保留、外部权限、撤回后当前计数及冷启动历史回执。见[测试日志](tests.log)。全项目[类型检查](typecheck.log)、受影响[lint](lint.log)及[机械布局检测](layout-detector.json)通过。测试日志仍包含原Complaint模拟用例的重复key告警；不影响本次通过结果，不据此宣称该旧告警已修复。

浏览器检查覆盖真实项目PRJ-A1：1440桌面亮/暗、390手机总览和阶段、从总览进入问题及刷新自动定位、默认清单零展开详情、只展开目标记录、键盘箭头导航、项目设置入口。页面宽度分别为1440/390，没有页面横向溢出；手机主入口与长泳道各由自身容器滚动。见[浏览器记录](browser-checks.json)、[桌面总览](overview-desktop.png)、[问题清单](issues-desktop.png)、[任务清单](work-items-desktop.png)、[暗色总览](overview-dark.png)、[手机总览](overview-mobile.png)及[手机阶段](stages-mobile.png)。过期本地测试登录已续接，临时视口已重置，亮主题已恢复，新的总览预览保留。原预览标签连接失效，关闭也未成功；其登录页仍保留，不影响新预览和上述业务检查。

本次没有直接数据库维护、迁移、真实模型执行、业务记录变更、生产构建或Git推送。权限、独立验证、T0/T1/T2、具名签核及原专业域功能保留；外部成员仍只能进入概览、阶段和原授权服务范围。后端自动化缺口、真实阶段要求实例化、岗位/排期来源及专业域进一步流程整合按原N项推进，本检查点不关闭原N/P/Q验收。
