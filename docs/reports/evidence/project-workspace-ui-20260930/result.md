# 项目工作区 UI 重组 · 2026-09-30

> 后续用户明确“项目阶段单独入口”。最新布局与候选见[阶段独立入口检查点](stage-entry/result.md)：泳道、指南和阶段操作已移到“项目阶段”，总览保留摘要与动态。以下保留第一次重组时的证据。

用户要求先优化项目工作区，采用新的 Linear 风格，参考飞书项目等工作区的内容分布，让项目阶段以泳道呈现。此次改动限于项目工作区前端，7份候选文件及SHA256见[candidate.json](candidate.json)，相对开工前共享工作树的增量见[ui.patch](ui.patch)。原有项目控制器 `project-workspace.tsx` 与开工快照逐字一致；未提交或推送 Git。

## 已完成的布局

- 统一项目标题、编号、状态和当前阶段，去掉重复项目标题及以阶段序号计算的百分比。摘要只保留描述、真实日期和当前任务/问题/风险数；加载或失败时不显示假零。
- 总览以阶段泳道为主要内容：横向为实际流程阶段，纵向为项目任务、协同行动和问题闭环。当前阶段突出，空阶段显示真实空态；无归属或原阶段已移除的事项进入“未归阶段”，风险按现有模型单独显示跨阶段摘要。支持未完成过滤、真实前置任务标题和阶段列表，任务/问题卡片链接原有办理入口。
- 成员、流程与初始化、报告与导出、接口与测量、结项与交接进入独立“项目管理”，按分类展示。ID方案、交接、冻结及规格责任进入工程域。原权限和领域操作组件保留，旧初始化/结项/ID/规格责任链接自动进入对应位置，其他显式业务标签仍优先。
- 流程指南、知识辅助和旧项目AI入口收拢为可展开辅助区；活动默认显示最近6条，可展开全部已加载记录，旧事件定位保留。外部成员仍只见已授权概览、阶段及原有项目服务，不增加内部工作项访问。

## 布局评估与参考

开工时总览同时装有资料、成员、多个导出中心、API/Webhook、测量、模板、初始化、ID、结项、流程说明、阶段和59条活动，阶段在较深的位置，同一项目身份重复出现。按工作目标拆成总览、领域办理和项目管理，把阶段与工作项提升至主要区域。

参考[飞书项目泳道说明](https://www.feishu.cn/content/77en5sm8)的多维度协作和分组思路，以及[飞书项目实践](https://project.feishu.cn/home/blogs/practice-gd)的流程/视图区分；沿用本项目已采用的 Linear UI 基线、组件库、主题和颜色。本次泳道按已有阶段和工作类型分组，不补造部门/岗位归属，不把阶段位置当任务完成率，不虚构阶段起止排期。具体计划与资源仍进入现有计划域。
