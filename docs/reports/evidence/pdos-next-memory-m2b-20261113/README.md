## 带库测试覆盖的门禁

`test_scope_notes_pg.py`、`test_scope_note_t0_pg.py`、`test_scope_note_context_pg.py`、`test_scope_note_scopes_pg.py`：

- **他人不可读**：挂在私有产品、私有提案、私有项目上的条目，只有该对象的受众读得到；同品类的其他成员列表返回 403、单条返回 404、直接查表得不到行；跨租户 403。对象由共享改为私有后，原来读得到的人立刻读不到（没有存受众副本）。G0 评审人因为在项目受众里，读得到私有项目的条目；另加的第三名品类成员读不到。
- **AI 身份不能直写**：以 AI 写入身份直接向 `scope_notes`、`scope_note_versions`、`scope_note_evidence` 插入都被数据库拒绝；本人绕过命令直接插入版本，因为没有对应回执，提交时被拒；版本不能更新、不能删除。
- **T1 一次确认**：不带确认凭据提交被拒（`CONFIRMATION_REQUIRED`）；预览不写入任何行；确认后写入版本和通用回执，回执里没有条目正文。只读成员预览即被拒。
- **无资格不走 T0**：没有“租户 × 技能包 × 模型版本”资格时，`scope_note.observation.record` 被拒（`QUALIFICATION_REQUIRED`），不写条目、不写回执、不留完成的工具调用；同一条命令改由本人预览并确认后写入，标“小Pai 起草，成员确认”，回执是本人的。有资格时写入署小Pai 名、可信状态不是“已核实”、确认状态为“提议”、不置顶、只进背景区。有资格的运行仍不能执行 `scope_note.save`、`scope_note.retire`。小Pai 只能记在本次运行自己的范围上；已有相似条目时不重复记录。
- **按运行撤回**：`scope_note.retire` 带运行编号，撤回该运行自动记下、尚无成员接手的观察，并用撤回行收回它加的证据链接（证据行不删除）；成员接手过的条目不动。
- **撤权后不返回且不带入**：条目引用的对象对读者不可读后，运行里的带入、`memory.search`、“用到了 N 条记忆”都不再出现这条；负责人仍读得到。
- **停用或撤回后运行里不留正文**：运行行上只存条目编号、版本号和分区（`scope_notes_context`、`memory_usage.scope_notes`），正文每次从版本表读；停用或撤回后再次组装不带这条，运行行的 JSON 里查不到正文；已带入过的运行在下一次模型调用前停下（`CONVERSATION_HISTORY_REVOKED`）。
- **四种与分区**：只有“约定”进约束区；关注点、决策背景、观察进背景区；决策背景不挂正式对象时标“未形成正式决定”，挂了的绑定对象当前版本，对象出新版本后标“对象已更新”并降到背景区；互相冲突的两条都降到背景区。
- **替代按生效时间**：新条目生效更晚，旧条目进历史并记失效时间；补录的更早信息只进历史，不替代现有条目。相似条目不选处理方式不能保存；完全相同的被拒。
- **已核实**：须关联一条业务记录，或两个相互独立的来源；证据行不存引文原文，只存摘要。
- **客户标签**：提案上没有登记的客户标识被拒；带标签的条目只在运行绑定了同一客户时带入和检出。
- **预算与配方**：带入不超过 800 token，置顶优先，超出的计数并提示用 `memory.search`；技能合同里的 `x-memory` 声明取并集、预算取最大值并受服务器上限约束，不认识的声明使技能目录加载失败；声明了配方的技能摘要随之变化。
- **范围近况**：项目范围复用驾驶舱动态流的查询，加上本范围备忘的变更，只列“谁、何时、做了什么”，不含备忘正文；同一水位重复读取一致；不超过 400 token。
- **作者离开**：作者停用或失去品类授权后，条目保留，作者标“已离开”，复核人显示为对象负责人。
- **分享到项目**：只有本人能把自己的记忆条目带成一条新的团队备忘；个人条目不变，仍只有本人可见。
