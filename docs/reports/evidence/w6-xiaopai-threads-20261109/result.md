## 做了什么

| 部分 | 内容 |
|---|---|
| 发起（`ai.thread.invoke`） | 发帖时 @小Pai，同一事务按发起人本人建运行：小Pai 为写入人，范围由服务器从串所挂项目绑定；每位发起人每串一个会话，再次 @ 续接本人会话（P52），上一条未完成时拒绝；任务串预载 `work_management`（租户已启用时）；共享串会话设为“不进记忆”。只经交接通道可见的人、看不到对象的人不能发起（服务层与数据库守卫两处）。编辑不能新增 @小Pai。提交后交给 XiaopaiWork（Temporal → LangGraph 注册执行图），Temporal 不可用时运行保持排队，由现有待启动运行调度恢复 |
| 动态上下文 | 截至 @ 时的串内公开内容（人的发言、小Pai 已公开的回复与正文分享；不含只给发起人看的提示）冻结进运行，经 `host.skill_context` 以 `discussion_thread` 背景字段追加在 context 末尾，按 `combine_contracts` 的字段合同投影；冻结前缀未改，模型输出合同未改 |
| 投递（`discussion.ai_reply.deliver`，P54） | worker 发现运行结束后启动 `DiscussionAgentReply`，在注册“xiaopai”图的确定性节点里：按发起人用 P32 的读取清单重建本次运行读取的全部来源（工具读取、携带历史、项目事实、引用、MCP），再按 `discussion_thread_audience` 列出的每位当前受众本人的 RLS 逐一复核。全部可见才贴回；任一人看不到任一来源、或来源未能核对，整条回复只给发起人，串里只显示固定提示。正文由 SQL 从运行结果读取，不接受传入。回执只记人数与来源种类 |
| 运行卡与回复 | 发起消息下显示运行卡：进行中、等你回答（他人看到“等发起人回答”）、完成、部分完成、失败、正在核对来源；发起人可查看私下回复、在小Pai 中打开、去回答。小Pai 消息署名“小Pai · 应某某请求”，不能编辑，只能由发起人或项目负责人撤回（P54 第 3 项） |
| 分享（`discussion.ai_reply.share`，P62） | 仅发起人。读过客户私有资料只能分享链接，读者打开时按本人权限复核冻结的全部来源；其他情形分享正文前提示“正文可能含有部分成员无权看到的内容”并须勾选确认；回执记分享人、方式、是否确认与未覆盖的来源种类 |
| 主动提及（`ai.mention.notify`，P34 第 5 项） | `agent_mention_notify`：只允许小Pai 作写入人、为在职的发起人或规则负责人；双方此刻都须看得到对象；同一对象同一原因冷却 1 个工作日（上海时区周一至周五，P41 第 10 项），已读也不重复。①小Pai 分派任务改走它（P53 受派人照常收到）；②P105 补充信息：运行等待时 worker 发现，任务评论串 @ 受派人（无则负责人），项目串不另 @ 人，通知只带串的链接；③规则例外：原语与签名“小Pai · 按某某的规则”已备，规则侧接入归自动化规则会话 |
| 前端 | 提及选择器首项 @小Pai（不可用时置灰并说明）、“小Pai 的回复只给我看”；运行卡与回复/分享；小Pai 消息标识；进行中时每 3 秒重读；项目讨论与任务抽屉都接上“在小Pai 中打开/去回答”；BFF 放行 `agent-requests/{id}/reply`（GET）与 `/share`（POST） |
| 合同 | `auxiliary-operations.json` 加 5 项：`ai.thread.invoke`、`discussion.ai_reply.deliver`、`discussion.ai_reply.share`（仅人工，按 D56 先例追加）、`discussion.ai_reply.retract`、`ai.mention.notify`；`openapi.json` 重导（+2 接口）；校验通过 |
