## 已接通

- 从实际 AgentSession 身份聚合同一会话的多条 Run。个人入口只查个人范围，品类入口固定该品类，本案助手再按 proposal_id 收窄。服务器在普通 RLS 下先核对本人、父型号和提案可读性，再搜索、计数与分页，不先泄出目标或隐藏对象数量。
- 服务器搜索可读历史 Run 的原目标或明确标识；命中历史工作时明确标示，最新原目标不是可改标题，最新工作状态不是整会话状态。搜索保留字面 % / _ / 反斜线语义，前端不重算 PostgreSQL 匹配规则。
- 先选会话，再选具体工作；两个读集各自分页，打开/搜索/切换均只 GET。主卡显示真实友好日期，完整身份和原时间收进详情。原 Run 的上下文链、技能加载、候选、答复与回执入口保留。
- 继续仍先读取原运行的 continuation 事实，再按 continue_from_run_id 保存；不借 session_id 假称继承全部历史。已有子工作、未终止、已撤回等情形保留原服务端限制。关闭、缩回、转后台不创建新运行。
- API、本人、品类、型号、提案或搜索/显式刷新变化隐藏旧读集及线程；迟到响应不能恢复旧内容。权限或协议失败清旧列表与结果，只有明确的 503 可保留刚核对的列表。修正原 readRun 失败保留同 ID 旧正文/候选的路径；同会话继续成功后的历史刷新不误清新子工作。
