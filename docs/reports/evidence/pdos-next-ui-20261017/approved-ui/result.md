# 已确认 UI · 首批实施（2026-10-17）

依据现行 v1.1 §01.6/§05、确认稿 P15–P20/P22 和已确认 A 类规则，已开始在 `pdos-next/` 落地用户决定的 UI。本记录只关闭首批可用界面，不宣称全部 UI、S1 或 S2 完成。

## 可用能力

- 全局主干改为我的工作、项目、组合与资源、知识；产品管理独立分组，默认落地仍是我的工作。品类开发和立项提案入口使用本人有效 `Grant.product_manager` 的服务器只读能力投影，缺失、失效或读取失败不补授能力；小Pai 对所有岗位保留。未加入角色模拟开关。
- 项目列表提供同一授权读集的列表、看板、时间轴；支持搜索、品类筛选、本人负责筛选和列表分组。看板无拖拽写入；分组控件只在列表出现。当前没有阶段模板时明确待接入，不把已有计划当阶段，也不把风险、到期任务当健康度。
- 项目工作区增加属性头、“现在”和“阶段与门禁”读法，保留实际任务/风险、固定定义、四时间、下一 Build、关键承诺及项目范围。实际 Build/交接/结果入口绑定原品类、型号与项目。未把仍按型号读取的“问题与变更”包装成项目专属入口。
- 小Pai 使用运行历史与对话线程呈现目标和结果，可搜索与打开既有记录；技能 chip 只来自实际加载事件，发送区列出本次携带范围与来源版本。转后台只关闭/折起界面，同一 Run 与原请求保持；仍沿用现有采用、追问、撤回和幂等恢复入口。
- 橙色、Geist、8px 圆角、双主题、Phosphor 与现有组件栈保持。没有复制设计稿里的演示项目、六段阶段、健康度或状态更新到业务事实。

1. 阶段模板/实例、门禁规则及可下钻健康度、冻结点与具名阶段历史尚未进入当前项目投影；下一门禁、三种成熟度保持未知。计划完成预测不能冒充门禁预测。
2. P18 的只追加具名 `ProjectStatusUpdate` 尚需领域对象、受控命令与读取；目前不以领域事件、用途文本或客户端编辑冒充状态更新。其余项目工作区标签继续使用既有真实办理页，未完成全量视觉重排。
3. 我的工作仍需把真实决定、接收、验证、外部等待、本人承诺逐类接入，不能把它们全改名为 Task 或补零。
4. 项目页小Pai的具体项目 ContextSnapshot 绑定仍需接通；目前明确显示实际品类范围。小Pai 持久会话列表、重命名/置顶/归档恢复、范围选择与 `@` 对象、消息级复制/新运行重跑、受限撤回逐项结果仍需接通；没有把 Run 假称 Conversation，也没有用 localStorage 伪造服务器会话事实。
5. 服务端能力投影尚未做真实隔离 PG/RLS 的登录 HTTP 联验；本轮不操作正在施工的 S2 数据库、迁移或业务文件。后续公共模型与迁移按实际 head 统一协调，不抢占正在施工的文件。
