## 可用能力

- **资源与方案比较**：当前计划、多个保存候选之间可比较任务增删、预测日期、资源冲突/待核对和原承诺影响。资源需求包含任务、人员/实际登记资源、协调人、数量与用途；服务器读取已有计划及实际占用，按容量和半开时间区间判断。同一方案的前后依赖不会被误算为并行冲突。不可读项目的名称和内容保持隐去；计划与实际占用无法可靠去重、缺少日期或容量事实时保留待核对。无已知冲突不等于已预约或已确认可用。
- **后续计划修订**：从当前计划带入完整输入、依赖和资源需求，保存新候选，再经一次确认追加计划版本。过期候选可以比较，不能覆盖当前计划。旧计划、批准基线、任务关联、个人承诺与实际记录保留；新任务使用不可复用的键，避免误接历史任务。失败或结果未知时保留原请求恢复路径。
- **阶段与门禁**：显式采用标准/派生/小改模板，关联真实任务里程碑，具名批准计划基线、提交固定评审并具名办理阶段决定。当前出口与下一阶段进入条件分开展示；下一阶段缺口不阻塞当前出口。阶段历史保留办理人、回执和实际通过时间；不能由完成比例或预测日期猜测阶段。
- **健康度与事实接入**：目录、项目概览、计划和门禁共用服务端投影；实际 G0、当前定义、批准基线、专业发布包规则与当前签核、承诺履约共同提供判断依据。专业材料换版、撤回、失效或范围不匹配后不沿用旧批准。基线/预测/承诺/实际四时间口径分离；未绑定当前门禁任务时明确提示，整体计划预测保留在任务表和方案比较中。
- **新 UI**：办理入口收在折叠区及确认侧栏，保留旧能力。读取失败清理旧比较值，提交失败退出确认层后可恢复原请求；本地存储失败时不发出业务写入。发布包选择可继续分页。
