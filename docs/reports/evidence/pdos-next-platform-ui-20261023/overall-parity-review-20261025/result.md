# 确认版 UI 与正式实现整体差异审查 · 2026-10-25

当前正式实现仍未完整对齐确认版。外层导航、部分密度和新的单输入框已统一；主要剩余问题在操作流程、资料编辑范围、数据入口和页面组织。本轮只做检查与证据记录，没有修改业务代码或业务数据。

## 范围与证据口径

- 对照基准：`pdos-next/web/src/app/ui-lab/platform/DESIGN.md`、用户已确认的 `/ui-lab/platform`。保持 Linear 紧凑方向、原技术栈、权限与人工确认边界。
- 实际浏览器覆盖：我的工作、收件箱、项目集、项目列表、项目任务/计划/文件、品类总览/详情、提案列表/文档、小Pai历史、知识；提案另核对390×844布局。正式预览使用现有本地合成Owner身份，设计预览使用产品经理示例。
- 两端样本量、人员、任务内容不同，空数据本身不计为设计缺陷；缺入口、组件结构和源码数据路径另行核对。提案文档实看已立项样本，草稿编辑能力以源码核对，不把只读样本的禁用状态报成缺陷。
- 采用 Impeccable 的实现审查方法，未执行完整设计评分或性能验收。`detect.mjs --json pdos-next/web/src/components/pai` 返回空数组，见[pai-detector.json](pai-detector.json)；该扫描不能检测下面的流程缺口，也不是全产品可用性通过。
- 不发送消息、不触发模型、不保存提案/任务、不修改数据库。没有重新运行不变代码的测试或构建。浏览器临时标签页用于审查；原用户标签与未保存原型保持。

## 已一致的部分

- 主要导航、独立项目集入口、取消独立资源协调入口、浮动小Pai入口已落地。
- 个人/品类小Pai单输入框、紧凑会话头、历史标题单行已改；读取与重试守卫保留。01指出的是更深一层的会话模型差异。
- 竞品、声音、参数的大编辑区/旁聊及保存后续编已实现；本轮没重新执行业务保存，上轮证据见[品类资料闭环](../material-pai-parity-20261025/result.md)。
- 提案规格的搜索、多选、全选搜索结果、清空已选、新增与删除已接实现。06不应被理解为这部分全部缺失。
- 当前抽查未见全页横向溢出；主题、语义标签和焦点样式已有公共基础。没有把本次有限检查等同全面WCAG或性能通过。

## 建议实施次序

1. 小Pai与品类/提案共创：01–06、13，优先关闭已反复确认的编辑/上下文/保存续聊差异。
2. 我的工作与项目任务/计划：07–09，接NPI实际实例、日期与协调场景。
3. 组织消息与项目集：10–11，必须补领域服务，不能仅补按钮。
4. 知识/文件与专业页统一：12、14，最后统一做 Impeccable polish；不改变已批准的业务与确认语义。

这些是迁移余项，不需要另起视觉设计方向。后续按用户选定范围实施；本轮没有默认开始修改。
