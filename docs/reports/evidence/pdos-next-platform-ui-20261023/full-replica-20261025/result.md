# 正式平台 UI 全范围迁移检查点 · 2026-10-25

本轮按用户确认的两个条件实施：覆盖整个 `/ui-lab/platform` 的导航；现有额外业务能力一起进入新 UI，放入详情、折叠区或“更多”。使用 Impeccable 的既有产品工作流。**这是前端迁移检查点，不是全部原型功能或 S1–S5 业务验收完成声明。**

## 本轮交付

- 项目默认任务，常用标签为概览、任务、计划、文件；更多承接产品与工程、试制与验证、问题与变更、评审与交付、阶段与门禁、现场反馈。旧链接保留品类、型号、项目及固定对象参数后进入对应的新面板。
- 任务使用紧凑列表/看板和分组筛选。新建、办理、任务详情与状态更新改为右侧抽屉；确认、原请求重试、读取/本机存储失败的恢复入口均在抽屉内。关闭不提交，原有草稿与命令确认保留。
- 专业工作使用统一页头、分组标签、摘要与“维护记录与专业办理”折叠。工程配置、制造准备/发布、齐套、成本、实际产出、验证与交接、问题/CAPA/变更、试产、交付包、例外及外部移交保留原命令组件。已打开的编辑组件保持挂载，跨标签保留输入；保存后刷新上方摘要。
- 项目文件的“上传与管理”、原文/事实与保留/隔离入口进入实际业务组件。产品定义、平台与差异、费用记录等保留在型号页，维护表单按需展开。
- 设置分为个人偏好、成员与范围、小Pai与模型、集成与治理；模型、技能资格、预算、自动化、MCP 与协议仍走原有受控组件。
- 品类提案查找使用紧凑搜索/状态列表与侧抽屉；概览动态收为紧凑可展开行，实际执行人、请求人、时间、回执、对象版本和来源保留在详情。
- 修复“写状态更新”关闭后需要点击两次才重开的状态衔接；修复文件管理跳回文件列表及专业摘要保存后不刷新的问题。
- 全量 lint 暴露两处既有错误：我的工作“全部提案”改用 Link 并接续现有 popstate 导航；候选编辑测试的局部变量改名。两处已修复。

## 剩余实现与验收边界

1. 原型中的跨项目资源冲突、替代方案对比/采用和后续计划修订仍未实现完整领域闭环。现有正式计划服务明确限制首版（`domain/projects/service.py`），不能通过去掉前端限制伪装完成；目前资源标签保留人员、任务与承诺协调，专业资源核对仍在试制/验证办理。
2. 阶段、健康度及正式门禁的完整投影未接齐；界面显示未知/待确认，不使用原型示例、任务数量或名称推断真实阶段与放行结论。
3. 专业功能已接入新容器并保留原领域命令，本轮未逐域重跑真实保存、具名批准、外部移交或权限全矩阵验收。合成页读取和组件检查不等于这些验收通过。

本轮没有后端/迁移/数据库操作、git push、部署或真实外发。原有未提交修改及本地环境保留。
