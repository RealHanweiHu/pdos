# 产品经理闭环 · 逐能力评测与真实输入修复

2026-09-29，0404工作树，接续[采集恢复](collection-recovery.md)。本次补只读离线评测入口，并修复产品分析资料在模型网关投影时丢失的问题。没有真实模型调用、数据库操作或资格发布。

## 发现与决策

原通用模型评测只比较标签和证据编号，不能检查八项产品管理能力的实际输出合同。新增评测复用当前提示词、输出结构、来源校验和网关输入投影，分别接受研究规划、竞品分析、市场分析、机会映射、实验设计、产品策略、产品定义、产品矩阵及RFQ的候选材料；没有自动生成或改写可信golden-case。

预检中发现产品分析的 `model_context` 提供了顶层能力、必需章节、警告、覆盖限制和证据目录，引用还包含原字段与摘要；共享网关只允许问题和标准引用字段，原输入会丢掉上述信息。固定响应的模拟调用不能发现这个缺陷。

修复复用矩阵已有的标准输入形式：动态范围/要求放入问题末尾，引用的原字段和摘要放入标准excerpt，保留服务器绑定的证据目录及用户补充要求。没有扩大通用字段白名单，原资料中的额外字段不会自动出站；固定system prompt及instruction不变。产品工作资料适配版本更新到 `product-work-source-adapter.v2`，进入应用合同摘要，旧合同摘要不能冒充当前候选。该摘要绑定提示词、结构和适配版本，不等于整个服务端构建的代码证明。

## 可用能力与判定边界

- 候选文件须提供原文件SHA256；每例固定来源摘要、原投影版本、能力、当前应用合同摘要及候选答案。全部来源、答案和每次重试的消息长度在第一次执行前验证，后续坏样例不会造成前面已调用。
- 执行器只获得实际输入、结构和模型配置声明，不获得候选答案。每例保留输入/来源/输出摘要、原输出、规范化结构、失败原因、调用用量、分片结果及报告摘要。超大输出仅留摘要及元数据。
- 格式错误最多按配置尝试1～3次，默认2次；伪造引用、范围错误、合法答案不匹配或调用异常不靠再次生成消除失败。调用失败保留已报告用量，不记录异常原文。
- **通过只表示规范化后的完整结构等于预先固定的某个候选答案。** 同义但措辞不同的答案也会不匹配；这不是语义质量评分，不能据此宣布某个模型业务可用。报告显式标记匹配规则和需人工复核。
- 来源授权、真实服务商调用、答案审批、模型资格四项始终为未验证/未授予；调用方声明的回执不被当作独立真实证明。能力仍为SHADOW。当前没有获批的产品评测集或真实调用执行器。

离线使用方式（从仓库server目录运行）：

```text
.venv/bin/python -m scripts.evaluate_product --suite /绝对路径/candidate.json --suite-sha256 <原文件摘要> --responses /绝对路径/responses.json
```

响应文件为“case_id → 按尝试顺序排列的原始响应字符串数组”。标准输出为JSON报告；退出码0表示候选匹配、1表示评测失败、2表示输入不可用。命令不读取凭据、访问网络/数据库或修改输入文件。报告包含原材料及答案，后续共享仍遵循材料权限。
