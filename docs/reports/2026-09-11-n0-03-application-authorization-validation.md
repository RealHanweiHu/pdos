# N0-03 主动请求用户授权验证

2026-09-11，本地候选 `0081_application_authorization`。Chat、风险建议、测试计划建议与报告映射已在实际创建事务固定用户AuthorizationEnvelope，并把当前用户、项目成员/委托和会话版本检查接到模型准入、计量、派发及结果返回。[运行说明与剩余](../runbooks/application-user-authorization.md)。N0-03保持部分完成。

## 已验证结果

184项不同测试通过：23项新增、161项回归。共享应用批次77项通过，唯一Chat迁移配置路径失败修正后在独立库复验通过；独立真实角色57项、通用Gateway45项全部通过。收尾四入口HTTP处理的10项复验全部通过，其中新增4项，其他为重复验证。计数为77+1+57+45+4=184。

- 四个真实HTTP入口在模型调用前已提交用户授权和原预算lineage关联。用户身份不借用服务主体；DTO中的principal、purpose、项目锚点、委托ID和期限与实际创建记录一致，内部授权ID没有进入模型请求正文。
- 普通成员、Owner和委托三种授权来源均经过真实Gateway/账本。操作资格来自用户自身角色；委托只借项目成员范围，期限不超过原lineage及原委托截止时间。测试计划续写复用原预算和原绝对期限，同时记录新run的当前用户授权。
- 角色、会话版本、账号状态、原成员记录或委托失效后，计量前停止；预留后失权取消未派发预留。数据库门禁还覆盖应用预检后、真正派发前的撤权竞态。删除后以另一成员记录重新添加不能恢复旧授权。
- 模型响应后失权时，保留真实已发生用量与模型trace，返回结果没有模型输出。模型策略摘要或调用项目/Agent绑定变化不产生新的授权。旧预算主动run缺授权时停止，不在调用时补签。
- 原登录会话版本经过四个HTTP入口传到签发事务。模拟等待期间会话版本改变，四入口均返回403，run/预算/授权整体回滚且模型调用为零；正常Chat和报告映射的重复请求仍只调用一次，既有建议流程及测试计划预算续写回归通过。
- 授权历史不可修改/删除；run、lineage、用户、项目四组复合外键及metadata一致性验证通过。空历史可迁移往返，有历史拒绝降级。真实Agent和Worker不能读取或删除用户授权表、不能执行私有检查函数；最终数据库权限检查确认SELECT/INSERT/UPDATE/DELETE/TRUNCATE均无授权。

首轮应用预算回归17项通过。新增授权测试初轮12项通过、2项失败：一个错项目负例先被既有调用登记拒绝，随后错误trace再次命中项目外键；已将应用授权范围预检前置到调用登记之前，返回受控拒绝。另一个直接旧账本负例错误地预期封装异常，已按实际数据库拒绝校正预期，受限新账本竞态另有独立测试。
