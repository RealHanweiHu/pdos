## 实现与边界

Owner 与 Agent 复用 `reserve_run_budget` 的事务锁、冻结 profile、最新 journal、并行数/调用数/累计 token/租户每日上限；`unbound_model_usage` 统一旧 trace、人工对账与绑定预算的去重计算。移除原 Python 中重复的预留/汇总实现；0066共同转换函数继续承担派发与结算。

受限 SQL 只接受 attempt、实际计量输入和请求 binding，租户/项目/run/Agent 均由有效租约派生。每日限额来自当前租户模型设置，模型选择在预留时复查，profile来自已冻结的服务端 lineage；Agent不能自行创建/改换策略、预算lineage或模型资格。缺少预算绑定或租户设置时拒绝，不读取模型提供的限额，也不把调用方汇总当成额度真值。

新增 `ModelBudgetPort` 结构化接口，让同一控制器显式装配 Owner 或受限实现。受限 `open_lineage` 只读取并核对既有 profile；`agent_open_budgeted_model_call` 要求有效租约、既有预算和租户设置，再进入原调用会话/排空保护。默认 Agent/应用工厂保持原采用状态。

未知用量和已知超额差额跨日保留；迟到汇总不重复计算昨日已结算用量。draining拒绝新预留，精确重放只返回原记录。预留在取得运行和租户设置行锁后读取数据库时间，防止等锁期间过期后仍获准；模型调用实际用量超过预留仍照实保存，不压成上限或零。

操作与采用前提见[运行手册](../runbooks/agent-budget-reservations.md)。回执与计量输入由受信运行代码提供，SQL校验结构、作用域和预算；这些校验不能独立证明供应商回执或计量资格真实性。
