# N0-03 事件 ContextManifest 验证

2026-09-11，本地候选 `0080_context_manifests`。预算事件的每次实际模型尝试已关联不可变 ContextManifest、原授权、真实观察集合及预算准入行；首次工具读取前固定本地运行内容包。[执行顺序与边界](../runbooks/event-context-manifests.md)。N0-03保持部分完成。

## 已验证结果

244项不同测试通过：16项新增、228项回归。独立真实角色批次153项、共享后端91项全部通过。最终工具集摘要修正后，Manifest、当前来源权限及工具循环36项再次全部通过；复验不重复计数。

- 实际两步模型循环生成连续revision及parent；结构化修复为各次真实尝试创建独立Manifest和预算关联，同时保留同一ContextReceipt。冻结DTO、授权、事件watermark、来源、遗漏、完整性及PostgreSQL正文摘要均验证通过。
- 输入估计和输出预留来自实际准入行。Manifest先提交，provider adapter才收到请求；预算拒绝不产生假Manifest，冻结失败取消尚未派发的预留，未发生HTTP调用。数据库直接dispatch绕过Manifest及伪造trace的尝试被拒绝。
- 当前知识验证状态、项目和内容摘要在输入计量前、Manifest冻结时、派发时及成功结果/Finding前复核。四个撤权时点分别验证计量/外发停止、未派发预留取消或已发生用量保留；原生计数可能外发提示词，因而同样受计量前复核约束。测试未调用真实模型或嵌入供应商。
- 内容包保存本地服务端Python、prompt JSON、迁移及安全SQL摘要，以及实际编译配置。工具集与HTTP实际system prompt中的定义完全一致，未把登记但不可选的工具算入循环。运行中模型资格改变或恢复时内容包改变均停止继续调用，历史保留。
- Agent/Worker不能直接读写Manifest表；追加历史及首次固定后的内容包不可改写。五组tenant/run外键、metadata一致性、空历史迁移往返及有历史时拒绝降级通过。迁移前已派发模型请求仍能结算真实用量，不补造Manifest。
- 事件授权、工具意图/观察、模型循环、checkpoint、数据库权限、预算/触发期限以及旧执行器、Gateway、schema和调用身份回归通过。业务Finding仍沿既有人工接受与独立应用流程。
