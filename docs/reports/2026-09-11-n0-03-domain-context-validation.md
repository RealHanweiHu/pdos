## 已验证行为

- 三个真实 API 在模型 HTTP 请求前已提交原用户授权、来源 Observation 和实际预算准入 Manifest；原请求重放复用结果，测试计划续写继续使用原预算。
- 风险复核项目、业务指标和触发事件；当日调用数与剩余额度保留原时点事实。测试计划重读原计划/用例/结果及所选依据，并检查上一候选的状态和载荷。
- 报告映射记录文件摘要、表头、真实前五行样本及解析后总行数；一行/七行参数证明完整与 partial 的区别。未展示行只提供来源定位，未宣称已实现模型续读或完整原文件快照。
- 风险与测试计划在计量前、预留后和响应后发生来源变化均阻止新候选；报告请求身份在调用前或返回后变化时没有导入批次。已经发生的调用仍保留 trace 并结算真实用量。
- 跳过应用冻结回调时，数据库拒绝无 Manifest 的派发。存在观察的运行不能用另一 budget_call_id 伪造正次数 trace；每次结构化尝试必须关联真实准入和原观察。
- 旧运行已有调用历史却缺少原观察时，不补造调用前历史、不发起新模型请求；旧在途 trace 仍可留存。发现错误被通用模型失败掩盖后，三个入口已保留可识别的上下文错误码。
- 非 Chat Manifest 历史拒绝降级到 0082；Chat 历史继续受 0082 保护。空库往返及物理 metadata 对比通过，人工审阅/应用和报告确认流程回归通过。
