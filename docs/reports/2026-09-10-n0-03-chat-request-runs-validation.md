# N0-03 Chat持久运行与预算接线验证

2026-09-10。已存在的只读Chat API接入持久用户请求运行、服务端发起人绑定、同号重放和稳定模型调用身份。0068允许`ai_chat`运行零业务事件，不生成假事件、不增加Finding类型或事件Agent订阅。事件Agent仍须满足原真实事件要求；worker只能INSERT旧字段，不能伪造新用户请求身份。

Chat在模型出口和披露前重新读取当前身份/权限，并对冻结来源做当前可读性与摘要比较。历史重放也复查；撤权或来源变化不会返回旧答案或触发自动重算。项目运行列表中的Chat仅对原发起人可见。首次合格调用可通过上一片显式应用工厂接入预算，已有run/lineage/model trace对应同一身份。未知异常保留结果/在途状态，禁止重放重新发出模型调用。

前端为每次主动提交生成请求号；网络响应丢失时，在组件仍存续且问题/项目不变的情况下重用；终态后下一次主动提问生成新号。未传号的旧客户端仍由服务器生成新号。运行卡使用“项目问答/主动请求”标签。详见[运行手册](../runbooks/chat-request-runs.md)。
