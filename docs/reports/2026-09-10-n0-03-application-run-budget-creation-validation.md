# N0-03 主动请求创建时预算与续写共账验证

2026-09-10。Chat、风险建议、测试计划建议和报告映射已在新运行创建事务内冻结预算。实际应用工厂只接受已有绑定，不再为已提交的旧运行在模型调用时开启新期限。测试计划“继续修改”从已校验的上一条Finding取得父run，继承同一lineage的profile、绝对期限与累计调用，不产生新额度。

新运行、预算和该入口的请求记录共同提交或回滚；重复请求沿原结果重放分支，不修改预算。新分配不在已经持有租户行锁后取得预算advisory锁，避免与模型准入形成反向锁顺序；模型预留和结算仍使用原SQL事务锁。父绑定和profile不可变，新的run link由唯一约束约束。

父预算即使在legacy进程续写也会被继承，随后由0070共同准入返回`MODEL_CALL_BUDGET_REQUIRED`，不能通过无预算子run绕行。旧未绑定父run、跨scope、档位冲突或过期均拒绝新预算。详见[操作手册](../runbooks/application-run-budget-creation.md)。

## 已验证

147项不同测试通过，包括13项新增用例和134项回归：

- 新创建预算与运行一起回滚；已提交未绑定运行不能在模型准入时补额度；已绑定父run由budgeted或legacy子请求继承后profile/期限保持。过期用例使用仅测试的一秒profile和真实数据库时间，证明不能开启新期限。
- 风险建议通过真实API和配置工厂，在Gateway入口前由第二个连接读到已提交预算，此时没有该run的调用journal；同号重放没有新provider调用或预算变化。
- 测试计划经过真实API、应用工厂、合成计量与HTTP，连续三次请求共用原预算；short档位第四次返回精确`BUDGET_CALL_COUNT_EXHAUSTED`，仍只有三次provider调用。四个run共享同一lineage、profile和原始deadline。
- 切回legacy的续写继承预算后零模型请求；旧未绑定对话在budgeted模式续写返回409，并回滚新run和新绑定。既有Chat及报告映射的真实API预算链、风险/测试计划业务回归通过。
- 原子账本、模型控制器、计量发布包、配置、未知回执与有据对账回归通过。两处旧迁移测试硬编码0067及旧异常类型，已改为核对失败降级后保持测试前head、匹配0070外层历史保护；不将其计为单独执行旧层保护。
- 生产Compose模板新增应用预算配置，仅传给API服务，web/dispatcher/executor不接收该组参数；默认legacy。真实计量文件仍须另按部署授权挂载，本次没有运行生产Compose或部署。

测试批次为79项与74项，其中7项重复，另1项生产配置隔离检查，去重为147。新增/变更入口均通过Ruff/格式17文件、Mypy11实现文件及共同合同4产物/运行合同5产物一致性检查；获批draft.3原件保持。没有前端代码变更。

仅使用`127.0.0.1:57432/pdos_test`，迁移head保持0070。本片无新增表/迁移/角色权限，也没有更改共享库角色密码、真实模型调用、golden写入、git push或生产操作。模型响应、计量资格和部分过期profile均为合成测试材料，不能当真实资格发布。
