# SIM-BIKE-01：从想法到归档的项目模拟

日期：2026-09-09。依据用户“可以模拟一个项目，从理想到结束”，按“从想法到结束”执行。结论：使用现有系统 API 跑完一条 NPD 主线，并从真实前端核对最终状态；发现两个待修系统缺口。全部业务内容、读数、签核、交付物与接收回执均为合成数据，不是 D14-04 或 D14-02 的业务记录。

## 项目设定与人员

项目：**SIM-BIKE-01 便携锂电自行车泵**，用于骑行途中补气，有预设压力停机和 USB-C 充电，不带照明。演示判据为预设 60 psi、停止压力误差不超过 ±2 psi；该数值仅为本次模拟假设，不是实际产品指标或法规要求。

| 模拟人员 | 实际使用的系统角色 | 负责工作 |
|---|---|---|
| 林经理 | Project Manager | 需求与项目推进、任务分配、产品签核、变更审批 |
| 陈工 | Engineer | 规格、设计/BOM、样机、问题整改、工程签核 |
| 王工 | Quality | 测试计划、失败登记和验证报告 |
| 赵工 | Quality，独立账号 | 报告复核、独立验证、问题关闭、品质签核 |
| 周工 | Admin，模拟接收方 | 试产交接、移交记录、接收对账；实际接收角色最小权限需后续细化 |

## 实际跑过的过程

| 环节 | 操作及结果 | 系统形成的记录 |
|---|---|---|
| 想法与需求 | 录入骑行补气场景，确认范围，评估开发案例 | 1 条需求、1 个开发案例、转化决策 |
| 立项 | 案例转项目，按 draft → proposed → approved → active 启动 | NPD 七阶段、独立业务账号与成员关系 |
| 概念与规划 | 分配负责人、期限及前置任务；建立规格并关联原需求 | 规格版本、分工决策与任务依赖 |
| 设计 | 建立原型 BOM、EBOM 和组件记录，记录设计评审 | 2 份 BOM、2 条组件、设计决策 |
| EVT | 建批次、样机和 FW1 配置；模拟停止压力 65 psi，判定失败 | 失败 TestRun、高优先级 Issue、阶段阻塞 |
| 整改 | 研发分析滤波延迟，发起 ECR；项目经理独立审批，发布 FW2 ECN | ECR、影响分析、ECN、生效决策与待交接快照 |
| 复测 | 模拟停止压力 61 psi；保留原失败运行，赵工引用复测证据关闭 Issue | 新增通过运行；责任人与关闭验证人不同 |
| DVT | 建立新批次、样机和 FW2 配置，执行代表性用例并审核报告 | DVT 样机、运行、审核报告及 Gate 决策 |
| PVT | 首件与配置一致性模拟检查；三方评审后导出人工交接包 | PVT 记录、冻结 EBOM 快照、模拟接收回执 |
| MP 与结束 | 模拟稳定观察、接收维护责任、核对遗留项，记录复盘草稿后结项归档 | 移交/结项决策；最终项目 archived、当前阶段 mp |

七个 Gate 均由项目、研发、品质三个不同账号分别签核后批准。没有用 Owner 一个账号代替所有业务角色。

## 结果与有效拦截

记录了 **464 次 API 请求**，包含成功业务动作、查询及预期拒绝场景；不是 464 项独立测试。最终通过真实前端与同源 API 核对：

- 7 个 Gate 批准，8 个任务完成，1 个问题关闭。
- EVT/DVT/PVT 共 3 个批次、3 个样机、6 个代表性用例、7 次运行（1 次失败保留、6 次通过）和 3 份审核报告。
- 1 条 ECR→ECN→生效→人工交接链；接收对账仅在模拟内完成，未外发、调用或写入真实 ERP。
- 阶段未批准禁止推进；前置任务未完成禁止开工；带未解决问题的 Gate 放行被拒；整改人不能自行关闭高优先级问题；PVT 未批准时不能准备交接。
- 从现有 687 项资产库中为该 NPD 实例生成 282 个检查项，逐项使用显式“模拟占位证据”验证状态操作。**这些占位记录不代表实际交付物已制作，也不验证其业务内容质量。**

技术路径为 FastAPI TestClient + 真实 PostgreSQL 事务及现有领域逻辑；最终另用 Next.js 前端和本机真实浏览器核对概览、质量与阶段评审页面。未逐个从 UI 表单录入全部数据，因此没有据此宣称所有录入界面均可完成多人全流程。

## 暴露的两个缺口

| 编号 | 实际观察 | 本次处理与后续 |
|---|---|---|
| SIM-GAP-01 | 概念阶段、Gate 未批准时，项目状态 API 仍允许 active → completed | 在独立保存点探测后立即回滚；正式模拟主动完成七阶段再结项。后续需补结项条件和阻塞提示，不能只依赖人工纪律。 |
| SIM-GAP-02 | Quality 能管理计划和结果，但 TestRun 写入要求 PRODUCT_ENGINEERING_EDIT，品质账号返回 403 | 未提升账号权限；本次由 Engineer 代录，conditions 明确模拟报告人，品质审核报告、独立关闭 Issue。后续需修正逐次测试录入的业务权限及相关界面。 |

定位：[项目状态迁移](../../server/app/domain/projects.py)、[TestRun API](../../server/app/api/npi_execution.py)、[权限矩阵](../../server/app/auth/roles.py)。模拟完成不等于这两个缺口已修复。
