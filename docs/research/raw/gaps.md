- 制造业场景下 ambient capture 的数据底座完全未验证:PLM/PDM/CAD/试验数据/ECO-ECN/供应商往来/IM 这些真实数据源的 API 可达性、on-prem 数据孤岛比例、第三方接入门槛、冷启动回填路径,六份调研均未触及: 调研已确立「数据由系统环境式采集、人变审核者」是 AI-native 的架构判据(Lightfield 靠邮件/日历/会议录音,可回填 2 年历史),但制造研发的原始数据不在邮箱里,而在 Teamcenter/Windchill/Arena 等 PLM、CAD 文件、试验报告和共享盘 Excel 里,且大量 on-prem 部署。如果拿不到这些数据,world model、自动 gate 材料装配、状态自动生成全部失去输入,整个架构立论坍塌——这是所有后续设计决策的前置条件,而非其中一项。初步抽查显示该领域正在快速变化(Teamcenter MCP server、Windchill agentic REST skill 已出现,见 https://github.com/srinivasmd/windchill-plm),值得专门补研。
- 「AI-native NPD 项目管理层尚无赢家、是清晰空窗」这一立项核心假设未经对抗性验证,且取样系统性偏向欧美:本轮抽查即发现飞书项目已有服务 100+ 客户的 IPD 行业专版(含智能硬件制造方案、AI PMO、评审遗留问题自动转任务),而 Teamcenter 2606 的 agentic AI(BOM agent 可多步执行)也说明 PLM 大厂不只是「旧系统加助手」: 整个产品的差异化定位建立在这个空窗结论上。抽查证据(https://project.feishu.cn/home/ipd 、https://blogs.sw.siemens.com/teamcenter/teamcenter-2606/)表明空窗边界比 rnd-domain 综述声称的更窄且在快速收缩:中国市场已有贴着 IPD 打的成熟玩家,PLM 厂商正从数据层向上延伸。若不做一轮含中国厂商和 2025-2026 新入场者的对抗性竞品扫描,后续设计可能瞄准一个已被占领的位置。
- 目标市场与方法论体系未定义(需先问用户):目标客户是中国制造业还是全球?企业规模(几十人研发部还是千人研发体系)?买家是老板/研发总监还是 PMO?现有调研全部以 Cooper stage-gate 为流程假设,但中国制造业主导方法论是华为系 IPD(TR 技术评审/DCP 决策评审点、重量级跨部门团队),两者的模板、角色、评审语义并不相同: 这个答案改变几乎所有下游设计:流程模板做 stage-gate 还是 IPD、竞品清单是 Lightfield 还是飞书项目、集成对象是 Slack/Teams 还是飞书/钉钉/企业微信、可用模型受不受数据出境与国产化约束、定价对标 SaaS seat 还是本土项目制。这是问用户的问题而非网络调研能回答的;用户自身背景(制造业、ERP、飞书生态)暗示答案偏中国,但必须显式确认,不能靠猜。
- 质量体系与审计合规对 AI 产物的硬约束未调研:制造业 gate 交付物是 ISO 9001/IATF 16949(APQP/PPAP)/ISO 13485 设计控制下的审计对象,AI 自动生成的评审材料和状态报告在签核责任、证据链、审计方接受度上如何处理,现有素材只有 Linear「agent 不可担责」一条设计原则可类比: 这决定「AI 自动装配 gate 材料」到底是核心卖点还是合规雷区,也划出人审/签核环节不可被自动化压缩的硬边界(比如汽车供应链客户的 PPAP 文件不能是无人签核的 AI 产物)。但调研深度取决于目标行业——是否含汽车/医疗客户应先问用户,故列为 gap 而不立即补研;确认后可做一轮针对性调研(审核方对 AI 生成文档的立场、电子签核要求)。
- 「人从操作者变审核者」只有模式没有实证:三态人审(notify/question/review)、审批队列、autonomy slider 全部停留在概念层,缺少 review fatigue、橡皮图章化、信任校准的真实行为证据,也缺审核 UI 的具体设计实践(批量审批、diff 视图、置信度阈值、抽查机制);现有唯一实证线索是 Lightfield 的 AI 错录争议和 Height 关停: 这是产品最大的单点失败风险:制造业里错误数据会进入 gate 决策并按 rule of ten 逐阶段放大成本,若审核环节形同虚设,系统数据可信度会比手工录入更糟,重蹈 Height 覆辙。公开的实证材料稀少(多为 HCI 文献与零散用户抱怨),网络补研性价比不高,更适合在原型阶段用自家真实项目(如用户自己的 CEHub 场景)做小规模验证,故列为 gap 而不占用补研名额。
