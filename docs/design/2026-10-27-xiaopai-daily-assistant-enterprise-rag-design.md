## 1. 背景与要解决的问题

小Pai已能通过同一运行体系完成业务研究、候选起草和受控领域动作，但当前能力主要围绕明确技能、品类、提案和项目工作展开。要成为全公司员工愿意每天使用的助手，还需同时满足四类需要：

1. **日常问题**：解释、翻译、写作、总结和一般知识，不应强制用户理解技能包或进入复杂业务流程。
2. **企业事实与知识问题**：既包括“项目现在为什么停着”等当前事实，也包括“过去类似问题怎样处理”等需要跨文档、跨历史语义发现的问题。
3. **问答后的行动**：用户回答后可以继续补资料、建任务、形成问题或修订草稿，但不能因聊天方便而绕过权限、确认和回执。
4. **不提问也能用上**：员工往往想不起去问。新建问题、查看对象和每周例行时，按本人权限主动呈现相关历史与当前事实，经验沉淀才真正被用上。

当前实现起点：

- 普通对话已由同一张 Agent 图支持。`pdos-next/server/pdos_next/agent_kernel/graph.py:25` 的固定提示要求一般讨论直接回答，无需业务查询时不查资料。
- 个人全局入口默认预载 `category_framing`，品类/提案入口也有默认业务技能，见 `agent_kernel/bootstrap.py:464`。日常问答需要减少不必要的技能与业务上下文。
- `agent_kernel/domain_reads.py:315` 的 `evidence.search` 只对本次 Run 显式绑定原件做标题包含查询，不是企业全文或向量检索。
- 上传原件和导入文件按不可信内容处理：`evidence.artifact.read` 只登记在 `extract` 隔离（`agent_kernel/registry.py:23`），主循环读取原文会被拒绝（`domain_reads.py:333`）；`evidence.extract`（`extract_service.py:124`）按来源派发只读子任务，主循环只拿到核对过的台账行。企业问答沿用这一结构。
- `personal_search.py:14` 已有本人权限内的跨品类对象元数据查找；`personal_views.py:90` 已有项目、定义、计划、门禁和状态更新的权威读模型。两者目前都没有登记为小Pai工具。
- 原件已有解析、内容哈希、扫描状态和行/页/单元格定位；`agent_kernel/extract_sources.py:34`、`extract_pages.py:56` 可复用为固定版本原文核对。
- `source_for`（`pdos_next/service.py:446`）按单个型号做访问检查，不能直接用于跨型号批量复核。
- 续接对话时，`conversation.prepare`（`agent_kernel/conversation.py:26`）让子 Run 继承父 Run 的 `read_sources` 固定版本，并沿用会话、型号、提案和项目范围；跨轮引用继承按同一模式设计。
- 当前代码没有 embedding 或向量召回实现，依赖中也没有 v1.1 §07.2 指定的 jieba，数据库没有全文索引。本地环境已使用 pgvector 0.8.6 镜像，但扩展、迁移、索引与真实 embedding 配置均未形成企业问答能力。
- v1.1 R14 写作“jieba……进隔离解析”，§07.2 正文只把 Office/PDF 解析限定在隔离环境。本稿需要对查询串分词，按 §07.2 正文理解；R14 已于 2026-10-28 按此加注（§19 Q3）。
- 现有操作中：`quality.issue.merge`（T1）可合并重复问题；`category.knowledge.add`（T0，AI 来源标 ai_draft）/`category.knowledge.promote`（T1，须人工确认已去标识）与 `knowledge.candidate.create`（T0）/`knowledge.rule.publish`（T2）构成现有知识沉淀流程；AutomationRule 已支持定时、领域事件与相对里程碑触发（`domain/automations/schemas.py:106`），启用为 `ai.automation.activate`（T1）。
- 个人关注读模型（`personal_attention*.py`）已汇集本人工作、外部等待、项目风险、验证与待决定事项，可作为定时摘要的事实来源。
- 已有本人私有的工作成果（`agent_kernel/work_products.py`，2026-10-28 工作树）：可把实际 Run 的结果保存为文档或表格并追加修订，可复用为“保存结果”。质量问题已有根因、临时措施、CAPA 措施与有效性记录（`domain/quality_issues`、`domain/capa_effectiveness`），可直接用于相似历史卡片。
- 当前没有钉钉连接；[原工程 S5-1 钉钉连接器合同](2026-08-12-s5-1-dingtalk-connector-contract.md)已随原工程归档，只参考技术约束。钉钉只读入口按 P31 设计（§11.9）。
- 前端已有回复、研究来源、候选确认、运行详情、来源绑定和反馈组件，可扩展复用。

## 2. 目标与非目标

### 2.1 目标

G1. **一个小Pai服务全部岗位**：不按工程师、品质、生产、采购拆 Agent 或建四套聊天产品。  
G2. **日常问答轻量自然**：不强制选择角色、技能或业务模式，不把普通问题变成长时间委派。  
G3. **企业回答有依据**：当前事实来自权威对象，语义回答来自可核来源，保留版本、定位、适用范围和未知项。  
G4. **权限一致**：检索、模型上下文、回答、缓存与派生索引遵循同一用户、品类范围根和对象受众。  
G5. **问答可接续行动**：继续使用现有领域命令、确认、回执、审计和撤回，不增加聊天专用写通道。  
G6. **检索可演进**：先建立精确条件、编号通道与 jieba 中文关键词基线，再以同一问题集验证向量混合检索的实际收益。  
G7. **运行可恢复**：会话、检索、索引与 Worker 重启后能够恢复或对账，不盲目重复外部调用。  
G8. **主动呈现**：在新建与查看对象、例行摘要时按本人权限呈现相关历史与当前事实，不依赖用户先想起提问。  
G9. **知识可沉淀**：反复被问、经人工核实的答案能沉淀为有负责人和复核期的公司知识；答不上来的问题能被知识负责人看到。

### 2.2 非目标

N1. 不新增第二 Agent、第二套 LangGraph 主图或独立聊天后端。  
N2. 不把 PDOS 改成无边界通用聊天软件；日常问答是统一工作助手的基础能力。  
N3. 不用向量相似性决定权限、当前状态、零件等价、测试覆盖、工程阈值或专业结论。  
N4. 不把所有业务表无差别向量化，不以摘要替代结构化当前事实。  
N5. 不新增独立向量数据库、任意 SQL、任意 HTTP 或生产 Shell 能力。  
N6. 不把私人会话自动加入企业共享知识、模型训练或其他用户的检索范围。  
N7. 不因 READ 问答自动授予 T0，不因回答转行动绕过 T1/T2。  
N8. 不在第一阶段强制建设 LLM reranker 或全量来源连接；token 级流式呈现是切片 A 的可选项，按时延实测决定（§6.4）。  
N9. 不让主循环读取上传原件、导入文档等不可信正文；原文只在没有写工具的隔离子任务中读取。  
N10. 不做全量抓取外部系统的企业搜索；外部系统资料（钉钉文档、ERP 等）需要时经已准入的 MCP 连接器实时只读查询，按源系统权限返回，返回内容按不可信内容在隔离子任务中处理（v1.1 §06.2）。  
N11. 主动呈现不自动执行业务动作；相似历史、定时摘要只读，进一步处理仍走候选、确认或具名决定。  
N12. 不做隐式记忆；个人偏好由本人显式设置、可查看和修改，不作为权限来源，不进入企业知识（§6.5）。

## 3. 名词与事实层级

| 名词 | 本稿含义 |
|---|---|
| 日常问答 | 不依赖企业内部事实的一般对话、解释、翻译、写作或总结 |
| 当前事实回答 | 对当前项目、任务、定义、测试、承诺等权威对象的结构化读取与解释 |
| 企业语义问答 | 在本人可访问的文档、知识和历史记录中发现相关资料，经原文核对后回答 |
| 权威读取 | 通过现有领域读模型/只读工具获得当前事实及其版本、as_of 与权限 |
| 检索投影 | 从权威来源重建的派生查询数据，不拥有业务事实、批准或专业结论 |
| Citation | 服务器签发的本次运行引用身份，指向固定来源版本和可核定位，不是模型编写的说明文字 |
| 不可信正文 | 上传原件、导入文档以及来自邮件、IM、外部系统或网页的文本；只能在隔离子任务中读取 |
| 内部记录 | 经领域命令写入的结构化字段与说明，按现有只读工具进入主循环 |
| 证据行 | 隔离子任务交回的封闭结构：citation ID、简短发现、逐字引文、定位与状态；主循环只看证据行，不看原文 |
| 检索读账本 | 本次 Run 实际搜索词项、读取、过滤、来源、版本、失败与覆盖记录，用于验证、恢复和页面展示 |
| 回答依据状态 | 服务器按读账本与实际引用给出的四种状态：未查公司资料 / 未找到 / 有相关记录未引用 / 有来源；页面主文案按查找范围与记录数生成（§8.2） |
| 编号通道 | 对型号、料号、标准号和对象编号做规范化抽取与精确/族匹配的独立召回通道，不依赖分词 |
| 主动呈现 | 不由提问触发、按本人权限在页面或定时摘要中呈现的只读结果 |
| 核实答案 | 经人工发起、具名发布，带负责人、适用范围和复核日期的公司知识条目 |

事实使用优先级固定为：

1. 当前权威对象及其结构化读模型；
2. 固定版本的原始文档、记录和有效知识；
3. 可重建的检索投影、历史摘要和会话记忆；
4. 模型通用知识；需要实时公开信息时另走受控公开研究。

低层级的信息不得覆盖高层级事实。历史摘要、向量chunk和模型记忆均不能冒充“当前”。在第 2 层内，已发布且在复核期内的核实答案优先于原件和未核实知识；超过复核日期未复核的照常可检索，但降级并标注“待复核”（§11.7）。

## 4. 用户场景与响应路径

| 用户输入或触发 | 响应路径 | 事实与引用要求 | 写入 |
|---|---|---|---|
| “解释一下 IP67 和 IPX7 的区别” | 日常直接回答 | 使用通用知识；页面标明“未查公司资料”，不冒充公司标准 | 无 |
| “我们的 IP67 测试怎么做？” | 企业语义检索 | 问法像通用问题，实为公司口径，须先查公司资料；未查即答计为“该查没查”（§14） | 无 |
| “这个项目为什么还没进入 DVT？” | 权威对象读取 | 当前项目、阶段门禁、计划、承诺和阻塞，带 as_of | 无 |
| “以前类似的进水问题怎么处理？” | 企业语义检索 | 检索 Issue/CAPA/Change、报告与知识；当前项目命中不足时补查同品类历史（§7.1）；不可信原文由隔离子任务读取并交回证据行，按固定版本引用 | 无 |
| 选择规格书 V2 与 V3：“改了什么、影响什么？” | 资料比较 | 代码逐段比对两版解析文本，变化段落交隔离子任务解读并交回差异行，引用两侧定位（§7.9） | 无；可保存为本人工作成果 |
| “根据这个答案准备一条采购跟进任务” | 问答转业务办理 | 沿用已核对来源和精确对象，生成现有命令候选；携带来源须通过受众检查（§9.3） | 按现有 T0/T1/T2 |
| 新建问题“D16-01 充气后接口处漏气” | 主动呈现：相似历史 | 问题详情页列出相似的历史问题、CAPA 与变更，只显示元数据与链接，不调用模型（§11.5） | 无；“标为重复”走 `quality.issue.merge`（T1） |
| 每周一早上（管理层订阅） | 主动呈现：定时摘要 | 按本人权限读取项目最新具名状态与风险变化；健康度以具名状态为准，AI 不自评（§11.6） | 无 |

对话中的路径属于同一 Run、同一 Agent 图和同一前端会话，不是四个产品模式。模型可以选择读取工具，但服务器决定实际可用工具、范围和权限。主动呈现不经对话：相似历史是页面只读请求，不调用模型、不建 Run；定时摘要是本人 AutomationRule 发起的 Run。

岗位只改变默认上下文与有效范围：

- 工程师可追问设计依据、定义版本、工程影响与测试资料；
- 品质可追问失效、根因假设、CAPA、复验和独立结论；
- 生产可追问 Build、实际配置、作业资料、交接和制造准备；
- 采购可追问供应承诺、外部等待、交付与供应异常。

上述能力不表示任何角色可以读取全部资料或办理其他专业动作。数据可读与专业决定权分别判断。

## 5. 总体架构

```text
用户（独立小Pai / 页内小Pai）
  │ 同一 StartInput、会话和权限上下文
  ▼
现有 Agent API ── 创建/恢复同一 Run
  ▼
Temporal Workflow
  ▼
LangGraph 小Pai主图（主循环，不接触不可信原文）
  ├─ prepare_context：导航范围、显式对象、已声明技能、会话记忆、本人偏好
  ├─ model
  │    ├─ 日常问题 → 直接形成回答
  │    ├─ 当前事实 → 现有权威只读工具
  │    ├─ 企业语义问题 → assistant.search（只回元数据）
  │    │                 → assistant.extract（派发隔离子任务，只收证据行）
  │    └─ 业务办理 → 现有技能与领域命令候选
  ├─ verify
  │    ├─ 输出 schema
  │    ├─ 权威读取 / 检索读账本 / 证据行
  │    ├─ 引用、来源版本、权限与可用性复核；回答依据状态
  │    └─ T0/T1/T2 与范围复核（如有动作）
  └─ finalize：Run 结果、实际来源、失败、覆盖和回执

隔离只读子任务（每个不可信来源一个，复用 extract 隔离）
  └─ 工具表只有 assistant.passage.read；无写工具、无 skill.load、无再检索
       → 交回证据行，引文由代码核对为固定来源正文子串

主动呈现
  ├─ 页面只读请求（相似历史、新建表单防重复提示）
  │    └─ 同一检索服务与权限连接；不调用模型、不建 Run、无出站
  └─ 本人 AutomationRule（定时摘要）
       └─ Run → 权威读模型与个人关注读模型 → 结构化条目（可选模型导语）→ 本人小Pai会话

检索数据面
  ├─ 权威表/读模型：当前事实与权限；召回 SQL 与之连接过滤；显式关系表用于一跳扩展
  ├─ 全文投影（切片 B）：chunk、jieba 词项、编号列、定位、版本；本地生成，无出站
  └─ 向量列（切片 C）：embedding profile、向量、重建水位
         ▲
         ├─ Outbox → 全文投影 Activity（本地）
         └─ Outbox → embedding Activity（P30 第2条启用后）→ provider-neutral embedding 端口
```

约束：

- 对话与回答仍经 Temporal Activity 调用已注册 LangGraph 图，模型网关不绕开注册执行图。
- 不可信原文只在隔离只读子任务中读取，主循环与写工具不接触原文。隔离靠工具表的物理分离保证，不依赖提示词（v1.1 §06.1/§06.6）。
- 页面只读请求复用同一检索服务和权限连接，不调用模型，不产生出站。
- 索引 Activity 是查询投影维护，不是另一 Agent，不取得业务写权。
- embedding 使用独立受控 provider 端口、固定版本和出站/预算记录；不以临时脚本或隐蔽备用通道代替。
- 领域命令仍是唯一业务写入口；检索投影的写入不属于业务事实写入。

## 6. 轻量日常问答与技能加载

### 6.1 原则

普通问题不应因为用户打开了小Pai，就自动加载立项方法和大段业务资料。与此同时，不能用关键词路由器替模型决定权限，也不能为每条消息增加一次 LLM 意图分类调用。

### 6.2 预载规则

1. 个人全局自由对话默认使用 navigation 上下文和固定技能目录，不再无条件预载 `category_framing`。
2. 页面专用动作通过现有 `requested_skills` 显式声明固定技能、版本与摘要，例如“新建品类”明确请求 `category_framing`。
3. 用户直接在对话中发起业务工作时，由同一 Agent 使用 `skill.load`；服务器继续校验当前启用、范围和版本。
4. 品类、提案、项目页的现有默认预载采用渐进迁移：先把页面动作改为显式声明，再取消对应自由对话的默认业务预载。不得一次性删除所有默认技能导致既有入口退化。
5. 固定系统提示只表达稳定规则，动态目标、页面、对象、技能和本人偏好仍由代码追加到上下文末尾，保持前缀冻结规则。

### 6.3 回答规则

- 日常问题：不触发企业检索，不伪造公司事实；服务器据读账本标注“未查公司资料”。
- 问到“我们 / 公司 / 本厂”的做法、标准、参数时，即使问法像通用知识，也先查公司资料；未查即答计为“该查没查”（§14）。
- 企业当前事实：优先权威读取，不能以“模型记得”回答。
- 企业语义问题：实际检索后才给出有来源的回答。
- 未找到：只能说明本次检索范围内未找到，不能推出业务上不存在；检索未命中后用通用知识回答的，页面按 §8.2 显示“未找到”的具体说明，不标“未查公司资料”。
- 普通问答与复杂研究共享 Run 恢复能力，但过程展示和预算消耗应与其复杂度匹配（§6.4）；处理进度与部分交付见 §11.12。

### 6.4 快慢两档

快慢是流程与预算的分档，不是两个产品模式，也不增加意图分类调用：

- **快档（默认）**：日常问题一次模型收尾调用；企业问题在主循环内一次检索，`assistant.extract` 每轮读取的来源数有上限（初始 3 个，按实测调整）。
- **深入查**：资料多、跨品类或需要多轮查找时，由模型发起，或用户在回答下点“深入查”。深入查作为同会话的续接 Run 在后台运行，可多轮检索、读取更多来源，沿用研究工作的后台运行、进度与完成提醒；预算按其复杂度计。
- **模型选择**：主循环模型不按问题类型切换，避免小模型漏查；只有隔离子任务可按模型网关现行规则使用较小模型（§7.4）。
- **流式呈现**：P28 的连接已支持流式响应；快档是否启用 token 级流式，按切片 A 的时延实测决定。启用时只流式呈现正文，来源区、依据状态和候选仍在 verify 后由服务器附加；verify 发现失效引用时按 §8.2 降为 partial 并标注，不静默改写已呈现的正文。

### 6.5 个人偏好

- 本人可设置：回答语言、详略程度、常用品类/项目（作为默认导航范围的候选，不扩大权限）；
- 岗位与部门：账户中已有则读取，没有时由本人选择；只用于默认上下文提示、欢迎示例和定时摘要默认模板，不作为权限来源；
- 偏好对本人可见、可改、可清空，不由小Pai自动学习写入，不进入企业知识或其他用户的上下文（N6、N12）；
- 偏好以固定格式追加在动态上下文中，不改变固定系统提示前缀；
- 存储于本人账户偏好；如无现成存储，实施时按最小新增登记。偏好不属于业务记录，不走 T1/T2。

## 7. 企业检索设计

### 7.1 检索范围

个人全局 Run 的默认范围是“当前本人全部可访问对象”；品类/提案/项目 Run 默认先查当前服务器绑定范围。模型传入的过滤条件只能进一步收窄，不得扩大。

**同品类补查**：项目、提案范围内的企业检索命中不足（初始为少于 3 条有效候选）时，服务器按固定规则在同品类、本人可读范围内补查一次，结果分组标为“当前项目”与“同品类其他项目”：

- 补查由服务器规则触发，不由模型参数或关键词触发；范围仍在品类范围根内（I21），召回照常连接权威表过滤；
- 默认只纳入内部记录（Issue/CAPA/Change 等）与非客户私有资料；其他客户项目的私有资料只有在用户点“包含其他客户项目资料”后才纳入，并按 §9.4 判定出站类别；
- 补查得到的来源带进草稿或其他对象时，照常按 §9.3 检查受众；
- 用户可在背景条把范围改回“只查当前项目”，选择写入工作状态；跨品类查找通过个人全局入口。

`assistant.search` 不接受 tenant、requester、writer 或权限布尔值。可接受的过滤包括：

- `query`：用户检索语句，可以是原句或关键词；服务器按固定 jieba 版本分词并抽取编号，实际词项与编号写入检索读账本；
- `source_types`：允许的来源类型；
- `category_id/product_id/project_id/proposal_id`：可选的 narrower scope，服务器逐项验证；
- `time_range`：来源或业务发生时间条件；
- `include_history`：是否包含明确的历史版本；
- `limit`：每页候选数量上限（请求大小与分页上限，不是业务规则）。

跨范围查询只能通过服务器认可的个人范围或显式会话范围切换实现，不能通过 `all_categories=true` 等模型参数绕开 Run 范围。

### 7.2 来源接入顺序

第一批来源保持小而完整：

| 来源 | 第一阶段用途 | 正文性质与读取方式 | 权威核对 |
|---|---|---|---|
| Artifact / UploadedOriginal | 文档、报告、规格和导入资料语义检索 | 不可信正文，只经隔离子任务读取 | 固定 Artifact 版本、内容哈希、扫描状态、parse manifest 与 locator |
| 当前有效品类知识 | 场景、竞品、用户声音、法规等知识问答 | 已核对知识行，服务器直接返回结构化行，同现有品类知识只读工具 | KnowledgeCurrent + 固定 KnowledgeEntry 版本 + source_refs |
| 项目权威读模型 | 当前项目、定义、计划、门禁和最新具名状态 | 内部结构化记录，不经向量 | `personal_views.projects` 及既有治理投影 |
| Issue / CAPA / Change | 以前类似问题怎么处理、根因、措施与变更历史 | 内部记录：员工经领域命令写入的标题、描述、根因、措施、结论等字段；服务器直接返回结构化行 | 对象当前版本、状态、品类范围与对象受众；关联取自显式关系表 |
| 外部等待、供应承诺、Build/TestRun | 供应与交付跟进、样机与测试状态 | 内部记录：结构化字段，服务器直接返回结构化行 | 对象当前版本、状态、品类范围与对象受众 |

现场反馈与客户投诉中的客户原话、外部附件和导入文本，即使挂在问题对象下，也按不可信正文处理，在切片 D 随 `field_feedback` 等来源接入。

后续通过统一 SourceProjector 增加：项目状态更新、现场反馈原文、测试报告等非结构化文档、制造与交接文档。数值、负责人、当前状态仍由结构化读取提供，不因新增来源连接器而改变。

每个 SourceProjector 负责：

1. 将固定来源版本投影为可检索文本和定位；
2. 提供 tenant/category 与源对象引用（受众在查询时由权威表判定，见 §7.7）及来源元数据；
3. 提供当前有效性、撤回、扫描和适用性检查；
4. 提供回到原对象/文档的读取与页面链接信息；
5. 支持按内容哈希与版本幂等重建；
6. 声明正文性质：内部记录或不可信正文。导入、邮件、IM、外部系统或附件来源的文本一律按不可信正文处理；
7. 声明可用于一跳扩展的显式关系类型（§7.5）；
8. 声明编号抽取字段（标题、型号、料号、对象编号等），供编号通道使用（§7.6）。

### 7.3 检索顺序

```text
用户问题
  → 精确 ID / 明确对象 / 结构化条件
  → 编号通道（规范化编号的精确与族匹配）
  → 关键词召回（jieba 全文投影，OR 组合 + IDF 加权）+ 向量召回（切片 C 加入）
  → 确定性融合与规则重排（含个人化与新近度）
  → 召回 SQL 内连接权威来源：当前权限、受众、来源版本、扫描/撤回与适用范围
  → 显式关系一跳扩展（同样经权威连接过滤）
  → assistant.search 向主循环返回候选元数据与 citation ID（不含正文）
  → assistant.extract 为选中候选读取证据
       ├─ 不可信正文：派发隔离只读子任务，经 assistant.passage.read 读取有界段落
       └─ 知识行/内部记录：服务器直接返回结构化行，不调用模型
  → 主循环依据证据行与权威读取作答，只引用 citation ID
  → 服务器验证并附加来源、引文、覆盖与回答依据状态
```

第一阶段不等待 embedding：切片 B 完成精确 ID、编号通道、结构化条件、jieba 全文投影和固定版本原文读取，形成可比较的基线。全文投影是本地生成的可重建查询投影，不调用外部服务；切片 C 只在同一投影上增加向量列。工具合同不随实现变化，不把查询实现泄漏给模型或前端。

### 7.4 分块、定位与原文隔离

- 文本/Markdown 按段落与连续行分块，保留原始行号；
- PDF 优先按页内段落分块，保留页码；
- XLSX 按工作表识别表头行，按行序列化为“表头: 值”后连续若干行成块，locator 保留 sheet、行范围与单元格；没有可识别表头的区域按连续单元格区域分块；
- 其他类型只有在既有隔离解析和定位能力具备后接入，不用无定位纯文本冒充完整解析；
- chunk 保存 `source_id/source_revision/content_hash/chunker_version/tokenizer_version/locator`。

原文读取：

- `assistant.passage.read` 只出现在隔离子任务的工具表中，主循环工具表没有它，与 `evidence.artifact.read` 相同；它只读所绑定来源的有界段落及相邻上下文，可按页续读，不能一次读取整份客户原件。
- 子任务的可读集合由服务器按本 Run 已签发、或按 §10.1 继承后重新签发的 citation 绑定，不扩大 `run.read_sources` 的显式绑定语义。子任务没有写工具、`skill.load` 或再检索能力，只交回封闭 schema 的证据行。
- 证据行字段：citation ID、简短发现、逐字引文、定位、适用/冲突标记与状态（ok / partial / unavailable）。发现和引文都有长度上限（请求大小上限，不是业务规则）；覆盖与失败由代码根据读账本生成，不让模型复述。
- 文档内容始终是不可信数据，其中的“忽略权限”“调用工具”“已经批准”等文字不修改指令、权限或业务状态。这一点由隔离结构保证，不依赖提示词。
- 实现复用 extract 隔离、`ArtifactSeal`、`ExtractReadLedger` 及“恢复时重核、不重派”的模式；是否为此新增独立 isolation 值（需改执行绑定约束并迁移）在实施时按最小改动决定。
- 代价：每次需要读原文的企业回答，比主循环直接读多一次子任务模型调用。时延和费用在切片 B 实测记录；子任务所用模型按模型网关现行规则选择。

引用片段必须能够由确定性代码核对为固定来源正文的子串或既有定位投影，不能由模型复述后冒充原文。

### 7.5 混合召回、排序与关系扩展

混合检索采用：

1. 精确对象与条件过滤；
2. 编号通道（§7.6）：料号、型号、标准号与对象编号；
3. jieba 全文召回（§7.6）；
4. 向量语义召回（切片 C）；
5. 可测试的 RRF 或等价确定性融合；
6. 规则重排：精确对象/编号命中、来源有效性与版本、适用范围；个人化（本人为成员的项目、当前页面对象所在品类/项目加权）；新近度（按来源业务时间的固定半衰期衰减，明确的历史查询不衰减）；
7. 显式关系一跳扩展；
8. 最终权威来源与引用验证。

**显式关系一跳扩展**：命中某对象时，按 SourceProjector 声明的显式关系带出一跳关联对象，例如命中 CAPA 时带出其来源问题与关联变更，命中问题时带出其 CAPA 与变更。规则：

- 只用显式登记的关系（领域命令写入的关联、合并与引用）；规则推导和 AI 怀疑的关系不参与扩展（v1.1 §07.7“显式依赖、规则推导和 AI 怀疑分开”）；
- 关联对象同样经权威连接过滤；不可读的关联对象不返回，也不计数；
- 关联候选标明关系类型与来源对象，排在其来源候选之后，不占直接命中的数量上限；
- 只扩展一跳，不递归。

**排序版本**：字段权重、BM25 参数、半衰期、个人化加权与融合参数作为排序版本固定，写入检索读账本；修改只能通过新排序版本，并在问题集上对比后启用。

初版不增加 LLM reranker。向量得分只表示语义相似度，不表示事实正确、当前有效、权限可用或专业等价。若混合模式不能在固定问题集上相对 jieba 基线改善召回和答案质量，则保留关键词为默认路径。

### 7.6 中文关键词基线与编号通道

**关键词基线**：

- **分词**：采用 v1.1 §07.2 指定的 jieba，固定版本与词典；需要租户术语词典时按版本登记。投影时对 chunk 分词，以空格连接后写入 PostgreSQL `simple` 配置的 tsvector 并建 GIN 索引；查询用同一版本分词。
- **运行位置**：jieba 只处理字符串（查询串和已由隔离解析得到的纯文本），不解析文件，可在 API 进程（页面只读请求）与检索 Worker 内运行，词典懒加载。Office/PDF 文件解析仍只在隔离环境（v1.1 §07.2）。v1.1 R14 已按此加注（§19 Q3）。
- **停用词**：固定停用词表去掉虚词和疑问词（如“的、了、怎么、什么、以前、类似、一下”），与分词器同版本管理。领域高频词（如“问题、处理、产品”）不进停用词表，由 IDF 降权。
- **组合**：查询词项用 OR 组合（`to_tsquery` 以 `|` 连接），不用 `plainto_tsquery` 默认的 AND，避免整句提问因一个词不在 chunk 中而零命中。
- **排序**：按 BM25 形式打分：每个命中词项按 IDF 加权，标题字段权重高于正文，按 chunk 长度归一；k1、b 与字段权重进入排序版本（§7.5）。IDF 统计按 tenant 维护，随投影批次更新，只用于排序，不返回调用方。`ts_rank_cd` 不考虑词项稀有度，不单独作为排序依据。并列时按来源 ID、chunk ID 确定性排序。
- **检索词记录**：实际词项、去掉的停用词与命中编号写入检索读账本，同一输入可复现。
- **版本**：分词器、词典、停用词表与编号规则版本进入索引工作键（§10.2），换版本按重建批次处理。
- **扩展**：不预先引入 zhparser、pg_trgm 等扩展；问题集显示 jieba 基线有系统性漏召回时再评估。
- **对照**：切片 C 的向量对比以本基线为对照，不以标题包含匹配为对照。

**编号通道**：jieba 会把 D16-01 拆成“D16 / - / 01”，型号、料号、标准号不能依赖分词。

- **抽取**：投影时用固定正则，从 SourceProjector 声明的字段和正文中抽取型号、料号、标准号与对象编号（如 D16-01、IP67、IPX7、GB/T 4706.1），规范化为大写、半角、统一连接符后写入 `codes text[]` 并建 GIN 索引；同时写入编号族（如 D16-01 的族 D16），支持按族查询；
- **查询**：用同一正则与规范化规则从 query 中抽取编号；精确命中与族命中分别加权，编号命中的候选在融合时优先；
- **独立性**：编号不受停用词和分词影响；正则与规范化规则版本化并进入工作键；
- **误抽取**（如把日期抽成编号）通过新规则版本修正，不在查询时临时放宽。

### 7.7 派生索引

切片 B 在同一 PostgreSQL 内建立可重建的全文投影；切片 C 在同一投影上增加向量列，不引入独立向量数据库。逻辑字段至少包括：

| 字段组 | 内容 |
|---|---|
| 身份 | tenant、source_type、source_id、source_revision、chunk_id |
| 范围 | tenant、category（RLS 第一键），product/project/proposal 引用；不复制对象受众名单 |
| 内容 | chunk text、jieba 词项（tsvector）、编号（`codes text[]`）、locator、content hash、parser/chunker/tokenizer 版本 |
| 向量（切片 C） | embedding provider/model/dimensions/version、vector、向量生成时间 |
| 有效性 | 投影时的来源状态，只用于加速；查询时以权威来源为准 |
| 统计 | 每 tenant 的词项文档频率（IDF），随投影批次更新，只用于排序 |
| 运维 | 来源水位、索引水位、重建批次、错误与最近核对时间 |

**权限过滤**：召回 SQL 与权威来源表连接，由权威表现行 RLS 和对象受众判定在同一查询、同一快照内过滤；索引行自身按 tenant/category 设 RLS，作为纵深防御。撤权、改受众、撤回和扫描失效在下一次查询即生效，不依赖索引重建。索引行的 category 与权威不一致（如对象改属品类）时以权威为准并标记重建，不得 fail-open。

**向量召回与过滤**：HNSW 先找近邻再过滤，在权限或范围较窄时，返回数会少于请求数量。使用 pgvector 0.8（本地镜像 `pgvector/pgvector:0.8.6-pg16-bookworm`）的迭代索引扫描；过滤后候选规模较小（如单品类、单项目范围）时直接精确扫描。权限负向矩阵之外另测召回：低权限用户在同一过滤集合上与精确扫描对照，记录差异。

**与 v1.1 §07.7 的关系**：v1.1 要求索引保存 tenant/scope/ACL、召回前过滤。本稿索引保存 tenant/category 范围，ACL 在召回 SQL 内由权威表判定，同样在召回阶段过滤，且没有副本滞后。

**批量复核**：跨型号、跨品类的候选复核在一次查询内完成，不逐条调用 `source_for`/`require_access`；同一请求内授权只查一次（v1.1 §08.11）。

不同 embedding 模型或维度不能混用同一向量空间；换模型使用独立 profile 和重建批次，完成 shadow 对比后再切换。

原始向量、对象存储键和凭据引用不得进入工具结果、API、Event、Audit、普通日志或前端；这些接口只返回必要的安全元数据、引用与定位。

### 7.8 embedding 配置

P28/P29 解决的是 Chat Completions 与聊天模型多连接，不自动意味着同一连接支持 embedding。本稿因此采用独立 provider-neutral embedding 端口：

- 固定 provider、model、dimensions、version 和凭据引用；
- 启用 embedding profile 按 P30 第2条由管理员一次确认（T1，§19 Q1），未启用时只用关键词路径，不发生任何 embedding 出站（§9.5）；
- 可以使用自建或本机的 OpenAI 兼容 embeddings 端点；服务商身份由服务器按实际端点判定，出站照常记录；
- 复用 KMS/Keychain、服务器出站分类、预算和运行记录的安全边界；
- 测试使用确定性向量，真实服务商未配置时只启用关键词路径；
- 不自动复用聊天 API Key 调用 embedding，不静默转发到备用服务商；
- 真实启用前核对端点、密钥、计量、资料类别与质量，不因接口兼容宣称质量资格；
- 校验响应形状、有界输入、超时、有限数值与精确维度，异常时 fail-close，不以“零结果”伪装 embedding 不可用。

### 7.9 资料比较

- **适用**：同一资料的两个固定版本，或用户选择的两份资料；首期支持已能解析并定位的文本、Markdown、PDF、XLSX。照片、截图、图纸不在首期承诺内。
- **比对**：代码按段落与表格行对齐两版解析文本，得到新增、删除、修改的段落及两侧定位；XLSX 按表头对齐行后比对单元格值。
- **解读**：变化段落属于不可信正文，交隔离子任务解读，交回差异行：变化项、旧值引文、新值引文、两侧定位、可能影响（只能引用文中依据，没有依据标“待确认”）、待核对事项与状态。
- **主循环**只拿差异行与比对统计（变化段数、未能对齐的部分），不读两份原文。未能对齐或解析失败的部分单列，不当作“无变化”。
- **结构化定义**：产品定义与规格条目的比较继续使用现有 `m3_definition_diff`、`m3_spec_compare`，不经文本比对。
- **体积**：变化段落多时分批交子任务，主循环每批只收差异行，总量受[小Pai上下文设计](2026-10-28-xiaopai-context-design.md) §6 预算约束。

## 8. 只读工具与回答合同

### 8.1 新增工具

现有 `evidence.search` 继续只搜索 Run 显式绑定来源，不扩大为跨范围企业搜索。新增三个 READ 工具，沿用 `research.fanout`/`research.read` 与 `evidence.extract`/`evidence.artifact.read` 的现有分工：

| 工具 | 所在位置 | 作用 |
|---|---|---|
| `assistant.search` | 主循环 | 返回服务器签发的 citation ID、来源类型、标题、版本、定位、有效性、关系类型与 as_of；不返回正文或片段 |
| `assistant.extract` | 主循环 | 为本 Run 已签发的 citation ID 读取证据：不可信正文派发隔离子任务；知识行和内部记录由服务器直接返回结构化行，不调用模型。一律交回证据行与覆盖 |
| `assistant.passage.read` | 仅隔离子任务 | 读取所绑定来源的有界段落及相邻上下文，可续读 |

项目、Issue/CAPA/Change 等内部记录同样经 `assistant.search` 签发 citation ID，由 `assistant.extract` 直接返回权威读模型的结构化行（含 as_of），不调用模型；精确对象名查找复用 `personal_search` 的本人范围元数据查找。

三个工具均加入现有 ToolRegistry、读账本、执行绑定和恢复机制；`assistant.passage.read` 登记为隔离工具，不出现在主循环工具表。恢复时按现有 extract 模式对固定来源重核，不重新派发子任务。不开放任意 SQL/HTTP，不授予业务写权限。

### 8.2 回答结构

沿用 Run 的 `status/summary/result/questions/unfinished` 外壳，在 `result` 内增加 `assistant`。模型只提交正文和实际获得的 citation IDs；服务器根据工具账本和证据行生成完整来源区。

示意结构（不是实际业务记录）：

```json
{
  "status": "completed",
  "summary": "基于已核对资料形成的自然语言回答",
  "result": {
    "assistant": {
      "version": 1,
      "kind": "enterprise",
      "lookup": "cited",
      "citation_ids": ["server-issued-citation-id"],
      "sources": [
        {
          "source_type": "artifact",
          "source_id": "…",
          "source_revision": 3,
          "content_hash": "…",
          "title": "…",
          "locator": "page:4",
          "quote": "固定来源中的逐字片段",
          "currentness": "current"
        }
      ],
      "as_of": "服务器读取水位",
      "coverage": {"returned": 1, "unavailable": []},
      "unknowns": []
    }
  },
  "questions": [],
  "unfinished": []
}
```

`kind` 与 `lookup` 都由服务器确定，不由模型自报：

- `kind` 按回答实际引用的 citation 类型判定：引用了检索来源的证据行为 enterprise；只引用权威读取为 current_fact；没有引用为 general。
- `lookup` 按读账本与实际引用判定，并决定未引用来源的回答在页面上的标注：

| lookup | 条件 | 状态标签（次要） | 页面主文案（服务器生成） |
|---|---|---|---|
| `not_run` | 本 Run 没有发起企业检索或权威读取 | 未查公司资料 | — |
| `no_match` | 发起了检索或读取，本次范围内没有命中 | 未找到 | “在{查找范围}中没有找到相关记录”，附下一步操作（§11.11） |
| `uncited` | 有命中，但回答没有引用 | 有相关记录未引用 | “找到 {N} 条相关记录”，后接回答中的未知项（如“没有查到本次复验结果”），附查看记录、指定资料等操作 |
| `cited` | 回答引用了来源 | — | 显示来源区 |

查找范围与条数由服务器按读账本计算；“没有查到什么”取自回答的 `unknowns`，作为小Pai的说明展示，不作为业务事实。P30 第1条的“未查公司资料”只用于 `not_run`；`no_match`、`uncited` 同样不冒充公司口径。确认稿 P30 与 v1.1 §01.9 已按本表加注（2026-10-28 第二次措辞同步，§19 Q4）。页面来源、引文、数量和覆盖同样由服务器附加，模型不能自填。

状态规则：

- 检索成功但没有命中，可以是 completed，答案必须限定为“本次范围内未找到”；
- 部分来源失败或覆盖不完整，使用 partial 并保留未完成项；
- 最终 verify 发现当前事实来源已变化、撤权或引用失效：失效引用从来源区移除，status 降为 partial，`unfinished` 写明哪些来源已变化或无权读取、需重新查询；不保留旧引文，也不以 completed 输出旧答案；
- 没有可靠企业来源时，可以明确转为一般知识解释（kind=general，lookup 为 `no_match` 或 `uncited`），但不得冒充公司事实。

schema 能证明引用身份、原文和来源状态可核，不能单独证明每句自然语言完全忠实。语义忠实度必须通过独立问题集和人工评价验证。

### 8.3 按任务交付的结果结构

同一个小Pai，按任务给出登记的结果结构，用户不需要切换模式。模型从登记的结构中选择并填写；每格须引用 citation，或标“未记录”“待确认”；服务器校验结构与引用，前端按结构渲染。

| 用户想完成的事 | 结构 | 字段 |
|---|---|---|
| 看清项目为什么卡住 | 阻塞清单 | 当前结论、阻塞事项、责任人、下一步、待决定事项 |
| 找以前的处理经验 | 案例表 | 相似案例、根因、措施、验证结果、适用条件与差异 |
| 比较两个版本 | 差异表 | 变化项、旧版、新版、可能影响、待确认 |
| 准备评审 | 评审清单 | 关键变化、未解决问题、需决定事项 |
| 跟进供应承诺 | 承诺表 | 当前承诺、偏差、相关对象、需跟进事项 |

- 解释、写作、翻译等不适合结构的回答照常用正文；
- 责任人、日期只取自已有记录，没有记录的标“未指定”，不由模型推断；
- 结构化结果可一键保存为本人工作成果（§11.12）。

## 9. 权限、隐私与安全合同

### 9.1 检索前过滤

- 在同一 tenant/actor/requester 与 RR/RLS 快照内执行来源和索引查询；召回 SQL 与权威来源表连接，不依赖复制的受众名单；
- 品类是范围根，私有提案、指定受众、客户资料和个人资料继续按对象收窄；
- 过滤必须发生在数据库召回阶段，不得先从全库取回再只在页面隐藏；
- 不可读对象的标题、ID、正文、数量和相似度均不返回，避免元数据侧泄漏；
- 批量复核一次完成，不逐条授权查询（§7.7）。

### 9.2 输出前复核

- `assistant.extract`、隔离子任务读取和最终 `verify` 均重新核对当前权限、来源版本、扫描、撤回和适用范围；
- 检索完成后、最终回答前发生撤权/撤回，旧 citation 必须失效（状态处理见 §8.2）；
- 恢复历史会话时重新验证读取来源，历史摘要只是缓存；
- 索引不保存受众名单；索引行的 category 与权威不一致时以权威拒绝为准并标记重建，不得 fail-open。

### 9.3 私人、客户资料与跨范围携带

- 私人会话默认只服务本人，不进入共享企业索引；
- 客户私有资料不进入共享品类知识、对标和矩阵，既有去标识规则不变；
- 向量索引、chunk、缓存、摘要和备份都继承来源受众与撤回传播；
- 不因为资料被用于一次回答，就自动学习为长期记忆或企业规则；
- 问答转行动时，携带来源的受众必须覆盖目标对象的受众（I14）：私有或指定受众来源不能被带进受众更宽的对象；客户原件或由其派生的内容不能被带进共享品类对象（I22），需要沉淀时走既有人工去标识流程。服务器在形成候选时检查，前端预填不构成许可。

### 9.4 对话中的模型出站

每次对话中的模型出站（含用户问题的查询向量化）由服务器按该次调用实际携带的来源判断服务商与资料类别；一次调用含多个品类或客户资料时按并集判定，并记入运行回执。保留现行 P26/P28/P29 的回执、预算、凭据和协议治理。聊天连接可配置不等于业务资料可以自动发往新端点。

### 9.5 后台索引出站

后台 embedding 不由用户提问触发，会把已入索引的资料主动发往 embedding 服务商，是 P26/I24 原先未覆盖的出站形态，按 P30 第2条处理：

- **启用**：管理员一次确认启用 embedding profile。确认内容列出服务商、模型、维度、包含的数据类别、预计来源数与费用；客户原件类别须单独勾选，默认不含。保存 profile 不发起出站，确认生效后才开始批次。启用操作为 T1（P30 第2条；2026-10-28 复核维持，§19 Q1），作为新增 T1 操作登记到操作清单。
- **记录**：每个索引批次生成出站回执，记录服务商、数据类别、来源数、字符量、费用与批次 ID；费用计入租户索引预算，不占用任何用户 Run 的预算。
- **协议**：已登记当前有效 ProviderDataAgreement 的，按“服务商 × 数据类别”限制（P26），超出许可类别的来源跳过并记入覆盖；未登记不阻断。
- **停用**：停用 profile 立即停止新批次与向量召回，回到关键词路径；已有向量随 profile 退役清除。
- 查询向量化随 Run 出站，按 §9.4 判定，不属于后台出站。页面只读请求（§11.5）不为查询单独发起 embedding。

### 9.6 主动呈现与外部渠道

- 相似历史与新建表单提示按当前查看者本人权限计算，与对话检索使用同一权限连接；不显示不可读对象的标题、数量或“有更多结果”之类提示；
- 定时摘要由订阅者本人作为 AutomationRule 所有者，按本人权限在生成时读取；不提供替他人订阅；
- 缺口报表只汇总用户主动提交的“请补充资料”与无文字的按品类未找到率（§11.8），不展示私人会话原话与提问人；
- 回答或摘要投递到钉钉属于出站，按 P31 与 §11.9 执行；其他外部渠道另行决策。

## 10. 会话、索引与恢复

### 10.1 会话恢复与跨轮引用

- 新工具接入现有 `read_restores` 与历史读取器；继续会话时重新核对搜索、证据行和原文定位；
- 来源撤权、撤回或扫描失效时隐藏对应历史回答；来源仅有更新时保留并标注 as_of；运行内冻结历史，只复核权限（P32，[小Pai上下文设计](2026-10-28-xiaopai-context-design.md) §5）；
- 页面刷新、响应丢失和重开仍读取同一 Run，不自动重新发起检索、子任务或业务动作；
- 当前事实回答在继续对话时按需重读，不把上次回答当作永久事实。

**跨轮引用**：用户追问上一轮的来源（如“第二条来源里还说了什么”）时，新一轮是续接的子 Run。按 `conversation.prepare` 继承 `read_sources` 的同一模式处理：

- 子 Run 继承同一 lineage 内已签发的 citation（来源身份、固定版本与定位），数量上限按请求大小规则；
- 继承的 citation 使用前重新核对当前权限、受众、扫描与撤回，通过后在子 Run 内重新签发 ID，读账本记录继承关系；
- 来源已有新版本的，继承的 citation 仍指向原固定版本并标为历史，回答须说明；需要当前内容时重新检索；
- 不跨会话、不跨 lineage 继承；范围随 `prepare` 沿用父 Run，不因继承而扩大；
- 可继承引用、排除条件与焦点对象存入会话工作状态（[小Pai上下文设计](2026-10-28-xiaopai-context-design.md) §5.3）。

### 10.2 索引幂等与重建

索引工作键至少包含：

```text
source_type + source_id + source_revision + content_hash
+ parser_version + chunker_version
+ tokenizer_version（含词典与停用词表） + code_rule_version
+ embedding_profile
```

- 同一来源重复 Outbox 不重复生成有效chunk；
- 来源续版建立新投影，旧版本仅在明确历史查询中可用；
- Worker 硬重启后从固定批次与来源水位继续；
- 索引可从权威来源全量重建，备份恢复不以索引为唯一事实；
- embedding 没有业务副作用：超时或结果未知时按有限次退避重试；用量已知的调用照实记入批次回执与索引预算；结果未知的调用按现行未知调用规则保守占用预算，不补零，经与 `ai.model_call.reconcile` 同类的对账流程结清（是否复用同一操作在实施时登记）；索引写入按内容键幂等。不进入外部副作用对账（I18 针对有副作用的外发）；
- 索引失败只阻断依赖它的语义能力，关键词与权威读取继续可用，并明确显示覆盖与滞后。

### 10.3 可观测性

按 Run、页面请求和索引批次记录：查询类型、实际分词词项、命中编号、召回数量、关系扩展数、排序版本、子任务调用次数、实际引用、回答依据状态分布、快档/深入查比例、未覆盖原因、来源水位、索引水位、DB 检索时延与 SQL 次数、模型总时延、embedding 版本与费用；相似历史的采纳与“不相关”次数；定时摘要的投递与打开次数。用户界面不展示 token 用量，治理视图可按既有规则展示实际费用和运行限制。

## 11. 页面与交互

### 11.1 同一对话，不增加模式开关

独立小Pai与页内小Pai继续共用组件和会话。欢迎示例可以覆盖“问一个日常问题、查公司资料、处理当前工作”，按本人岗位偏好调整，只展示当时已能完成的任务，不要求用户先选择回答模式。

输入区背景条（v1.1 B14）显示当前对象与查找范围，例如“当前对象：D16 接口漏气问题｜查找范围：当前项目 + 同品类补查”，可点开修改范围或移除对象。用户说“这一版”“上次那个报告”时，有页面或附件背景就直接承接；有歧义时只问一个关键问题，例如“你说的是结构 V2，还是本次试产样机？”。

### 11.2 回答呈现

- 普通回答直接在对话内显示，不强制展开运行过程；未引用来源的回答按 §8.2 显示具体说明与次要的状态标签；
- 企业回答增加 `AnswerSources`，复用研究来源的安静展示方式；
- 来源显示标题、版本、定位、读取时点和当前/历史/失效状态；关系扩展带出的来源标明关系类型；
- 原文片段取自核对过的证据行，与覆盖和失败一起按需展开；来源可点击回到实际对象或文档；
- 冲突来源并列呈现，未知和未覆盖不以空白隐藏；
- 回答下提供“深入查”（§6.4）与“保存”（§11.12）；企业回答下提供“存为公司知识”（§11.7）；未找到或未引用时按 §11.11 给出下一步操作，“请补充资料”（§11.8）是其中一项，不是唯一出口；
- 技术诊断、运行记录和反馈继续放入对话详情，不增加首页技术信息负担。

### 11.3 回答后行动：直接到草稿

回答后按内容给出少量明确动作。点击后以固定技能、已核对来源和会话工作状态启动续接运行，直接产出候选，用户只补真正缺少的内容。确认仍走现有候选、预览、一次确认或具名决定，不提供绕过确认的“直接创建”按钮。

| 回答内容 | 动作 | 使用的现有命令或结构 |
|---|---|---|
| 查到问题处理经验 | 准备复验请求 | `verification.request.create` |
| 查到缺失资料 | 创建资料跟进任务 | `work.task.create`；负责人经 `work.task.assign`（T1） |
| 查到项目阻塞 | 整理待决定事项 | 阻塞清单（§8.3），可保存为工作成果；需要正式任务时同上 |
| 比较两个版本后 | 生成评审清单 | 评审清单（§8.3），可保存为工作成果 |

草稿字段规则：关联项目与对象自动带入；目标按本次讨论起草；参考资料带入已选来源；方法与验收依据有明确依据的预填，没有的标“待确认”；负责人、日期取已有安排，否则由用户选择；完成后显示任务卡与打开入口。

小Pai没有相应 T0 资格时，这些命令按现有规则形成候选等待确认，不改变档位。服务器在形成候选时按 §9.3 检查来源受众与目标受众，不满足时拒绝并说明原因。首期完整打通“质量问题查历史 → 准备复验请求”。

### 11.4 兼容与可访问性

沿用 shadcn/ui、Tailwind、Geist、Phosphor 和双主题，不增加第二套 UI 库。来源列表、展开/收起、继续行动、相似历史侧栏和摘要条目支持键盘、清晰焦点及 390/320px 窄屏；长引文和表格只在自身容器滚动。

### 11.5 对象页相似历史（切片 E）

- **位置**：质量问题与变更申请的详情页侧栏；新建表单中按标题做防重复提示。
- **查询**：以对象标题与描述（内部记录）为查询，复用同一检索服务、编号通道、关系扩展与权限连接。切片 C 后，对象自身已入向量索引的，用其向量做近邻召回，不为页面请求单独发起 embedding。
- **呈现**：最多 5 张卡片，显示类型、标题、状态、品类/项目、命中原因（同编号、同失效词、关联对象），以及取自结构化记录的根因、临时措施、CAPA 措施、复验或有效性状态；没有记录的显示“未记录”或“待复验”。与当前对象的差异只比较结构化字段（型号、料号、编号、阶段），工况等未结构化的差异留给小Pai判断。不显示正文，不调用模型；排除对象自身与已关联对象。
- **动作**：打开；“标为重复”只用于问题与问题之间，走 `quality.issue.merge` 的 T1 预览与确认；“不相关”记入检索反馈；需要判断时点“让小Pai看看”，以该对象为上下文打开页内小Pai，按普通 Run 处理，默认以案例表（§8.3）给出相同点、不同点、可参考的处理方式与目前缺少的信息。不新增通用的“相关”关系命令，需要时另行设计。
- **性能**：页面只读请求，p95 ≤1 秒（v1.1 §07.11、P3）。
- **检索反馈**：只记录查看者、对象、候选、排序版本与动作，用于评估和排序版本对比，不自动改变排序，不是业务事实。

### 11.6 定时摘要（切片 E）

- **订阅**：本人选择模板与频率（默认每周一，可选每个工作日），作为本人的 AutomationRule，启用沿用 `ai.automation.activate` 的一次确认。摘要读取按订阅者本人的权限上下文执行；如现有 AutomationRule 的服务授权不能按本人权限读取，实施时先补齐，不以共享服务账号读取。
- **模板**（按岗位默认，本人可改）：管理层——项目最新具名状态与风险变化；产品/项目经理——阻塞、临近门禁、待决定事项；品质——新开问题、到期 CAPA；采购——外部等待与供应承诺到期。
- **内容**：服务器从权威读模型与个人关注读模型生成结构化条目（对象、变化、as_of、链接）；模型只写简短导语并引用条目，不新增事实；模型不可用时只投递结构化条目。
- **组织**：每条摘要回答四个问题：发生了什么变化、为什么与我有关、接下来需要谁做什么、从哪里继续处理。“与我有关”按本人是负责人、评审人、等待方或订阅者由服务器给出；“可能影响”只在有记录依据时写，没有依据写“待确认”。
- **分组**：需要我决定或处理的事；我在等待别人完成的事；我关注项目的新变化。持续未变的事项折叠，重要变化优先。可按分组或类型退订、降低频率。
- **健康度**：以项目最新具名状态更新为准，摘要不自行评定健康度或风险等级。
- **投递**：本人小Pai会话与个人关注页；切片 G 完成后，本人可选择同时投递到钉钉单聊（按 P31 记出站回执）。
- **出站与预算**：每次生成是一个 Run，按 P26 判定出站，计入预算。

### 11.7 核实答案（切片 F）

- 企业回答下点“存为公司知识”：以回答正文与已核对来源起草知识候选，AI 起草部分标 ai_draft。
- 品类知识走 `category.knowledge.add` 与 `category.knowledge.promote`（客户来源须人工确认已去标识）；公司规则（如测试方法、设计规则）走 `knowledge.candidate.create` 与 `knowledge.rule.publish`（T2，具名发布）。
- 核实答案须有负责人、适用范围和复核日期；现有知识模型没有复核日期的，实施时补字段并同步合同。
- 检索排序：在 §3 第 2 层内优先于原件；超过复核日期未复核的降级并标“待复核”，并提醒负责人。
- 只能人工发起、具名发布；小Pai不自动沉淀（D11）。

### 11.8 知识缺口报表（切片 F）

- “未找到”的说明旁提供“请补充资料”，与 §11.11 的其他操作并列。提交前向用户展示将分享给哪个品类的知识负责人、分享哪些内容（问题原文与检索范围，不含会话其他内容）。
- 每周按品类汇总：用户提交的补充请求、用户在反馈中选择分享给知识负责人的被点踩回答、无文字的未找到率（少于 5 次不显示）。
- 归因由知识负责人标注：资料缺失、版本冲突、内容不清、检索未召回、回答问题。系统不为归因去查询提问人无权读取的资料。
- 不展示未提交的私人会话原话和提问人。

### 11.9 钉钉只读入口（切片 G，P31）

- **账号**：钉钉用户与 PDOS 账户一对一绑定，未绑定不回答。绑定由本人发起，管理员可撤销；钉钉应用凭据存服务器 KMS/Keychain，不进入模型上下文。绑定与凭据管理操作在实施时登记。
- **入站内容**：只处理单聊消息和 @小Pai 的那一条群消息，不读取群聊历史。
- **单聊**：按本人权限回答，与 PDOS 内使用同一检索与 verify。
- **群聊**：@小Pai 时默认只私发给提问人。提问人点“发到群里”时只贴回答正文与 PDOS 链接，不贴原文引文；只有全部引用来源的受众覆盖群内所有成员、且群内没有未绑定成员时，才允许连同引文贴出。
- **客户资料**：客户原件与由其派生的内容默认不进入钉钉消息。
- **动作**：业务动作不在钉钉内完成，一律给出跳回 PDOS 的链接。
- **出站**：每次向钉钉投递按 P26 记出站回执，服务商记为钉钉。
- **深链**：跳回 PDOS 的链接直接打开对应项目或问题、本次答案、已准备的候选或明确的待确认位置；链接只带标识，打开时重新登录并核对权限。
- **等待与提醒**：收到问题即回复“收到，正在查”；群内提问提示“答案已私发”；后台完成后私信提醒。

### 11.10 拿着资料来问

| 入口 | 用户怎么用 | 得到什么 |
|---|---|---|
| 附上新资料 | 把 PDF、Excel 等放进对话 | 摘要、关键结论、待确认项 |
| 选择现有资料 | 从当前项目选一份或多份资料 | 围绕指定资料回答，不再全库检索 |
| 选择两个版本 | 选旧版与新版，或两份资料 | 差异表（§7.9、§8.3） |

- 上传后逐个文件显示：已收到、可以提问、处理中、无法读取及原因（如扫描件需 OCR），直接对应现有扫描状态与解析清单；
- 随后给少量贴合资料的建议，如“总结这份报告”“与上一版比较”“提取待跟进项”；
- 选定资料后，本轮检索限定在所选资料内，限定写入工作状态，用户可解除；
- 首期只承诺已能解析并定位的文本、PDF、XLSX；照片、截图、图纸另行明确能力边界。

### 11.11 查错、答偏、未找到时当场纠正

| 用户遇到的问题 | 可用操作 | 服务器记录 |
|---|---|---|
| 查错型号或零件 | 换成正确对象后重新查 | 替换工作状态中的焦点对象 |
| 找到的是旧版本 | 只看指定版本或当前有效资料 | 版本条件 |
| 结果与问题无关 | 收起该结果并补充一句条件 | 排除条件与用户补充 |
| 找到资料但答偏 | 指定某份资料或某一段重新回答 | 限定来源 |
| 当前范围没找到 | 扩展到同品类历史或附上资料 | 范围条件 |
| 信息不足 | 只补缺的那一项 | 待答问题 |

- 这些操作作为下一轮的明确条件写入工作状态（[小Pai上下文设计](2026-10-28-xiaopai-context-design.md) §5.3），不要求用户重新组织语言；条件只能收窄或切换到服务器认可的范围，不扩大权限。
- “不相关”同时收起结果、写入排除条件并记入检索反馈。

### 11.12 进度、保存与找回

- **进度**：普通问题直接给简洁答案；多资料处理显示有意义的进度（如“正在比较两份报告的测试条件”），反映真实步骤；先交付已完成且核对过的部分并说明还在处理什么；用户可离开、取消，之后在同一会话继续查看。
- **深入查**：点击前说明准备进一步查什么（范围、来源类型、预计耗时）。
- **保存**：回答与结构化结果可收藏到会话，或保存为本人工作成果（现有 `work_products`，本人私有、可追加修订）。
- **找回**：项目页显示本人在该项目的最近相关讨论（仅本人可见）；再次打开时可选“查看当时结果”或“按最新资料更新”，后者发起新一轮并重读。
- **共享**：保存为项目中他人可见的草稿或对象属于业务写入，按 §9.3 受众检查与现有档位办理，不作为收藏的一种。

## 14. 验证与评价矩阵

| 维度 | 必测内容 |
|---|---|
| 普通问答 | 中文/英文、一般解释、写作、追问；无误检索、无业务写入、无不必要技能、general 标注 |
| 依据状态 | `not_run`/`no_match`/`uncited`/`cited` 与读账本一致；“该查没查”题单列统计 |
| 当前事实 | 当前项目/定义/计划/承诺；版本变化后重读；不从旧摘要回答当前 |
| 语义回答 | 单来源、多来源、同义词、精确编号、冲突、无结果、部分失败 |
| 编号 | 型号/料号/标准号的精确与族命中；与分词无关；误抽取 |
| 引用 | citation 属于本 Run 或经继承重签、原文子串、locator、版本、来源链接、服务器附加数量 |
| 跨轮引用 | 追问上一轮来源；继承后撤权失效；新版本标为历史 |
| 排序 | 关系一跳扩展只用显式关系且经权限过滤；个人化与新近度按排序版本可复现 |
| 权限 | 跨租户、跨品类、私有提案、指定受众、客户资料、撤权、撤回、扫描失效、跨范围携带（I14/I22）、低权限向量召回对照 |
| 隔离与注入 | 主循环工具表无原文读取；子任务无写工具；文档中的工具指令、权限声明和批准文字只作为数据，不改变行为 |
| 恢复 | 响应丢失、Worker 重启、继续会话、重复 Outbox、索引重建、embedding 超时重试与未知用量占账 |
| 出站 | 未启用 profile 零 embedding 出站；批次回执、索引预算、协议类别限制、停用回退；页面请求零出站 |
| 行动 | 回答后预填、T1 一次确认、T2 具名决定、未确认零写入、回执一致 |
| 主动呈现 | 相似历史不调用模型、权限无痕迹、p95；重复合并 T1；摘要条目回链、导语无新增事实、按本人权限 |
| 知识沉淀 | 人工发起与具名发布、去标识、待复核降级、周报隐私阈值 |
| 钉钉 | 绑定与撤销、默认私发、群内受众覆盖、客户资料过滤、不读群聊历史、出站回执 |
| 体验 | 安静普通回复、依据标注、来源展开、深入查、键盘、焦点、桌面/390/320px、亮暗主题 |
| 性能与成本 | 检索读取与页面请求 p95 与 SQL 次数、A/B 端到端时延 p50/p95、子任务调用、模型总时延、索引滞后、embedding 与模型费用、无效调用率 |
| 范围补查 | 命中不足才触发、分组标注、其他客户私有资料默认不纳入、用户改回只查当前项目 |
| 资料比较 | 两版对齐、未对齐部分单列、差异行引文为两侧原文子串、主循环不读原文 |
| 结果与纠正 | 结构逐格引用、责任人不推断、纠正条件进入下一轮且不扩大权限、“不相关”收起并排除 |

### 14.1 首期验收故事

以下是拟定场景，不代表实际项目数据。品质人员在一个接口漏气问题页里说：“找找以前的处理经验，帮我准备下一步复验。”理想体验应连续完成：

1. **带入背景**：知道当前项目、型号和问题，只询问确实缺少的关键条件；
2. **找到经验**：当前项目不足时补查同品类历史，列出措施及验证结果；
3. **帮助判断**：说明历史案例与当前问题的相同点、不同点和待确认项；
4. **形成草稿**：准备复验请求，已有信息自动带入，缺少的留待确认；
5. **留下结果**：确认后能打开请求，之后能从当前问题或会话继续查看。

| 观察项 | 想确认什么 |
|---|---|
| 用户能否独立开始 | 是否知道从哪里问、怎么附资料 |
| 是否需要重复说明背景 | 小Pai是否承接了项目、对象和上轮条件 |
| 还要打开多少记录 | 回答是否已提供足够信息帮助判断 |
| 还要复制、手填多少内容 | 从答案到实际工作的衔接是否省事 |
| 遇到错误能否快速纠正 | 用户能否继续完成这次任务 |
| 下次遇到同类工作是否愿意再用 | 这个场景是否形成了实际价值 |

| D18 | 关键词召回用 OR 组合与 IDF 加权（BM25 形式）；停用词表与分词器同版本管理 |

| D21 | 同一 lineage 内的 citation 可跨轮继承，使用前重核并重新签发；不跨会话 |
| D22 | Issue/CAPA/Change 的内部记录在切片 B 接入；客户与现场原话按不可信正文 |
| D23 | 关系一跳扩展只用显式关系，规则推导与 AI 怀疑的关系不参与；排序参数按排序版本固定 |
| D24 | 主动呈现只读、按本人权限；相似历史页面请求不调用模型、不产生出站 |

| D27 | 缺口报表只汇总用户主动提交的内容与无文字统计，不展示私人会话原话与提问人 |
| D28 | 钉钉只读入口按提问人本人权限、默认私发；群内引文须受众覆盖全部成员；客户资料默认不进钉钉；每次投递记出站回执（P31） |

| D30 | 资料比较由代码逐段比对，变化段落交隔离子任务解读，主循环只收差异行 |
| D31 | 按任务交付登记的结果结构，每格须引用或标“未记录/待确认”；责任人与日期不由模型推断 |
| D32 | “继续处理”直接产出候选，沿用现有命令与档位 |
| D33 | 纠正操作作为服务器记录的条件进入下一轮，只能收窄或切换到服务器认可的范围 |
| D34 | 未找到、未引用的页面主文案由服务器按查找范围与记录数生成，状态标签退为次要（P30 第二次措辞同步） |
