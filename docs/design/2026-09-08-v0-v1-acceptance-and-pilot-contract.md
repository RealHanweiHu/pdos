真实数字链执行顺序：

1. 数据 Owner 对原始报告与待导入字段逐行建立人工核对结果，冻结文件 digest、映射版本、需求/规格/用例/样机关联。
2. 以普通工程/品质成员从浏览器上传 Excel；记录批次、模型/prompt/映射版本、跳行/未知值/缺失项。确认前仅草稿，失败测试不得提前更新正式用例或开正式 Issue。
3. 人检查 diff 后批量确认；核对有效行数、Test Run、样机配置、FW/Build 与来源引用。重复确认、重复文件、同模板再导入分别记录行为，区分拒绝/复用/新批次，不能只看请求成功。
4. 选一个失败测试的 Issue，指定 Owner、独立 Verifier、关闭标准；走提交、无证据拒绝、非 Verifier 拒绝、退回、重新提交、凭证关闭及重开。核对事件/审计与知识 draft，未验证知识不得进入可信检索。
5. 记录相关 Decision，聚合 Gate 证据，先演示缺必需证据被阻断，再演示满足条件后的合法裁决；条件放行的 Action 有责任人/到期日/关闭证据，不能借 conditional 绕过 readiness。
6. 非成员、其他租户及真实受限 Agent 凭据执行负例；保留 HTTP 状态、零业务写与审计证明。停止 LLM、超预算和禁外发均须可见且业务人工路径可用。

单日工作流按独立开发者模式，由用户本人分别以研发、品质角色完成，记录为“一位使用者、两类角色场景”，不声称两位独立用户已验证。使用对应成员权限，观察人不代操作：登录找待办→更新 Issue/上传报告→查配置与引用→处理验证/草稿→检查下游提醒/知识候选。用同一任务包对照原工作方式，记录总主动操作时长、重复录入时长、点击数、人工求助次数及未完成步骤；首次学习时间单列。两类角色均须完成关键路径，重复录入负担减少且总主动操作时长不增加；未达标保留失败原因与复测计划，不取平均掩盖某角色退化。

## 6. 指标定义、校准与通过规则

以下为采集定义；Owner 冻结样本范围后方可计算。每次报告同时给分子/分母、样本量、时间窗、缺失/排除原因、可追溯明细。分母为 0 记 N/A，不能记 100%。

| 指标 | 计算口径 | 阈值地位 |
|---|---|---|
| 需求追溯覆盖率 | 有可测 Spec 且连到验证用例的范围内 Requirement 数 / 范围内 Requirement 数 | 原目标 ≥90%，须 Pilot 校准 |
| 样机配置完整率 | 具备模板要求配置字段及版本引用的样机数 / 纳入测试的样机数 | 原目标 ≥95%，须 Pilot 校准；不适用字段由 Owner 预先注明 |
| 结构化测试率 | 已人工确认且可追源的结构化有效测试记录数 / 原始报告范围内应导入的有效测试记录数 | 原目标 ≥80%，须 Pilot 校准；跳行不能从分母静默删除 |
| 导入字段准确率 | 与 Owner 人工核对结果一致的字段数 / 抽查字段数 | 逐模板/字段报告；阈值待定，不能只以解析成功率衡量 |
| 高/严重 Issue 闭环完整率 | 根因、独立验证、关闭证据及批准留痕齐全的已关闭高/严重 Issue 数 / 范围内已关闭高/严重 Issue 数 | 原统计目标 ≥90% 待校准；单条硬关闭规则不降级 |
| Gate 必需证据 | 满足该轮版本化政策的必需证据项 / 该轮全部必需项 | 硬闸 100%，缺项必须拦截，不由基线校准放宽 |
| AI 引用正确率 | 人工确认引用确实支持结论的抽查事实主张数 / 全部抽查事实主张数（缺引用也计入） | 原关键场景目标 ≥95%，按 capability 校准；golden 资格门禁独立保留 |
| Finding 接受/行动 | 已接受裁决数 / 已裁决数；被应用的唯一 Finding 数另列；修改/拒绝/未审单列 | 不以产出量或批量点击数代替采纳；不将确认草稿混入 Finding 分母 |
| 录入负担 | (基线重复录入时长−试点重复录入时长) / 基线时长；总主动时长另列 | V1 按 §5 两角色走查；PM 减少 ≥40% 为后续校准目标 |
| 首屏性能 | My Work、项目概览、Review Inbox 从导航至可操作内容的耗时，各页分别 P95 | 既有硬线 <1.5s；建议每页固定设备/网络/数据规模采集至少 30 次，冻结采样方案后执行 |
| 里程碑/预警/会议/齐套 | 与 V3/V2/V4 的指标合同衔接，保存当前人工基线及数据时间点 | V0 收基线、对应 Phase 验收、V6 汇总；不声称 V1 已实现 |
