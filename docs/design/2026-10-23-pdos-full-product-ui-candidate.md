## 1. 用户首先需要什么

产品每天的第一件事，是告诉本人“哪些工作需要我，现在为什么需要我，处理以后由谁继续”。从待办直接进入准确对象，核对依据，完成当前动作，回到原队列。项目页用于理解全局、继续专业工作；治理和技术细节在需要时展开。

九种岗位共享一套应用和组件。正式应用由服务器返回本人范围与可用动作，不设置“选择岗位才能工作”的入口。预览顶部的身份、状态、明暗、窄屏选择器只服务设计评审；里面的名称、数量、日期、签署和内容都是合成示例。

### 设计依据

- 业务与权限：[v1.1 §01 / §03 / §05 / §06 / §08](2026-10-08-pdos-complete-target-architecture-v1.1.md)，尤其 §05.12 的展示边界。
- 视觉与技术：[既有 UI 基线](2026-08-09-ui-baseline.md)：Geist / Geist Mono、Phosphor、shadcn/ui、Tailwind v4、8px、橙色双主题。不引入第二套 UI 库。
- Linear 的[设计整理](https://linear.app/now/behind-the-latest-design-refresh)强调安静的框架与内容优先；[My issues](https://linear.app/docs/my-issues)将与本人有关的工作集中；[Projects](https://linear.app/docs/projects)在同一对象上提供不同视图。这里采用这些组织原则，不复制其业务实体或配色。

### 四项取舍

1. 全局六个稳定入口（我的工作、收件箱、小Pai、项目、项目集、知识），业务对象留在相应工作空间内；不会把所有后台模块平铺到侧栏。
2. 队列只显示有内容的分组；一条事项一行，保留名称、责任、期限与必要状态。没有空卡片占据首屏。
3. 页面先呈现当前判断和下一动作，来源、版本、运行详情在详情面板或二级视图中查看。
4. 小Pai有独立的通用聊天工作区，也融入各页。页内面板默认收起；成果、技能与过程按需展开。调用次数和运行技术信息不成为产品首页重点。

## 2. 信息架构

```text
工作空间
├─ 我的工作：待我处理 / 承诺 / 已完成
├─ 收件箱：通知 / 聊天（私聊、群聊） / 关注动态
├─ 小Pai：通用聊天 / 私人会话 / 按需展开的成果
├─ 项目：列表 / 看板 / 时间轴
│  └─ 一个项目
│     ├─ 概览
│     ├─ 任务（默认）：NPI 流程任务 + 额外任务；列表 / 看板、阶段与来源筛选
│     ├─ 计划：里程碑 / 资源需求 / 承诺与外部等待
│     ├─ 文件
│     └─ 更多：产品与工程 / 试制与验证 / 问题与变更 / 评审与交付 / 阶段与门禁 / 现场反馈
├─ 项目集：列表 / 看板 → 项目集详情与移入项目
├─ 知识：已发布 / 候选 / 已失效
├─ 产品管理（按权限）：品类 / 立项提案 / 型号与定义
└─ 低频入口：设置
```

项目任务是进入项目的默认视图，以 NPI 阶段任务与额外创建任务为两类来源。默认展示当前阶段，支持其他阶段和全部阶段；NPI 名称、阶段、说明、交付物与检查要求直接来自仓库现有清单，不把接收、协调等办理事项直接当作整套项目任务。“我的工作”聚合分配给本人的项目任务，状态更新在两处同步。列表和看板共享记录，搜索与阶段 / 来源 / 负责人 / 状态筛选帮助收窄范围；任务详情可修改名称、说明、负责人、状态、优先级与截止日期，并跳到关联专业事项。任务完成不等于样件接收、验证结论或正式批准。计划专注里程碑和资源安排，不再复制另一份任务列表。当前编辑边界只是原型演示，正式接入仍采用服务端动作能力。

全局搜索按可读范围返回页面与对象，支持 ⌘/Ctrl K。收藏项目提供直接入口。面包屑始终保留当前对象，项目内切换视图不丢失项目范围。外部协作者保留“我的工作”“小Pai”和“收到的交付”，不进入组织收件箱与项目集，固定包之外的项目、原件和内部会话不出现。

## 3. 九类岗位的第一条路径

| 使用者 | 打开应用时的重点 | 当前动作 | 完成后的接续 |
|---|---|---|---|
| 产品经理 | 定义未知项、待审提案 | 查看来源和工况，修订草稿，确认定义候选 | 形成待冻结内容；正式发布独立办理 |
| 项目负责人 | 冲突、依赖、外部等待 | 比较计划方案，确认自己负责的变更 | 更新预测或工作安排；原承诺单独保留 |
| 研发工程师 | 设计工作、工程影响 | 登记制品版本、具名工程决定 | 后续配置和实际采用继续留痕 |
| 品质 / 测试 | 精确接收、待独立验证 | 核对 Lot / 样件 / 双配置，按实到接收 | 未到部分保持等待；开测与处置独立 |
| 制造工程 / NPI | 制造影响与准备缺项 | 独立制造决定，补齐工具、方法、人员、物料、检验 | 明确后续活动与负责人 |
| 生产执行 | 实制、交样、异常 | 按实物登记批次与实际配置 | 交给指定接收方，不自行代接收 |
| 采购 / 供应 | 供应承诺与到样 | 分别登记对方承诺和实际点收 | 影响工作负责人继续接续 |
| 管理者 | 跨项目资源冲突 | 查看方案影响并具名决定取舍 | 各项目确认自己的计划，不自动改全部日期 |
| 外部协作者 | 本人收到的固定包 | 核对授权内容、样品标识，记录收到回执 | 生效与对账仍单独记录 |

“岗位”决定预览故事，正式权限仍由品类范围、责任、授权和服务端动作能力决定。页面可以向有权阅读者展示其他负责人的工作，但不会让其代签。

## 4. 完整页面合同

| 页面 / 工作 | 首要呈现 | 主要办理入口 | 必须保留的边界 |
|---|---|---|---|
| 我的工作 | 要我决定 / 接收 / 验证 / 我的任务 / 等外部；仅显示非空组 | 打开具体事项 | 动态不混成待办；已完成项移出待处理 |
| 品类 | 型号、提案、共享场景证据、规格字典 | 准备提案或继续型号 | 客户私有原件不自动进入共享资料 |
| 客户输入与匹配 | 原件覆盖、抽取值、条件和未知 | 逐条核对，带入私有提案 | 部分解析不能给出整份满足；不自动立项 |
| 提案 | 用户与场景、取舍、未知、证据 | 编辑草稿、提交相应评审 | 提案四视图共用定义数据；未知不画点，不把宣传当实测 |
| 型号与定义 | 用途、版本、平台父版、派生差异 | 继续定义或准备派生 | 草稿、冻结版和项目采用版独立 |
| 项目列表 / 看板 / 时间轴 | 阶段位置、负责人、健康度、下一门禁 | 打开项目 | 看板不能拖动推进阶段；模板按项目解释 |
| 概览 | 当前重点、办理队列、下一 Build、关键承诺 | 进入当前动作 | Build 保留目的、配置、数量、样件与验证范围 |
| 任务 | NPI / 额外来源、阶段、名称、状态、负责人、截止日期 | 新建、分配和更新进展；追到关联办理 | 与我的工作共用记录；完成任务不自动执行专业批准或接收 |
| 计划 | 里程碑、资源冲突、承诺、外部等待 | 比较候选并确认 | 基线、预测、承诺、实际四行独立；未知有明确文本 |
| 产品与工程 | 定义、工程配置、制品/BOM、平台差异 | 当前对象修订或专业决定 | 新版出现不追改已固定配置；过期、撤回、漂移分开 |
| 试制与验证 | Build → Lot → 样件；实际工程/制造配置 | 按批交样、接收、开测、处置 | 每次精确到实物范围；部分结果不是整体通过 |
| 制造准备 / 试产 | 五类准备、实际产出、已检与剩余 | 补记录、准备专业放行 | 不以综合分代替缺项，不推算未检结果 |
| 问题与变更 | 现象、原值、根因、措施、双线影响 | 各专业具名决定、独立验证 | 工程与制造分别决定；措施、变更、问题分别关闭 |
| 评审与交付 | 固定包版本、用途、例外、专业结论 | 有权本人评审、放行或外发 | 固定包更新产生新版本；AI不能执行 T2 |
| 外部交接 | 授权固定包、收到与业务生效 | 接收者回应、内部对账 | 收到≠生效；外部仅看到授权内容 |
| 阶段与门禁 | 当前出口、下一阶段准备、阶段历史 | 补缺项或发起阶段评审 | 下一阶段条件不变为当前新增阻塞；三种成熟度独立 |
| 现场反馈 | 原始现象、实际对象、分诊结果、接续工作 | 记录反馈，进入正式改进 | 原件与转写/归纳区分；追到后续实际采用与验证 |
| 知识 | 发布状态、适用范围、来源 | 查证后采用，具名发布候选 | 候选和失效经验不能冒充当前规则 |
| 设置 / 治理 | 个人偏好、成员范围、模型、集成、运行 | 低频管理 | 资格按租户×技能包×模型版本；协议按现行 P26 执行 |

预览为以上工作提供 **完整业务页面与多个子视图**。P1 是专业流程的主要合成案例；S2 与 D3 用于验证多项目范围、阶段模板与未知状态，进入专业视图时明确说明示例范围，不把 P1 内容冒充其他项目事实。

## 5. 一套可重复使用的办理模式

### 事项 → 详情 → 确认 → 结果

点击一行后从右侧打开详情。顺序固定为：工作名称与当前状态 → 对象/版本/数量等关键事实 → 来源 → 当前动作 → 本人说明 → 确认摘要。桌面保持原列表位置；窄屏使用全屏详情。

- T0：只有当前资格与授权有效才可执行；自动完成进入动态，失败或需决定才进入本人工作。预览不演示实际 T0 执行。
- T1：预填准确对象与修改范围，最终只需一次明确确认。详情里的“继续办理”只展开摘要，不是一次业务提交。
- T2：确认摘要必须显示具名执行人、动作、对象和版本/用途；不把签署按钮交给小Pai。独立专业决定各自形成记录。
- 成功：显示实际范围与剩余部分，例如“4 件已接收，另 2 件待交付”。队列和对象视图引用同一事实更新。
- 结果未知：保留当前请求，先查询回执，不提示重新创建一个相同动作。

原型中的确认只更新当前标签页内存。刷新可重置演示；没有业务请求、数据库写入、模型调用、真实签署或对外发送。

### 小Pai：通用对话与当前工作（用户访谈确认，2026-10-23）

用户经 grill-me 访谈确认 Q1–Q8，并授权按以下方向修改预览。小Pai默认是通用聊天 Agent；角色决定权限与可用技能，不把不同岗位做成不同的任务向导。独立入口：[小Pai工作区](http://localhost:57859/ui-lab/platform?view=pai)。应用登录默认仍为“我的工作”。

1. **两种空间，同一段对话**：侧栏“小Pai”进入完整工作区；各页右下角悬浮按钮打开非模态侧面板，业务页面继续可操作。展开/收回延续同一会话和输入。手机中页面、对话和成果逐层切换，提供返回路径。悬浮入口为 48px 圆形按钮，面板或整页对话打开时隐藏，关闭后恢复焦点；Next.js 的 N 开发指示器已隐藏，不属于产品导航。
2. **自动上下文**：项目页自动携带当前项目和视图。不同项目分别保留会话，回到项目恢复最近使用的对话；独立入口汇总私人会话。发起中的工作保留自己的范围，页面变化不追改它。上下文摘要可展开查看和返回关联页面。
3. **自然语言为默认**：正常聊天无需先选角色、项目或技能。按意图匹配能力；输入框有可选技能入口，仅展示当前预览身份的可用技能。已用技能与来源范围在回复下按需展开。
4. **成果按内容呈现**：短回答在聊天内。文档和比较表通过结果入口展开到内容区，可直接编辑，也可继续对话生成修订版；原稿从历史消息找回。内容默认私有，不自动发布到项目。业务对象的正式保存、批准与外发仍依既有 T0/T1/T2 规则。
5. **会话承载持续工作**：进行中、需要你处理、已完成、已停止显示在会话中；关闭面板或切换页面不取消演示任务。需要介入的工作同时出现在本人待办与独立收件箱通知中，点击回到原会话；没有新增独立委托任务管理器。
6. **会话管理**：支持新建、搜索、切换、重命名、置顶、归档与恢复。进行中或等待处理的会话先结束工作再归档；没有删除入口。各预览身份的私人会话隔离。

**已实现的演示范围**：普通问候/想法拆解、文档与表格草稿、直接编辑、对话修订、后台等待、停止/继续、收件箱接续、离线草稿、连接失败重试、权限失效收起内容、亮暗与窄屏。具体结果使用合成模板和短计时器；任意自由输入不调用模型，并如实提示预览限制。附件只展示文件名，不上传或读取内容。全部会话、草稿、成果与运行状态仅存在本标签页内存，刷新重置，不能当作真实持久运行或权限验收。

**正式接入要求保留**：服务器绑定上下文和权限；持久私人会话跨刷新恢复；Temporal/LangGraph 执行与原 run 接续；当前资格/授权、引用、回执、撤回与幂等守卫；真实文件处理和业务对象成果；T1 一次确认及 T2 具名办理。当前设计原型不替代这些能力或阶段验收。

## 5.1 本人工作、组织沟通与项目归类（用户本轮修订）

用户要求调整“我的工作 / 我的承诺 / 动态”，增加项目集，并明确收件箱同时支持工作通知与完整的私聊、群聊。此处是可交互的设计候选；聊天服务、消息受众和项目集正式模型没有因此自动上线，也不改变冻结权限根。

- **我的工作**：待我处理、承诺、已完成。承诺按“我承诺的 / 别人承诺给我的”查看，显示双方、具体交付、承诺日期和最新预计；同一记录在不同身份下保持一致。已完成可回看结果和办理说明，无重复确认入口。
- **收件箱 / 通知**：汇总同事提及、工作通知和小Pai需要介入的消息；搜索、未读过滤、全部已读、归档及恢复。通知关联原项目，可以继续办理或找同事沟通。已读和归档不等于业务完成；小Pai阅读状态按每次待处理事件记录。
- **收件箱 / 聊天**：持续私聊与群聊、搜索会话或消息、创建群聊、查看成员、可选关联项目、跨页保留输入、离线禁用发送。发送仅追加本地预览消息，并明确提示未发送给真实成员；不伪造已读回执。

## 6. 状态、错误和恢复

| 状态 | 使用者看到什么 | 可继续做什么 |
|---|---|---|
| 读取中 | 保持页面标题和框架，局部骨架/状态文本 | 已可用部分仍可查看；提交按钮防重复 |
| 真正空态 | “当前事项已处理”及下一入口 | 继续项目；不制造待办填空 |
| 读取失败 | 明确“未能读回”，不显示成空态 | 重试本页，已有草稿不变 |
| 离线 | 页面级连接提示；正式确认禁用 | 查看已有内容和准备说明，恢复后再核对 |
| 版本冲突 | 原版与当前版变化、保留的草稿 | 查看差异、采用当前版本、重新确认动作 |
| 权限失效 | 收起对象内容，禁用动作 | 返回本人工作或核对授权，不能由前端自授 |
| 部分接收 / 部分原值 | 已完成与剩余范围并列 | 只处理明确范围，等待或追踪剩余部分 |
| 外部无回应 / 生效未知 | 发出、收到、生效三个事实 | 追踪相同交接或对账，不假报成功 |
| 撤回 / 过期 / 引用漂移 | 原因、影响、可替代版本 | 按守卫重新准备；漂移本身不一律阻断 |
| AI取消 / 失能 / 待确认 | 当前 run、已形成结果和下一步 | 恢复同一工作或明确重跑；不重复写入 |

预览状态选择器覆盖空态、读取失败、离线、版本冲突、权限失效。部分数据、外部等待在对应页面中常驻。读取骨架、真实请求重试/幂等、细粒度授权变化与撤回执行保留为正式接入验收项，不能凭静态预览宣称已完成。

## 8. 原型与正式落地的差距

2026-10-25整体走查后，公共标题、表头、列表与工具栏对齐既有紧凑密度，收紧我的工作、项目集、收件箱、承诺和品类资料的留白；侧栏在常见桌面高度完整呈现，手机保留待办计数。NPI任务与小Pai独立编辑/保存续聊保持原交互，见[整体优化与预览验证](../reports/evidence/pdos-next-platform-ui-20261023/overall-polish-20261025/result.md)。

### 本轮可评审

信息架构、九岗位入口、项目任务列表/看板与个人待办同步、原业务页面与新增收件箱/项目集、事项办理、一次确认摘要、双专业签署、分批接收、本地状态反馈、搜索、按需小Pai、亮暗主题、窄屏、五类异常状态。

### 仍需正式接入

现有真实业务页尚未替换。任务目录在本地服务端直接消费 `assets/cehub/deliverable-guide-manifest.json`：P1/D3 采用 NPD 基础任务族，S2 采用派生任务族；模板族选择、阶段实例、角色、日期与状态仍是设计预览，尚未接入正式模板适用性与发布版本。旧模板 Gate 编号在列表标题省略、详情保留原名，不将参考清单当作新的批准规则。列表和详情需连接实际查询；对象版本、授权、回执、幂等、并发冲突、撤回、后台运行需与既有领域 API 对齐；页面内草稿需按租户/用户/对象隔离保存；正式评审、发布、放行、外发仍走已批准命令。预览中的部分资料行只打开只读说明，现场记录、派生提案和治理页面不具备真实业务操作。

### 建议落地顺序

1. **统一应用框架 + 本人工作闭环**：导航、列表、详情、确认摘要、真实结果与异常；先消除当前入口和办理负担。
2. **项目日常推进**：任务、概览、计划、独立承诺、资源比较；统一项目范围与真实跳转。
3. **专业工作闭环**：配置→实物→分批接收→原值→问题/变更→双专业决定→独立验证→固定包与交付。
4. **产品与知识**：品类、客户输入、提案四视图、型号派生、反馈和知识治理。
5. **共用能力收尾**：小Pai上下文/后台、各页错误恢复、键盘/窄屏、实际用户走查。

每个业务闭环集中验证；不把每个组件或接口变成单独验收阶段。最终以用户能完成实际工作、原有领域规则未被削弱为判据，不按预览页数量或截图判断业务完成。
