## 2. 对话和入口

右下角小入口打开侧边对话，可放大至完整页；两处使用同一会话、消息、附件、委托和运行结果。跨页、刷新或关闭面板后可继续。普通用户直接表达目标，不必先选择操作类型或专业 Agent。

消息以自然语言为主，必要时嵌入对象链接、变更差异、确认卡和待补问题。每次办理区分已完成、进行中、未完成，并为未完成项给出原因及下一步；“消息已保存”“已排队”“已生成方案”不能表述为业务办理完成。

独立动作可部分完成；相互依赖的批准单元保持原子性。重试先核对原回执，仅续做未完成部分。成功低风险动作在会话中给出结果，不逐项新增通知或待办。

## 3. 三层上下文

1. **页面上下文**：当前项目、对象、页面视图和选中内容，随导航自动变化；对象内容由服务器鉴权后读取。
2. **任务上下文**：当前用户目标、已选目标对象、实际输入版本、办理进度、未决问题及回执，独立于页面生命周期保存。
3. **长期记忆**：个人偏好、项目工作记忆和正式知识分别处理，按需要召回并重验来源。

从 A 页面切到 B 后，B 成为下一轮可用的页面上下文，已经运行的 A 任务仍绑定 A。代词结合页面和对话理解；只有指代歧义会实质影响读取或修改目标时追问。界面轻量显示当前相关项目/对象，可纠正，但无需反复点击切换。每次实际工具调用由服务器固定范围与权限，不把模型输出的项目 ID 当授权。

长对话按任务保存可恢复摘要，保留目标、约束、精确对象/版本、已完成与未完成动作、来源和原始记录定位；业务事实重新读取，历史模型回答不当成事实或批准。固定 prompt/工具定义维持稳定，动态上下文追加至末尾。

## 4. 项目共享与自动记忆

新项目共享会话在输入区持续标明“项目成员可见”。共享包括原始聊天、项目附件、持续委托状态和项目工作记忆；既有私人会话与附件不因本次功能升级而追溯公开。

一个用户可以在连续交互中涉及 A、B 项目，但 A 项目成员不能借共享会话、附件、摘要、检索或记忆读到其无权访问的 B 内容。项目记忆按项目归属保存；跨项目内容按受众权限投影，无法安全拆分时不发布原始混合内容，并说明未共享的部分。项目共享空间使用对项目成员开放的材料；受限来源和个人记忆不自动提升为全项目可见。

自动记忆应保存来源、作者或生成主体、归属、时间、版本和有效性。成员可查阅、提出纠正或停止复用；冲突保留并列依据，正式业务记录优先，不能靠最后一次聊天静默改事实。成员退出项目后停止读取相关历史及记忆。

自动沉淀的是可追溯工作记忆；正式组织知识、Design Rule 和可信 golden 继续沿原发布/审核边界，不因记忆功能自动获批。

## 5. 持续委托与项目跟进

委托持久保存目标、项目/对象范围、发起人、责任人、可执行操作、检查条件、期限或结束条件、进度及停止状态。首次接受委托时用简短回执展示这些信息。支持调整、暂停、恢复和结束；恢复前重新鉴权，不用旧委托永久保留权限。

推荐生命周期：优先使用用户给出的期限或完成条件；没有期限时持续到用户停止或项目正式结束，期间保留预算与失能可见性。只有获授权的人可调整或结束委托，可见性不自动授予修改权。以上默认设计已随 Q16 获批；不代表真实委托已启用。

事件变化触发检查，定时检查补足无人更新的场景；具体截止点由调度器触发，不依赖聊天窗口。无变化不重复推理、重复询问或制造新记录。恢复事实到来后更新原跟进状态并取消过期催问，已发送历史保留。

首条闭环：项目内一句持续委托 → 来源更新/延期 → 影响核对 → 自动预测传播 → 风险预警 → 向负责人询问 → 读取回复及业务进展 → 未响应/未推进升级 → 每日项目摘要 → 有证据后结束该跟进。

### 5.1 延期传播

日期由现有确定性排程引擎按依赖、缓冲、工作日历和实际输入计算。只传播至受影响的后置节点；缓冲可吸收部分影响，无依赖任务不一律顺延。预计日期变化同时呈现旧值、新值、来源和影响路径。

Baseline、Commitment 与 Actual 不随 Forecast 自动改写，原承诺的逾期仍可见。新预计日期不能重置旧承诺对应的催办或升级时钟。未知剩余工期显示缺项，询问负责人或准备情景，不伪造精确日期。预测变化不等于已修改正式资源预约；冲突进入待处理结果。

### 5.2 主动询问与升级

站内询问关联真实任务/问题与本次委托，说明需要补充的进展、阻塞、预计完成或证据。合并同对象多来源询问，沿派发端静默时段、日额度、幂等和投递回执；不因投递失败归责负责人未回复。

“未回复”与“未推进”分别计时。已读或“收到”不等于业务推进；回复能结束未回复状态，但仍须跟踪约定检查点。业务进度必须由相关记录、交付或可核对说明支持；发现明确阻塞时升级请求协助，不继续机械催人。不单凭模型主观判定自动升级。

**现有实现事实（代码核查，非当前项目配置证明）**：默认到期前3天、前1天、当天、逾期1/3天提醒，逾期3天升级至项目负责人；项目模板可覆盖。问题分析/行动状态连续7天无更新提醒 Owner，当前以更新时间判断。组织汇报线存在，但现有到期提醒未接逐级上报。通用未回复计时和有效推进检查尚非现有能力。

**已批准的新委托默认规则**：询问送达后1个工作日未回复，升级至项目负责人；已回复则在约定的下一检查点核对推进，无检查点时建议下一工作日检查。关键交付风险即时预警。先沿已有项目负责人升级路径，不自行猜测更高层接收人；需要逐级上报时使用明确配置。旧到期SLA保持，同一事项的通知合并，不因新增规则重复催问。

### 5.3 每日项目摘要

摘要包含关键变化、最新预计排程及与承诺的差异、小Pai已完成事项、进行中事项、未完成及原因、待决定项、询问与升级状态，链接实际对象和来源。对原始问题持续未解决的情况不得因排程顺延而显示恢复正常。

推荐默认：按项目时区每日09:00生成一份站内共享摘要，时间可配置；项目时区缺失时须在委托配置中明确，不使用服务器时区暗中代替。无变化只给简短“无新增变化”，不重复制造待办。每日摘要订阅与紧急预警分开，站外发送沿独立授权。本段默认时间已随 Q16 获批。

## 6. 写入与既有合同

本访谈确认产品行为，不授予任何能力实际 T0 资格，不构成外部通道真实发送或生产部署授权。撤回沿单条/整次运行及后继引用守卫；人工已改内容不被后台自动覆盖。

## 8. 首条验收场景

| 场景 | 必须看到的结果 |
|---|---|
| 任意页面开启、侧边放大、刷新恢复 | 同一对话/委托/附件/结果连续；上下文自动带入 |
| A委托运行中切B继续交流 | A执行目标不漂移；B信息自然可用；不读取或发布越权内容 |
| 项目成员共同使用 | 新共享会话与记忆可见；个人/旧私人历史不公开；跨项目及撤权隔离 |
| 测试延期与后置依赖 | 按缓冲、日历传播；页面显示新排程及原因；原批准计划/承诺/实际值保持 |
| 无剩余工期或资源冲突 | 明示不可计算/待处理；不编造日期、不冒充已预约 |
| 主动询问后无人回复 | 依据送达时间及规则升级至正确接收人；投递失败单独报告 |
| 回复“收到”但未推进 | 进入后续检查，不能当作业务完成；有效阻塞升级请求协助 |
| 部分写入成功、部分受阻 | 分列已完成/进行中/未完成；原因及下一步明确；重试不重复写 |
| 关闭页面、重启、暂停及撤权 | 后台可恢复、暂停停止后续动作、重新鉴权、预算不重置 |
| 每日摘要 | 项目成员看到真实变化和未完成项；无变化不重复产生待办 |
| 来源纠正、冲突和记忆过期 | 可追溯、可纠正、停止复用旧事实；不把工作记忆当正式批准 |

实现验证按当前仓库节奏集中进行。数据库测试只用显式核对的独立临时 `TEST_DATABASE_URL`，不得使用存续联验库；真实模型资格与模拟验证分别报告。本文件记录批准的目标；实际实现、验证证据与未完成项见唯一清单。
