# S3 质量与迭代接续合同

本合同细化完整目标架构 v1.1 §04.13、§08.10、§09.2 路径 D、§09.6、附录 B AT-23/AT-24，并依据设计确认稿 P21 接续。S2 在候选 `3d6cb71` 已完成同一实际领域链的多批产出、分批接收、独立 Run 承诺/Start 和部分/最终结果功能检查；S1、S2 正式验收仍未完成，性能采样按 P13 暂缓。

## 本闭环结果

沿用实际测试 Run、原始读数和事件建立唯一失败 Issue，保留精确样件、配置、用途、来源、回执及责任人；在同一项目办理分诊、遏制、CAPA、根因和措施完成，读取实际后续输出。后续双线影响、正式变更、新配置、新 Run 与适用独立有效性仍须分别以真实领域记录贯通，不能以候选可读取或图存在代替完成。

## 分批测试与质量回链

- Run 固定其创建时的请求版本、计划、实际覆盖子集、样件、项和配置。该子集非空，属于当时已接收范围；同请求的其他 Run 或后续接收不扩大它。
- 原请求后续可继续接收已交接范围内尚未接收的样件。质量读取保留旧接收/退回记录和首个聚合时钟，不能把后续接收当成旧 Run 范围改写，也不能因此使整个质量跟进读取失败。
- 每个 Run 的承诺与实际 Start 取其自身不可变动作事实及实际共同回执；请求首个承诺/Start 不能冒充后续 Run 的事实。请求的结果与处置由实际领域服务按兄弟 Run 聚合。
- paired 纯结构校验只说明材料一致；实际当前指针、不可变动作事实、来源、用途、授权及回执仍由既有同事务 owner 校验，不能据此赋予业务批准或复验合格。
- 多个当前 Run 动作可以合法保留同一聚合请求版本；该 Formal 不能唯一代表某一个配对 Run 时，选项直接列各 Run 的精确当前输出。只有唯一配对事实的 Formal 才作为配对选项，显式读取歧义 Formal 仍拒绝；不按排序猜选，也不吞掉 owner 校验错误。
- 历史交接 offered 与聚合首 promise 保留在不可变快照并参与结构核对，但不重新当成本次动作消费；当前 Fact、Run、载荷的精确来源仍须完整，并由实际 owner 重核原件。对齐 v1.1 §08.11 最小必要来源读集，不补回整条历史读集来扩大当前依赖。

## 项目入口

质量与整改工作台从当前项目可读取的 Build 开始，随后才读取所选 Run、失败、Issue、变更和后续输出。草稿、旧预览及未知提交的恢复都绑定具名用户、型号和项目；不把全型号旧草稿迁入项目。服务器继续拥有权限和实际项目事实。

## 必要检查与剩余边界

使用显式临时 `pdos_test` 合成资料，经实际上传、解析、领域命令和共同回执验证：A 批失败建单去重后，B 批继续接收、独立计划/承诺/Start/结果；重新读取 A 的 Issue、根因、措施与精确后续输出，A/B 历史和来源均保留。集中执行受影响纯检查及同链 PostgreSQL/API 检查；不重复启动攻防或性能采样。

当前不含真实模型联验、真实客户资料出站、试点资格授予或生产启用。MiniMax 国内 M3 的协议、凭据、可外发资料范围与真实外发授权仍按 S1 记录处理；只暂停依赖部分。正式变更批准、独立有效性结论与阶段验收保留原有具名操作和验收标准。

## 正式变更准备接续

共享的 Issue/CAPA 由实际品类受众承接，读取当前 Issue 版本取真实 Current 的 `issue_revision`。保留私有记录的原受众，不通过改写旧记录来扩大访问。

政策由既有受控 host 出版端口登记，页面只读实际有效政策及缺项。逐项适用性源于已登记的专业原件，服务器核对其实际 Change、项目、CAPA 措施、执行人、范围、有效期和当前具名人，生成待 T2 决定的候选；读取候选不保存决定或授予资格。当前 Selection 及政策通过真实 owner 读取，失效或缺项保持明确状态。

用户选择实际具名 Selection 对应的计划项，逐对象填写影响处置、依据、关联项和原因，再通过 T1 实质预览与一次确认准备变更令。未填写的处置保持 unknown，不从图或文本猜测适用性，不自动把对象改成“无需变更”。此步允许形成等待批准的订单草稿；实际影响 unknown、工程/制造批准、新配置、实施、生效和复验仍各自办理。

页面提供当前项目的明确 Change 选择，草稿、预览及未知提交按用户、型号、项目和 Change 隔离。未知结果恢复沿用原 command/key/token；最终写入仍走现有具名 T2/T1 预备、共同消费与原子尾部。新增读取不作为新的权限事实或批准。

## 批准后的配置实施

v1.1 §04.13 的两条路径是业务示例。实际物料到工序关系须来自固定 BOM 行与工序的明确引用；缺关系仍未知。有原文依据的不适用须精确到对象、维度或后续目标组，保留理由与固定原文；实际关系与不适用冲突时保留缺项。v2 覆盖原文经既有可信出版与具名证明接入；v1 原文、固定图及其摘要保持原义，不根据阶段名称或查无记录自动补不适用。

工程与制造分别具名批准同一固定订单内容。实际配置输出由原领域命令保存，通过共同回执验证本人、固定前版、批准后保存时序和计划项，不能重用原配置冒充实施。每次实施登记保留批准图，重新遍历当前真实关系；旧节点、依赖边及完整 owner 依据须与原批准闭包一致，只接纳该计划的实际捕获输出及其明确工序/SOP子节点。新增输出不继承旧覆盖资格。

项目页面按当前 Change 与订单显示两专业的真实批准状态；具名人选择专业、填写意见和固定原文后，先读取 T2 实质预览，再由本人确认提交。未知结果保留原 command/key/token，由用户显式恢复同一次提交；切换人员、项目或 Change 不沿用旧预览。读取共享批准依据时仍使用当前读取人的事务身份，只核验可读共同回执的请求键绑定是否存在，不开放其他人的请求键内容。

原覆盖的发布证明与原依赖版本作为历史保留，实施时重新核对原件、当前权限、来源、可信出版人、固定用途和发布组；不把原依赖版本称为当前。新依赖版本在同事务读取前后受锁和守卫核对。任何不属于已验证输出的新增可达对象、旧关系变化、失效来源或隐藏依赖均阻止登记。失败与未知实施仍可如实记录，不据此宣布生效、复验或关闭。

实施页面从当前订单选择实际计划项与已登记原文整行，经服务器捕获核对实际输出，再由本人预览和确认保存。捕获成功只表示材料已保存；专业批准、原计划和正式实施记录分别显示。捕获重放沿用原请求标识，正式提交保留原 command/key/token；原件、版本或权限变化时保留待核对状态，不推断成功。当前候选支持系统内登记原文；上传附件的实施原件及跨续版未知捕获的独立读回仍待补齐。

本检查点只贯通双专业批准和真实新工程/制造配置的实施记录。新 Build、独立 Run、实际生效、适用独立验证和 S3 正式验收继续建设；不制造 PilotRun、ManufacturingRelease 或复验通过事实。

## 本人完成与新轮实物复测

具名根因在冻结本轮变更影响前记录。本人完成须有九字段实际发生原件，并绑定已保存的批准计划项实施原件及精确工程/制造输出；同一批次仍逐项核对原专业批准、执行人、来源、资格与当前状态。共享问题按实际品类受众保存，原件摘要与正式依据包内的 `artifacts` 层精确比较，整包的批准/领域证明保留。品质顶层 sources 仅列实际原文；变更图原生对象引用保留在实际实施版本、完整 owner 材料及其证明摘要内，投影前仍执行完整来源守卫与 read/refresh/attest。

新 Build 明确关联前轮并选择实际已保存的工程/制造新版本，重新登记实际配置、产出与样件。新的正式请求经过方法适用、实际样件方法和具名接收，再独立计划、承诺、开测并返回原值；后续链接固定新 Build 和新 Run 的不可变结果版本。测试人员与措施执行人分别具名，人员容量/日历声明有原件，经真实资源导入创建新镜像，不改旧 Run 的容量或占用。

本接续检查只记录措施完成、单独新轮实物与代码计算结果，保留旧失败与原窗口。适用性、观察期完成、独立有效性决定和 Issue 关闭仍分别建设与验证；不以测量通过替代它们，不制造生效或生产放行。

## 正式措施履行的实际读取

默认启动在既有实际适用性 owner 中装配正式变更措施履行端口。读取从精确的本人完成锚、原订单全部批准计划项及原 Selection 共同回执重建义务，再核对当前 Selection、双专业批准、实际实施原件和输出；不能只读已保存的分类或完成标签生成履行结论。原批准计划中的任何义务都不能因当前指针缺失而被忽略。read/refresh 保持同一实际事务、调用人、范围、原件及证明材料，只有完整重读一致才移除对应的待接线诊断。显式传入的复核 owner 保持原配置；默认启动不自动登记出版人、专业资格或试点资格。

已消费 T2 证明中的 expires_at 沿用共同层真实可空值；仅真实存在截止时间时检查决定发生在期限前。当前资格、本人、用途、范围、材料摘要、共同消费、时序与来源不因此省略，不另加固定批准时限。

本接续仅验证已完成的正式措施可被独立读取为履行输入，并保留后续完整观察与有效性链的缺项。Rule 使用新样件的实际身份与固定方法/判据，原一天观察窗口不变；本轮不创建观察、独立有效性结论或关闭。
