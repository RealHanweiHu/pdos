## 1. 设计系统 Token

| 类别 | 定义 |
|---|---|
| 字体 | UI 与正文 **Geist**；编号/数值/证据指针/代码 **Geist Mono**（next/font 自托管） |
| 字号 | 产品面板基准 13px；正文 14px；页标题 18px semibold；显示数值 24-28px mono |
| 中性色 | zinc 族。亮：bg `#fafafa` / surface `#ffffff` / border `#e4e4e7` / text `#18181b`；暗：bg `#101214` / surface `#17191c` / border `#26282c` / text `#e4e4e7`（禁纯黑纯白） |
| 强调色（唯一） | **公司主题橙**。交互主色 `#c2410c`（亮，AA 达标；纯橙 #ea580c 对比度不足只作大面积展示不作文字）/ `#fb923c`（暗）；全站锁定，不出现第二强调色 |
| 状态语义色 | pending **纯黄**（`#a16207`，因强调色为橙，待审状态从琥珀移到黄避免混淆）/ accepted 绿 / rejected 玫红 / applied 蓝 / blocked 灰。仅用于状态，不作装饰 |
| 圆角 | **全站 8px 单一体系**；筛选 chip 用 full-pill（这是文档化的双规则，除此再无第三种） |
| 间距 | 4px 网格；面板内边距 16；区块间 24；页面留白 32 |
| 阴影 | 仅浮层（弹窗/下拉）用；卡片分组优先 border + 留白，不堆卡片 |
| 主题 | 双主题跟随系统 + 手动切换；语义 token（`--surface/--text/--accent`）CSS 变量策略，section 不得反转主题 |
| 动效 | 150-200ms ease-out，仅限：hover/active 反馈（`active:scale-[0.98]`）、面板切换、toast。无循环动效、无滚动劫持 |
| 图标 | Phosphor（`@phosphor-icons/react`），线性图标统一 `weight="regular"`，状态强调可用 `fill`，单一族；Server Component 从 `/ssr` 子路径导入 |

## 2. 信息架构（导航树定稿）

```
① 全局域导航（十项，D31 上层）
Home 工作台            驾驶舱（管理层视角落地页）/ 我的工作
Portfolio 项目组合      组合与阻塞（V3 接入管理层看板：决策请求中心 + 全项目进度）
Products 产品          需求池 / 开发案例
Projects 项目          项目工作区（内含下层九标签）
Engineering 工程       工程·变更
Quality 质量           试制·测试·质量
Delivery 交付          Gate·交付物 / 钉钉集成
Knowledge 知识         知识库
AI Workbench AI 工作台  统一对话与会话历史 / Review 收件箱（集中人审队列）/ AI 治理
Admin 管理             事件流 / 模型治理 / 成员与角色 / 组织与代理 / 账户安全

② 历史九业务域划分（D9；当前界面入口由v0.6.3及§3.3组织）
概览·控制塔 | 计划·资源 | 工作项 | 物料·供应 | 工程·变更 | 例会·决策 | Gate·交付物 | 试制·测试·质量 | 文档·知识
```

**入口与兼容**：工作项合并原任务/问题/风险并依真实对象或旧标签定位类型，产品工程保留工程域。旧时间线入口转项目阶段，带事件定位的链接仍回总览；旧项目AI对话链接保留原会话查看入口。书签、钉钉卡片与历史证据的对象选择器保持，未知标签不猜测。后台能力不逐项成为入口，未实现能力不以空白页、假进度或虚构自动结果冒充可用。

规则：左侧固定侧栏 224px（可折叠 56px 图标态），顶部工作区内页签，**层级最深两级**；外部角色（客户/供应商）只见被授权项目的受限视图，无工程师工作区与治理入口。

## 3. 三个承重界面的交互定义

### 3.0 统一对话入口（v0.4增量）

Home保留本人工作并提供直接输入框，全局入口随处唤起；完整会话位于AI Workbench，对象页侧面板使用同一会话。输入框支持文字、选择/拖放文件与`@`对象，展示当前上下文、逐附件状态；刷新返回可续问。消息流呈现有来源答案、字段映射/差异、必要补充、审阅动作和实际结果。320px使用完整会话布局及可展开引用/预览，桌面可用侧面板。

对话内复用Review详情与相同接口，Inbox保留集中队列；各入口共用唯一Finding状态、审计和接受/独立应用动作。原“唯一入口”按当前用户要求更新为同一裁决真值的多个呈现入口，不另造审批流程。只读问答直接显示答案，专用原值导入沿原确认规则；上传、解析、候选、正式录入分别标状态，普通“好的”不替代明确动作。专业页、旧深链及零导航本人工作保持可用。

### 3.1 AI Review 收件箱（决定北极星接受率的界面）

- **双栏**：左=队列（288px），右=详情。队列行含：Agent 徽标、标题、项目、置信度、时间；未读实心点（语义性）。
- **过滤 chip**：全部 / 风险建议 / 阻塞预警 / Gate 异常 / 知识草稿；同类 finding 折叠合并显示条数。
- **详情结构**（自上而下）：标题与触发链（事件→Agent→run 可展开）→ **建议内容 diff 视图**（AI 建议字段 vs 现状，逐字段）→ **证据引用列表**（每条一键跳源：事件/文档段落/记录），无据字段显式标"无引用"。
- **三键裁决**：`接受建议`（公司橙主按钮）/ `修改后接受`（进入行内编辑再确认）/ `拒绝`（必选原因：不准确/重复/不相关/证据不足）。键盘 A / E / R，j/k 换行——目标单条裁决 < 30 秒。
- **接受与应用分离**：裁决只把 finding 变为 `accepted`，不写业务对象；accepted 详情页再提供独立的 `应用到业务对象` 动作，点击后重新鉴权、展示最终写入预览，由服务端按数据库真值复核后才变为 `applied`。UI 不得出现一步完成 accepted→applied 的按钮。
- **裁决后**：pending 队列乐观移除 + toast 撤销（5s）；accepted 进入“待应用”视图；接受率遥测在页头常驻（本周接受率、待办数）。
- **状态**：清零态（正向插画+"Agent 正在值守"文案）；加载=骨架行；失败=行内重试。

### 3.2 驾驶舱 Dashboard

- **三区**：① Portfolio 项目卡网格（阶段 chip EVT/DVT/PVT、Gate 就绪度、健康色点=语义）② 风险榜（跨项目 Top，按暴露度排序）③ **AI 简报卡**（汇报员产物：3-5 条结论，每条尾部引用角标可跳，底部唯一 CTA「去收件箱处理 N 条」）。
- 拆除测试可见性：LLM 关闭时 AI 简报卡显示降级态（"AI 暂停，最近简报为 X 日前"），不隐藏。

### 3.3 项目工作区

- **页头**：项目名、编号、真实状态与当前阶段；切换项目及项目设置，不以阶段位置推算完成百分比。
- **主要入口**：登录身份自动组织主角色工作，管理员保存的兼任模块同时加入本人首页与常用导航；项目按主角色或已配置模块链接呈现六个常用领域，当前正在办理的其他领域也保持选中入口；“更多项目工作”可进入其余已授权领域。新选择项目进入该视角的实际专业工作，显式路由和旧记录选择器优先。专业页面以任务导航与单一办理区承接现有领域动作，切换不丢任务草稿；后台能力不逐一占据主菜单。
- **总览**：项目摘要、真实日期与工作计数、最多6项待推进记录、最近6条业务变化。事项直接打开对应清单与记录；后台提醒记账默认归入完整历史，显式事件链接仍可定位。
- **项目阶段**：独立入口，按真实阶段及工作归属展示泳道；推进操作保留原条件。静态指南不进入日常工作面，阶段要求应落到真实工作项、交付检查和评审缺项。
- **工作清单**：任务、问题、风险按类型切换；新建表单按需打开，来源、关联及模板办理在具体记录详情中展示。证据、验证与具名批准仍由原办理动作承接。
- **AI**：全局小Pai作为个人对话入口，自动接当前页面上下文。总览不再嵌入重复聊天或手动经验检索面板；来源与实际结果跟随对话或事项，未完成的上下文/执行链明确区分。

## 4. 反模式清单（本产品专属）

- 收件箱不做全自动批量接受（一键全收=北极星作弊）；
- 状态色不作装饰用；一个界面强调色只有公司橙；
- 不用卡片套卡片，分组优先 border-t/留白；
- 数字一律 Geist Mono，右对齐可比列；
- AI 产出的任何展示必须携带证据入口，无引用即标注，禁止"裸结论"UI。
