# S5 项目行动、个人承诺与成果验收接续

依据 v1.1 §02 的项目与工作对象、§03.3/5/6 的任务状态和四时间、§05 的项目/个人工作入口、附录 A 的任务/分派/承诺操作，及确认稿 P18/P19/P21，在已满足前置的项目工作范围内续建。本合同只细化实施，S1 未验收、P13 性能暂缓及 S3 一天观察保持；不宣称 S5 正式验收或生产启用。

从已登记会议原件、项目待决资料或制造/交付记录的原文，显式创建有目标和结果要求的任务。任务可以固定引用既有计划任务，但不修改计划快照、预测或批准基线。分派明确受派人及成果接收人；受派人本人接受责任后，仍未产生日期承诺。本人可就具体结果范围，对不同接收者分别作出承诺；未知时间保留 null，续版必须精确替代本人的同接收者当前承诺。保存 UTC、原始时区和实际已绑定的日历引用；无日历 owner 时明确未知或拒绝未绑定引用。

任务按 proposed→assigned→accepted→in_progress→submitted→completed 办理。实际开始、成果提交与具名接收验收分别记录；退回追加原文理由及逐项结果，任务回到进行中，原提交/验收历史保留。完成必须由已指定的成果接收者确认必需结果，缺失、部分或未知不冒充完成；不因此为全部简单任务增加通用第二人审批。分派人不替受派人承接，提交人不替成果接收者验收。

任务和承诺以不可变事实、精确版本及 Current 办理。来源原行、项目受众、当前成员与实际办理人由服务器核对，模型不能提供权限事实；T0 仍由既有资格/当前授权/注册执行图控制，AI 不取得正式人员身份。T1 沿共同预览、本人一次确认、幂等、Receipt/Audit/Outbox 与原子回滚；响应未知保存原请求，刷新不自动再写，显式重放才核对同一提交。

具名项目状态更新按 P18 只追加事实摘要、下一步和明确选择的任务固定版本，不改变任何任务、基线、预测、承诺、实际或批准；不自动建任务/注意项。项目工作页显示实际任务和成果，个人入口按当前可读范围展示本人待承接、待验收、任务与对各接收者的当前承诺。不同接收者的数据永不合并。

个人队列使用本人普通只读快照跨品类分页：待承接仅包括当前指派给本人的 assigned；待验收仅包括本人为指定成果接收人的 submitted；本人任务包括 accepted/in_progress/submitted。当前承诺逐接收者展示固定承诺版本与任务当前状态，日期状态只表示时间比较。承诺履行独立保存：原接收者本人通过辅助 T1 `work.commitment.review` 核对当前固定承诺、当前任务版本及承诺人真实 submit 事实。逐项覆盖全部已承诺成果（含可选项），实际 present 且全部核对接收才形成 fulfilled；退回保留 open 与历史。任务 completed 不自动履行承诺，完整任务验收也不是独立承诺履行的前置。承诺续版重新 open，旧版履行历史保留；本人待办仅排除精确当前承诺版已有 fulfilled 的事项。服务器登记核对时刻，不推断或补造实际完成日期，不改承诺原文、日期或任务状态。项目列表、经营总览及单项目摘要批量读取真实最新具名更新，保留作者、时间、回执和固定任务引用，不重读历史正文或改写领域事实。

主操作保留 `work.task.create`（T0）、`work.task.assign`（T1）、`work.commitment.accept`（T1）、`work.status_update.create`（P18，T1）；具体人工办理叶操作为 `work.task.accept/start/submit/review`、`work.commitment.review`（T1），作为辅助目录细化任务状态，不新增 T2、资格授予或额外时限。

以一个实际合成闭环统一验证：两位本人分派/承接、无日期与多接收者承诺、部分成果退回后再提交验收、具名周报引用、原请求恢复，以及版本、来源、失权和原子尾部失败。迁移由主会话核对真实 head 后单调分配；不反复执行无变化攻防，不调用真实模型或外发。覆盖以 AT-34 为主，涉及 AT-19/33/40/45/46/49 的实际路径按证据登记，正式出口不由本合同代替。

项目动态直接投影当前本人可读的固定项目事实及实际共同回执/主Outbox事件；不新增Activity真相表、不按同型号推断私人Run或会话、不重复计算子事实，也不把计算返回写成通过。具名更新与小Pai实际领域动作使用同一事件格式，保留actor/requester、版本、登记与实际发生时间及来源引用。游标固定本人/品类/型号/项目与读取水位，每页重核实际可见锚点；刷新/失权清旧资料，工作区链接不冒充固定记录详情。领域自身私有和上游来源RLS仍生效，回执布尔证明以app INVOKER读取实际来源及项目，不能改用owner内部宽读。

承诺相对触发消费精确当前版本的独立履行：fulfilled优先于未知日期及另行Task等待条件持久停止；returned/open继续。已排队旧版本在实际Run受理前由Category锁内SQL守卫抑制，实际已受理Run历史不回滚；承诺续版不自动恢复已停止的服务授权。保留用户明确的Task终态停止条件与既有预算、冷却、过期和范围守卫，不新增模型调用、写权限或真实外发授权。
