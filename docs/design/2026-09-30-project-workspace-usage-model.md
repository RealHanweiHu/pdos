# 项目工作区使用模型 · 2026-09-30

用户要求沿项目管理软件的使用逻辑重设计工作区：系统自动处理的能力不逐一成为菜单，用户关注项目进展、具体工作、交付结果及需要自己决定的事项。延续已采用的 Linear 视觉、独立项目阶段和全局个人 Agent 小Pai；本记录调整展示与交互组织，不授予新的 AI 写入资格。

## 日常路径

进入项目先看到目标、真实日期、未完成工作和近期业务变化。点击事项直接打开对应任务、问题或风险，沿其状态办理；从阶段泳道进入也自动定位记录类型。专业人员从工作项进入工程变更、试制测试质量或物料供应。计划用于排期与资源安排，评审与交付用于补缺项、签核和核对结果，资料与协作用于项目文件、例会及决策。低频成员权限、流程维护、报告导出和接口配置进入项目设置。

主要入口为：总览、项目阶段、工作项、计划、评审与交付、资料与协作。工作项内切换任务／问题／风险，一次显示一个清单。新建表单按需展开，问题和风险的来源、关联、模板办理与质量材料在具体记录详情中展示，原状态动作、证据要求与独立验证保留。

小Pai从全局入口打开。项目总览不再嵌入第二套聊天或经验检索面板；旧项目会话链接仍可查看原会话，不能因导航简化将共享记录改成私人对话。阶段页不再放独立指南；阶段要求须逐步进入真实工作项、交付检查和评审缺项，静态指南不能冒充已实例化任务。

## 隐式能力与可见结果

下表是后续能力接入的使用规则，不能据此宣称所有自动化已实现。

| 场景 | 系统处理 | 用户可见内容与必要动作 |
|---|---|---|
| 从页面打开小Pai | 绑定当前页面／项目／记录范围，按权限准备上下文 | 对话及必要来源说明，不要求先选项目或启动上下文采集 |
| 提供文件或指令 | 提取文件、关联原件、在已获资格与授权内调度 | 处理结果、相关记录；无法读取／归属不明／权限不足时才要求补充 |
| 推进任务 | 核对依赖、更新就绪状态、保留实际进度 | 等待前置、阻塞原因、下一步动作，不让用户手动运行依赖检查 |
| 出现异常 | 按事件、真实资格和写入分级准备建议或执行受控动作 | 已有问题／待确认建议／运行失败；不把生成器、重试器做成常用菜单 |
| 核对评审交付 | 汇集当前材料、版本、缺项及相关责任 | 缺项、证据、具名签核与正式批准，T2 保持人工边界 |
| 经验与跟进 | 按实际可用能力检索经验、安排提醒、持续跟踪 | 引用、业务变化及需处理事项；后台提醒重排／已读记录归入历史 |

正常成功的准备、校验、检索和记账不形成独立操作步骤。自动产生的业务结果保留入口和来源；失败、冲突、权限变化、需要判断或批准时，在对应事项显示原因与可执行动作。隐藏内部模块不能替代实现自动触发、完成回执、失败恢复或权限控制。

## 本次实现与剩余边界

本次实现六入口及上下文子视图、设置入口、总览真实待推进事项、按记录定位的清单与详情、后台提醒记录的默认过滤。移除总览的辅助查阅与重复聊天，以及阶段页的静态指南；历史动态、原专业页面、会话及事项回执保留。外部成员仍只见授权概览、阶段和原有服务范围。

本次没有改后端自动化、模型资格、业务写入分级、具名签核或数据模型。当前非项目持久对话、文件与统一执行调度的缺口继续按[小Pai设计与实现核对](../reports/evidence/xiaopai-personal-ui-20260930/design-alignment.md)处理；阶段要求的真实实例化和专业页面内的进一步流程整合，继续按对应 N 项实现，不能以本次 UI 收起入口视为完成。

验证与候选范围见[使用流程检查点](../reports/evidence/project-workspace-ui-20260930/usage-flow/result.md)。本记录服从 [DC-13](2026-09-28-pdos-design-direction-integration.md)、原领域合同及现行 T0/T1/T2 政策，不改变原 N/P/Q 验收。
