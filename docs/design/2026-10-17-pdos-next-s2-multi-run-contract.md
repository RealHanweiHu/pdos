# S2 分批接收与多 Run 接续合同

依据为已冻结的[完整目标架构 v1.1](2026-10-08-pdos-complete-target-architecture-v1.1.md) §02.6–7、§04 的品质交接与验证、§08 的事务/时钟规则及附录 B 的 AT-07/08/11–15，以及[确认稿 P13](2026-10-08-pdos-next-design-confirmation.md#p13-暂缓性能验收并提前恢复-s2用户-2026-10-17)。用户授权先恢复 S2，S1 保持未验收，性能验收暂缓。本文细化既有测试请求与 TestRun，不新增业务实体或阶段批准。

同一正式请求可分次接收尚未接受的样件/测试项。已计划、已开始或已有部分结果时，后续接收与退缺项沿原请求追加版本，保留首个接收、承诺、开测和初步结果时钟；不重写已有 Run 的对象、配置、方法、计划或结果。每个 Run 的明确非空覆盖范围须属于已实际接收范围，测试资源事实精确绑定这部分范围。请求剩余缺口继续可见。

每个 Run 单独计划和具名承诺，实际开始须消费本 Run、版本与计划摘要对应的真实承诺事实，不能借用同请求其他 Run 的承诺。计划与承诺无资源/样件消费，实际开测继续同事务登记资源占用和样件使用，保留设备/校准、执行资格、破坏性冲突、来源、版本、确认和重放守卫。请求级首个承诺时钟只表达请求里程碑，逐 Run 承诺从实际保存的办理事实读取。

结果仍经原件字节核对、固定 Run 对象/配置、实测原值和确定性判定办理。请求父指针统一串行化接收、开测与结果写入，聚合时只读取同请求每个 Run 的当前版本，不重复累计历史版本。全部实际交样范围已接收且测试结果覆盖所需范围后才记录请求最终返回；专业结论、处置按各 Run 具名办理，请求处置按现有领域核规则汇总。非结果命令须逐值保留前版结果时钟，数据库 INSERT 守卫同步约束。

页面显式选择 Run，查看旧 Run 时仍可准备另一个明确范围的新计划。计划草稿按请求保存，承诺/开测草稿和来源按 Build × 请求 × Run 保存；结果未知的提交保留原命令、标识、载荷和令牌，不自动提交或移给其他 Run。旧本机草稿仅在原来已有明确 Run 身份时恢复该 Run 的编辑内容。

迁移从真实 `s0_0772` 单调续建 `s0_0773`–`s0_0774`，移除请求级单 Run 唯一限制，保留 Run 身份/版本和全部范围外键；测试资源父版允许已接收、已排期与测试中，继续核对精确请求版、Run、用途及资源事实前后版。回退遇到多 Run、部分范围或高级交接/承诺历史时须先拒绝，不删除历史。S3 配对消费者按实际输出事实精确定位 Run；其既有配对合同对多 Run 部分范围仍明确拒绝，本批不开放 S3 配对能力。

验证聚焦同候选的真实合成 API/事务链、不可伪造结果时钟、Run 承诺隔离、旧 Run/消费证明保真、必要并发/原子性和前端草稿恢复。合成专业事实不代表真实制造、专业资格或人工验收；无真实模型、业务资料外发、生产或 push。进度与实际结果登记于[唯一清单](../../tasks/ai-native-integrated-todo.md#current-queue)。
