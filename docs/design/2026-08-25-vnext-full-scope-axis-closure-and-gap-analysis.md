## 1. D33 交付模式声明：全量范围，不做 MVP

用户决策：**不做 MVP，尽可能一次性完善功能。**正确的工程表述是：

- **范围一次冻结**：本文档确认的十条功能轴、全部对象与闭环边，全部进入 vNext 范围，不做"首版砍掉、以后再说"的功能裁剪。此前的 MVP 化条目全部撤销：I1（Phase 5 收敛为最小链）撤销、V3-1 首发只开 FS 依赖的限制撤销（FS/SS/FF/SF + 日历 + 跨项目一次建全）、V5-3"首版最小链到此"撤销。
- **交付分轨并行，验收持续进行**：不做 MVP ≠ 不排顺序。数据骨架仍必须先于依赖它的智能层（没有结构化 Test 就没有可辩论的证据），但各轨最大化并行，且每条轴按"垂直切片全量完成"验收，而不是按"先做薄版"验收。
- **诚实的风险声明**（记录在案，供 PO 知情）：全量交付的代价是首个可用版本时间后移、集成风险后置。缓解手段是第 2 节的轴级闭环验收（每条轴独立可验收、可试点）+ Pilot 项目全程陪跑，而不是砍范围。

## 2. 十条功能轴闭环确认

每条轴按统一模式确认：`入口（事件/数据）→ 对象链 → 确定性引擎 → Agent 介入 → 人的动作（按 D32 三级授权）→ 出口 → 回链（闭环边）`。**断点检查**列出计划中缺失或薄弱的闭环边，全部补入执行清单（第 6 节映射）。

### 轴 1：个人工作与问题追责

- **闭环**：事件/会议/测试失败/短缺 → 草稿 Issue（Agent 自由区直落）→ 分派（Owner/Verifier/关闭条件）→ 行动（Action 带来源对象）→ 提交验证 → 独立确认/退回 → 关闭（高/严重硬闸四眼）→ Knowledge Candidate 自动生成 → 提醒/升级全程伴随。
- **引擎**：提醒 SLA、逾期扫描、升级链、停滞检测。Agent：发现异常、起草、解释退回、相似问题检索。
- **断点检查**：✅ 主链完整。⚠️ 补两条边：(a) **确认疲劳治理**——D32 自由区放开后 Agent 会大量落草稿，必须有 Review Inbox 的 digest/优先级/批量确认/草稿 TTL 自动过期，否则"人被草稿淹没"会杀死整个采纳率（→ 新任务 V1-A10）；(b) **代理与交接**——Owner 休假/离职时的委托与批量移交，制造业现场高频场景（→ V1-A11）。

### 轴 2：会议与决策

- **闭环**：会前例外自动装配 → 议程 → 转写 → Minutes/候选提案（引用片段）→ 批量确认（涉硬闸对象逐项）→ Decision/Action 落对象 → 下次会议自动复查 → 未闭项升级。
- **断点检查**：✅ 完整。⚠️ 补：会议决议若触发硬闸动作（如重基线），Decision 对象与硬闸流程的衔接要显式（Decision 记录"待执行硬闸动作"状态，执行后回写）。

### 轴 3：时间与延期传播

- **闭环**：任务/测试/短缺事件 → 依赖传播（FS/SS/FF/SF + lag + 日历，含跨项目，一次建全）→ Forecast 自动更新 → 影响路径可视 → 恢复场景对比（辩论可介入）→ 人审重基线（硬闸）→ Commitment 另行确认 → 兑现率回测校准。
- **断点检查**：✅ 完整。⚠️ 补：**预测校准回路**前移——Forecast 误差从 Phase 3 上线即开始采集，不等 Phase 6（否则校准无历史数据）。

### 轴 4：物料与供应

- **闭环**：Build 冻结 BOM snapshot → 物料需求 → ERP as-of snapshot → 齐套/短缺 → Material Exception → Issue/会议/Gate 阻断 → 催交/替代（辩论席位）→ 供给恢复 → 齐套回升。
- **断点检查**：✅ 完整。⚠️ 补：**供应商打样轮次管理**——EVT/DVT 各轮打样的批次、交期承诺与实际、良率记录，是硬件项目经理的日常主战场，两来源都只隐含在 Build 里（→ V4-12 样机资产与批次）。

### 轴 5：工程变更

- **闭环**：Issue/成本/供应商动因 → ECR（Why/What/Options）→ 辩论（结构/硬件/DQE/项目经理/产品经理席位）→ Decision Brief → 人批 ECN（硬闸）→ Impact Graph → Retest/Re-review/Re-cert 清单 → 执行验证 → 影响关闭。
- **断点检查**：⚠️ **重大盲区：需求级变更缺失**。ECR/ECN 只覆盖工程变更；**客户需求变更**（客户改规格、改交期、改认证市场）是另一条高频链：Customer Change Request → 受影响 Requirement/Spec/Test/成本/排期分析 → 报价/交期回复 → 客户确认 → 内部 ECR 联动。两来源文档都没有这条链（→ 新任务 V1-B8）。

### 轴 6：测试与验证（数字链核心轴）

- **闭环**：Spec（Verification Method）→ Test Plan/Case → 排测（实验室/设备资源）→ Test Run（结构化 + Sample Configuration）→ 失败自动 Issue → 变更后 Impact Graph 生成重测 → Coverage 回升 → Gate 证据。
- **断点检查**：⚠️ 补三条：(a) **测试数据低摩擦入口**——按 D36：工程师照常产 Excel，AI 解析填充为结构化 Test Run 草稿、人批量确认，"结构化测试率 ≥80%"靠 AI 导入而非人肉重录（→ V1-B10，提前至 Phase 1；设备直采延后）；(b) **实验室排队与设备占用**——测试资源预约是排期真实瓶颈，应并入 V6 Resource 而不是只管人（V6-1 已含实验室，确认覆盖测试设备台架）；(c) **样机建档闭环**——按 D37 以整机测试报告为准：AI 抽取样机编号/配置/批次自动建档，无条码扫码与位置管理（→ V1-B2/V4-12）。

### 轴 7：质量与可靠性

- **闭环**：Defect/Failure（含 RMA/field failure 回流）→ Containment → Root Cause → CAPA → Verification → Prevention → Living FMEA 回写 → Design Rule 更新 → 下项目复用。
- **断点检查**：✅ 链完整。⚠️ 补：**8D/DFMEA 客户格式导出**——品质团队对客户的交付物是 8D 报告和 FMEA 表格，系统内闭环若不能一键出客户格式文档，团队会退回 Excel 双轨维护（→ V6-8 报表中心）。

### 轴 8：产品管理（市场 → 定义 → IPD）

- **闭环**：agent-reach 持续采集 → 证据 → 竞品/市场/JTBD 分析 → 机会树 → 实验（VUVF 假设验证/证伪）→ 策略/定义版本化发布（产品经理审）→ 候选 Requirement → DCP/TR → IPD 立项 → 上市后质量/服务/实验结果回链假设。
- **断点检查**：✅ 完整（V5-11 回链已建）。范围按 D33 全量：12 个任务不再收敛，竞品/细分/机会树/策略/定义/矩阵并行建设。⚠️ 补：**定价与成本轴衔接**——产品定义的目标成本/价格带要与轴 9 的 Design-to-Cost 双向：BOM 成本超标自动回告产品经理席位（定义假设受威胁）。

### 轴 9：成本（Design-to-Cost）

- **闭环**：Target Cost（来自产品定义）→ 分解到子系统/模块 → Current Estimate（BOM 滚算）→ Supplier Quote → Cost Gap 与 Top Drivers → 超标触发 Issue/Decision/辩论（产品经理 vs 硬件/结构席位的真实博弈场）→ 降本方案 → Frozen Cost → 量产成本回测。
- **断点检查**：⚠️ 此轴在两来源中被拆散（B 的 5.12 + A 的矩阵评分），此处确认为独立轴：**成本目标分解**（Target 逐级分解到子系统）与**汇率/多币种**（海外供应商报价）需要补合同（→ V4-14）。

### 轴 10：知识与组织记忆

- **闭环**：Issue 关闭/Decision/Test Review/复盘 → Knowledge Candidate 自动生成 → 确认区发布 → 分类（Design Rule/Failure Case/Supplier Experience/Benchmark）→ 检索进 Agent context（verified 才可用）→ **主动推送**（新项目 kickoff、新 ECR、新选型时自动检索相似历史并推送到现场）→ 引用计数 → 过期/冲突提醒 → 复核。
- **断点检查**：⚠️ **主动推送边缺失**——两来源都只有"可检索"，没有"在正确时机自动出现"。知识复用率指标要靠推送边成立：新项目立项时自动比对相似项目/失败案例/供应商历史（→ V1-B9）。项目**复盘（post-mortem）模板**也未显式列入会议模板（V2-2 已含试制复盘，确认扩展为项目级复盘）。

## 4. 人机交互体验合同（UX1-UX10，作为各 Phase 验收硬条款）

1. **UX1 零点击开工**：登录即见"今天由我负责什么"，不需要任何导航动作（V1-A3 已有，升为全局验收）。
2. **UX2 三击确认**：确认区任何单项操作 ≤3 次点击；同类草稿支持全选批量；批量确认前有 diff 预览。
3. **UX3 确认疲劳防线**：Review Inbox 按优先级/对象/席位聚合成 digest；草稿态对象有质量分排序与 TTL 自动过期（默认 14 天未理会自动归档，可恢复）；每日推送上限与静默时段。**这是 D32 放开自由区后的第一体验风险。**
4. **UX4 一键跳源**：任何 AI 结论/健康度/风险/辩论论点，点击即达证据对象或快照原文，无死链。
5. **UX5 可撤销可见**：确认区动作完成后显示撤销入口（含批量撤销）；撤销窗口与留痕规则统一。
6. **UX6 移动现场优先**：Issue 快速记录、测试拍照、待办确认三个场景在手机端一等公民；320px 可用（DoD 已有分辨率门槛，补场景清单）。
7. **UX7 辩论呈现**：辩论异步执行，结束后推送 Decision Brief 摘要；用户可展开完整 transcript 回放（席位/轮次/引用可视化）；进行中可"观战"但不阻塞用户其他操作；用户可随时插入人工意见成为辩论输入。
8. **UX8 AI 失能显式**：每个 AI 触点在停 LLM/超预算时显示明确失能态与人工替代路径，绝不静默消失（G24）。
9. **UX9 录入即产出**：任何一次录入（测试上传、会议、Issue 更新）必须至少自动产生一个下游价值（状态聚合/提醒/知识候选），用户可感知"系统在替我干活"；禁止出现"录入只是为了汇报"的字段。
10. **UX10 性能预算**：My Work/项目概览/Review Inbox 首屏 <1.5s（P95）；辩论/深度分析异步化，不阻塞前台。
