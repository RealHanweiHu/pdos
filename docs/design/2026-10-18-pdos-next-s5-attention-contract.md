# S5 · 当前注意项与个人分诊

依据冻结 v1.1 §02.11、§05.2–05.3 与确认稿 P19，细化已有只读投影，不改变阶段出口或业务权限。

`GET /v1/personal/attention` 在本人普通 RLS、单次只读 RR 事务中，按 `decide / receive / verify / external` 分页。没有 AttentionItem 业务表、存储待办状态或后台复制任务。来源办理仍走原领域入口。

| 分组 | 当前事实与本人关系 | 自动更新依据 |
|---|---|---|
| 要我决定 | 当前提案固定提交的具名审阅人；尚无本次提交的决定 | 原决定完成即离队；续提更新固定提交与水位 |
| 要我接收 | 当前 assigned 任务的承接人 | 本人承接后转入原“我的任务” |
| 要我接收 | 当前交样退缺项、部分测试结果的具名下一负责人 | 对每个样件/测试项先取最新分派，再筛本人；后续接收或实际测量覆盖后移除 |
| 要我验证 | 当前 submitted 任务的成果接收人 | 验收或退回后离开当前成果验收项 |
| 要我验证 | 当前独立承诺的接收人；承诺人具有对应实际提交且履行仍 open | 仅该固定承诺履行确认后离队；Task.completed 不替代独立履行 |
| 等外部回复 | 原移交负责人、已有实际阶段回执、发送/接收/生效尚未齐全 | 一移交一项、三阶段分别显示；未知、部分、拒绝、失败和冲突保留，三阶段成功才离队 |

只有授权意图、零回执的移交不作为已发送等待。只有接收或生效回执仍不能推定发送成功；保留“发送状态未核实”的原卡标记。不新增默认期限、催办时钟或自动重发。

每项保留稳定来源 ID、固定版本、实际水位、记录时点、当前责任、本人原因和原对象入口。期限与有效期只使用原事实；办理授权有效期不冒充资料期限。页面按钮仅查看原提案/原项目，实际办理资格、来源与版本仍在原页核对。阻塞在卡内呈现，不成为第五种动作分组。

稳定键为 `kind:logical_source_id`，续版更新同项。游标绑定当前租户、本人、分组及来源水位；当前来源已变、办结、转派或失权时要求刷新，不沿用旧分页位置。数量和列表来自相同快照，读取失败显示未知；客户端身份或 API 变化立即隐去旧读数，失权清除已读页。

“我的任务”“我作出的承诺”继续独立。暂停 Run 仅标记“运行需查看”，不能把缺模型、结果未知等全部标为等待本人答复，也不自动共享私人会话。

当前未将缺具名接收/审批责任的发布、变更、专业接收，或未核对实时领域能力的品质/CAPA 状态推成人工待办。通用 ExternalWait 及 G0 ProjectOpenItem 处置命令仍需建设；本投影不替代这些生命周期，也不宣称完整分诊或 S5 正式验收完成。
