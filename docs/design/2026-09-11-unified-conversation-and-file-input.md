## 1. 产品定位

统一对话暂称“Ask PDOS”，是日常工作的主要交互入口之一。用户描述目标、上传资料、补充或纠正信息，由系统查证、组织资料并调用已就绪的领域能力。用户不必先选择Agent或学会数据库对象名称。Home同时保留本人可办理工作，项目表格、计划及专业页面承载详细查看和操作。

贯通体验为：**说清目标或上传文件 → AI识别内容和归属 → 只补充必要缺项 → 展示答案或录入预览 → 按适用流程办理 → 回到同一对话查看实际结果与后续影响。**

上传资料可以仅用于阅读、比较或提问；只有用户表达录入/更新意图时，才准备相应业务输入。文件已上传、内容已抽取、候选已准备、正式数据已录入、实际工作已完成必须分别显示。

## 2. 一个会话，多处入口

| 入口或交互 | 必需行为 |
|---|---|
| Home与全局入口 | Home有直接输入框；全局按钮/快捷操作随处打开对话，不增加第十一业务域 |
| 完整对话页与侧面板 | 完整会话位于AI Workbench；项目、测试、文档、会议页侧面板共用同一会话身份和消息记录 |
| 页面上下文 | 从对象页发起时显示当前项目/对象，可显式调整；已有会话切页面时不悄悄换范围 |
| 指定对象 | 支持自然语言识别和`@`选择已授权项目、对象及附件；歧义候选只来自当前可见范围 |
| 持续追问 | 服务端保存消息、附件关联和运行/操作引用；刷新、离开后返回能够继续，不只保存在组件内存 |
| 文件输入 | 拖放/选择文件、同一条消息附多个文件及说明；每个文件独立显示上传、解析、失败与重试状态 |
| 结果与办理 | 答案带事实来源和时间；候选卡显示差异、缺项及动作；应用回执显示真实对象链接和下一步 |
| 进度与中断 | 显示排队、查证、解析、等待补充、完成、停止及失败；支持补充说明和停止，可展开工作摘要与工具结果，不展示隐藏推理链 |

跨项目查询只汇总服务端验证后可见的对象，并标明实际查询范围。没有项目的产品研究或待分类资料使用获批typed scope及用户私有暂存设计，不虚构Project；非项目接线尚未就绪时明确范围限制。全局入口不等于一次读取全租户全部数据。

## 3. 对话中的文件输入

用户无需先在不同业务模块重复上传同一份材料。系统保留原文件及定位，按用途复用抽取、映射、导入和问答服务；再次提问引用同一附件句柄。

1. **接收与归属**：在现有权限和出站政策内接收文件及用途；明确项目/产品或私有暂存范围。文件名、正文及模型推断只提供匹配候选，不能自行授权或静默选择冲突项目。
2. **解析与说明**：展示识别到的文件类型、内容摘要、页/表范围及解析缺项。各文件成功/失败独立呈现。只有扫描内容的PDF显示需要OCR，不能当成空文件或已成功读完。
3. **用途分流**：只读请求直接回答；原值导入展示字段映射与预览；自然语言生成的任务、问题、变更等进入类型化候选。未就绪能力说明可用替代入口，不能报告“已录入”。
4. **核对与补充**：提供原文/页码/工作表/单元格、原值/单位、目标字段、已有记录、拟新增/更新及冲突。只询问影响归属或当前操作的必需缺项，已明确的信息继续复用。
5. **办理与回执**：沿对应领域流程提交，展示created/reused、目标对象及状态；同一会话可接着问“现在还缺什么”“这些结果影响哪些任务”。答案重新读取当前业务事实，不能仅复述模型先前的文本。

首个可用切片复用已存在的PDF/XLSX抽取链；格式支持由实际解析器、上传限制和验证结果决定。图片/扫描件OCR、语音及其他文档格式按领域输入能力逐项接入，并在上传前展示当前支持情况。不得把“可上传附件”宣称为任意格式已能理解或结构化录入。

### 三类操作的准确边界

| 用户意图 | 执行路径 | 成功的依据 |
|---|---|---|
| “解释这份报告”“项目还有哪些风险” | 授权资料读取/确定性查询→有引用答案；无需人审业务流程 | 引用可核对，缺项、陈旧和未覆盖范围可见 |
| “把报告里的实测结果录入项目” | 已批准专用导入：可信服务抽取原值/保存导入草稿→原值预览→有权限的人确认 | 领域确认回执及正式结果；模型只建议映射，不生成实测值 |
| “根据会议内容建立任务和问题” | 模型形成类型化Finding→人工接受→独立应用→领域写入 | 已应用回执、对象版本、来源及事件/审计 |

复用同一Finding及审阅服务，在对话中嵌入现有审阅详情/操作面；Review Inbox保持集中队列和同一裁决真值。接受与应用仍是两个明确动作；普通对话“好的”不自动转为批量应用或专业签核。专用原值导入不额外套一层不适用的Finding流程；一份材料同时含原值和建议时，按上述路径分别呈现。

重复上传按既有tenant/project/目标版本/内容指纹规则复用适用批次，改名不新建重复结果；跨权限不泄漏重复存在。语义相似仅提示人工判断，复测、新日期或新配置不自动合并。同号重试复用请求与回执；同号不同载荷冲突。多批准单元显示各自结果，不能把部分成功画成全部完成。

## 4. 会话、运行与业务状态

会话是持续交互记录，一段会话可以包含多个请求/运行，不能等同于一个永不结束、预算无限的Agent Run。消息和附件保存也不产生正式Task/Test/Decision真值。

实施时明确以下逻辑记录的字段级schema、物理映射、版本/状态、API、复合约束、保留及旧接口兼容；逻辑职责如下；0176–0177候选的已接范围及物理映射见本节后表，尚不代表全部逻辑字段已交付：

| 记录 | 最小职责 |
|---|---|
| Conversation | 租户、创建者、标题、当前上下文版本、消息顺序、归档状态；默认仅创建者可见，项目成员身份不自动授予阅读他人会话权 |
| Message | 稳定消息/请求号、作者、类型、正文/版本、回复关系、提交和结果状态；客户端不可伪造系统/工具消息 |
| Attachment reference | 文件/解析产物句柄、内容摘要、归属、原件定位、状态及来源权限依赖；原件复用现有私有存储 |
| Run/Operation link | 消息→现有run/lineage→观察/候选/导入批次→审阅/应用/回执，保持可追溯 |

## 5. LangGraph与已有架构的衔接

统一对话负责用户交互；服务端识别意图并校验适用能力，单次解释可复用现有Chat/Gateway，复杂查证和工作包沿LangGraph组织上下文、工具观察、条件分支和有界循环。确定性上传、查询、映射模板及业务确认直接复用领域服务，不强迫每个动作调用模型。

身份/授权、ContextManifest、预算、租约、停止、幂等和审计由项目公共运行控制提供；LangGraph本身不承担业务授权真值。正式业务状态、审批和事务仍在FastAPI领域服务；`pdos_agent`业务表零写，模型工具不暴露review/apply/批准操作。

当前基础已有项目内单次Chat、持久请求与重放、PDF/XLSX抽取、专用报告导入及测试计划候选；事件执行器已有LangGraph骨架和受控工具循环切片。会话历史、全局上下文切换、附件随消息提交、跨入口恢复及统一结果办理仍须实际接线。不能以单次run持久化推导完整会话已实现。
