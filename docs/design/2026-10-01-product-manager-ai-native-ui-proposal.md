# 产品经理空间 AI native 界面优化方案

日期：2026-10-01。状态：用户授权后已实施首版 UI，并完成本地检查，具体范围、证据和剩余能力见 [首版检查点](../reports/evidence/product-space-ui-20261001/result.md)。下文保留完整目标方案，未全部实施；主参考为用户指定的 [产品空间 HTML 初稿](2026-10-01-product-space-mockup.html)，PDF 仅作辅助。不修改现行业务状态、AI 资格、写入分级或 N/P/Q 验收状态。

本次优化沿用已采用的 Linear 风格，以用户给出的“欧美车载应急锂电池充气泵”场景为主线。用户从小Pai表达目标或提供文件，系统在已授权范围内准备并推进工作，用户在信息缺口、内容取舍、具名批准和发布节点参与。总览显示待裁决候选、进行中的工作和证据缺口，八区提供专业成果视图和必要编辑。

## 1 视觉风格与页面骨架

复用当前 `WorkspaceShell`、shadcn/ui、Tailwind v4、Geist 和 Phosphor。全局侧栏宽 224px，顶栏高 48px；面板基准字号 13px、正文 14px、页标题 18px。圆角 8px，筛选标签可用圆角胶囊；边框和留白组织内容，阴影只用于浮层。品牌橙只强调当前主要动作，状态以文字和语义色共同表达。

| 表面 | 亮主题 | 暗主题 |
|---|---|---|
| 页面背景 | `#fafafa` | `#0f1113` |
| 主内容表面 | `#ffffff` | `#16181d` |
| 全局侧栏 | `#f7f7f8` | `#131519` |
| 内容边框 | `#e4e4e7` | `#26292e` |
| 主动作 | `#c2410c` | `#fb923c` |

采用 HTML 主参考的“空间目录 → 产品主题列表 → 主题工作台”三层结构，保留当前全局侧栏，局部面包屑返回上一层。空间首页先展示产品主题，不将研究、竞品和定义成果直接混在空间根页。主题工作台默认总览，随后是七个聚合入口；小Pai从当前主题展开抽屉，必要时进入完整目标画布。内容按 4px 网格排布，页面留白 24–32px、区块间距 24px、面板内边距 14–16px。

“产品主题”先作为现有产品线与相关工作目标的业务视图，使用真实空间/产品线身份和权限，不因改名创建新实体或把对话当产品线。一个产品主题可以尚无正式型号；定义发布后的家族/平台/系列/型号沿现有布局能力关联。空间共享研究有独立真实范围，不通过把主题标题改成“共享”来复用另一条产品线的数据。

## 2 信息架构与功能归位

| 导航层级 / 入口 | 默认工作内容 | 八区能力归属 |
|---|---|---|
| 空间目录 | 空间摘要、待我裁决、最近活动；一句话发起 | 市场空间入口 |
| 空间首页 | 产品主题卡：当前进展、待办、下一动作；共享研究和设置 | 产品线/工作目标阅读视图 |
| 主题 / 总览 | 等待我裁决、缺口与信号、进行中、真实 AI 运行 | 聚合视图，不建立新的业务对象 |
| 主题 / 研究 | 研究任务、结构化词条及来源复核 | 研究中心 |
| 主题 / 竞品 | 价格区间图、同口径对比表、观察列表 | 竞品情报 |
| 主题 / 细分 | 用户、JTBD、规模区间和假设 | 市场细分/JTBD |
| 主题 / 机会·策略 | 机会排序、方案对照、策略取舍 | 机会树、产品策略 |
| 主题 / PRD·Spec | 定义叙述、规格表、缺项与协审/发布 | 产品定义；PRD由定义生成 |
| 主题 / 验证 | 价值、可用性、商业可持续性、技术可行性及决定 | 实验/决策 |
| 空间次级入口 / 布局 | 覆盖矩阵、家族挂接与路线安排 | 产品矩阵/路线图 |

导出放在具体定义的动作菜单，定义区另有导出记录入口。投入观察放在总览的“成效与投入”次级入口。能力评测进入统一设置中的 AI 治理，深链保留当前空间和产品线，服务器仍核对租户模型管理员权限。空间成员、空间配置及具名空间责任进入页头的空间设置，产品层级维护在产品布局中按权限展开。

旧 `tab`、对象锚点、run、责任办理和导出/评测链接仍可访问；新导航映射到对应视图和记录，不静默跳回总览。未实现的视图展示真实能力状态和已有替代动作，不能显示成无数据。

七个主题入口用于查阅和深入处理成果，不要求用户依次进入七页推进流程。默认通过总览和小Pai连续办理；最近主题、My Work 原工作深链和“待我裁决”直接进入当前主题或对象，避免每次都走目录三层。主题卡的下一动作来自实际阻塞或待办，不能根据固定阶段文案推测。

## 3 总览的默认布局

总览首屏显示当前产品目标和实际推进位置。推进位置来自已存在的工作、候选和业务结果，不以静态阶段位置或手填百分比计算完成度。研究、专业约束和实验允许并行或反复进入。

采纳 HTML 主参考的两列布局：左列约 60% 展示等待你裁决，其下是缺口与信号；右列展示进行中及真实 AI 最近运行。内容容器不足 900px 时上下排列，待裁决与阻塞缺口在前。页头保留一句话继续推进和上下文场景动作。无事项时显示“当前没有等待你处理的事项”，不会虚构“AI 正在值守”。

卡片直接说明“来自哪里 → 将影响什么成果”，并提供当前合法动作。高风险批准先进入版本与证据核对，不能因为总览上有按钮就立即签名。全局总览聚合可访问空间，空间总览使用同一个组件与查询规则，不能复制两套状态。卡片中的数字、状态、来源必须来自真实回执；参考稿中的占位数不带入实现。

| 分区 | 纳入内容 | 每行必须显示 |
|---|---|---|
| 待我裁决 | 待核对候选、已接受待应用、成果待接收、适用协审/批准 | 标题、需要我的原因、业务状态、当前动作、来源概况 |
| 正在推进 | 已开始的研究、实验、专业工作和真实 AI 运行 | 当前办理人、最近进展、期限或停止条件、结果/原工作链接 |
| 证据缺口 | 缺必要来源、来源冲突/陈旧、专业约束待确认、能力/权限失能 | 缺什么、影响哪个动作、谁可处理、恢复入口 |

普通用户默认看本人可办理事项，管理者可切团队范围。排序先看是否阻塞下游，再看逾期、临期和新到事项；依据可查看。研究待结论按负责人和真实状态聚合，工作项待接收依据 `submitted`、receiver 和 `acceptance_required`，不强制普通阅读也走接收。

总览、My Work、小Pai和原业务页共享唯一业务状态。相同事项按业务身份聚合一次；不同人有不同职责时分别获得自己的合法动作。纯信息分析、T0 成功记账和已完成结果不进入待裁决。

## 4 从一句话到定义发布的界面

| 环节 | 用户可见界面 | 人的动作 | 完成后如何继续 |
|---|---|---|---|
| 发起 | 小Pai识别目标并呈现空间/产品线候选，预填编号、用户群、地区、场景和研究问题 | 核对归属，适用 T1 一次确认 | 建立真实归属，继续准备研究计划 |
| 研究计划 | 五项可逐项查看的研究计划草案，每项含方法、停止条件和建议负责人 | 接受、调整、排除及确认责任 | 合法创建的研究/专业工作进入 My Work |
| 主动研究与竞品 | 竞品候选摘要、逐项差异、口径和原快照引用 | 按当前 Finding 边界接受、修订、独立应用 | 正式记录回链，准备用户问题与细分候选 |
| 细分与机会 | JTBD 候选、评分依据、三方案对照、约束及未知项 | 修改判断、保留未知、写取舍原因 | 准备待验证假设和实验草案 |
| 实验 | 计划摘要、四维假设、成功/证伪判据、样本建议；实际结果到来后展示结果对照草稿 | 具名批准；执行后核对结果 | 将适用反馈送回原机会与方案，准备策略取舍 |
| 策略与定义 | 策略 Canvas、约束差异、带来源和验证建议的规格草案 | 修订、协审、具名正式发布 | 发布版本回链，准备布局与需求/Case 候选 |
| 矩阵与立项 | 家族挂接建议、定位冲突、发布定义与需求/Case 关联 | 核对建议，沿 N1-07/G0/G1 办理 | 进入已有项目入口和正式裁决页面 |

现有空间存在时提示复用与归属差异，不强制新建。空间和产品线创建仍核对当前 `can_create`、成员角色及对象/操作分级；候选卡的一次确认不授予新权限。创建后的自动接续、分派和运行须由实际后端能力完成，前端跳转不能冒充业务推进。

研究主题中的认证、法规及安全要求仅是待研究问题，必须依据实际产品配置、销售市场、适用工况和权威来源形成结论。演示中不提供法律合规结论或模拟认证通过。

## 5 候选卡与裁决面板

空间目录和小Pai保留一句话目标入口，可选择岗位任务作辅助。任务用于提供上下文与合适问题，结果只落到实际需要的对象；商业测算使用已有投入/风险能力及受控外部引用，不增设平行财务系统。只追问阻塞目标和判断的信息，其他缺项列入后续工作。

建立归属候选增加已检索范围、相近空间及重复原因，允许选择已有空间。负责人、成员只是建议，当前有效权限决定是否可确认；跨空间引用仍重新核对资料权限与受众。缺零售价或上市地区时说明影响的步骤；不阻塞建立归属的缺项不强迫填写，也不自动复制相关空间的私有资料。

列表行先显示候选标题、摘要、状态、重要缺项和一个当前动作。点击后桌面打开宽约 480px 的详情面板；内容较多时可进入完整详情。手机使用同一内容的完整页面。对话中的候选与总览中的候选打开同一审阅内容和状态。

面板从上到下为：标题与归属、建议/差异、主要依据、缺项及影响、适用裁决动作。证据和历史以独立分区展开。默认是可读的草案，点击“修订”或用小Pai表达修改才打开局部输入。来源过期、权限变化和实验失败等重要状态始终可见。

| 当前办理规则 | 面板动作与状态 |
|---|---|
| T1 | “确认并创建/应用”；展示具体写入对象与范围 |
| 尚未迁移的 Finding | “接受候选”后显示“已接受，待应用”；再显示独立“应用到业务记录” |
| T2 | AI 准备申请或评审材料；进入具名批准/发布，不能由 AI 执行 |
| 来源变化 | 提示受影响项，提供重新核对/重新分析；禁止沿旧版继续应用 |
| 结果未确认 | 显示待确认状态，读取原回执或按原请求恢复，不能重复新建 |

用户希望逐条接受/修订时，服务器须支持对应分项裁决身份及应用回执。现有整批 Finding 可以逐项查看和修改，但不能仅把 UI 拆成卡片就显示某一项已独立接受或应用。部分接受、排除和依赖单元的原子性须在实施时接入真实领域服务。

必要的决定原因和具名说明保持；普通采纳不额外增加没有业务用途的必填作文。允许按实际接口支持程度用原因选项和可选补充减轻录入。

## 6 专业视图与信息层级

| 页面 | 主视图 | 默认内容 | 按需展开 |
|---|---|---|---|
| 研究 | 工作清单与主题词条 | 问题、预期决定、进展、下一动作；可复用的研究判断 | 方法、停止条件、原资料、词条推导与修订 |
| 竞品 | 价格区间图 / 同口径比较表 / 观察列表 | 品牌/型号、选定指标、日期和可比性 | 配置、工况、报价口径、原文 |
| 细分/JTBD | 用户问题清单 | 用户、场景、任务和目标结果 | 市场规模参数、来源和推导 |
| 机会 | 机会树与方案对照 | 用户问题、状态、关键差异、待验证项 | 评分依据、完整约束、需求和历史 |
| 实验 | 状态清单与结果对照 | 假设、负责人、状态、结果/下一动作 | 完整计划、批准及执行证据 |
| 策略 | 分区 Canvas | 当前取舍、依据、约束和未决问题 | 完整九区、比较路线、历史意见 |
| 定义 | 规格表与缺项审阅 | 条目、值/单位/工况、确认状态、验证建议 | 原引用、版本差异、协审和发布历史 |
| 矩阵/路线图 | 覆盖矩阵与真实路线安排 | 覆盖、重叠、定位冲突和已知日期 | 层级维护、主数据引用、处置历史 |

责任人和期限作为元信息显示。“调整责任”进入负责人菜单或详情的协作分区，空间级责任进入空间设置。责任调整预览、原因、接续历史和批准失效规则保留。

词条承载已有研究结论、约束和来源的阅读视图：显示值或判断、适用范围、来源、候选/已生效/被质疑状态，以及受影响的机会和规格。先映射现有对象和引用；需要独立持久化身份时另按共同合同建设，不能仅新增前端列表就产生正式知识。

竞品三种视图读取同一来源集合。宣传、实测、推断、未知，以及我方目标值分别标注；缺工况或口径不一致时明确不可比。机会分布图和排序使用同一组换算值及确定性评分；没有依据的点不画在图上。市场规模只有输入、适用范围和推导均可核对时才显示区间：不同细分存在重叠时不能直接相加，缺可靠输入则显示未知。

PRD 是当前产品定义的叙述视图，规格是同一版本的条目视图。桌面并列呈现，选中规格显示来源、验证方法和专业缺项；手机上下排列。叙述不得自行补出目标价、成本、上市日期或已完成验证。

## 7 数值和证据呈现

机会评分使用现有确定性规则 `重要度 × (1 − 满意度)`。AI 从来源提取原始数值、样本和量表，规则引擎按实际政策归一化并计算；人可修改原始值及依据。面板显示原始量表、换算结果及来源，缺数据时为未知。不会用滑块、默认中值或模型主观评分替代证据。

证据默认显示“来源名称 + 时间 + 引用片段 + 质量提示”，重要的陈旧、冲突、有新版及不可读取状态可见。阅读固定原快照，服务器继续校验其身份和 digest。哈希、快照 ID、请求 ID 和批准 ID 放在“技术核对”分区。批准摘要首先显示具名人、时间和所批准的业务版本。

专业规格未知时显示“待专业确认”并给出相关工作入口。实验样本建议与真实样本、计划阈值与实测结果分别呈现。AI 生成完成、候选接受、业务应用、实验实际完成和正式发布分别标状态。

## 8 小Pai与持续推进

使用现有小Pai全局入口和侧面板。主题中的“召唤小Pai”打开参考稿的上下文抽屉，明确当前空间、产品主题、目标及资料范围，呈现真实步骤回执和同一批候选。复杂的跨步骤工作可展开完整目标画布：主列是目标、候选、接续结果及冲突差异；右列是目标、实际进度、未完成事项和固定版本资料。两种呈现共享同一会话和业务状态，窄屏上下排列，先办理事项再查看上下文。

新证据与人工修改冲突时显示当前值、修改时间、新建议、引用及影响；默认保留原值，提供保留、标记不可比或形成待验证候选。没有可靠依据的新建议不能直接替换正式规格。关闭、换区或刷新后恢复目标与业务回执；自动保存提示只在成功保存后出现。某一步等待批准、缺信息或能力不可用时，其他独立工作继续。

普通业务区移除重复的资料核对和运行器顶部面板，将其能力接入“比较方案”“准备实验”“检查规格缺口”等上下文动作。完整来源选择、运行记录和失能原因仍可展开。

任务范围独立于页面范围；切换产品线或页面不改写已运行任务。首次委托说明目标、归属及停止条件，后台按授权、预算、依赖和资格接续。页面关闭后持续推进是后端交付要求，不以原型动画或页面定时器证明。无变化不反复生成相同候选。

个人对话和私人附件不因创建空间自动共享。只有明确用于该工作且当前授权允许的资料进入空间成果；共享摘要、来源和原文分别按受众权限呈现。每次实际读取、裁决、应用和接续重新鉴权。

## 9 统一范围与自动更新

唯一范围选择器支持全部可访问工作、空间共同工作和具体产品线，所有专业视图读取同一 URL 状态。候选所属产品线独立显示；“全部”筛选不会被当作新建归属。切区、后退和分享链接保留范围，未知或无权范围明确报错。

业务写入回执、AI 运行完成和成果接收后按受影响对象刷新总览、列表、详情和计数。跨用户变化先利用已有事件能力；不足时采用页面焦点恢复及适度后台读取。失败显示数据待更新，手动刷新留作恢复动作。

后台更新不得覆盖脏表单。新版本提示可比较差异，权限变化清除敏感内容，旧范围迟到响应不能污染当前视图。锁定范围缩小到当前对象及冲突写入，其他工作保持可读和可办理；原请求回执、提交中的范围和版本守卫不能删除。

## 10 移动端与键盘

在 320/390px 下全局侧栏折叠，七个主题入口改为有标签的选择器，避免重复参考稿的横向滚动导航。范围选择独占一行，总览依次呈现待裁决、缺口、进行中和运行记录。目标上下文放在候选之后。规格及竞品宽表只在表格容器内滚动，关键编号、条目和选中详情仍可读取；不让整个页面横向滚动。小Pai抽屉与长详情采用完整页面，主要动作位于内容之后，避免固定工具栏遮住来源和输入。

触摸动作有效区域至少 44px；正文和编辑输入保持可读字号。所有主要动作提供文字，不仅依赖图标、颜色或 hover。键盘能打开/关闭面板、查看来源、修订和裁决；关闭后焦点回到原触发控件。涉及签名和正式发布不增加容易误触的单键快捷批准。

## 11 实施范围和顺序

| 顺序 | 连续交付范围 | 核心验收 |
|---|---|---|
| 第一轮 | 三层导航、主题总览、小Pai抽屉、统一范围、设置归位、候选详情和受影响更新 | 从总览找到真实事项、完成适用裁决/应用、看到业务成果与一致状态 |
| 第二轮 | 无空间发起、空间/产品线候选、研究分项与具名分派、接续协调和恢复 | 一句话进入研究；任务真实出现在责任人的 My Work，关闭页面可续接 |
| 第三轮 | 竞品→细分→机会→实验→策略→定义的上下文衔接与专业视图 | 来源可核对，未知不补造，失败实验反馈，具名协审/发布沿原服务 |
| 后续汇合 | 产品布局、发布定义→需求/Case→G0/G1 | 真实关联、版本、批准及 N1-07 衔接完整 |

前端可独立实施页面结构、专业详情和设置归位。分项裁决、建议负责人分派、空间 T1 入口、持久接续与跨能力调度属于领域/运行缺口，不能用隐藏按钮或模拟状态宣称已经完成。沿 N1-01～07、N3-01/02、N0-03、N6-04、N7-02 等原归属建设，不新增平行状态清单。

## 12 验收场景与设计交付

以锂电池汽车充气泵的七步场景集中验证：发起并建立归属、五项研究及 My Work 分派、竞品候选裁决与应用、细分与三方案/评分、具名实验与结果核对、策略/专业约束/定义协审发布、矩阵与立项候选。用户无需先打开空白表单或背跨区顺序；需要修订时进入局部编辑。

同时检查：旧深链恢复、范围连续、无权/撤权、来源漂移、未知和冲突、部分结果/原请求恢复、协作者更新、脏表单保护、局部锁、模型未开放及人工替代。实施时按影响集中做亮暗和 320/390/1024/1440px 的实际浏览器检查，包含键盘和手机办理。真实模型资格、原正式出口和 N/P/Q 状态分别按原条件验收。

方案阶段交付包括本方案和同风格的可交互页面演示。演示中的候选、数量、来源和状态为模拟资料，不调用模型、不采集外部资料、不写业务数据库，不证明持续调度或真实资格。演示用于核对导航、布局、候选审阅、局部修订、Finding 双动作和 T2 入口。用户随后授权的真实应用实施另见首版检查点，不将下述方案演示证据当作业务验收。

演示已完成 [19 项本地交互检查](../../output/pm-ui-proposal-20261001/reference-html-interaction-checks.json)，覆盖三层导航、七个专业视图、词条与竞品三视图、证据类型、PRD/规格选择、T2 发布守卫、主题/空间/共同研究隔离、小Pai与总览同步裁决、接受后独立应用、归属候选复用、负责人缺失守卫、评分校验和换算、冲突保留原判断、具名批准后仍待执行、范围保持与恢复。此处的分派、批准及应用均为本地模拟交互，不是业务验收。

本地浏览器检查覆盖亮暗主题，以及 320/390/1024/1440px 视口；内嵌预览在 320px 下可用宽度为 288px，1024px 下七区导航宽度与滚动宽度均为 942px，根容器没有横向溢出。桌面沿用 224px 全局侧栏，手机使用全局导航按钮和主题视图选择器。检查了总览、小Pai、机会刻度、PRD/规格和发布缺项；Escape 关闭详情后焦点回到发布核对入口。长详情打开后定位至标题，桌面动作与正文滚动分离，手机动作放在内容后。
