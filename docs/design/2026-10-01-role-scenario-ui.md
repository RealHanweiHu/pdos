# 岗位场景 UI 使用模型 · 2026-10-01

用户要求重构整个 UI，并按不同角色的真实使用场景设计。2026-10-04 用户纠正“千人千面”的含义：登录即进入本人的页面，不由用户先选择工作视角。本模型按该要求更新。

本模型继承公司橙、Linear 密度、Geist、Phosphor、双主题、shadcn/ui 与 Tailwind v4，覆盖当前全站入口、本人工作和项目专业办理的组织方式。

## 角色、专业与办理责任

账户角色为 owner、admin、product_manager、project_manager、engineer、quality、supplier、customer。工作体验由已验证的登录身份自动生成：产品经理对应产品工作、项目经理对应项目推进、工程师对应工程设计、品质对应测试与品质、Owner 对应管理工作、Admin 对应系统管理。岗位只组织界面；Owner、Receiver、Verifier、具名评审、代理与批准政策继续以服务器记录为准。

所有内部成员登录直接进入 `/my-work` 本人工作台。首页显示本人姓名、岗位相关入口、实际具名分派的任务和待签核事项；产品经理的本人研究与定义队列直接可见。工程和品质根据实际待办的紧急程度展开执行或验证场景。侧栏和手机导航自动排列岗位常用工作，不显示工作视角选择器，不读取旧的 `pdos.work-perspective` 浏览器偏好。兼任岗位产生的责任继续由服务器待办覆盖，不靠手动视角切换声明任命。

管理员在“成员与角色”中按实际兼任情况勾选并保存额外工作模块：产品、项目、工程、品质、PIE、供应和管理决策。主角色模块自动保留；兼任配置持久保存、记录审计，已登录成员重新加载页面也读取最新配置。本人首页同时呈现主角色与兼任模块，侧栏取这些模块入口的并集，不再让用户选择工作身份；产品兼任者的本人研究与定义也直接前置。模块项目链接在选择项目后进入对应专业页，原本人全部待办仍保持。

模块配置只由当前租户有权管理员维护，不赋予专业资格、具名批准或管理员权限；系统管理模块只由已有 Admin 主角色产生。Admin 不维护 Owner/Admin 账户，Owner 保留原范围。外部账户只进入已授权项目及对应样机回应，不接受内部兼任模块；改为外部角色前须清空兼任配置，角色与模块可在同一次更新中原子改变。未知账号角色不推断内部身份。

## 日常场景及入口

| 工作视角 | 日常目标 | 首页与实际办理路径 |
|---|---|---|
| 本人工作 | 找到当前责任，提交结果与交接 | 我的工作 → 执行/验证接收/批准协调/AI 建议/立项前工作 → 原事项办理 |
| 产品工作 | 从用户场景及证据形成定义和立项输入 | 产品工作台 → 原主题研究、机会与定义 → 需求池/开发案例 → 产品反馈 |
| 项目推进 | 核对计划责任、处理阻塞并组织评审 | 项目 → 计划任务 → 本人协调待办 → 组合例外 → 原评审与交付 |
| 工程设计 | 沿真实版本推进专业设计、整改及交付 | 我的工作 → 项目工程/规格与研发 BOM → 变更与实施 → 验证及交付 |
| 测试与品质 | 执行测试，核对配置证据并验证整改 | 我的工作 → 项目执行测试 → 问题与 CAPA → 独立验证/签核 |
| PIE 与制造导入 | 核对导入输入、齐套、工装与试制证据 | 我的工作 → 项目试制与样机/工装 → 原任务结果 → 文件与交付接收 |
| 供应协作 | 处理齐套、供样、供方异常和成本协调 | 项目物料与供应 → 恢复方案/实际到货 → 原问题复核 → 成本与供方记录 |
| 管理决策 | 处理需要取舍的例外，追溯依据和落实 | 组合待决与例外 → 产品投入/案例评审 → 原项目与责任 |
| 系统管理 | 维护访问、组织、模型及运行条件 | 成员与角色 → 组织与流程 → 模型与 AI 治理 → 运行事件 |

系统管理自动优先给 Admin，Owner 仍由设置进入已有管理功能。上述业务路径不声明本人已经被任命为产品经理、PIE、供应负责人或管理批准人。没有独立接口的完整工艺路线、SOP、工时及生产接收流程不能借视角文案宣称已实现。

## 全站布局

工作首页 `/` 解析当前身份后打开本人工作台；本地账号登录直接进入本人工作台，钉钉的原首页回调沿同一入口承接。项目快照保留在 `/dashboard`。常用工作在侧栏优先显示，其余已授权入口在“其他工作入口”中展开；设置保留固定入口。搜索、采集和小Pai由原上下文承接。保持 224/56px 可记忆侧栏、48px 固定顶栏、当前路径、内容自适应、手机 44px 操作及键盘焦点。

产品、需求、案例和知识详情移除通用的岗位工作路径横幅。岗位常用动作归入本人首页，专业数据与动作继续由原领域组件呈现。小Pai可在本人首页直接打开，承接现有个人上下文。

## 本人工作

默认根据实际已读取待办的紧急程度打开执行、验证接收、协调或 AI 场景，而非按身份猜任务。保留“全部办理”、完整服务器计数、实际已加载数量和分页。立项前工作单独查询与计数，无法读到时显示未知，不记成零。

优先事项点击先切到所属场景，再定位原记录。旧锚点、hashchange 与前后导航同样能打开正确场景。已打开的独立办理面板持续可见；隐藏场景的原组件保持挂载，未保存输入不丢失。查找、提醒与批量办理收在工具抽屉，错误与实际回执按原规则呈现。

## 项目办理

项目主导航按视角显示六个常用工作，其他领域通过“更多项目工作”选择；当前非优先领域仍显示其选中标签。所有现有领域路由与查询保持，显式旧链接优先于默认视角。新选择项目时进入该视角的专业工作；登录身份自动排列入口，正在办理的显式页面与草稿保持。

专业页面采用任务导航与单一办理区，避免把所有专业表单同时展开：

- 计划：执行基线、正式排期、进度预测、日期承诺、资源台账、资源协调。
- 工程：规格与研发 BOM、设计修订与交付、工程变更、客户新要求、工程评审。
- 试制/测试/品质：试制与样机、执行测试、规格验证覆盖、实际配置、固件结果、问题整改、失效预防、样机回应。
- 物料/供应：齐套、短缺恢复、成本资料/输入/冻结、供方工程、准入合规、工装试样、通知跟进。
- 例会/决策：当前轮次与行动、决策依据、例会节奏与名单。
- 评审/交付：当前评审及签核、交付清单及缺项。
- 组合：待决例外优先，进度、健康、里程碑、比较、物料、供方、资源、产品投入和管理简报分别办理。

任务间保留组件与草稿。查询、锚点、延迟记录和嵌套折叠记录能够打开所属任务；手动切换取消旧链接的延迟定位，刷新数据保留当前选择。桌面为任务左列与办理右区，手机仅任务导航横向滚动，页面主体不横向溢出。Tab/方向键/Home/End 与明确 tabpanel 关联可用。

## 外部回应与可信边界

客户和兼容 supplier 账户只读取原授权投影中同 audience 的样机回应，不读取内部 Build、样机配置或测试详情。仅对当前 pending 请求提交真实的 approved/rejected 结果及说明，无 waiver 入口。响应后重读原记录，未知结果、403/409 和不完整资料显示可恢复错误并保留输入。该界面不新增外部门户、外部账号或真实外发权限。

AI 接受/独立应用、T0/T1/T2、独立验证、正式冻结/发布、具名签核和服务器鉴权保持。界面可读入口、工作视角或空态都不能替代这些事实。
