# PDOS 完整目标架构 v1 · 执行方案

日期：2026-10-02。依据：[完整目标设计](2026-10-02-pdos-complete-target-architecture-v1.md)。本方案落实用户“按照这个完成执行方案，并开始执行”的授权。目标是独立新系统；本次启动不代表全系统、真实模型资格或生产验收完成。

## 1. 授权、工程与状态来源

新工程位于仓库内 `pdos-next/`，拥有独立 Python 包、Next.js 应用、依赖锁、Alembic 历史、数据库与运行配置，不导入旧 PDOS 业务模块，不连接旧业务库。复用既定技术栈和 UI tokens，不以旧表、任务编号或现有能力限制新目标。目录选择是可逆的实施选择，未来可独立迁出。保留原工作树所有未提交修改。

用户随后要求衔接已有成果并提高执行速度。按[复用与并行方案](2026-10-02-pdos-next-reuse-and-parallel-plan.md)，独立组件/资产可以复制，协议与确定性算法按新接口抽取，旧批准/资格/业务实例不继承；新工程独立不意味着重写这些已有成果。三路只读核对形成施工包文件归属与依赖；公共接线和候选验证由主会话统一执行，活动状态只在唯一清单维护。

本方案记录目标、依赖、交付及验收，活动状态只在[唯一清单的新工程队列](../../tasks/ai-native-integrated-todo.md#pdos-next-queue)维护。旧 N/P/Q 编号、未完义务及 9/27 数据恢复边界保留，不把新 G 阶段冒充旧条目完成；本轮新工程优先于旧队列继续开发。G0～G5 为工程检查点，不新增每步审批；原正式人工出口及生产、git push、云资源、真实外发、敏感材料模型出站仍需对应明确授权。

仅取得合订 Markdown，没有原始 contracts JSON、分册目录、示例和 validate_contracts.py。从正文/附录重建的实施契约标记 `derived_from_consolidated_markdown`，不是声称收到原设计包。专用 payload 在对应切片实现；尚未实现的命令不暴露为可调用工具。目录覆盖检查不代替业务验证。

### 3.1 当前施工与收口规则（2026-10-03 执行优化）

用户要求优化慢进度。本节把既有“连续建设、按影响验证”落实到当前新工程，适用于后续施工；§4及§7～13的首轮/历史分工只供核对接口与复用，不重新开工。目标、对象职责、AT-01～48、I01～I20及原N/P/Q人工出口保持。

- **一个主业务结果在制。** 从入口连续做到领域保存、结果/历史回读与必要异常；DTO、端口、配置、迁移、一次对话都属于内部步骤。默认主会话执行，历史并行容量/分工不构成新Agent或任务消息授权；明确授权且文件归属齐备的独立交付才并行，公共接线和验证集中。
- **带着实际调用方接入。** 先核真实DTO、唯一写入口、保存组、范围与来源读集；复用已有模块和组件，后端/持久端口/API/UI在同一闭环接通。仅因接口或职责实质改变才修订对应合同，不为每个窄修另起草案和交接报告；隔离包完成只记待接入，不计业务可用。
- **真实条件分层。** 独立测试夹具可以用明确合成职责、来源和测量覆盖正向领域事务，生产资格/专业结论仍须真实依据。缺真实资料、模型许可或人工出口只暂停依赖动作；不向实际缺资格角色补造事实，不把拒绝负例当正向业务完成。当前闭环本地实现无可推进项时，登记恢复条件后接现有已满足依赖的业务工作。

| 时点 | 必须执行 | 通过后继续 |
|---|---|---|
| 连续开发 | 合并必要类型/lint/编译；权限、写入、事务、已知缺陷立即做最小受影响验证。 | 接本闭环下一动作；不因接线或对话结束启动完整构建、整链浏览器、迁移往返和长报告。 |
| 接入实际端口 | 核同一实际DTO/持久端口/命令/API/UI及正向保存；必要失败覆盖作用域、来源漂移、幂等与原子性。 | 保留原失败及定向修复证据；只扩展有新失败或具体依赖风险的范围。 |
| 业务候选收口 | 固定候选与覆盖，集中构建、受影响HTTP/浏览器及按风险选取的主题/尺寸、迁移往返、数据/权限/恢复检查。 | 记录已验证开发能力和未覆盖条件，继续下一可建设闭环；正式判据未齐不勾完成。 |
| 原正式出口 | 按适用AT/原DoD与P/Q合同执行同一冻结候选的联合门禁和真实资格/试用证据，保留人工确认。 | 不用分散旧通过拼成新候选联合通过，不削减必需判据。 |

每次追加检查须对应源码/接口变化、前次失败或明确风险；无变化的同候选与覆盖不重跑。公共schema、依赖锁、备份/迁移按候选集中整合，兼容检查复用核对过的隔离环境；必要备份仍在数据库变更前执行，权限与写入检查不能为提速延后。

**当前性能任务并入业务闭环。** 第二十/二十一波Current配对深读实测约230/225秒，600秒传输容忍不表示提速。先在核对过的本地合成材料上记录一次调用链、SQL/重复读取和锁等待；以数据确定优化点，不猜原因或不断重读同一深链。若消除重复解析/查询，保留完整来源闭包、范围/版本/撤回与执行守卫；请求内复用必须明确依赖和重核时钟，不跨请求缓存资格或替代提交前重核。复用同材料验证结果/读集与耗时；没有实测前后数据不报提升。原资源摘要兼容也须固定实际依赖，候选摘要匹配不代表当前执行有效，撤回/占用变化仍拒绝。

**状态只在唯一清单。** 每个闭环一个状态：可用业务结果、候选/必要覆盖证据、剩余缺口/恢复条件。原始日志与失败版本放证据目录；已封存波次转只读留存，续接不默认加载。以正向可用结果和待条件验收衡量进度，不用波次、文件、表数或测试数充当完成率；正式完成继续按原条目全部判据裁决。

## 4. 首轮开工合同：G0.1 + G0.2 的窄路径

用户结果：在真实产品范围登记 UTF-8 文本资料，查看不可变原文，选择准确行与引用，记录一条来源事实；刷新能回到原记录/工作；查询真实回执；对未被消费且无人后续编辑的记录预览后一次确认撤回。可以创建目标型工作，AI 未配置/未获资格时明确等待，仍可人工办理。

初始输入只支持粘贴/导入小型 UTF-8 `.txt/.md`，不冒充 PDF/OCR/病毒扫描全覆盖。AI 合成 provider 仅测试注入，生产没有自动晋升入口；真实模型接线、出站许可、独立 golden-case 资格留至 G0.2 后续。临时领域持久 Run 验证 stable intent 与结果恢复，不称为已经完成 Temporal/持久 LangGraph 检查点。

最低守卫：服务器会话绑定 tenant/actor；来源与目标同产品；来源可读且有效；原文定位真实；目标 audience 不扩大；请求 payload 禁止可信身份字段；AI writer 与 human owner 分离；资格绑定能力/provider/operation/purpose/版本/到期；开始和提交前检查 cancel_epoch；同 key 不同 payload 冲突，跨 key 同意图返回原副作用；事务内事实+回执+审计+事件；撤回保留历史、阻止人工修改/下游消费。

首轮不建几十个空页面，前台只暴露实际可办理的产品资料和工作。单一入口同时看到来源、事实、委派结果和活动；桌面、320px、双主题、键盘与错误状态按实际路径检查。

## 5. 验证、证据与退出标准

每次 DB 操作先核对实例、端口、数据库、唯一 marker、角色和允许目标。测试仅使用显式 `TEST_DATABASE_URL` 指向本轮自建独立 `pdos_test`，绝不回退 `.env`，绝不操作 57432 存续联验或已有预览容器。应用/认证/迁移身份分离；新迁移链独立编号，不在旧 0416 历史插入。

开发中合并类型/lint；写入、权限、事务立即做最小影响验证。闭环候选固定源码摘要后集中：真实 PG API/事务、并发、重复意图、来源/租户/ACL、RLS、取消/补偿、迁移往返，以及当前 UI 的构建与 HTTP/浏览器路径。恢复、长工作、模型/工厂与外部生效在其切片补齐，不伪造本轮全覆盖。

首轮证据位于 `docs/reports/evidence/pdos-next-g0-20261002/`；后续沿当前业务证据目录记录候选 hash、环境标记、运行命令/结果、适用 AT 子范围及未覆盖项，不另设重复索引。测试数不等于完成率，合成 provider 不等于真实资格。完成一个切片必须实际 UI 可办理、领域结果真实、必要异常通过且限制明确；G0 完整退出仍须 G0.1～4 全部及适用真实条件。

## 8. 专业验证前置的接入合同

按目标架构“试模前的品质准备”接入具名专业职责与资格、固定版本的验证请求、逐项方法适用核对和请求级暂定窗口。复用既有 Build、双配置、样件身份、资料安全与验证准备；当前准备记录继续保持原义。活动状态仍只在唯一清单更新。

| 接入面 | 复用与新增事实 | 必须保持的边界 |
|---|---|---|

最小接口固定后可三路并行：工程包独占新增专业权威及验证前段领域模块；验证包独占对应夹具和行为测试；界面包独占专业验证组件及其读模型。主会话独占共同模型、按真实 head 分配的迁移、命令注册、API/BFF、引用覆盖目录与统一验收；各包不得旁路写共同事实。沿用现有验证与资源纯包，避免另建 Build、样件或资源状态机。

集中验证覆盖职责/资格分离、作用域与来源、撤销后恢复的版本变化、固定准备绑定、新旧时钟、幂等、一次确认后读集变化、事务回滚，以及未知方法/资源的页面路径。缺真实资格只阻塞对应正式动作，受控本地实现与合成负例可继续。实际交样、品质接收、开测与样件消费依赖真实执行和预约端口，后续按 G2.3～4 接通。

联合检查仍由主会话统一发起，固定同一候选后可按独立进程和唯一租户夹具并行。Build、成本、验证准备等重夹具模块优先分散，结合实际耗时调整分组，不只按测试函数数量平均；会改变公共表结构或停用门栓的用例单独串行，schema 核对随后执行。同一进程内的运行时注入和事件钩子不使用线程并发，各分组通过不能与旧候选结果拼接。

## 9. 实物交接的前置衔接

目标架构已明确 Build 的 `preparing→authorized→executing` 与 canonical `build.start`。当前计划 Build 和外部已发生产出记录只实现其中部分事实；不能把已有样件、合成职责、`nature=real` 或零占用窗口映射为已经批准并开工。后续先接用途绑定的准备度事实、必要具名授权与开工记录，再将实际执行状态供验证核读取；固定计划、双配置与旧产出历史保持，执行事实绑定同一 Build 身份，不建立另一套 Build 真值。

开工前逐项核对真实权威供给、资源资格/校准/日历、适用规则与限定用途；缺项仍为未知。探索用途的例外必须有真实限定依据，不能以通用“已确认”解除不可豁免条件。一次 `build.start` 确认绑定本轮当前事实与批准范围，不兼任工程发布、制造放行或客户承认。

上述端口齐备后形成“具名实物就绪/暂缓 → 实际配置的方法适用 → 交样 → 品质部分接收或退缺项”闭环。复用已有 SampleUnit、BuildLot、ActualConfiguration、专业事实与验证核；只扩展现有 FormalVerificationRequest 不可变版本链及 Current 指针，保留前段 draft 版本和各自时钟。方法在计划配置上适用不自动适用于实际配置。样件可用性须核对当前就绪/暂缓、配置、精确测试项与已有预约/消耗；未知不能接收。开测进一步依赖资源和样件同事务预约/消费，结果导入另接原值核验。

依赖合同固定后可独占并行：准备度/执行事实与其行为测试、实物就绪及交接适配、对应 UI/helper。主线统一共同状态约束、迁移、职责操作映射、命令/API、来源引用覆盖和联合验证。此节是后续依赖合同，实际开工和验收状态仍只在唯一清单登记，不以设计端口存在宣称实际能力。

## 10. 固定范围的内部开工闭环

沿用同一 Build 和已固定双配置，canonical `build.readiness.compute` 增加执行范围模式，旧准备读集和摘要保持兼容。执行范围固定用途、计划数量与单位、场地、完整区间及 IANA 时区。真实库存/外部占用和设备资格从受控事实入口接入；签发上下文由服务器配置，资料中自称获批不能授予资格。物料池与资源在同租户跨项目共享锁定，未知数量、质量冻结、资格缺失、日历缺失及超额占用明确阻断。原始资料引用留在产品范围的不可变事实，公共资产只保留容量派生镜像。

物料/资源通过仅允许专业审查，不能自行形成全部准备就绪。工程分别核对产品定义与验证目标适用性，制造分别核对工艺配置与产出处置适用性；两方以具名 T2 决定绑定同一评估摘要、当前专业资格、来源和有效期。v1 规则仅支持 prototype/tool_trial 的内部制造范围；pilot 缺真实制造基线端口时保留不可豁免未知。具名决定须接受四项限定：不授权开测或样件资格、不授权外部交付、保留可追溯产出、配置偏离时停工重核。决定不兼任工程发布、制造放行或客户承认。

canonical `build.start` 为 T1，重新核对两项当前批准和事实完整性。实际开工发生时间与具名来源须落在固定区间内且晚于批准；不能从计划时间或旧样件历史推断。库存保留、资源占用、不可变开工事实、回执、审计和事件同事务提交；未知回执重试原请求，禁止重复占用。已发生配置偏离阻止开工，开工后的真实偏离应保持记录并提示停工重核。撤销、过期、来源失效、容量变化及版本恢复都会重新触发核对。

本轮三路独占：build_start 领域与本包测试；build_operational_facts 领域与本包测试；build-start 界面与 helper。主线负责共同注册、API、next_0014 迁移、引用覆盖、事务集成和统一 PG/浏览器检查。合成环境只验证业务守卫，不授予真实库存、工厂人员或设备资格；真实权威端口和 G4 制造基线保持后续缺口。

## 11. 实物就绪与品质部分接收的接线边界

下一闭环沿现有 SampleUnit → BuildLot → ActualConfiguration → Build 固定关系，以及现有 FormalVerificationRequest/Current 版本链推进。制造具名登记有精确事件依据的实物就绪或暂缓，新增不可变状态事实与当前指针，不能把开工、产出、样件身份存在或旧 `availability=unknown` 自动转换为可测试。当前生产事实、来源、权限与用途仍逐次核对；未知、暂缓、配置不符、已消费或冲突预约不能获得肯定可用性。

品质方法适用须绑定明确 sample/item pair 及其实际配置，计划配置上的方法核对不自动继承。资料是否完整、实物是否就绪和方法是否适用各自计算、各自保留时钟。交样仅固定这一次真实交付范围；部分接收只接收明确满足条件的 pair，其余缺项、原因与当前可承接的下一责任人保留。退缺项不伪造接收时间；已接收范围和原文不可被续版重写。

复用验证核的 HandoffOffer/Accept/Return、覆盖计算与事件时间合同，通过新领域适配真实持久端口。主线扩展当前请求快照只容 draft 的前段守卫，使同一版本链容纳交接事实；不新增第二套请求、样件或实际配置真值。旧核的 `production` 角色仅在服务器已核验制造职责、精确操作与用途后作受限适配，页面不能自行切换角色或推断权限。T1 发起/接收/退缺项保持一次确认与当前具名权限，资料齐全不等于已发生品质接收。

可以独占并行：`domain/sample_handoff/` 及测试负责实物就绪/暂缓事实和可用性端口；`domain/verification_handoff/` 及测试负责实际方法/交接适配与现有请求版本突变；`components/builds/build-handoff.tsx`、对应 helper 与测试负责办理与历史读取。主线持有公共请求模型/守卫、专业事实操作映射、现行迁移、命令/API/BFF、引用保护及统一验证。先固定双方接口再施工，共用模型与公共验证不并行改写。

该闭环完成前不开放承诺开测时间、样件/资源预约消费、TestRun 或结果导入；接收成功也不表示已经开测。正式开测在后续独立核对资源和样件的同事务占用、资格与来源时钟。此节仅固定后续施工依赖，不登记任何实现或验收完成，唯一清单仍是活动状态来源。

## 12. 已接收范围到实际开测的后续合同

本节保留施工前合同；当前实现与验证证据见[第十三波](../reports/evidence/pdos-next-wave13-20261002/result.md)，活动状态仍以唯一清单为准。

实物交接闭环验证通过后，下一施工入口为“明确接收的 sample/item 范围 → 固定 Run 计划与完整资源窗口 → 具名承诺 → 同事务占用并实际开测”。复用同一正式请求版本链、真实样件身份、实际配置和现有 verification/resource_readiness 核；旧版暂定时点只作参考，不推断工时、资源区间或已开测。

Run 固定已接收的精确覆盖、规程/方法/判据、配置、执行条件、设备校准与人员资格。未接收、实物暂缓、方法未知及缺项范围继续各自阻断。设备/治具/人员/样件的当前资格与可用性由受控事实供给；用完整窗口检查跨请求与跨项目冲突，破坏性样件不可重复有效分配。正式占用、实际开始、样件消耗状态、请求/Run 版本及回执事件同事务完成；结果未知恢复原请求，不重复消费。承诺开始和实际开始保留各自有依据的事件时间，不以当前系统时间补造发生时间。

可并行三路：测试资源与样件占用端口及冲突守卫；验证 Run 适配与正式请求状态推进；排程、承诺和开测办理界面。主线统一持久模型/当前指针、公共角色与命令、真实 head 迁移、引用保护和冻结候选验证。先明确 Run 与预约的原子关系，再分派文件归属，不另建样件或请求账本。结果原值导入、部分覆盖判定、专业复核与处置按后续闭环接入，本节不声明这些能力已完成。

源码衔接已定向核对：沿用 `domain/verification/handlers.py` 的请求动作、Run 动作及覆盖/缺项规则，沿用 `domain/resource_readiness/handlers.py` 的 preview、stage_formal 与 recheck_execution。现有 SchedulePromise 只有时点、RunPlan 只有身份与覆盖，不能承担完整资源计划；新增宿主 ExecutionPlan 固定区间、资源用量和依据。最小版本承诺覆盖必须与核实际推进的全部已接收范围一致；若要分别承诺多个子范围，先显式扩展核合同，不能让单个 Run 的子集代表整请求承诺。

施工前 Build 的 ResourceOccupancy 仅绑定 BuildStart，不可把 TestRun 身份塞入现表，也不可另建不互查的占用。主线须先统一预约归属和同租户全部占用的读取合同，再按稳定顺序锁定 Product、请求、Run、共享资源和样件使用门栓。测试事实须绑定实际配置、方法、执行者、日历/维护/校准与可信具名资格，制造开工资格不授予测试资格。施工前交接适配器的 reserve/run/runs 为未接通端口；本合同要求以受控持久实现替换，复用请求精确用途，不能把核内部的通用字符串当成实际授权用途。一次 T1 确认覆盖完整读集，资源子协议不得另发或重复消费确认凭证。

对已经开始的资源窗口，宿主必须提供经精确事件来源核验的 `verified_actual_start`：晚于对应接收、落在固定窗口内，并核对实际执行者。请求中的 `at` 或系统当前时间不能直接成为该事实；缺少依据时保持阻断。

## 13. 开测后的原值返回与专业复核衔接
