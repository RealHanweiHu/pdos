# Actual stored fact atom reader · staged contract

`read_fact_atom` performs bounded PostgreSQL SELECTs of an exact immutable fact and its actual common Receipt, original RequestKey association, Audit, Outbox and T1/T2 Confirmation. All queries use the actual caller Session and scope; private facts remain owner-only. The body envelope, payload/read-set digests, writer, event/family, historical proof revision/expiry and consumed clock must match. Later lawful aliases can have different request digests; at least one original writer/key/digest association must still exist.

The actual common semantic `intent_digest` is saved by the future trusted host before apply. It is not the domain `_intent`. Receipt result has exact id/revision/status and flattened `fact_kind`/`payload_sha256`, matching existing `append_receipt` behavior; no full FactRef SHA appears there. The full SHA includes Receipt/group material and is assembled later, avoiding a circular digest. Actual fact created_at is `FactAtom.received_at`; the common Receipt can be received slightly later and its own actual clock is retained.

The deterministic `pdos-capa-fact-transaction-group-v1` digest includes exact scope/fact, operation/tier, payload/read-set, received clock, fixed Receipt/proof/Audit/Outbox bindings. Outbox delivery state is excluded. T1/T2 group identity is the actual Confirmation UUID; host-only Rule import uses the actual common Receipt UUID. Confirmation expiry is checked at the saved event clock, not at later history reads. A historical current-watermark change is not substituted for the saved proof revision.

The returned `StoredAtomRead` has `current_evidence_authorized=false` and `same_uow_consumption_attested=false`. Historical consumed=True plus stored clock does not establish a real false-to-true UOW transition. The future common hook, reciprocal SQL target guards and actual schema binding still need Root implementation. The seven live FactReader gates, source bytes/issuer/participants/actual applicability/coverage/professional authority and post-all-IO refresh remain mandatory. This reader performs no writes, preview, consumption, commit, qualifications or effectiveness/closure decision and is not a public handler.

Real Session/SessionTransaction and the complete active parent chain are checked before public SQLAlchemy root getters, preventing a corrupt ancestry cycle from hanging them. Query autoflush is disabled; no pending writer effects are flushed. After group IO, actual named caller/Grant are re-read with populate_existing at a fresh server clock, followed by caller/UOW identity comparison. This does not attest all downstream owner IO; the actual authorization reader must make its final refresh after those additional reads.

Root owns this three-file staged package; `fact_storage_models.py`/codec are A-owned dependencies. Pure tests use real ORM expressions and real active Session transactions with explicit SELECT substitutes. They cannot count as installed PostgreSQL constraints, real data/ACL, source bytes, production qualification or current evidence authorization. The public484-file candidate remains unchanged.
