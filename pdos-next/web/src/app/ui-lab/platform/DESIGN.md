# 完整体验预览 · 设计上下文

这是既有 PDOS 产品世界的扩展候选。业务权威是仓库 v1.1；视觉权威是 `docs/design/2026-08-09-ui-baseline.md`。不要从此目录推导出新的业务规则或生产权限。

完整设计说明：`docs/design/2026-10-23-pdos-full-product-ui-candidate.md`。

## 方向合同

- **THESIS**：从本人要完成的事进入对象，以同一办理方式贯穿研发全流程。
- **OWN-WORLD**：沿用 Geist、Phosphor、橙色、8px、双主题与 shadcn/ui。用列表、留白和按需详情形成层次。
- **STORY**：看见责任与期限，打开依据，完成当前动作，返回原工作。
- **FIRST VIEWPORT**：224px 稳定导航、48px 顶栏、本人待办；小Pai默认收起。
- **FORM**：用户明确指定 Linear 的简洁原则；减少入口、框架和无效说明，不另造视觉品牌。

## 关键约束

六个全局入口（我的工作、收件箱、小Pai、项目、项目集、知识）与按权限产品管理；外部用户受限入口；项目四个常用视图（概览、任务、计划、文件）和专业工作更多菜单。不得合并四时间、双专业决定或三种成熟度。未知、部分结果和未生效有文字状态。所有数据是合成例子，交互只改 React 内存，没有业务/模型网络请求。

`design-data.ts` 保存岗位、工作和范围。`platform-preview.tsx` 复用队列、表格、详情、搜索和同一小Pai。`platform.module.css` 只作用于本候选，不覆盖真实应用页面。

预览顶部身份/状态/窄屏工具不属于正式应用。主案例是 P1；S2/D3 专业页面显示自己的范围摘要，明确引导到 P1 查看完整专业设计，避免跨项目拼接假事实。刷新清空演示办理和草稿。

## 工作与组织协作修订（2026-10-23）

用户要求收件箱同时容纳工作消息和团队聊天。我的工作保留待办、承诺、已完成；承诺从共享记录按“我承诺的 / 别人承诺给我的”投影，明确双方、交付、日期与预计。

“项目”页直接展示列表 / 看板 / 时间轴，不再增加全部项目、资源协调的二级导航。项目集是与项目同级的单一侧栏入口，主页面提供列表 / 看板，不展开文件夹树。页面内新建、编辑项目集，进入详情后批量移入项目；归属调整仅在项目集详情中操作；“项目”页不再显示项目集筛选、归属列或移动控件。当前候选按“移入”演示一个项目归属一个项目集或未归类，正式模型尚未冻结，不改变权限、责任与业务事实。看板按成员项目的健康状态汇总为需关注、进展正常、暂无项目，不引入新的项目集业务状态。资源需求融入项目的计划，按资源、用途、需求时间、状态和协调人呈现；点击复用同一工作事项详情，按需比较跨项目影响。我的工作新增“要我协调”分组，项目负责人办理计划、品质核对替代时段、管理者保留独立具名取舍。确认后同步计划与本人待办；计划采用不等于实际预约、样件接收或测试完成。旧 portfolio 预览链接转入 plan，不保留独立页面或搜索入口。

新模块 organization-state.ts 共用合成记录，organization-preview.tsx 与 organization.module.css 使用既有主题。新布局用容器查询，兼容实际手机和桌面内嵌窄屏；长聊天在打开和发送时滚到末尾。
